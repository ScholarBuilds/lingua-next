# 02.前端与交互规范

- 状态：active
- Owner：scholar
- 适用范围：`web/`

## 用途

定义前端里**跨页面复用的交互契约**：同一种交互在全站必须是同一种行为。

## 全产品视觉资产

- NEXUS 自有图标、按钮插图、内置封面、空状态、场景背景和数字人采用统一二次元风格。新增及替换素材遵循此约定，不混入写实摄影、拟真 3D 静物或无关风格的默认图标。
- 图标优先复用 `NexusIcon`、`LearningIcon` 中语义对应的格位；缺失语义用 Image2 补齐，同步维护图集映射。文字标签、状态和可访问名称由代码渲染，不烘焙进图片。
- 使用现有颜色、字体和间距令牌。场景插画服务人物与内容，不抢占交互空间；人物保持透明背景、原始比例，字幕置于可读的稳定区域。
- Image2 源图和生成规格分别放在 `garden-gpt-image-2/source/` 与 `prompt/`；运行时使用压缩后的本地资产，记录用途和来源。第三方人物及模型另行保留许可证，不把生成背景的许可套用到人物。
- 用户上传的封面、学习视频、书籍原封面、截图及引用资料保留原貌，不强制转绘。品牌或版权标识保持其规定形态。
- 验收覆盖深浅主题、窄宽窗口、加载与失败状态。词本缩略图固定 6:5，布局调整只能改变等比尺寸，不能拉伸。

## 背景与问题

交互不一致的代价不是"不好看"，而是**用户学不会**。同一个动作在 A 页面有效、
在 B 页面没反应时，用户不会归因到"这一页没做"，而是归因到"这个功能不靠谱"，
之后连能用的地方也不再尝试。

这类约定单靠 code review 兜不住：写新浮层的人不会先去数全站有多少个浮层。
所以约定要落到**共用组件**上——不是"记得加"，而是"想漏也漏不掉"。

## 1. 浮层（Overlay）

### STD-UI-001 浮层只准用两种机制，不许手写

| 机制 | 用在哪 | 提供什么 |
| --- | --- | --- |
| `components/Overlay` | 本仓自制的浮层，需要进本仓浮层栈的 | 遮罩点击关闭、Esc 只关栈顶、`role="dialog"` |
| `components/ui/dialog`（radix） | 表单型、需要焦点陷阱与进出场动画的 | Esc、遮罩、焦点管理、`aria-*` 一整套 |

**不允许再手写 `<div className="overlay" onClick={onClose}>`。**

两种机制**不要在同一摞里混用**：radix 的 Esc 走 document 冒泡，本仓浮层栈走 window，
一次 Esc 会被两边各收一次，把整摞一起关掉。真要叠，在里层 radix 的
`onEscapeKeyDown` 里 `e.stopPropagation()` 截住，并实测一次。

> [!note] 为什么不是「一律 Overlay」
>
> 这条原先写的是「浮层一律走 Overlay」，但全仓十二处在用 radix Dialog——设置页的
> 凭据、模型、音色，视频导入，管线，以及生图的四个配置弹窗。radix 提供的焦点陷阱
> 与 `aria` 是 Overlay 没有的，表单型浮层用它更对。规范跟着实际做法走，
> 而不是让实际做法长期违规。

```tsx
import { Overlay } from '@/components/Overlay'

<Overlay onClose={close} card="sp-modal">
  <div className="overlay-head">…</div>
  …
</Overlay>
```

| 入参 | 说明 |
| --- | --- |
| `onClose` | 关闭回调。点遮罩与按 Esc 都调它 |
| `card` | 追加到 `.overlay-card` 上的尺寸/布局类，如 `sp-modal`、`ov-narrow` |
| `dismissable` | 默认 `true`。设 `false` 后 Esc 与点遮罩都不关——留给必须做出选择的确认框 |
| `labelledBy` | 可选，指向标题元素 id，供读屏 |

组件已包办：遮罩点击关闭、`stopPropagation`、`role="dialog"` / `aria-modal`、
以及下面 STD-UI-002 的 Esc 语义。

> [!danger] 这条不是风格偏好，是修一个真实的一致性缺口
>
> 收编前全仓 **15 处**手写浮层，其中**只有 4 处**接了 Esc——阅读器快捷键表、
> 词表导入、文章导入、对话场景编辑。其余 11 处按 Esc 毫无反应：产物大图、
> 语法讲解、影子跟读、种子选择、学习帮助、场景本生成、删除确认、音色选择、
> 数据管理、生图产物、管线节点弹窗。
>
> 讽刺的是阅读器那张快捷键表**自己写着「Esc 关闭浮层」**，而当时全站多数浮层做不到。

### STD-UI-002 Esc 只关最上面那一层浮层

浮层会嵌套：管线节点弹窗里点开生成图的大图、设置弹窗里再开二级面板。

**禁止**每个浮层各挂一个 `window` keydown 监听。那样一次 Esc 会把整摞全关掉——
用户只想退出大图，结果连节点弹窗一起没了，还得重新找回刚才那个节点。

正确做法已在 `Overlay` 内实现：模块级维护一个浮层栈，全局只绑一个监听，只调栈顶。

```
打开两层 → 大图 ✓ 节点弹窗 ✓
第一次 Esc → 大图 ✗ 节点弹窗 ✓   ← 只关最上层
第二次 Esc → 大图 ✗ 节点弹窗 ✗
```

### STD-UI-002a 用不了 `<Overlay>` 结构的层，用 `useEscapeClose` 入同一个栈

侧滑抽屉、`FullscreenPortal` 里的浮层、自带遮罩的面板套不进 `.overlay > .overlay-card`
的结构，但**必须与 `<Overlay>` 共用同一个栈**——各管各的 Esc，嵌套时又会一次全关掉。

```tsx
import { useEscapeClose } from '@/components/Overlay'

function HelpSheet({ onClose }) {
  useEscapeClose(onClose)
  return <aside className="sp-help">…</aside>
}
```

`enabled` 传 `false` 时不入栈：用于组件已挂载但层未展开，或"正在打字，这一下 Esc 不该关"。
`Overlay` 内部用的就是这个 hook，只有一份栈逻辑。

### STD-UI-002b 带输入框的浮层用两段式 Esc

直接关会把用户刚打的字连同面板一起丢掉，而这类面板恰恰是用来打字的。
正确行为：**焦点在输入框内且有未发送内容时，第一次 Esc 只失焦，第二次才关闭。**

```tsx
// web/src/features/pipeline/RepairPanel.tsx
useEscapeClose(() => {
  if (draft.trim() !== '' && document.activeElement === inputRef.current) {
    inputRef.current?.blur()
    return
  }
  onClose()
})
```

不要用"有输入框就不给 Esc"的做法——那等于这个面板永远关不掉。

### STD-UI-003 页面级 Esc 必须排除已被浮层接管的层次

有些页面自己有分层 Esc（如管线追踪页的「重跑弹窗 → 节点弹窗 → 问题浮层」）。
其中已经改用 `Overlay` 的那一层要从页面处理里去掉，否则两份处理同时跑。

```tsx
// web/src/features/pipeline/PipelinePage.tsx
const onKey = (e: KeyboardEvent) => {
  // picked（节点弹窗）与 repair（修复会话）都已入浮层栈，这里显式排除，
  // 只处理尚未入栈的重跑弹窗与问题浮层
  if (e.key !== 'Escape' || repair !== null || picked !== null) return
  if (rerunStep !== null) setRerunStep(null)
  else if (overlay !== null) setOverlay(null)
}
```

排除的判据是**那一层有没有自己入栈**，不是"它有没有输入框"——有输入框的按
STD-UI-002b 做两段式，同样入栈。

### STD-UI-003a 浮层的类名前缀必须独占

浮层类同时决定**定位方式**，撞名的后果比普通样式冲突严重得多，而且是双向的。

实测过一次：视频域节点弹窗复用了问题清单已占用的 `.pl-modal`。那条旧规则是
`position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%)`
的自居中写法，于是——

- **我的卡片**被它变成 `absolute`，脱离 `.overlay` 的 flex 居中；而 `-50%, -50%`
  的居中修正又被 `.overlay-card` 的入场动画 `translateY(12px)` 覆盖掉，
  卡片左上角落在视口正中、向右下溢出，动画结束才跳回中间——就是用户看到的
  「先从右下角弹出再校准」；
- **它的 `.pl-modal-body`** 被我的两栏 grid 盖掉，问题清单布局同时坏了，而这一处
  没有任何报错，纯靠肉眼才发现。

新浮层一律另起前缀（该次改用 `pl-node-`）。加类名前先 `grep` 一次全仓。

**一个类只能有一个主人。** 后来又踩了同一族的三次：

- `.sst-edit` 在**同一个文件里**既是卡片上的铅笔按钮（`position:absolute; opacity:0`，
  hover 才显形）又是新建画风弹窗的 `DialogContent`。后者只重声明了尺寸、没重声明
  `opacity`——弹窗照常挂载、照常占位，就是一个像素都看不见，控制台不报错。
- `.ph-example`（音标 / 阅读器）、`.sc-card` `.sc-row`（阅读器 / 词库）、
  `.sp-note`（管线 / 词库）、`.gd-zh`（视频 / 词库）各自被两个 feature 占着。
- `.pc-empty` `.pc-sub` 被同一个文件里的两个不同组件抢。

根子在 **CSS 规则是合并不是替换**：A 声明了 B 从不重声明的那些属性，
它们无条件生效，永远不会报错。所以这件事只能靠扫描发现，不能靠自觉。

守卫是 `pnpm check:css`（`web/scripts/check-css.mjs`）：同文件或跨文件出现两条
「独立的单类顶层规则」即失败。`.a, .b {}` 这种基类 + 细化、`:hover`、后代选择器、
`@media` 里的重复都不算。同一个元素的后续改版覆盖（各自只有一个消费方组件）
可以进白名单，但**必须逐条写明理由**。

### STD-UI-008 基础样式的特异性要低于它的覆盖入口

给了覆盖入口，就要保证覆盖真的能盖住。

`Overlay` 的 `card="xxx"` 是为「这个弹窗要更宽 / 不要内边距」准备的覆盖入口。
但基础样式 `.overlay-card` 与传进来的 `.xxx` **特异性一样**，都是 0,1,0——
谁赢只看谁发射得晚，而那个顺序由打包器按模块图决定，**dev 与 build 还不一致**。

实测：同一个 `.ss-card` 在 dev 里拿到 900px，在生产产物里却排在 `.overlay-card`
之前被压回 520px。**开发时一切正常、上线才塌**，是最难查的一类。
修之前 `.sc-card`（720）、`.sp-card`（760）、`.fp-card`（720）、`.lc-help`（380）
四个弹窗全被压在 520px。

做法：基础样式套 `:where()` 把特异性归零。

```css
/* 基础层：特异性 0,0,0，任何覆盖类都稳赢，与发射顺序无关 */
:where(.overlay-card) { max-width: 520px; padding: 20px; /* … */ }
:where(.overlay-card.wide) { max-width: 660px; }
```

判据：**任何「基础类 + 可选覆盖类」的组合**都适用，不只是浮层。
基础类和覆盖类特异性相同，就等于把结果交给打包顺序，而打包顺序不是契约。

### STD-UI-004 同一类信息的浮层形态要统一

管线三个域（视频 / 词库场景本 / 生图）的节点详情共用一套居中大弹窗
（`max-width: 1040px`，左产物右操作），不允许某个域自己做成侧栏。

判据是**内容量**而不是"改动小"：节点详情要同时容纳图、说明、指标表、参数表、
执行日志与重跑表单，400px 侧栏里全会挤成一条，读不动也改不动。

### STD-UI-005 常驻挂载的浮层，每次打开都要把内部状态同步回当前值

浮层有两种挂法，行为差别很大：

| 挂法 | 关闭后 | 内部 `useState` |
| --- | --- | --- |
| 条件挂载 `{open && <X />}` | 组件卸载 | 丢弃，下次是全新实例——**天然正确** |
| 常驻挂载 `<X open={open} />` | 只是不渲染 | **原样留着** |

第二种是要进出场动画、或者想省掉重建开销时的必然选择，代价就是状态跨越开合活下来。
所以凡是**指向数据**的状态，必须在「关 → 开」这一次同步回当前真实值。

判据是这个状态**指不指向具体数据**：

| 类别 | 例子 | 打开时 |
| --- | --- | --- |
| 指向数据 | 选中项、当前分类、搜索词、编辑中的表单、上一次的结果列表 | **必须同步** |
| 纯视图偏好 | 展开/折叠、视图模式（结构 / 原始 JSON）、缩放档 | 可以保留 |

```tsx
/* 用 ref 抓「关 → 开」这一次边沿，不要挂在 [open] 上无条件重置——
   那样关闭动画播到一半内容就被清空了。 */
const wasOpen = useRef(false)
useEffect(() => {
  if (open && !wasOpen.current) {
    setCategory(currentItem?.category ?? tabs[0].key)
    setSearch('')
    setEditing(undefined)
  }
  wasOpen.current = open
}, [open, tabs, currentItem])
```

> [!danger] 这条是两个真实缺陷换来的
>
> **画风选择器**：上次翻到「我的自定义」（0 条）再打开，看到的是一片空白，而当前
> 正在用的风格在哪一类完全无从得知。初始化写成了「只在首次跑」，弹窗关掉组件仍挂载，
> 分类就一直停在上次那里。
>
> **视频批量导入**：导完一批关掉再打开，**上一批的导入结果和粘贴的 URL 还在**，
> 看起来像这次已经导过了。五个状态一个都没重置。
>
> 两处都不报错、不崩，只是让人看到一个与当下无关的界面。

同一条规则适用于**浮层开着但主体换了**：查看器切到下一张图时，上一张放大到 400%
的视野不能原样套过去。做法一样，只是边沿换成主体 id：

```tsx
// web/src/features/image/ResultViewer.tsx
useEffect(() => {
  setView(RESET)
  setHiRes(false)
}, [asset.id])
```

**自查**：给浮层加 `useState` 时问一句——这个值指向某条具体数据吗？是的话，
它在第二次打开时还对吗？

### STD-UI-006 设置项在当前状态下不生效时，界面必须说出来

一个控件摆在那里、值也显示着，用户就默认它生效。如果某个上游状态让它**实际不参与**，
不说出来就是在骗人——用户会反复调它，然后怀疑整个功能坏了。

判断很简单：**这个设置现在改了，结果会变吗？** 不会变，就必须在控件旁边说明原因，
并给出恢复生效的路径。

> [!danger] 这条是一个真实缺陷换来的
>
> 生图控制台的「画风」选了一百多个可选项，而管线看到 `prompt_override` 非空就把它
> **原样**发给模型，风格预设完全不参与。「先看提示词」按当时的画风生成一份正文之后，
> 用户再换画风——侧栏显示新画风、出的图却一直是旧画风。用户的原话是
> **「为什么所有默认生成的都是这种柔和扁平插画风格」**，从界面上完全看不出原因。

两种处理，按能不能自动恢复来选：

| 情况 | 做法 |
| --- | --- |
| 能自动恢复生效 | **自动恢复**，并告诉用户会这么做。上例：画风变了就把那份预览作废，出图时按新画风重写 |
| 不能（用户明确输入的东西） | 说明为什么不生效 + 给出让它生效的操作。上例：手写提示词不动它，但写明「要用画风就把它清空」 |

**不要**只把控件禁用了事：禁用能表达「不能改」，表达不了「改了没用」。

### STD-UI-007 常驻工作区的会话状态不随路由卸载而丢

切走再回来，写了一半的内容不该没。判据是这个页面**是不是要反复进出**：
生图控制台是（出图 → 回词库看效果 → 回来改图），一次性表单不是。

要留的放 store（本仓用 zustand），只属于「这一次停留」的留在组件里：

| 放 store | 留组件里 |
| --- | --- |
| 用户输入、参数选择、结果列表、**正在跑的任务 id** | 打开着的浮层、拖拽中的临时态、计时器 |

正在跑的任务 id 尤其要留：丢了就再也接不回进度，图只会默默落进列表，用户以为没出。

> [!warning] 挂在 effect 上的「切换重置」要能分辨「换了对象」与「页面重进」
>
> 状态搬进 store 之后，组件重新挂载会再跑一次那些 effect。不判断的话，切回控制台
> 画风就被悄悄重置回默认——用户挑好的风格没了，而他什么都没做。让 store 自己记住
> 上一个对象，相同就整个跳过：
>
> ```ts
> onAppChanged: (appKey, ...) => set((s) => {
>   if (s.appKey === appKey) return {}   // 只是重新挂载，不是换应用
>   return { appKey, styleKey: null, ... }
> })
> ```
>
> objectURL 同理：改由 store 持有，只在真正移除时 `revokeObjectURL`，
> 卸载时释放的话切回来图就裂了。

### STD-UI-009 下拉一律走 `components/ui/picker`，不留原生 `<select>`

> [!danger] 原生 `<select>` 与自绘下拉并存 = 界面上同时有两套外观
>
> macOS 会画自己的系统下拉、Windows 画另一种，而项目自己那套是第三种。
> 用户一眼就能看出哪几个控件"不是一伙的"，而这件事不报错、也不会被测试发现。
> 收编前全仓 22 个文件、44 处原生 `<select>`。

四个形态，一个来源（`web/src/components/ui/picker.tsx`）：

| 形态 | 内核 | 用在哪 | 触发 |
| --- | --- | --- | --- |
| `Picker` | Radix Select | 表单里的普通下拉，`<select>` 的 drop-in 替代 | 点击 |
| `PillPicker` | Radix DropdownMenu | 密集控件条上的胶囊（生成条、工具条） | **悬停** |
| `PopoverPicker` | Radix Popover | 内容不是一列选项（分档 tab、两列、内嵌输入框） | **悬停** |
| `ActionPicker` | Radix DropdownMenu | 选完就执行的动作，没有选中态 | 点击 |

**为什么不自己写弹层**：焦点陷阱、Esc、点外面关闭、方向键、碰撞翻转、滚动跟随、
`aria-*`——手写要么漏一半，要么写成第二套和别处不一致的东西。Radix 全带，
而且本仓早就装了（`components/ui/` 下十几个封装在用）。

**为什么控件条上是悬停**：抄的是蓝本 Infinite-Canvas 的 `.smart-control` 体系
（`static/css/smart-canvas.css:1132`，`:hover` / `:focus-within` / `.pinned` 三态）。
密集控件条上悬停最快——不用为了看一眼选项而点两次。表单里的下拉仍是点击：
那是 `<select>` 的固有语义，悬停打开一个表单字段反直觉。

#### 三个必须一起做的细节

1. **悬停桥**。触发器与弹层之间有 8px 的 `sideOffset`，鼠标斜着穿过去会掉出
   hover 区把弹层关掉，表现为"要点第二次"。用伪元素把这段空隙补上
   （`.ui-picker-hover::before/after` + `.ui-picker-pop::before/after`，两个方向都要）。
   蓝本的注释自己写明了这一点。
2. **`pinned`**。点击之后就不再随鼠标离开而关，否则移向弹层里的输入框时
   只要路径偏一点就关了。
3. **触屏让开**。`pointerType === 'touch'` 时整套悬停不生效，交给点击。

#### 两个会静默出错的地方

- **空串不能当选项值**。Radix Select 拿空串表示"清空"，`<option value="">未归组</option>`
  这种直译过去会变成"没选中"，界面上显示 placeholder。要换一个具名值
  （`'none'` / `'all'` / `'global'`）再在 `onChange` 里翻译回 `null`。
- **键盘让路的判据要按 role 判，不能按标签判**。各处原来写的是
  `closest('input, textarea, select, [contenteditable]')`，换成 Radix 之后**静默失效**：
  它的触发器是 `<button role="combobox">`，不是 `<select>`，于是焦点停在下拉上按方向键，
  画布会去微移节点。统一用 `picker.tsx` 导出的 `FORM_FOCUS_SELECTOR`。

守卫：`pnpm check:select`（源码级扫描，`components/ui/` 除外——那一层就是包原生能力的）。
运行时 DOM 里出现 `<select aria-hidden tabindex="-1">` 是 Radix 为原生表单提交
渲染的隐藏节点，不算违规。

### STD-UI-012 说明性小字只写标签讲不清的事

> [!danger] 这是自己人每天用几百次的工具，第二次之后所有解释都是噪音
>
> 全项目普查（2026-08-21）扫出 **469 条**渲染给用户看的说明性小字，
> 其中 241 条长在选择器与对话框里。抽查判定：**该删 30、该收敛 8、该留 2**。

写之前先问一句：**这段话带了标签之外的约束、代价或反预期吗？**

| 判 | 什么样 | 例 |
| --- | --- | --- |
| 删 | 在解释标签本身就说明了的事 | 「自动」档配一段"自动就是不指定"；「预览」配"滚轮缩放、拖动查看" |
| 收敛 | 确实带了增量信息，但写长了 | 「重绘细节。注意不是超分——上游没有放大模型」→「重绘细节，不放大像素」 |
| 留 | 不看就会做错，且没有更短的表达 | 「执行流」→「不发参考图」（选错这条线，图静默地不发，任务照跑不报错） |

#### 三个反复出现的形态

1. **标签回声**。说明渲染在标签正下方，句首却又把标签念一遍
   （「历史归档：留个来源记录…」）。同一个词上下两行。
2. **同一句话说 N 遍**。「产物存进资产库，原图不动」在图片编辑器的 7 个模式里
   逐字重复了 6 次，而弹窗顶部已经有一句全局的。删到只剩顶部那一条。
3. **说错了还留着**。快捷键面板写「下拉不算输入框，只有方向键留给它」，
   而 `isEditable` 把下拉一并算作输入框、全部快捷键都让位——照着这句去按会得到
   相反结果。**错的说明比没有说明更坏**，发现即删，不要"顺手改对"就留下。

#### 约束用控件表达，不要用小字

尺寸输入框原来配一段「宽高都要是 16 的倍数、单边不超 3840…」。改成
`step={16} min={16} max={3840}`（上下箭头与浏览器校验直接按规则走）+
**填错了才出一行红字**。错误信息不是 tip——它不常驻，所以不占心智。

#### JSX 文本不解析 markdown

注释里写惯的 `**强调**` 抄进 JSX 文本节点，界面上会真的显示两对星号。
这已经漏出去三次（SetPlanDialog 两处、CanvasEditor 一处，普查又抓到 5 处）。
加粗写 `<b>`。守卫：`pnpm check:jsx`。

### STD-UI-010 页壳铺满工作区，限宽的是正文列不是页面

页面级容器不写 `max-width` + `margin: 0 auto`。左侧菜单栏之外的区域全部交给页面，
卡片网格自己按可用宽度多排一列，数据表自己把列摊开。

普查前全产品有 **9 个各写各的页壳限宽**（860 / 900 / 1180 / 1200 / 1240 / 1240 / 1280 / 1400），
宽屏上两侧留白比内容区还宽，而列表反倒挤成 5 列。这些数字彼此没有关系，
也没有一处说明它们从哪来。

**需要控制行长时限的是正文列**：讲义库的做法是壳铺满、正文列 `max-width: 760px`
且给一个「宽」开关；阅读器同理走 `--prose-width`。判据是「这段内容是拿来逐行读的吗」，
不是「这个页面看起来太宽了吗」。

> [!warning] 铺满档的选择器别撞上 check:scroll 的索引口径
>
> 守卫按「选择器最右复合项里的类名」建索引，`.page.xxx-full { display: flex }`
> 会把列向 flex 一并记进 `.page` 键，全仓 `main.page.*` 当场被判成列向 flex
> （实测误报 7 个 studio 滚动容器）。要么用标签限定（`main.xxx-full`），
> 要么让基础规则 `:not()` 从源头不生效。

## STD-UI-011　外壳令牌只有一份，学习前台**引用**而不是复制

> [!note] 2026-09-02 随 CR-006 退役：学习前台（learner-web）与 learning-core 已删除，外壳只剩一个，「引用而不是复制」不再有第二方。下文保留为当时的事实记录；教训（删复制块时别连基础重置一起删）仍然成立。

本产品有三个外壳：后台控制台（`web/src/App.tsx`，8080）、学习工作区
（`web/src/learning/LearningShell.tsx`，8081 的 `/learning-core/`）、
学习门面（`learner-web/src/app/AppShell.tsx`，8081 的 `/`）。
前两个本来就共用 `tokens.css` 里那一份 `.rail` / `.topbar`；第三个不是。

### 问题不是「设计不统一」，是「没有单一事实源」

`learner-web/src/styles.css` 把后台的 `:root` 与 `[data-theme="dark"]`
**逐字节复制**了一份（`diff` 返回空），文件头注释还写着「与后台同源」——
但同源只是当时的事实。两边各改一次就悄悄分叉，而分叉的表现是
「学习端和后台颜色差一点点」，没人会去 diff 两个文件。

分叉当时已经发生在尺寸上：

| | 后台 | 学习门面 | 现在 |
| --- | --- | --- | --- |
| rail 宽 | 64px（`--rail-w`） | 72px 硬编码 | `var(--rail-w)` |
| rail item 宽 | 52px | 54px | 52px |
| 激活左缘条 | `left: -6px` | `-9px` | `-6px` |
| 顶栏高 | `.topbar` 50 / `.appbar` 48 | 56px | 三者同取 `--topbar-h` |

`.appbar` 的 48 与 `.topbar` 的 50 也没有出处，一并收进 `--topbar-h`。

### 做法

`learner-web/src/styles.css` 顶部 `@import '../../web/src/styles/tokens.css'`，
删掉复制的两块。路径在本地与 Docker 里解析到同一个文件：learner 构建阶段
`WORKDIR /learner`，`COPY web/src/styles/tokens.css /web/src/styles/tokens.css`，
于是 `learner-web/src/` 出发的 `../../web/...` 两边都对。
dev 侧要放开 `server.fs.allow`（默认白名单只到 `learner-web/`）。

类名冲突扫过：两份样式表 191 个类里只有 `.active` 同名，且两边都是复合选择器里的
修饰符，合并无风险。产物里 `:root` 只剩一块。

> [!info] 不要为了统一去重写 learner 的 JSX
>
> 把 `.learner-rail` 改成共用的 `.rail-item` 结构收益很小、回归面很大。
> 类名各自独立没有坏处（前缀独占，见 STD-UI-003a），**坏的是数值各存一份**。
> 令牌统一之后两个外壳实测逐项一致：rail 64/64、item 52/52、字号 10/10、
> 内边距 `7px 0 5px`、圆角 10px、图标 19px、壳底色 `#22252A`。

### 顺带修掉的真缺陷：旧主题键迁移把「浅色」判成了「跟随系统」

`prefStore` 的迁移判据写的是 `v === '' ? 'light' : 'system'`——只有**空字符串**
映射到浅色，而学习端与门面写进 `ln-theme` 的恰恰是字符串 `'light'`
（两处都是 `setItem('ln-theme', dark ? 'dark' : 'light')`）。
于是「在学习端选了浅色」的用户进后台被判成跟随系统，系统是深色时就莫名变深色。

映射抽成 `web/src/lib/theme-legacy.ts`（`prefStore` 模块求值期就建 zustand store
并读 localStorage，而本仓 vitest 跑在 node 里没有 jsdom，纯计算留在那边测不了），
`ThemePref` 类型也一并由它持有、`prefStore` 转出，避免两处各定义一次。

## STD-UI-012　外壳是浅色托盘，不是深色块

2026-08-28 反转了「墨石轨」那版深色外壳。原来是 `--bg-shell: #22252A`：
一条黑柱加一条黑顶栏把内容框在中间，**页面上对比度最高的地方是导航而不是书**——
对一个以读为主的产品，这个重音下错了位置。

### 新口径：托盘比内容再浅/深一档，靠描边分界

| | 内容 | 外壳 |
| --- | --- | --- |
| 浅色 | `--bg-app: #F4F5F6` | `--bg-shell: #EAEDF0`（低一档） |
| 深色 | `--bg-app: #15171B` | `--bg-shell: #0E1013`（低一档） |

深色主题本来就是这个逻辑，浅色照着翻过来，于是**两个主题是同一个结构、
不是两套设计**。改动落在令牌一处，三个外壳（后台 / 学习工作区 / 学习门面）
全部跟着走——这是 STD-UI-011 把令牌收成一份换来的。

### 定值靠算不靠眼

- `--ink-shell-muted: #5F6771`，在 `#EAEDF0` 上 **4.88:1**。
  导航标签只有 10px，属小字，必须过 AA 的 4.5——先前 `#6B737D` 只有 4.24，不够。
- `--border-shell: #D5DBE2`：外壳与内容只差 1.08，分界几乎全靠这条描边，
  太淡就等于没有边界。
- `--accent-shell` 收敛成与 `--accent` 同值。它当初独立存在的唯一理由是
  「`--accent` 在墨石深底上对比度不足」，深底没了，理由也就没了（深色主题里
  两者本来就同值）。留着这个名字是因为它散在三个外壳里，改名的代价远大于收益。

### 顺带修掉的两处「为深底而生」的样式

`.rail-logo` 压着一道 `0 1px 3px rgba(15,15,25,.18)` 的投影——深底上看不出来，
浅底上就是左上角一块突兀的深斑。两个外壳各有一份，都去掉。

> [!danger] 删「重复的」样式前先确认另一边真的提供了它
>
> STD-UI-011 那次把 learner-web 里复制的令牌块整段删掉时，**连同一段基础重置
> 一起删了**（`a { text-decoration: none }`、`svg { width: 1.15em }`、
> `button, input { font: inherit }`）。后台是 Tailwind 项目，这些由 Preflight 兜着；
> learner-web 不装 Tailwind，没人兜。
>
> 后果：学习门面的导航项全部带上浏览器默认的蓝色下划线、图标尺寸失控导致
> 「退出」按钮折成两行。而当时外壳还是深色底，我只量了尺寸没看渲染就提交了——
> 外壳一转浅当场原形毕露。
>
> 教训是两条：删共享化后「看起来重复」的代码，要逐条确认接手方真的提供了它；
> 以及**样式改动必须看渲染，不能只量数值**。

## 改了样式看不到？先确认在看哪个地址

本仓有两套并行的访问入口，很容易在错的那套上验收：

| 地址 | 谁提供 | 是否含未提交/刚改的代码 |
| --- | --- | --- |
| `localhost:5173` / `5174` | vite dev server | **有**，HMR 即时 |
| `localhost:8080` / `8081` | Docker 里的 nginx | **没有**，是镜像构建那一刻的产物 |

2026-08-28 就在这上面空跑了一轮：外壳改浅色、三个外壳实测确认之后，
用户看到的仍是深色——因为他访问的是 8081，而那个镜像是 39 小时前构建的
（`docker exec … grep '#22252A'` 一查就实锤）。

**样式或前端行为要在容器上验收，必须先重建**：

```bash
cd deploy && docker compose build api worker admin-web learner-web && docker compose up -d
```

改了 server 的话 `api` 与 `worker` 都要重建（两个镜像各带一份代码）。
验收前先确认产物里确实有新值，别只看页面：

```bash
docker exec lingua-next-admin-web-1 sh -c 'grep -o "\-\-bg-shell:[^;]*" /usr/share/nginx/html/assets/*.css'
```

## STD-UI-013　讲义库对学习端只读开放

讲义是学习材料，学习者该读得到；它原来整个挂在 `admin_access` 下，
学习端的语法页连「讲义库」页签都不显示——显示了也是一路 403。

分权按**读/写**切，不按角色切页面：

| | 权限 | 端点 |
| --- | --- | --- |
| 读 | `learning_access` | `GET /tree` `/content` `/search` `/annotations` |
| 写 | `admin_access` | `POST /improve` `/apply`，批注的增改删，`/analyze` |

写留给 admin 有两条具体理由，不是「学习者权限低」这种泛泛判断：
`/improve` `/apply` 改的是用户 Obsidian vault 里的原文；
`grammar_doc_annotation` **没有 user_id 列**，一份批注全站共用，
开给多账号等于开出一个共写面。

> [!danger] 门必须在路由上，不能靠前端不显示按钮
>
> 前端的 `readOnly` 只负责「不摆出点了必然 403 的按钮」，任何人都能绕过它。
> 真正的门是 `grammar_docs.ADMIN_ONLY` 加在那六个写路由上。
> 实测（`user` 角色账号）：读 200 / 写全部 403。

## STD-UI-014　长清单不做「原地展开」，做浮层里的可搜索面板

考纲本的场景筛选条原来是三行药丸 + 一个「展开全部 67 个」。两头都不讨好：

- **折着时**，67 个里只露得出约 30 个，想找的那个多半不在其中；
- **展开后**是七八行药丸，**把下面的词卡整片推下屏**——用户点一下筛选器，
  代价是丢掉正在看的内容。

而且行数还会涨：高考 67 个场景，GRE 143 个。

改成「常驻一行 + 浮层面板」：

| | 内容 |
| --- | --- |
| 常驻行 | 「全部」+ 至多 6 个**在学的**场景 + 一个面板入口 |
| 浮层面板 | 搜索框 + 按轨别分组 + 全部场景（`Popover` + `Command`，与设置页 `Sel` 同一套原语） |

浮层开合不改变页面布局，「一展开内容全跑了」这个问题就不存在了；
67 个还是 143 个都是同一个交互，不随数量退化。

> [!danger] 「在学」只能认 `passed`，不能认 `learned`
>
> 常驻行按「动过的排前面」挑，第一版判据写成 `passed > 0 || learned > 0`。
> 但 `learned` 是**入册**（词进了生词本），随便翻几页就一片非零——判据恒真，
> 排序整个退化成按词数倒序，6 个位置全被最大的几个场景占满
> （实测：103 / 97 / 95 / 93 / 88 / 83），而用户正在啃的那个小场景排不进来。
> 改成只认 `passed`（真通过了自测）后是 3/103、4/95、1/74、2/30、1/28、1/24——
> 全是有实际进展的。
>
> 另外当前选中的场景**无条件在列**：否则从面板里挑一个冷门场景，
> 常驻行上看不见它，用户不知道自己正筛在哪。

## STD-UI-015　复用别处的面板时，先检查它自带的控件在新宿主里还有没有意义

词卡例句的语法分析直接复用了阅读器的 `SentencePanel`（翻译 / 句子结构 / 语法分析 /
朗读四件事都现成，不必另造一套，判定口径也不会分叉）。

但它工具条上那个 ✕ 原来调的是 `clearSelection`——**阅读器的选区**。
词库的浮层里没有「阅读器选区」这回事，于是那个按钮点了什么都不会发生，
是个不报错的死控件。

修法是给它一个可选的 `onClose`：传了就关这一层，不传退回原来的阅读器语义。
搬运组件时，逐个过一遍它自带的按钮/快捷键在新宿主里是否仍然接得上。

## STD-UI-016　词卡上的低频动作一律悬停露出

词卡网格一屏铺三四十张，每张卡上常驻一个图标就是三四十个图标在抢注意力。
判据是**频次**：打开词卡是主动作（整卡可点），而「标状态」「分析这句语法」
是想起来才用的——都做成悬停/聚焦才露出（`opacity: 0` → `1`）。

已按这条处理的：词卡状态徽标的下拉、例句块右下角的「语法」入口、
AI 对话场景卡的编辑/删除。

## STD-UI-017　主导航：10 项 + 中文标签装不进图标栏

原来是 64px 图标栏，图标 19px + 标签 **10px**，10 个主项 + 3 个工具项平铺。
三条可核查的理由说明这个形态不成立：

1. **10px 中文低于可读下限。** Chrome 曾对中文 UI 语言强制 12px 最小字号
   （简繁中文 12px、日韩泰 10px、其余无下限），正是因为这些字形在更小尺寸下辨识困难。
   导航是每天点几十次的东西，不该压在下限之下。
2. **容不下。** 图标 + 小字的行高约 54–56px，10 主项 = 560px，加 3 工具项 720px+。
   1080p 可用高度约 900px，塞满且无余量——分组线、徽章、滚动缓冲都没有位置。
3. **图标分不清。**「内容库 / 词汇资产 / 视频资产」的差别在**修饰语**不在中心词：
   中心词都是「集合」，画出来是书本 / 文件夹 / 卡片堆，用哪个都对也就都不对。
   复合图标（底图 + 角标）在 20px 下把「一个符号难辨」变成「两个符号都难辨」。

### 现在的形态

展开 232px 带完整标签（13px）与**组标题**，折叠 64px 图标 + `title`，状态存 `ui.navCollapsed`。

**默认展开**，这一条不是口味问题：折叠态能用靠的是**位置记忆**（在展开态学过「第 2 项是词汇资产」），
不是图标语义。首次访问没有这份记忆，所以必须先给展开态。

组标题（学习素材 / 创作与运行 / 运营管理）是带标签竖列相对图标栏的核心优势——
图标栏只能画无名分隔线，传达不了「这四个是素材、那四个是生产」。

实测：14 项标签全部左对齐于 x=47、零截断；对比度 5.7:1；热区 215×33；
折叠后 0 个可见标签 / 14 个 `.sr-only` / 14 个 `title`。

## STD-UI-018　导航项必须是链接，不是按钮

`<button onClick={() => navigate(to)}>` 会丢掉一整排浏览器原生能力：
中键新标签页、⌘/Ctrl 点击、右键「在新标签页打开」、复制链接地址、拖到书签栏、
悬停看目标 URL。`navigate()` 一个都补不回来。读屏也会念成「按钮」而不是「链接」。

侧栏与顶栏两支布局用**同一个** `RailLink` 组件渲染——先前只改了侧栏，
结果同一个「工坊」在两种布局下一个能 ⌘ 点开新标签页、一个不能。

> [!danger] `NavLink` 不会把你传的 `aria-current` 原样发出去
>
> 它只在**自己**算出的 `isActive` 为真时才发射；传进去的值只决定「发射什么」，
> 不决定「发不发」。而本项目的选中判据更宽——`shelfActive` 在 `/read/*` 下也算
> 「内容库」选中（阅读器是从内容库进去的），这时 NavLink 对 `/content` 的
> isActive 为假，**一个字都不发**：视觉高亮着，读屏读不到「当前页」。
> 它还会自己追加一个 `active` token，前缀命中的路由渲染成 `class="rail-item active active"`。
>
> 所以用 `Link` 而不是 `NavLink`，class 与 `aria-current` 同源，都由调用方的
> `item.active` 决定。

### 同批修掉的

- **跳转锚点**：键盘用户每次换页要穿过 13 个导航项才够得着正文。加 `.skip-link` +
  `#main`（`tabIndex={-1}`，焦点要真的落进去，否则只是滚动了一下）。
  包这一层会让 `.app.layout-top > .main` 这条直接子选择器**静默失效**，已改成后代选择器。
- **徽标读屏文本**：原来是二选一，`busy=1 / failed=2` 时眼睛看到 3、读屏念「1 个在跑」，
  失败数从文本里消失。改成两半都说全。
- **`.rail-item` 要写死 `text-align: left`**：导航项是 `<a>`（默认左对齐），
  而主题/设置/退出/收起是 `<button>`（UA 默认 `text-align: center`）——
  不写死的话只有那四项的文字被推到 flex-1 标签的正中间。
- `IconPipelineNav` 是唯一自己写 `<svg>` 的图标，漏了 `aria-hidden`，是全部导航图标里
  唯一暴露给读屏的无名图形节点。
- `.sr-only` 原先在 `settings.css` 里，已提到 `tokens.css`（它是全局无障碍工具类）。

## STD-UI-019　顶栏是组件，不是每页手抄一遍

顶栏原来不是组件，是 **14 份手抄**。没有共享契约的直接后果：

- 13 处各自重复写 `<div style={{ flex: 1 }} />` 撑中间
- 只有 3 处挂了 `sh-topbar` 才会在窄屏换行，其余在窄屏下被压扁
- 返回键有的用 `BackLink`、有的用 `btn-ghost-sm`、有的只有一个不可点的标题
- 面包屑当前页用 `<b>`，与祖先同为 13px，读起来分不出主次
- **大多数页面中间 95% 是空的**——因为「这里该放什么」从来没被定义过

契约是两段：**位置**（左）· **动作**（右），中间空隙由组件撑。

```tsx
<Topbar
  back={{ to: '/video', label: '视频库' }}   // 可省
  crumbs={[{ label: '词库', onClick }]}      // 祖先层级；当前页不放进来
  title="高考"                                // 当前在哪，必填
  meta={<span className="chip">41 本</span>}  // 贴标题的状态标记，不是动作
  actions={<>…</>}                            // 这一页能做什么
/>
```

- 窄屏换行是 `.topbar` 的**默认行为**，`sh-topbar` 已删。
- `.tb-title` 15px/600，与面包屑的 13px 拉开层级。
- 面包屑用 `<nav aria-label="当前位置">` 包住：页面里同时有主导航，
  两个无名 navigation 在读屏的 landmark 列表里分不出谁是谁。

> [!danger] 抽组件时别把「深链返回」语义弄丢
>
> `BackLink` 的语义是 BR-G-012：**有站内历史就退一步**回到用户真正来的地方，
> 深链直接打开时才去 `to`。第一版把 `back={{ to }}` 直接渲染成 `<Link to>`，
> 从站内跳进来再返回会跳到固定上级而不是上一页——用户会以为自己「多退了一层」。
> 这个语义现在收在 `Topbar` 内部，`BackLink.tsx` 与孤儿样式 `.back-link` 已删除。

### 还没做的

`/studio`、`/tasks`、`/catalog`、`/users` 四个页面**本来就没有顶栏**（不在那 14 处里），
它们用页内大标题代替。要不要一并收进 `Topbar` 是独立一轮的决定。

## STD-UI-013　程序化外链与下载只经 `lib/shell`

**规则**：页面代码里不再直接写 `window.open(...)` 去开外链或触发下载，也不再手搓
`document.createElement('a')` + `a.download` + `a.click()`。两件事各走一个助手：

```ts
import { openExternal, saveFile } from '@/lib/shell'

openExternal(channel.url)                                   // 外链：系统浏览器
saveFile(result.blob, result.filename)                      // Blob 下载
saveFile('/api/export/vocab.csv', 'vocab.csv')              // 同源 URL 下载
```

声明式的 `<a href target="_blank" rel="noopener">` 与 `<a href download>` 不受此限，
Electron 壳按 Chromium 默认行为接管它们。

**为什么**（ADR-014）：桌面壳把 `window.open` 一律交给系统浏览器——那是外链该走的路。
收编前全仓四处用 `window.open` 触发下载（词库导出 CSV / APKG、批注导出），在壳里会变成
Safari 打开一串文本。十六处手搓的下载锚点里，回收 objectURL 的时机从「立刻」到「10 秒后」都有，
收成一个函数之后只有一个时机可调。壳经 `preload` 往 `window.linguaShell` 挂实现，
页面代码不判断自己跑在哪。

**守卫**：code-review。`grep -rn "window\.open(\|\.download = " web/src/features` 应为空。

### 深链可达的页面必须自带出口

一个页面只要能被直接打开（`/talk/session?id=…`、`/read/48`、`/video/12`），就必须给
`back`，且 `crumbs` 里的祖先要带 `to`。这两样都不给的话，用户唯一剩下的出口是侧栏菜单项——
而它在本模块激活时曾经指向当前 URL，点了什么都不会发生，人是真的出不去。

侧栏本身是最后一道兜底（`lib/railTarget.ts`）：点已激活模块的子页回该模块首页，点模块首页本身
保持原地。这条兜底不替代页面自己的返回键——菜单项回的是模块根，返回键回的是用户真正来的地方。

## STD-UI-020　换模型只有一个弹窗，按厂商分组，模型位永远是上游真名

全产品**只有** `components/model-picker/ModelPicker.tsx` 一个换模型入口。收编前有四套：
设置页的 `Sel`（280px、按凭据名排序）、工坊对话页手写的两列 `.sgc-model-pop`、画布的 `PillPicker`、
修复代理的 `ActionPicker`——其中两套还把 `chat-general` 这种路由键摆在「模型」位上。

三条硬约束：

**分组按厂商，判据只认模型名**。`provider_type` 记的是接入协议不是厂商：实测五个凭据里四个都是
`openai_compatible`，按它分组等于不分组，而同一个中转后面同时挂着六家的模型。规则在
`web/src/lib/model-vendor.ts`，改它要跑 `model-vendor.test.ts`（拿开发库真实模型名对账）。

**嵌入 / 转写这类非对话模型单列一组、默认折叠**。旧下拉打开第一眼看到的正是 `embedding-3`——
按凭据名排序 + 组内字母序把一个连对话都不能做的模型顶到了第一位。搜索时照常出，不藏。

**「模型」位一律显示上游真名**（核心原则 6）。要同时说清能力就用 `<中文能力名> · <真实模型名>`。
钉了临时模型时能力名不跟着变——钉的是模型不是能力，跟着变会渲染出「kimi-for-coding · kimi-for-coding」。

弹窗走 `components/Overlay` 而不是 radix `Dialog`：Dialog 不进本仓的浮层栈，开着时
`useOverlayOpen()` 仍返回 false，页面级 Delete / ⌘Enter 会打到背后看不见的对象上。

## STD-UI-021　使用处换模型只影响这一次，且必须换缓存槽

设置里的绑定是「平时用哪个」，使用处的切换是「这一次试试别的」。后者**绝不写回绑定**——
用户在词卡上试了个更强的模型，不该因此把全站的词语解释都换掉。选择记在 localStorage，
换设备就回到跟随绑定。

`deployment_id` 必须进缓存寻址（`analyze.py` 的 `provider` 加 `#d<id>` 后缀）。不进的话换了模型
仍旧命中上一个模型的结果，**接口 200、日志干净**，用户看到的是「换了没反应」。跟随绑定时寻址键
不变，历史缓存照旧有效。

UI 上能改的参数，必须回头确认运行时真的读它：收了 `deployment_id` 字段却不透传给上游，
等于给用户一个假开关（`/analyze/translate` 走的是引擎降级链不是 `_generate_llm`，两条路都要接）。
