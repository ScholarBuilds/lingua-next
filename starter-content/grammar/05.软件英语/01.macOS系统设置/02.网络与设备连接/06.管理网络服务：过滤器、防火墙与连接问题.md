# 管理网络服务：过滤器、防火墙与连接问题

Network 页面把“当前连接用了什么服务”“哪些网络过滤器正在生效”“防火墙是否允许入站连接”放在相近位置，但它们不是同一个功能。过滤器和代理会处理网络流量怎样经过系统；防火墙主要控制外部连接怎样进入这台 Mac；网络服务状态则告诉你某个接口当前是否连接。区分这三层，才能避免一遇到网络异常就错误地关闭安全设置。

> [!warning] 不要把安全开关当作排障开关
>
> 关闭防火墙、移除网络过滤器或停用透明代理，可能让企业策略、隐私保护、远程访问或应用联网发生变化。只有在明确授权、知道原状态和恢复方法时才修改；学习本篇时只读页面即可。

## Network 首页怎样读

Network 首页通常把当前服务和其他服务分开显示。每个条目包含名称、连接状态，某些条目还会显示 `Filters`、`Firewall` 等相关入口。

| 页面表达 | 它代表什么 | 不代表什么 |
| --- | --- | --- |
| `Connected` | 该网络服务当前已建立连接 | 所有网站、App 和账户服务都已正常 |
| `Not connected` | 当前该服务没有连接 | 该接口永久损坏或不能使用 |
| `Other Services` | 其他可用网络接口或服务 | 这些服务一定应该删除 |
| `Filters` | 影响网络流量的过滤器或代理组件 | 浏览器广告拦截列表本身 |
| `Firewall` | 入站连接保护设置 | 所有出站网络流量都被控制 |
| `More` | 打开更多服务相关操作 | 一键修复网络 |

例如 `Thunderbolt Bridge`、`iPhone USB` 之类的服务显示 `Not connected`，通常只是说明当前没有通过相应接口建立连接。不要把每一个 Not connected 都当作错误。只有当你正准备通过该接口使用网络时，才需要进一步检查线缆、设备、授权或服务配置。

## 界面实例：服务状态、过滤器和防火墙在首页的关系

| 稳定界面表达 | 软件语境中文 | 读法 |
| --- | --- | --- |
| `Other Services` | 其他服务。 | 另一些网络接口或服务，不是错误清单。 |
| `Connected` | 已连接。 | 当前网络服务的连接状态。 |
| `Not connected` | 未连接。 | 当前没有通过该服务建立连接。 |
| `Filters` | 过滤器。 | 查看影响网络流量的系统级组件。 |
| `Active` | 已启用。 | 当前页面所列功能或组件正在生效。 |
| `Firewall` | 防火墙。 | 管理进入这台 Mac 的连接保护。 |
| `Inactive` | 未启用。 | 该功能当前没有开启；它和服务断开不是同一概念。 |
| `More` | 更多。 | 继续打开服务相关菜单。 |

有两个经常混淆的状态对：`Connected / Not connected` 描述网络服务关系；`Active / Inactive` 描述功能或组件是否生效。Wi-Fi 可以 Connected，同时防火墙 Inactive；过滤器可以 Active，而某个其他网络接口 Not connected。把这些状态放在不同层次读，才不会得出矛盾结论。

## Filters：谁在处理网络流量

Filters 页面会显示“以下过滤器和代理应用于你的网络流量”之类的说明。这里的关键词是 `apply to`：它表示某项组件的规则会作用到网络流量，不等于页面中列出的每个 App 都拥有同样的权限或效果。

<a id="interface-network-filters"></a>

> 本机截图未包含在公开版本中，以保护原图中的个人信息。

| 界面表达 | 中文理解 | 应该怎样判断 |
| --- | --- | --- |
| `Filters & Proxies` | 过滤器与代理。 | 页面同时呈现流量处理组件，不表示两者机制完全相同。 |
| `Following filters and proxies apply to your network traffic.` | 以下过滤器和代理会作用于你的网络流量。 | `apply to` 后面的对象是网络流量。 |
| `Name` | 名称。 | 用于识别组件；不要把组件名称自动当作功能说明。 |
| `Type` | 类型。 | 用于区分 DNS、透明代理或其他服务。 |
| `Status` | 状态。 | 用 Enabled 等状态确认是否正在生效。 |
| `Enabled` | 已启用。 | 组件当前有效，不说明它是导致问题的根因。 |
| `Add` / `Remove` | 添加 / 移除。 | 可能需要管理员权限或被系统策略禁用。 |
| `About VPNs & Privacy…` | 关于 VPN 与隐私。 | 打开解释资料，不会修改网络设置。 |

页面里可能列出系统或第三方提供的组件名称。名称和类型会随本机安装的软件变化，因此不应把具体组件名作为通用英语清单。应该学习的是 `DNS Proxy`、`Transparent Proxy`、`Enabled` 这样的功能语言，以及它们和网络流量的关系。

`Transparent Proxy` 的重点不是“看不见”，而是某些流量可能在用户没有逐一设置 App 的情况下被网络组件处理。看到这类项目时，不要擅自删除；它可能来自安全软件、企业管理或本机网络工具。先问清“谁安装的、作用在哪些流量、删除后如何恢复”。

## Firewall：保护入站连接的边界

防火墙页面的文案通常会明确讲“进入这台电脑的连接”。因此 `All incoming connections to this computer are allowed.` 应读成“所有入站连接都被允许”，而不是“所有网络连接都开放”或“互联网完全没有限制”。

<a id="interface-network-firewall"></a>

> 本机截图未包含在公开版本中，以保护原图中的个人信息。

| 完整英文 | 软件语境中文 | 关键边界 |
| --- | --- | --- |
| `This computer’s firewall is currently turned off.` | 这台电脑的防火墙当前已关闭。 | 描述的是防火墙状态，不是 Wi-Fi 开关。 |
| `All incoming connections to this computer are allowed.` | 所有进入这台电脑的连接都被允许。 | `incoming` 限定为入站连接。 |
| `Options…` | 选项。 | 通常需要先启用防火墙才可进入或可操作。 |
| `turned off` | 已关闭。 | 是功能状态；不要与 `disabled` 混为一谈。 |

防火墙关闭时，`Options…` 可能变为 disabled。这个灰色状态有逻辑关系：不是 Options 页面坏了，而是它依赖一个尚未启用的上级功能。可以这样说：

> `The firewall options are disabled because the firewall is currently turned off.`

这句解释了对象、原因和当前状态。它比“Options 不能点”更具可操作性。

## 过滤器、代理和防火墙怎样分层

三者都可能影响网络体验，但问的问题不同。

| 层次 | 它主要处理什么 | 典型问题 | 页面线索 |
| --- | --- | --- |
| 网络服务 | 通过哪种接口建立连接 | Wi-Fi、USB 网络、桥接是否连接 | `Connected`, `Not connected` |
| 过滤器 / 代理 | 流量是否被检查、转发或走例外路径 | 某些域名、App、内部服务能否访问 | `Filters`, `Proxies`, `Enabled` |
| 防火墙 | 外部连接怎样进入这台 Mac | 远程访问、共享服务、入站请求 | `Firewall`, `incoming connections` |
| VPN | 流量是否通过虚拟专用网络路径 | 企业资源、隐私路径、远程网络 | `VPN`, `Connected`, `On Demand` |

实际排查时可以先说事实，再选择对应层：

> `Wi-Fi is connected. I can see that a network filter is enabled, but I have not changed it. The firewall is a separate setting that controls incoming connections.`

这段话避免把“过滤器启用”说成“防火墙开着”，也不假定任何一项就是故障原因。

## 两个完整操作案例

### 案例一：只读核对 Network 首页的三种状态

1. 打开 **System Settings → Network**。
2. 找到当前主要网络服务，判断是 `Connected` 还是 `Not connected`。
3. 找到 **Filters** 和 **Firewall**，分别记录它们显示的是 `Active`、`Inactive` 还是其他状态。
4. 不点击 Add、Remove、More，也不改变防火墙开关。
5. 用英语复述：`I checked the network services, filters, and firewall status. I did not change any connection or security setting.`

这个案例的目标是训练状态分类，而不是完成某个网络修复。

### 案例二：解释为什么防火墙选项不能操作

1. 打开 **Network → Firewall**。
2. 观察防火墙开关和说明文字。
3. 如果 Options 灰色，读出防火墙当前是否为 `turned off`。
4. 不开启防火墙，仅说明依赖关系。
5. 用英语描述：`The Options button is unavailable because the firewall is turned off. I did not enable it just to access the options.`

这里的 `unavailable` 比 `broken` 更准确；页面没有损坏，它只是受当前条件限制。

## 常见错误与恢复方式

| 错误 | 误解在哪里 | 正确做法 |
| --- | --- | --- |
| 看见过滤器 Enabled 就删除 | Enabled 只说明组件生效，不说明它有害 | 先确认来源、类型、作用范围和恢复方法 |
| 为测试 Options 而打开防火墙 | 为了进入子页改变了高影响状态 | 先学习灰色控件的依赖关系，不必执行 |
| 把 Not connected 当故障 | 其他服务可能本来就未使用 | 先确认自己是否需要该接口 |
| 把防火墙和代理当成同一种设置 | 它们控制的网络方向不同 | 用 `incoming connections` 和 `network traffic` 区分 |
| 只说“网络不行” | 缺少可交接的状态证据 | 报告服务状态、过滤器状态和实际现象 |

## 在修改防火墙或过滤器前，先建立恢复点

过滤器和防火墙的风险不只在于“改错一个开关”。它们常与共享、远程访问、企业设备管理或第三方网络软件发生关系。一个可靠的操作准备至少包含当前状态、变更目标、预期影响和恢复路径四项内容。

| 准备项 | 应该写下或确认什么 | 可用英语 |
| --- | --- | --- |
| 当前状态 | 哪些服务 Connected，哪个组件 Enabled，防火墙是 On 还是 Off | `The firewall is currently off, and the network filter is enabled.` |
| 变更目标 | 只准备改哪一个项目 | `I intend to change only the firewall setting.` |
| 预期影响 | 你认为会影响入站、出站还是某个服务 | `This may affect incoming connections to the Mac.` |
| 恢复路径 | 怎样把值改回去并验证 | `I know where to restore the previous setting and how to verify it.` |

没有第四项就不应该开始改。特别是远程协助场景：如果你通过屏幕共享、远程管理或公司网络访问设备，随意开启或关闭防火墙可能改变正在使用的连接条件。安全的语言不是“你直接试一下”，而是：

> `Before changing the firewall, let’s confirm whether the current remote connection depends on this setting and how we can restore it if the connection is interrupted.`

这句话把风险、依赖和恢复写在同一个请求里。它适合让对方先判断，而不是把责任交给正在操作的人猜测。

## 报告网络问题时的证据层级

Network 页面能提供很多状态，但并不是所有状态都能证明同一件事。用证据层级组织描述，可以避免“一个红色提示就认定故障”的问题。

| 证据层级 | 你实际确认了什么 | 示例英文 | 还不能确认什么 |
| --- | --- | --- | --- |
| 页面状态 | 服务是否 Connected，组件是否 Enabled | `Wi-Fi is connected.` | 网站、账户或 App 是否能访问 |
| 配置存在 | 页面中存在某个过滤器、代理或防火墙状态 | `A network filter is enabled.` | 它是否造成当前问题 |
| 现象复现 | 某个服务确实不能使用 | `The internal service is not reachable.` | 为什么不能访问 |
| 范围比较 | 只有一个 App、一个地址或所有服务受影响 | `The issue affects one app but not the browser.` | 最终根因 |
| 恢复验证 | 改回原值后现象是否回到原状 | `The service behaved normally after the original setting was restored.` | 其他隐性影响是否完全不存在 |

以这五层写排障记录时，能自然避免把推测说成事实。例如：`A filter is enabled, and an internal service is not reachable. I have not confirmed that the filter is the cause.` 这就是一条高质量的问题报告。

## 从页面文本学三组安全表达

Network 页面适合练习下面三组英语，它们在很多系统软件中都可迁移。

| 目的 | 结构 | 示例 |
| --- | --- | --- |
| 描述状态 | `is currently + 状态` | `The firewall is currently turned off.` |
| 描述影响范围 | `apply to + 对象` | `These filters apply to network traffic.` |
| 描述条件限制 | `because + 原因` | `The options are disabled because the firewall is off.` |
| 描述未执行操作 | `did not + 动词` | `I did not remove or disable any filter.` |
| 描述下一步验证 | `need to confirm whether…` | `I need to confirm whether this filter affects the service.` |

把这些结构组合起来，可以得到不夸张、可执行的说明：

> `The network filter is currently enabled and applies to network traffic. An internal service is not reachable, but I did not remove the filter because I need to confirm whether it is required by the network policy.`

这段话既能用于英语学习，也能直接用于向技术支持说明情况。

## 自测

1. `Connected / Not connected` 与 `Active / Inactive` 分别描述什么？
2. 为什么 `All incoming connections…` 不能翻成“所有网络都开放”？
3. 过滤器 Enabled 时，为什么不应直接删除？
4. 用英语说明“我检查了网络服务、过滤器和防火墙状态，但没有修改任何连接或安全设置”。

<details>

1. 前者描述网络服务是否建立连接；后者描述某个功能或组件是否正在生效。
2. `incoming` 限定为进入这台 Mac 的连接，并不等于所有出站或全部网络行为。
3. 组件可能来自组织策略、安全软件或本机工具；必须先确认来源和恢复路径。
4. `I checked the network services, filters, and firewall status, but I did not change any connection or security setting.`
