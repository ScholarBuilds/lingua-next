# 控制常用入口：菜单栏与控制中心

菜单栏和控制中心都提供快速入口，但它们的工作方式不同：菜单栏是一条持续可见或按条件显示的顶部区域；控制中心是集中展开的系统控制面板；应用也可以请求在菜单栏放置自己的项目。这个页面的关键不是记住当前有哪些图标，而是读懂“显示在哪里、何时显示、关闭后会发生什么”。

> [!warning] 应用菜单项并不只是装饰
>
> 某些 App 借助菜单栏在主窗口关闭后仍提供任务、同步、录制、网络或快捷操作。关闭某个应用菜单项不一定退出 App，却可能让它不再提供快捷入口。学习时不要因为图标陌生就批量关闭开关。

## 三个入口层次

| 层次 | 英文 | 它提供什么 | 典型动作 |
| --- | --- | --- | --- |
| 菜单栏 | `Menu Bar` | 顶部常驻或条件显示的项目 | 显示时钟、Wi-Fi、声音、App 菜单项 |
| 控制中心 | `Control Center` | 集中展开的一组系统控制 | 查看或调整网络、显示、声音、专注等 |
| 控制图库 | `Control Gallery` | 可添加或组织的控制项集合 | 添加更多系统控制到控制中心或菜单栏 |

`Menu Bar Controls` 是页面中最重要的分组名。它说明系统和 App 控件可以被配置为出现在控制中心、菜单栏，或两处同时出现。一个项目是否显示，不等于它是否启用；例如 Wi-Fi 即使不在菜单栏里，网络功能仍可以存在于控制中心和系统设置中。

图片中出现的第三方应用名称是本机动态状态，不进入正文、搜索、词汇表或练习题。以下只学习稳定的系统表达。

| 完整英文 | 软件语境中文 | 关键边界 |
| --- | --- | --- |
| `Automatically hide and show the menu bar` | 自动隐藏和显示菜单栏。 | 管顶部栏何时可见，不关闭菜单栏功能。 |
| `In Full Screen Only` | 仅在全屏时。 | 是自动隐藏规则的条件值。 |
| `Show menu bar background` | 显示菜单栏背景。 | 管视觉背景，不管菜单项内容。 |
| `Recent documents, applications, and servers` | 最近文档、应用和服务器。 | 是最近项目显示数量或范围，不是历史记录的全部内容。 |
| `Show suggestions in Control Gallery` | 在控制图库中显示建议。 | 管建议是否出现，不会自动添加控制。 |
| `System and app controls can be configured to appear…` | 系统和应用控制可以被配置为显示在…… | `can be configured` 表示可配置能力，不代表当前已经显示。 |
| `Add Controls…` | 添加控制。 | 打开选择或添加流程，不等于立刻启用某功能。 |
| `Show When Active` | 活跃时显示。 | 只有项目处于活动状态时才显示。 |
| `Allow in the Menu Bar` | 允许出现在菜单栏。 | 决定应用是否可放置菜单栏项目。 |
| `Reset Control Center…` | 重置控制中心。 | 可能恢复布局或默认设置，是高影响操作。 |

这里的 `appear in both Control Center and the menu bar` 要完整理解。`both … and …` 是两处同时出现，不是“控制中心和菜单栏是同一个页面”。如果你只希望一个控制项在展开面板里出现，而不是始终占据菜单栏，应继续检查具体复选项或显示方式。

## 显示、允许与启用：三个相似动词的区别

| 词 | 关心什么 | 示例 | 不等于 |
| --- | --- | --- | --- |
| `show` | 某项是否可见 | `Show indicators for open applications.` | App 是否已启动 |
| `allow` | 系统是否允许某项出现在某处或执行某事 | `Allow in the Menu Bar.` | App 一定正在运行 |
| `enable` | 功能或组件是否处于可用状态 | `The feature is enabled.` | 它一定显示在菜单栏 |
| `active` | 当前是否正在使用或有状态 | `Show When Active.` | 永远显示 |
| `open` | App 或窗口是否正在运行 | `The application is open.` | 它在前台或有菜单栏图标 |

例如 Focus 的显示选项可能写 `Show When Active`。它不是“开启 Focus”，而是“当 Focus 已处于活动状态时，是否显示这个项目”。要正确描述，需要先知道 Focus 的状态，再谈菜单栏可见性。

## 菜单栏自动隐藏：条件、时机和恢复

`Automatically hide and show the menu bar` 是一个规则型设置。它需要和当前值一起读，例如 `In Full Screen Only`。规则型设置不能只背成“自动隐藏”，还要问“在哪种状态下自动隐藏”。

| 当前值 | 可用英语 | 用户实际会看到什么 |
| --- | --- | --- |
| `Always` | `The menu bar is hidden automatically.` | 需要触发相应显示方式才能看到。 |
| `In Full Screen Only` | `The menu bar is hidden only in full-screen apps.` | 普通窗口中仍可显示。 |
| `Never` | `The menu bar remains visible.` | 不按自动隐藏规则收起。 |

当别人说“菜单栏不见了”，先确认是否进入了全屏 App，再看隐藏规则。更精确的英文是：`The menu bar is hidden while the app is in full screen.` 这比说 `The menu bar is gone` 更准确，因为它描述的是条件性可见，而不是永久消失。

## 系统控制项：每项都要读显示位置

Wi-Fi、Bluetooth、Battery、Display、Sound、Focus、Screen Mirroring、Text Input 等都是常见的系统控制项。它们可能被勾选为菜单栏显示，也可能只在控制中心中出现，或仅在活跃时显示。

| 控制项类别 | 常见英文 | 学习时应确认 |
| --- | --- | --- |
| 连接 | `Wi-Fi`, `Bluetooth`, `AirDrop`, `Screen Mirroring` | 它显示在菜单栏还是控制中心，当前状态是否活跃 |
| 设备 | `Battery`, `Sound`, `Display`, `Keyboard Brightness` | 是显示信息、打开详情还是切换值 |
| 工作状态 | `Focus`, `Now Playing`, `Timer`, `Weather` | 是否采用 `Show When Active` 规则 |
| 输入与账户 | `Text Input`, `Fast User Switching`, `Time Machine` | 出现位置与具体权限或恢复行为 |

不要因为 `Battery` 出现在菜单栏就以为它控制电池充电策略；它可能只是显示电量或打开相关控制。软件页面的名词要结合控件类型读：同样是 `Battery`，一个是菜单项，一个可能是系统设置类别，另一个可能是电量状态。

## 应用菜单项：允许出现不等于授予系统权限

`Allow in the Menu Bar` 下列出的应用菜单项来自本机已安装 App。这个开关只决定应用是否可以在菜单栏显示一个项目。它不是隐私授权、屏幕录制权限、后台登录项或网络访问权限的总开关。

| 你想判断的事情 | 不应该看什么 | 应该去哪里 |
| --- | --- | --- |
| App 能否访问照片或麦克风 | Menu Bar 开关 | Privacy & Security 的对应权限页 |
| App 是否开机启动 | 菜单栏显示规则 | General → Login Items & Extensions |
| App 是否正在后台运行 | 只看菜单栏图标 | Activity Monitor、App 状态或后台项目设置 |
| App 是否可快速从菜单栏操作 | Allow in the Menu Bar | 本页开关和该 App 的菜单项 |
| App 是否能联网 | 图标是否显示 | 网络、代理、VPN 或 App 自己的连接状态 |

页面说明中 `when the application isn’t open` 很有价值。它说明有些应用的菜单栏项目可以在主窗口未打开时继续提供工具或任务。`isn’t open` 说的是窗口或 App 的可见运行状态，不自动代表应用已完全退出或没有任何后台行为。

> [!note] 关闭菜单栏项目之前先判断用途
>
> 若一个应用通过菜单栏提供同步、录制、网络控制、输入法、备份或快速状态，关闭菜单栏项目可能让你失去可见入口。它通常不等于删除应用，但恢复时需要知道回到哪个 App 或哪个系统页重新开启显示。

## 最近项目：列表、历史和权限不是一回事

`Recent documents, applications, and servers` 很容易被误读成“系统保存的全部使用历史”。它实际描述的是一个**用于快速访问的最近项目列表**，范围包括文档、应用和曾连接过的服务器。这个列表是否出现、显示多少条，与文件是否还存在、App 是否还安装、服务器是否仍然可访问分别是三件事。

| 界面表达 | 这个设置回答的问题 | 它不能证明什么 |
| --- | --- | --- |
| `Recent documents` | 最近文档是否出现在相关入口中 | 某个文档一定还在原来的位置 |
| `Recent applications` | 最近用过的 App 是否可作为快捷项出现 | App 当前仍在运行 |
| `Recent servers` | 最近连接过的服务器是否可被列出 | 服务器仍在线或当前有权限访问 |
| `None` | 不在这类入口显示最近项目 | 删除了文件、App 或网络连接记录 |

例如某个最近文档入口失效时，正确的判断顺序是：先确认条目是快捷记录，再检查原文件是否仍在、是否有权限、所在磁盘是否已连接。你可以说：`The recent item is only a shortcut to the original document, so I need to check whether the file is still available.` 这比把“最近项目消失”解释成数据丢失更可靠。

这里的 `recent` 是形容词，修饰 documents、applications 和 servers 三个并列名词；`documents, applications, and servers` 使用了完整并列结构。软件界面中出现三个以上对象时，经常借助逗号和 `and` 清晰地列出类别。学习这类表达时，先找并列的对象，再找它们共用的限定词，能减少把一个范围误套到另一个范围的错误。

## 从 Control Gallery 添加控制：先理解“可选项”再改变布局

`Show suggestions in Control Gallery` 和 `Add Controls…` 组成了一条常见的“发现—选择—放置”路径。前者只决定图库是否展示系统建议，后者才进入选择控制项的流程。看到建议不代表系统已经把某个控制添加到你的控制中心；点击添加也不意味着改变了 Wi-Fi、声音或专注模式本身的开关状态。

```mermaid
flowchart LR
    A[打开控制图库] --> B[查看建议]
    B --> C[选择控制]
    C --> D[确定显示位置]
    D --> E[检查入口]
    E -.-> F[保留原功能状态]
```

这个流程的重点是把“入口布局”和“底层功能”分层。打开图库后，系统可能给出建议；选择一个控制后，才需要决定它显示在控制中心、菜单栏还是两处。最后应检查入口是否按预期出现，而不是假设该功能已被启用。即使把 Sound 放进菜单栏，输出设备和音量仍需要在相应控制或声音设置中单独确认。

> [!tip] 修改前记录两件事
>
> - 记录控制项原先出现的位置，例如“只在 Control Center”。
> - 记录该控制项当时的实际功能状态，例如 Wi-Fi 是否已连接、Focus 是否处于 active 状态。
>
> 这样在恢复时可以分别核对布局和功能，避免“图标回来了”却误以为网络或专注状态也已恢复。

如果确实需要添加一个控制，操作后可以这样验证并表述：`The control now appears in Control Center. I checked its location without changing the setting that it represents.` 其中 `represents` 表示这个入口所代表的底层功能；它比 `is` 更准确，因为入口本身不是 Wi-Fi 或声音状态。

## 重置控制中心前的恢复策略

`Reset Control Center…` 不是普通的显示开关。`reset` 表示把一组已组织的控制恢复到系统定义的状态，可能影响多个入口的位置或可见性。因此它适合在布局已经难以整理、并且你已记录当前配置时使用，不适合作为“先点了再看看”的尝试。

| 步骤 | 目的 | 可用英语 |
| --- | --- | --- |
| 记录当前控制项 | 知道之后要恢复哪些入口 | `I recorded the controls currently shown in the menu bar.` |
| 只修改一个明确项目 | 缩小异常范围 | `I changed one display option at a time.` |
| 检查新位置 | 确认目标入口是否出现 | `I checked whether the control appeared in the expected location.` |
| 必要时手动恢复 | 回到记录的布局 | `I restored the previous menu bar arrangement.` |
| 最后才考虑 reset | 避免无意重置多项布局 | `I will reset Control Center only after reviewing the impact.` |

如果一个控制项意外不见，优先回到对应控制项的显示设置，而不是立刻选择 Reset。若重置后需要重新安排，按“一个控制项—一个显示位置—一次检查”的节奏操作。这样你知道每次变化来自哪里，也能在出现问题时准确描述：`The reset changed the Control Center layout, so I am restoring the controls one by one.`

## 用状态句避免把应用窗口和菜单栏项目混在一起

软件界面中的 `open`、`active`、`visible`、`available` 经常描述不同层面的状态。尤其在菜单栏场景里，App 主窗口没有打开，不代表它没有菜单栏项目；有菜单栏项目，也不代表它拥有某项隐私权限。把句子的主语说清楚，可以避免故障说明含糊。

| 你要表达的事实 | 推荐句子 | 为什么准确 |
| --- | --- | --- |
| 主窗口关闭，但菜单栏入口仍在 | `The app window is closed, but its menu bar item is still visible.` | 分别说明窗口和入口状态。 |
| 菜单栏入口不再显示 | `The menu bar item is no longer visible.` | 不武断推断 App 已卸载或退出。 |
| App 当前在使用中才出现 | `The control appears only while the feature is active.` | 对应 `Show When Active` 的条件。 |
| 入口存在但需要再打开设置 | `The shortcut is available, but I still need to open the related settings.` | 区分快捷入口与详细配置页。 |

当你记录问题时，也要避免写 `The app disappeared.`。这句话无法说明是窗口、菜单栏项目、Dock 图标，还是功能本身消失。用 `window`、`menu bar item`、`control`、`setting` 这类具体名词，后续才能回到正确位置恢复。

## 两个完整操作案例

### 案例一：只读检查菜单栏隐藏规则

1. 打开 **System Settings → Menu Bar**。
2. 找到 `Automatically hide and show the menu bar`，记录当前值。
3. 解释这个值的时间或窗口条件，例如 `In Full Screen Only`。
4. 不更改选项；如果正在全屏 App 中，也不要为了验证而强制切换工作区。
5. 用英语报告：`I checked when the menu bar is hidden. The current rule applies only under the condition shown in Menu Bar settings.`

### 案例二：判断一个控制项是“显示”还是“功能开关”

1. 在 **Menu Bar Controls** 中选择一个熟悉的系统项目，例如 Sound 或 Wi-Fi。
2. 观察它是否允许在菜单栏显示、是否有 `Show When Active` 等选项。
3. 说出它的页面设置控制的是“入口可见性”，不是相关功能本身的全部状态。
4. 不勾选或取消任何复选框。
5. 用英语说明：`I reviewed where the control can appear. I did not change the underlying Wi-Fi, sound, or display setting.`

## 常见错误与恢复方式

| 错误 | 为什么会误判 | 更好的做法 |
| --- | --- | --- |
| 菜单栏项目没显示就认为 App 被卸载 | 可见性和安装状态不同 | 先看 Allow in the Menu Bar 和 App 本身是否存在 |
| 关闭 App 菜单项以为能关闭后台活动 | 菜单栏显示不等于后台运行 | 到 Login Items 或 App 自己设置验证 |
| 把 Show When Active 当成启用功能 | 它只控制活跃时的显示 | 先确认功能本身是否已经 active |
| 把菜单栏自动隐藏当成菜单丢失 | 规则可能只在全屏生效 | 检查当前窗口模式和隐藏条件 |
| 为了整理布局使用 Reset Control Center | 重置可能影响多项布局 | 先记录当前显示项，只改一个明确项目 |

3. `Allow in the Menu Bar` 与隐私权限有什么关系？
4. 用英语说出“我检查了控制项显示在哪里，但没有修改 Wi-Fi、声音或显示器设置”。
