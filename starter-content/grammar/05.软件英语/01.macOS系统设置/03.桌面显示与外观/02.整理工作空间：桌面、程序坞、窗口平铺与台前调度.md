# 整理工作空间：桌面、程序坞、窗口平铺与台前调度

Desktop & Dock 页面控制的是工作空间怎样呈现在屏幕上：常用 App 如何放进程序坞、窗口怎样最小化、桌面项目何时显示、窗口能否拖拽平铺、最近窗口怎样被集中管理。它不替你关闭程序，也不会决定文件是否保存；它改变的是你看到和切换窗口的方式。

> [!info] 本篇要建立的判断
>
> - `Dock`、`Desktop`、`Stage Manager`、`Mission Control` 分别管理什么。
> - `hide`、`minimize`、`tile`、`restore`、`rearrange` 不是同一个动作。
> - 长说明句里 `when`、`while`、`to` 和 `based on` 如何限定窗口行为。
> - 怎样用英语说明一个窗口管理设置，而不把“窗口不见了”误说成“文件被删了”。

## 先把四个工作空间概念分开

| 名称 | 它管理什么 | 典型英文 | 不是 |
| --- | --- | --- | --- |
| Dock | 常用 App、最小化窗口和运行状态入口 | `Dock position`, `Minimize windows` | 桌面上的文件摆放 |
| Desktop | 桌面项目和小组件的显示 | `Show items on Desktop` | 所有打开窗口的总览 |
| Stage Manager | 最近窗口的集中展示与切换 | `recent windows`, `single strip` | 永久保存窗口布局 |
| Mission Control | 打开窗口、全屏 App 与 Spaces 的总览 | `overview`, `Spaces`, `group windows` | 单个窗口的最小化动画 |

如果某个窗口“不见了”，可能只是被最小化进 Dock、被 Stage Manager 收到侧边、切到另一个 Space、或被全屏 App 覆盖。先判断它属于哪一种窗口状态，再决定该去哪里找，不能把视觉状态误解为文件或 App 已经被删除。

## Dock：隐藏、最小化和运行指示各有不同结果

Dock 中最容易混淆的是 `hide`、`minimize` 和 `open`。它们都可能让窗口不在当前视野里，但系统状态不同。

| 动作或状态 | 表现 | 文件和 App 发生了什么 | 可用英语 |
| --- | --- | --- | --- |
| `hide` | App 的窗口暂时不显示 | App 仍在运行，窗口可再显示 | `The application is hidden.` |
| `minimize` | 窗口缩到 Dock 或 App 图标 | 单个窗口暂时收起，内容未删除 | `The window is minimized.` |
| `close` | 关闭窗口 | 有些 App 仍运行，有些可能提示保存 | `The window was closed.` |
| `quit` | 退出应用 | App 结束运行，未保存内容可能需要确认 | `The application was quit.` |
| `open` | App 正在运行 | 可能没有可见窗口，取决于 App | `The application is open.` |

`Minimize windows into application icon` 的完整逻辑是：最小化后的窗口被收进对应 App 图标，而不是作为单独缩略图保留在 Dock。它是 Dock 的组织方式，不影响文档本身是否保存。若你找不到窗口，可以先检查它是否 minimized，再检查是否切到别的 Space；不必立刻重新打开文件。

## Stage Manager：最近窗口的组织规则

Stage Manager 的说明句包含 `arranges`、`recent windows`、`single strip`、`reduced clutter` 和 `quick access`。这些词共同解释了它的设计目标：让最近使用的窗口集中在一侧，以减少当前桌面被多个窗口覆盖的程度。

| 片段 | 它回答的问题 | 中文理解 |
| --- | --- | --- |
| `arranges` | 系统做什么？ | 将窗口按某种规则排列。 |
| `your recent windows` | 管理哪些对象？ | 最近使用过的窗口。 |
| `into a single strip` | 排成什么形式？ | 排成一列或一条连续区域。 |
| `for reduced clutter` | 为什么这样做？ | 为了减少杂乱。 |
| `and quick access` | 还有什么目的？ | 为了快速访问。 |

`recent` 指最近使用，不等于所有打开窗口。`single strip` 描述排列形式，不是“把所有窗口合成一个窗口”。看到 `Show recent apps in Stage Manager` 时，也要分清 `apps` 和 `windows`：一个 App 可以有多个窗口，页面是否把它们一次全部展示，由另一个选项 `Show windows from an application` 控制。

> [!note] Stage Manager 不是保存功能
>
> 台前调度改变的是窗口在当前工作空间中的呈现与切换方式。它不会自动保存文档，也不会保证关闭 App 后恢复所有窗口。涉及恢复行为时，应另外阅读 `open documents and windows will not be restored…` 这类明确说明。

## 窗口平铺：拖动、边缘和快捷键的条件

窗口平铺设置的英文常围绕 `Drag windows`、`edge of screen`、`menu bar`、`fill screen`、`while dragging`。这些都在描述**触发方式**，不是当前窗口的固定属性。

| 完整英文 | 触发动作 | 预期结果 |
| --- | --- | --- |
| `Drag windows to left or right edge of screen to tile.` | 将窗口拖到屏幕左或右边缘 | 以平铺方式安排窗口。 |
| `Drag windows to menu bar to fill screen.` | 将窗口拖到菜单栏区域 | 让窗口填满屏幕区域。 |
| `Hold ⌥ key while dragging windows to tile.` | 拖动时按住 Option 键 | 使用额外快捷条件触发平铺。 |
| `Tiled windows have margins.` | 平铺窗口保留边距 | 改变平铺窗口之间的视觉留白。 |

`while dragging` 表示“在拖动期间”。不要把它读成“拖完以后按 Option”。这种短条件结构在系统快捷操作里很常见：动作发生期间按住某个键，系统才改变拖拽结果。

如果窗口没有按预期平铺，先确认开关是否 On，再确认你拖到了规定边缘，最后检查当前 App 或窗口是否允许这种布局。可以这样描述：

> `The tiling option is enabled, but I need to check whether this window supports the drag gesture.`

它不把问题直接归因给系统开关，也留下了 App 自身限制的可能性。

## Mission Control 与 Spaces：总览和工作区不是同一个概念

`Mission Control` 是总览界面，`Spaces` 是不同桌面或全屏工作区。Mission Control 可以显示 Spaces 的缩略图，但两者不能混为一谈。

| 表达 | 它指什么 | 常见误解 |
| --- | --- | --- |
| `overview of your open windows` | 当前打开窗口的总览 | 某一窗口的详细内容 |
| `full-screen applications` | 处于全屏的应用 | 已退出的应用 |
| `Spaces` | 不同桌面或工作区 | 文件夹或虚拟机本身 |
| `Automatically rearrange Spaces based on most recent use` | 按最近使用自动重排工作区 | 关闭所有旧桌面 |
| `switch to a Space with open windows` | 切到目标 App 有窗口的工作区 | 把窗口复制到当前桌面 |
| `Group windows by application` | 按应用分组窗口 | 将多个 App 合并成同一个程序 |

`based on most recent use` 是条件依据：系统根据最近使用情况重新排序。若你依赖固定的工作区顺序，这个自动规则可能不符合习惯。学习时先理解它会改变“排列顺序”，而不是改变窗口内容或关闭应用。

## 两个完整操作案例

### 案例一：只读检查 Dock 的可见与最小化规则

1. 打开 **System Settings → Desktop & Dock**。
2. 找到 `Automatically hide and show the Dock`、`Minimize windows into application icon` 和 `Show indicators for open applications`。
3. 分别说出它们控制的是 Dock 可见时机、最小化窗口归属和运行指示器。
4. 不切换任何开关，不最小化正在使用的窗口。
5. 用英语报告：`I reviewed the Dock visibility, minimize, and open-application indicator settings. I did not change how any window is displayed.`

### 案例二：理解窗口平铺条件而不改变布局

1. 在 **Windows** 区域找到三条以 `Drag windows` 或 `Hold ⌥ key` 开头的设置。
2. 指出每条的触发方式和目标结果：拖到边缘、拖到菜单栏、或拖动时按住 Option。
3. 观察 `Tiled windows have margins` 当前状态。
4. 不实际拖动窗口，不改变任何平铺开关。
5. 用英语说明：`I checked the window tiling rules and the drag conditions, but I did not rearrange any open window.`

## 常见错误与恢复方式

| 错误 | 为什么会出错 | 更好的判断 |
| --- | --- | --- |
| 窗口不见就以为文件被删 | 最小化、隐藏、Space 或全屏都会改变可见性 | 先判断窗口状态，再找文件状态 |
| 把 Stage Manager 当作自动保存 | 它只管理窗口呈现和切换 | 保存问题看 App 的保存提示与恢复设置 |
| 以为 Auto-hide Dock 会关闭 Dock | 它只是按条件隐藏和显示 | 移动指针到相应位置验证显示行为 |
| 拖拽失败就关闭所有平铺选项 | 可能是窗口类型或拖动位置不满足条件 | 先读触发条件，再确认 App 支持 |
| 把 Mission Control 和 Spaces 混成同一个桌面 | 一个是总览，一个是工作区组织 | 用 overview 与 workspace 分别描述 |

## 关闭后恢复窗口：保存内容和恢复窗口是两条规则

Windows 区域里可能出现类似 `Ask to keep changes when closing documents` 和 `open documents and windows will not be restored when you re-open an application` 的说明。它们看起来都和“关闭后回来”有关，实际管理的对象不同：一个关心文档内容是否在关闭前提示保存，另一个关心再次打开 App 时是否恢复先前窗口。

| 表达 | 管理的对象 | 不应混同为 |
| --- | --- | --- |
| `Ask to keep changes when closing documents` | 关闭文档时如何处理未保存内容 | 是否把窗口最小化 |
| `open documents and windows will not be restored…` | 重新打开应用时是否恢复窗口和文档 | 是否自动保存文件内容 |
| `Prefer tabs when opening documents` | 打开文档时优先用标签页还是窗口 | Dock 中 App 的显示方式 |
| `re-open an application` | 再次打开已经退出的 App | 只是回到上一个页面 |

如果你担心工作丢失，先确认文档是否已保存；如果你只是想让窗口下次仍然出现，再看恢复窗口的设置。正确的英语报告可以是：`The document was saved, but I need to check whether its window will be restored when I reopen the application.` 这句话把内容保存和窗口恢复明确分开。

## 用完整路径描述一次窗口整理

当你需要向别人说明自己改了哪一类工作空间设置，可以使用：

```text
Open System Settings, select Desktop & Dock, and go to the Windows section.
I reviewed the tiling and restore options without changing any open window.
```

如果实际改过且确认恢复，可以补充：`After the test, I restored the previous option and checked the window behavior again.` 这里的 `window behavior` 是比“桌面效果”更明确的对象，能让对方知道你验证的是窗口出现、排列还是恢复方式。

## 自测

1. `minimize`、`hide` 和 `quit` 分别对窗口或 App 做什么？
2. Stage Manager 的 `recent windows` 与 `single strip` 分别说明什么？
3. `Hold ⌥ key while dragging windows to tile` 的触发条件是什么？
4. 用英语说出“我检查了窗口平铺规则，但没有重新排列任何打开的窗口”。

<details>
<summary>查看参考答案</summary>

1. Minimize 收起一个窗口；hide 暂时隐藏 App 窗口；quit 退出应用。三者都不能简单等同于删除文件。
2. recent windows 指最近使用的窗口；single strip 指它们被排列在一条区域中。
3. 在拖动窗口的同时按住 Option 键。
4. `I checked the window tiling rules, but I did not rearrange any open window.`
