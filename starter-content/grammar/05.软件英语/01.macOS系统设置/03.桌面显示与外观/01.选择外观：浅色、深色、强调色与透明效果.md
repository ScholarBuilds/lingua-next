# 选择外观：浅色、深色、强调色与透明效果

Appearance 页面管理的是系统界面如何呈现，不是桌面壁纸本身，也不是每个 App 的独立主题。它会影响按钮、菜单、窗口、图标、侧边栏、滚动条和部分颜色反馈。学习这些英语时，重点是看懂“哪一个元素改变”“变化在什么时候发生”“这是外观偏好还是功能状态”。

> [!info] 本篇学会后可以做到
>
> - 区分 `Light`、`Dark`、`Auto` 的时间与范围。
> - 看懂 `Tint window background with wallpaper color` 等长开关说明。
> - 分清 `Color`、`Text highlight color`、`Icon & widget style` 影响的界面元素。
> - 在不改变当前视觉偏好的情况下，准确描述页面中的设置和状态。

## Appearance 不是“壁纸设置”

`Appearance` 在这里指系统 UI 的外观：窗口、按钮、菜单和其他系统控件采用怎样的浅深色与视觉样式。`Wallpaper` 则是桌面背景。两者可能在某些颜色效果上产生关联，但入口、影响范围和恢复方式不同。

| 英文 | 主要影响对象 | 不应理解成 |
| --- | --- | --- |
| `Appearance` | 按钮、菜单、窗口等系统界面 | 只改桌面背景 |
| `Light` | 采用浅色外观 | 显示器亮度提高 |
| `Dark` | 采用深色外观 | 所有图片和网页变黑 |
| `Auto` | 系统随时间自动调整外观 | 用户不能再手动选择 |
| `Wallpaper` | 桌面背景图像或颜色 | 所有窗口的主题样式 |
| `Theme` | 一组颜色和样式偏好 | 网络或账户主题 |

`Auto` 的说明通常会出现 `throughout the day`。它表示系统会在一天的不同时间自动调整外观，不是你点开后立即“自动修复”显示问题。若你需要稳定截图、演示或学习界面，明确选择 Light 或 Dark 往往更容易复现。

| 完整英文 | 软件语境中文 | 阅读时应确认什么 |
| --- | --- | --- |
| `Use a light appearance for buttons, menus, and windows.` | 对按钮、菜单和窗口使用浅色外观。 | 三个对象说明影响的是系统界面组件。 |
| `Use a dark appearance for buttons, menus, and windows.` | 对按钮、菜单和窗口使用深色外观。 | 与 Light 互为外观选择，不是安全模式。 |
| `Automatically adjusts the appearance … throughout the day.` | 在一天中自动调整外观。 | `automatically` 说明方式，`throughout the day` 限定时间。 |
| `Liquid Glass` | 液态玻璃视觉效果。 | 当前系统中一类界面视觉样式名称，不是网络或隐私功能。 |
| `Liquid Glass Tint Amount` | 液态玻璃色调量。 | 滑块控制程度，应观察数值或视觉结果而非猜测。 |
| `Color` | 颜色。 | 通常指系统强调色或交互反馈色。 |
| `Text highlight color` | 文本高亮颜色。 | 影响选择文本时的颜色，不是全文字体颜色。 |
| `Icon & widget style` | 图标与小组件样式。 | 改变呈现风格，不代表改变 App 功能。 |

外观页里有许多看起来“很像颜色”的项目。把对象读出来就不会混淆：`Color` 是整体强调色；`Text highlight color` 是选中文本时的颜色；`Folder color` 是文件夹呈现；`Icon & widget style` 是图标和小组件外观。不要把它们都说成 `background color`。

## Light、Dark 与 Auto：状态、选择和时间条件

三种外观选择不是三个不同的“功能模式”，而是同一组互斥的偏好值。读英语时，要把“当前值”“选择动作”和“自动条件”分开。

| 你想说什么 | 自然英语 | 说明 |
| --- | --- | --- |
| 当前使用浅色 | `The Mac is using the light appearance.` | 描述当前状态。 |
| 选择深色 | `Select Dark to use a dark appearance.` | 描述动作和结果。 |
| 使用自动模式 | `Auto adjusts the appearance throughout the day.` | 描述规则和时间范围。 |
| 不想自动改变 | `I prefer a fixed appearance instead of Auto.` | 描述偏好，不把 Auto 说成错误。 |
| 需要验证影响 | `I need to check how this appearance affects menus and windows.` | 说明要观察的 UI 对象。 |

`throughout` 指“贯穿整个期间”。在软件说明里，它常用来描述一个规则持续作用的范围。和 `at night` 这类单点时间不同，`throughout the day` 不承诺某一个精确切换时刻，只强调这一规则在全天范围内起作用。

## 色调、透明与背景：读清“with”后面的影响对象

页面里的 `Tint window background with wallpaper color` 是很好的长句练习。它不是“把壁纸涂到窗口上”，而是让窗口背景带有来自壁纸颜色的色调。词序可以这样拆：

| 片段 | 语法角色 | 中文理解 |
| --- | --- | --- |
| `Tint` | 动作动词 | 给某个界面元素加色调。 |
| `window background` | 被影响对象 | 窗口背景。 |
| `with wallpaper color` | 方式或颜色来源 | 使用壁纸颜色作为色调来源。 |

完整解释可以说：

> `This option tints the window background with colors from the wallpaper.`

这里的 `with` 不是“和窗口背景一起”，而是指出色调从哪里来。相同结构在其他系统页也常见，例如 `show icons with labels`、`connect with a password`、`share with other users`。看到 `with` 时，要问它是在表示工具、来源、伴随对象，还是连接对象。

> [!note] 视觉变化不等于可用性改善
>
> 深色、透明或色调设置可能让某些人更容易阅读，也可能在特定环境里降低对比度。Appearance 页面只是外观入口；文字大小、对比度、减少动态效果等可访问性需求，应继续到 Accessibility 中单独确认。

## 图标、文件夹和滚动条：不同控件有不同的时间行为

Appearance 页面除了颜色，还包含图标样式、侧边栏图标大小和滚动条行为。它们都是“如何显示”的选择，但有的控制静态样式，有的控制何时显示。

| 页面表达 | 它控制什么 | 关键英语关系 |
| --- | --- | --- |
| `Sidebar icon size` | 侧边栏图标尺寸 | `Small`、`Medium`、`Large` 是互斥值。 |
| `Show scroll bars` | 滚动条何时显示 | 是展示时机，不是滚动速度。 |
| `Automatically based on mouse or trackpad` | 根据鼠标或触控板自动决定 | `based on` 表示依据某种输入方式。 |
| `When scrolling` | 正在滚动时显示 | `when` 限定触发条件。 |
| `Always` | 始终显示 | 持续状态，没有条件限制。 |
| `Click in the scroll bar to` | 点击滚动条时的行为 | 后面接跳页或跳到点击位置的动作。 |
| `Jump to the next page` | 跳到下一页 | 按页跳转，不是精确定位。 |
| `Jump to the spot that’s clicked` | 跳到被点击的位置 | `that’s clicked` 限定目标位置。 |

`Automatically based on mouse or trackpad` 值得完整学习。它说明“自动”不是没有依据，而是系统根据当前使用鼠标还是触控板决定滚动条显示方式。软件英语里很多自动功能都有类似结构：`based on`、`depending on`、`when available` 都在说明系统依赖什么条件作出选择。

## 两个完整操作案例

### 案例一：只读判断当前外观模式与自动规则

1. 打开 **System Settings → Appearance**。
2. 看 Light、Dark、Auto 三个选项中哪一个被选中。
3. 读出每个选项的说明，特别是 buttons、menus、windows 和 throughout the day。
4. 不改变任何模式，只确认当前选择。
5. 用英语报告：`I checked the appearance mode. It affects buttons, menus, and windows, and I did not change the current selection.`

这里 `current selection` 比 `current color` 更准确，因为你检查的是一组互斥选项中的当前选择。

### 案例二：分析窗口色调开关而不切换

1. 在 Appearance 页面找到 `Tint window background with wallpaper color`。
2. 说出它影响的是 `window background`，颜色来源是 `wallpaper color`。
3. 记录开关当前是 On 还是 Off，不切换它。
4. 如果需要向他人说明，使用：`The window tint option is currently on, but I have not changed the wallpaper or the appearance mode.`
5. 返回前确认没有按下其他确认或恢复按钮。

这项练习训练你把一个长开关说明拆成对象、动作和来源，而不是只记 `tint = 染色`。

## 常见错误与恢复方式

| 错误 | 为什么会出错 | 正确做法 |
| --- | --- | --- |
| 把 Dark 当成降低屏幕亮度 | Dark 改的是界面配色，不是显示器亮度 | 显示器亮度到 Displays 查看 |
| 以为 Auto 是“系统自己修好显示问题” | Auto 只按时间调整外观 | 阅读它的时间条件和影响对象 |
| 把 Text highlight color 当字体颜色 | 它只影响选择文本时的高亮 | 选一段文本观察，再决定是否修改 |
| 为了进 Options 随意改外观 | 不需要改变状态就能理解页面 | 采用只读观察和完整复述 |
| 把滚动条显示方式当作滚动速度 | 一个管何时显示，一个管点击或输入行为 | 分别读 `Show scroll bars` 与 `Click in the scroll bar to` |

## 系统外观与 App 自己的主题怎样区分

不少 App 会遵循 macOS 的浅色或深色外观，但某些 App 同时提供自己的主题设置。看到一个窗口没有随系统变色时，不要立刻判断 Appearance 页面失效。先确定它是系统控件、遵循系统的 App，还是拥有独立主题的 App。

| 你看到的现象 | 可能的层级 | 该怎样确认 | 可用英语 |
| --- | --- | --- | --- |
| 菜单栏和 Finder 改变了 | 系统外观已生效 | 观察多个系统窗口 | `The system appearance changed in menus and windows.` |
| 某个 App 没有改变 | App 有独立主题或未遵循系统 | 到 App 自己的设置查看 | `This app may use its own appearance setting.` |
| 文字仍然不易读 | 可能是对比度、字体大小或显示器问题 | 查看 Accessibility 或 Displays | `The issue may be related to contrast or text size rather than appearance.` |
| 只有壁纸颜色影响窗口 | 窗口色调选项生效 | 核对 tint 开关和壁纸 | `The window background is tinted with the wallpaper color.` |

正确的报告方式是说明你已经观察到的范围：`The system menus changed to Dark, but one app did not. I need to check whether that app has its own theme.` 这比“深色模式没用”更准确，也能避免把一个 App 的行为归咎于系统设置。

## 外观变化的验证方法

外观设置不像网络状态那样有 `Connected` 文字可供确认，验证主要依靠同一组界面对象的前后对比。为了避免因为光线、屏幕校色或 App 自己的主题造成误判，可以采用固定对照点。

| 对照点 | 为什么选它 | 改动后看什么 |
| --- | --- | --- |
| 系统设置的侧边栏 | 受系统外观直接影响 | 背景、选中项和图标对比 |
| 顶部菜单与普通窗口 | 系统控件密集 | 菜单、按钮、窗口背景是否改变 |
| 选中的一段文本 | 可验证高亮颜色 | `Text highlight color` 是否在选择状态体现 |
| Finder 的文件夹 | 便于观察文件夹颜色和图标风格 | 只确认视觉呈现，不改变文件内容 |
| 滚动区域 | 便于观察何时显示滚动条 | 鼠标、触控板和滚动动作是否按预期呈现 |

如果你在授权范围内做测试，最小修改原则仍然适用：一次只改一个项目，观察固定对照点，再决定是否保留。可以这样记录：

```text
Before the change, the system was using [Light / Dark / Auto].
I changed only [one appearance option].
I checked [menus, windows, or scroll bars] to verify the visible effect.
I restored the previous selection after the test.
```

这段记录只谈视觉设置及可观察结果，不需要把屏幕截图或私人文件内容附进去。

## 高对比度、深色与“看得清”不是同一个目标

深色外观有时让人在暗环境里感觉舒适，但它不必然提高文字与背景的对比度；浅色外观也不保证所有内容易读。`Appearance` 管的是视觉风格，`Accessibility` 中的显示和文字设置才更直接处理可读性需求。

| 目标 | 更可能的入口 | 不应只靠 |
| --- | --- | --- |
| 想让界面采用深色风格 | Appearance → Dark | 把显示器亮度调低 |
| 想让字更大 | Accessibility → Display / Text Size | 单独改高亮颜色 |
| 想减少动态视觉干扰 | Accessibility → Motion | 只切换 Light / Dark |
| 想提高界面区分度 | Accessibility 的对比度相关选项 | 认为透明效果自动解决问题 |
| 想改变窗口色调来源 | Appearance → tint 开关 | 改变账户或网络设置 |

当你向他人描述需求时，尽量说实际目标而不是猜功能名：`I need text to be easier to read, so I want to check text size and contrast settings.` 这样即使你一开始进入 Appearance，也能根据目标转到真正相关的页面。

## 用英语描述一次外观问题

下面的模板适合记录或求助：

> `The Mac is using the dark appearance. Menus and system windows changed as expected, but the text is still difficult to read in one area. I have not changed the accessibility settings yet.`

它包含当前外观、已验证的对象、剩余问题和未执行动作。若问题只发生在某个 App，可以加一句：`The app may have its own appearance setting.` 这会让对方先检查正确层级，而不会建议你反复切换系统主题。
