## 1. 调研结论

> 本文第 1–5 节保留 Python 0.4.3 首版的决策与验证记录；当前实现以第 6 节为准。

**判断**：Python 版 Open Interpreter 就是「贾维斯执行引擎」——它的 `computer` API 覆盖了 scholar 列的四件事（浏览网页、管理文件、控制第三方软件、执行代码），我们缺的只是把它接进工作台并套上审批门。全量抄代码不划算（AGPL 会传染整个仓库），**作为独立进程的引擎**最干净：许可证隔在进程边界外，升级只换 venv。

## 2. 决策

| 编号 | 决策 |
| --- | --- |
| D1 | 引擎装独立 venv（Python 3.11，`open-interpreter[server]==0.4.3` + `setuptools<80` + `httpx[socks]`），一键启动脚本缺了就装；仓库不含引擎代码 |
| D2 | **用库不用它的 server**：`AsyncInterpreter` 的 WebSocket 服务在 `auto_run=False` 时吞掉 confirmation 块（实测三次），而库模式 `chat(stream=True)` 吐出 confirmation 后生成器停在 yield 上——这个暂停就是审批门：同意继续迭代即执行，拒绝关掉生成器 |
| D3 | 会话与步骤复用模块 21 的表（`scope=desktop`），步骤种类：user / message / code / console / image / note。新会话默认 `full_control=true`，不再逐代码块审批，包括删除等高风险代码；每一步仍落库并在 HUD 展示，随时可急停 |
| D4 | 模型走能力 `computer-use` 绑定（未绑回落 `chat-general`），以 `openai/<model>` + `api_base` 交给引擎里的 litellm；`supports_functions=False`（代码从 markdown 围栏解析，对中转最稳） |
| D5 | 贾维斯语音主路复用火山实时会话的麦克风 PCM、VAD 和增量 ASR，但不采用该会话模型的回复与下行音频；ASR 终稿只投递一次 Open Interpreter，最终回答只由执行引擎产生，再经现有单向 TTS 播报 |
| D6 | 助理多一个 `computer_task(goal)` 工具：开引擎会话、把目标说给它、跳到贾维斯页 |
| D7 | 贾维斯页全屏（immersive，无侧栏），三栏：身份与状态 / 反应堆 + 输入 / 引擎执行记录；全局 HUD 也显示最近步骤和引擎名 |
| D8 | 引擎开 `loop` 模式：模型只说「我这就去做」不写代码时，引擎自动追一句「继续」，直到它说出收尾语（「任务完成。」/「需要更多信息。」/「任务无法完成。」，英文同收）；连着 3 轮只说不做由 runner 关掉生成器并说明，避免无上限烧调用 |
| D9 | 产品只保留一个「贾维斯」入口；原 `/assistant`、`/computer` 与会话深链兼容跳转到 `/jarvis`，不再出现在侧栏与 ⌘K |
| D10 | 点击全局贾维斯按钮后进入连续指令模式：Silero VAD 直接收段，不要求每轮先喊唤醒词；关闭前持续在后台收音 |
| D11 | 原助理保留为不可见的工作台技能层，负责阅读、词汇、邮件、日历、任务与扩展；浏览网页、文件、代码和第三方软件统一调 `computer_task` 交给 Open Interpreter |
| D12 | TTS 播放期间暂停实时麦克风上行或本地 VAD，结束后恢复连续监听，避免贾维斯把自己的回复再次识别为用户指令 |
| D13 | Electron 只申请麦克风权限；原生桌面控制的辅助功能与屏幕录制属于 `CuaDriver.app`，由 `cua-driver permissions grant/status` 申请和读取。HUD 合并显示“麦克风 / 电脑控制”，不申请系统音频录制。macOS TCC 不能被应用绕过，完全接管只取消应用内审批 |
| D14 | `POST /jarvis/session/ensure` 是并发安全的唯一会话入口；全局按钮先建引擎再开收音，不得回落到旧助理 |
| D15 | 引擎 `busy=true` 时拒绝新指令，不在子进程 stdin 无界排队 |
| D16 | Jarvis 使用独立 `jarvis.speak` 偏好，默认开启；播放被拦截或输出设备失败时明示错误，不复用旧 `assistant.speak=off` |
| D17 | 实时语音不可用时自动降级到本地 VAD + ASR + TTS 常听链路，面板明示降级原因 |
| D18 | 全局急停同时提供 HUD、托盘和 `⌘/Ctrl+Shift+Esc`，直接终止所有引擎子进程并停止收音 |

## 3. 实施记录（2026-09-02）

- `server/engine_runner/oi_runner.py`（只依赖标准库与 interpreter）、`server/domain/jarvis.py`（子进程管理、事件落库、审批门、危险代码判据）、`server/app/routers/jarvis.py`（status / sessions / say / approve / auto-run / stop）。
- `web/src/features/jarvis/`（HUD 页 + CSS）、`lib/api-jarvis.ts`；store 与 listenClient 带 `jarvisSessionId`；导航「助理」组加「贾维斯」，⌘K 两条。
- `tools/launch_nexus.py`：`ensure_engine()`。
- 测试 `tests/test_jarvis.py`（7 条，假 runner 脚本走协议）；`tests/test_listening.py` 的 fake_answer 带 `jarvis_session_id`。
- **真实链路**：库模式用我们的上游模型（`gpt-5.6-luna` 中转）跑「在临时目录写 hello.txt 并打开计算器」：三次审批，写了文件、Calculator 真的弹出来，50 秒。
- **界面实测**（claude-in-chrome，`/jarvis?new=1`）：输入「在 /tmp 下新建 jarvis_hello.txt，内容写 hello from nexus，然后读出来告诉我」→ 引擎说一句、给出 python 块、页面右上出审批卡（AWAITING APPROVAL）→ 点「执行」→ 控制台输出 `hello from nexus` → 引擎「任务完成。」，`/tmp/jarvis_hello.txt` 在磁盘上。

**踩坑**

- 引擎 venv 用 `uv venv` 建没有 `setuptools`，而它 import `pkg_resources`；`setuptools>=80` 又把 `pkg_resources` 拿掉了，要钉 `setuptools<80`。
- `open-interpreter` 基础包不含 server 依赖（janus），要装 `[server]` extra，否则 `AsyncInterpreter()` 构造时 `FastAPI` 未定义。
- 起 API 的 shell 若导出 `all_proxy=socks5://`，引擎里的 litellm / httpx 同样需要 socksio。
- 它的 WebSocket 服务在 `auto_run=False` 下不发 confirmation（`_respond_and_store` 与 `AsyncInterpreter.respond` 两层过滤叠加），别再走那条路。
- **模型只宣布打算不写代码，引擎就当这一轮结束了**：`gpt-5.4-mini` 回「我这就新建文件并读出来」然后停笔，`busy` 归 false、没有审批卡，界面上看像引擎没反应。Open Interpreter 的 `respond` 循环规则是「最后一条 assistant 消息没代码 → 退出」，它自带的 `loop` 模式正是治这个的（D8）。收尾语要中英都收：系统提示词让它用用户的语言回答，只配英文 breaker 会让中文的「任务完成」永远匹配不上而一直被催。
- 页面刚从 `?new=1` 建完会话那几秒里打字会丢：URL 换成 `?session=N` 时输入框重挂载。等 STATE 变 online 再输入即可，不做特殊处理。

**已替 scholar 做的**：`computer-use` 从 `gpt-5.4-mini` 改绑 `gpt-5.6-luna`（`PUT /config/bindings/computer-use`，可在设置 · 模型服务里改回）。

**留给 scholar**：鼠标键盘要给引擎的 python（`data/engines/open-interpreter/bin/python3.11`）授「辅助功能」，截图授「屏幕录制」；看屏幕的任务要 `computer-use` 绑带视觉的模型。

## 4. 全局统一入口修订（2026-09-02）

Claude 首版把「助理」「电脑操控」「贾维斯」并列成三个产品入口，常听开关也仍要求喊 Hey Jarvis；这与本次确认的产品形态不符。修订后：

- `JarvisHud` 常驻全局，首次点击主动申请权限并开启连续指令模式；收起面板不停止监听，必须明确点「停止监听」。
- 工作台内的查书、复习、邮件、日历、任务仍复用原代理工具，但对用户只表现为贾维斯技能；外部网页、文件、代码和软件统一交给 Open Interpreter。
- Open Interpreter 的代码审批与邮件发送确认都进入全局面板；待确认增长时由桌面通知带回 `/jarvis`。
- `/assistant`、`/computer`、`/computer/:sessionId` 只保留兼容重定向，侧栏与命令面板不再展示。
- 连续监听协议新增 `continuous`、`pause`、`resume`；服务端单测覆盖无需唤醒词收段和 TTS 暂停/恢复控制。

本轮自动验证：前端 TypeScript、CSS 类名、JSX 文案、滚动守卫通过；Electron TypeScript 构建与桌面壳探针 15 项通过；`test_listening.py` 11 条与 `test_jarvis.py` 7 条通过。当前机器的麦克风、辅助功能、屏幕录制均已显示 `granted`；换机器或权限被收回时仍须由人在 macOS 弹窗中点击允许，自动化不能代替这次授权。

## 5. 完全接管与实时语音修订（2026-09-02）

本节覆盖前文的「代码逐块审批」与「01 语音层不用」结论。产品不引入 01 的源码，但复用项目现有、已验证的火山端到端实时语音作为语音前台；Open Interpreter 仍是唯一电脑执行引擎。

- 全局按钮并行申请 TCC 权限与 `ensure` 引擎，完成后直接建立端到端实时会话；火山断开才降级到 CR-008 常听。
- 火山会话在贾维斯模式下只提供 VAD 和 ASR；服务端不转发它的对话文本与下行音频，前端也不创建第二个 PCM 播放器。
- ASR 终稿只调用一次 Open Interpreter；引擎完成后通过 `jarvis_result` 返回唯一结果，再走工作台已有的单向 TTS。播放期间暂停麦克风上行，不会触发自我回声指令。
- 实测电脑操作：「打开 macOS 系统计算器」生成 `subprocess.run(["open", "-a", "Calculator"])`，无审批执行，返回码 0。
- 急停 API 实测约 15 ms；6 个并发 `ensure` 请求返回同一会话。桌面探针 16 项通过，读到麦克风、辅助功能和屏幕录制均为 `granted`。
- 当前执行后端仍是 Python Open Interpreter 0.4.3 sidecar。本机已验证新 Rust `interpreter app-server` 的线程、turn、审批和 MCP 协议，但本轮未切换运行时；界面明示真实引擎版本与协议，不将可用二进制误报为已集成。

## 6. Rust App Server 迁移（2026-09-02）

本节覆盖前文的 Python sidecar、库模式、confirmation 审批门和独立 venv 决策。

- 执行内核改为本机 `interpreter 0.0.40 app-server --stdio`，通过 JSON-RPC v2 管理 `initialize → thread/start → turn/start → item/* → turn/completed`。不再启动 `server/engine_runner/oi_runner.py`，不再安装或使用 `data/engines/open-interpreter` Python 0.4.3 venv。
- Rust thread 固定 `approvalPolicy=never` 与 `sandbox=danger-full-access`。App Server 仍将 command / file change / MCP call / agent message 落入 `computer_step`；HUD、托盘和 `CommandOrControl+Shift+Escape` 继续作为三处急停。
- 网页操作安装 `agent-browser 0.36.0` 及其专用 Chrome；原生软件操作安装 trycua `cua-driver 0.23.2`，并作为 App Server MCP 注入。Rust 线程实测三项状态为 `agent-browser=ready` / `cua_driver=ready` / `lingua=ready`。
- Lingua MCP 改为 API 进程总是在回环地址挂载；未配置 `LINGUA_MCP_TOKEN` 时生成进程内随机 Bearer 令牌，只注入当前 Rust App Server。真实 turn 已调用 `list_capabilities` 并返回 10 个 operation。
- 每个 turn 有 300 秒上限。超时先发 `turn/interrupt`；内核不响应或异常退出时自动重启 App Server、重建 thread，最多恢复两次，避免无界重试。
- Electron 新增独立 `/jarvis/notch` 刘海窗：无框、始终置顶、跨 Space、不占用任务栏，可后台唤醒、打开执行现场和急停。主窗口在 macOS 点关闭时改为隐藏，持续语音 renderer 不被销毁。
- 贾维斯实时输入继续复用 `MicCapture`，音频输入只有 `getUserMedia({audio: ...})`，不存在系统音频捕获；回答由工作台单向 TTS 播放。
- 真实只读验证：`agent-browser` 打开本地工作台并读到标题 `NEXUS`；`cua-driver permissions status --json` 返回 `accessibility=true` 与 `screen_recording=true`。HUD 按 CuaDriver 0.23.2 的实际布尔字段解析状态，授权面板打开期间自动刷新，不再显示 Electron 开发壳或备份 App 的错误权限归属。

当前门禁：贾维斯、常听、助理与单一回答桥相关后端 29 条测试通过；前端 typecheck、UI 守卫、生产构建和 1440 条 Vitest 通过；Electron 构建通过，桌面壳探针 18/18 通过，读到 CuaDriver 组合权限为 `granted`。
