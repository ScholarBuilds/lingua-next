# CR-015 自定义唤醒与 Codex 执行内核

- 提出：scholar，2026-09-03
- 状态：已被 [CR-016](./16.CR-016-贾维斯功能退场.md) 替代（2026-09-03）
- 基线：`aec2177`
- 影响模块：唤醒、语音设置、贾维斯舞台、App Server 适配、桌面运行时与合规清单

## 1. 决策

| 编号 | 决策 |
| --- | --- |
| D-1 | 设置中允许输入 2–32 字符的任意唤醒短语；预训练 openWakeWord 仍作为低资源选项 |
| D-2 | 自定义短语由独立的 macOS Speech 帮助进程在本机匹配；命中前不建云端语音会话，命中后发送有限文本与同句命令 |
| D-3 | 用户可配置唤醒后第一句回应；模型可生成最多 5 个简短变体，开启随机后每次只播一条 |
| D-4 | 中央形象使用 Three.js WebGL 舞台，状态驱动材质自发光、景深层级、粒子和环形规迹；WebGL 不可用时保留静态形象 |
| D-5 | 默认执行子进程从 Open Interpreter Rust 迁到官方 Codex App Server；NEXUS Kernel、Mission、审批、记忆、事件和工具分层保留 |
| D-6 | 安装包只携带 Codex arm64 运行时；开发档的旧引擎回落仅用于迁移排障 |
| D-7 | 火山语音继续作为 BYOK 稳定主路。`jarvis-codex` 的 Codex Realtime 只作为实验协议参考，不把 ChatGPT 登录隐式变成产品前置条件 |
| D-8 | NEXUS 不另造第二个通用 Codex：Codex 负责推理和通用执行，NEXUS 只负责工作台上下文、Mission、记忆、审批审计、唤醒与桌面呈现 |

## 2. 用户体验与失败语义

- 常听 + 自定义短语时，页面不长期占用麦克风与云端 WebSocket；本机命中后才启动一轮语音。
- 例如「你好，小爱，打开抖音」，唤醒帮助进程会传回完整识别文本，前端只将「打开抖音」送入当轮。
- Speech 权限、本地识别或帮助进程不可用时显示明确状态，不开启伪常听；用户仍可使用预训练词、按键说话或文字。
- 唤醒回应是同一语音状态机的 TTS item，可打断、可追踪，不与后续回答争抢播放队列。

## 3. 实施证据

- 后端语音设置、短语归一化、同句命令与唤醒回应均有定向测试。
- 前端 Store 证明自定义常听不提前建语音会话，命中后携 `wakeAck` 连接并传递命令尾部。
- 原生帮助进程为 arm64、独立 bundle identity 与有限麦克风/Speech entitlement；本地构建按输入指纹缓存，不触发整包重签。
- Electron 真机探针验证 WebGL 画布就绪、静态图兜底、1280×720 与 960×720 无页面级横向溢出。
- Codex 0.149.1 真实 App Server 完成 initialize/account 握手；包内运行时使用固定 `codex` 路径，不依赖用户全局 PATH。
- 急停在关闭 App Server 前持久化撤销待审批步骤，界面不会遗留 `awaiting` 卡片。
- 完整验证：后端 2372 条、Web 1522 条、桌面壳 29 条测试通过；Electron 运行探针 48 项通过，治理 L1 通过。

## 4. 尚未扩大的范围

- 本批没有把 Codex Realtime 升为默认语音。只有当账号类型、协议版本、断线回退和隐私提示都有发布级契约时，才作为可选传输实施。
- 本批不删除服务端的 `interpreter` 显式回落配置；等至少一个安装包版本验证迁移后删除。
