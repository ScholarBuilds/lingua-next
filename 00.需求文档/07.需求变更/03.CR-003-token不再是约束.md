# CR-003 token 不再是约束

- **提出日期**：2026-08-20
- **决策人**：scholar
- **涉及需求**：FR-445（反转其交互形态）、FR-446 ~ FR-450（新增）
- **触发**：用户原话「不用在乎花不花 ai 的 token，可以随便调用，我要的是最好的配置和
  最好的功能以及最好的交互，保证所有的东西都是真实可用的」
- **状态**：已实现（2026-08-20）

## 1. 反转项

| 编号 | 原口径 | 新口径 | 理由 |
| --- | --- | --- | --- |
| FR-445 的交互形态 | 画风变了只**提示**「出图时会按当前画风重写」，重写要用户点按钮 | 机器生成的提示词**自动按新画风重写** | 原设计的唯一理由是省一次文本调用。这个约束取消后，让用户手动点就成了纯粹的负担——他改画风的意思本来就是「按这个画风来」，不该要求他先理解「提示词是上一次画风的产物」这条内部机制 |
| 提示词解读 | 无此功能 | 创作台打开**默认就做**，不用点 | 同上：解读走文本模型，比出图便宜两个数量级。看不懂提示词的代价是花钱出一张不对的图，默认做掉更划算 |

## 2. 新增项

| 编号 | 内容 |
| --- | --- |
| FR-446 | 换画风即重写提示词（自动，两个前提：机器生成的 + 有中文想法） |
| FR-447 | 提示词的中文解读，含「你说了但提示词里没有」的遗漏比对 |
| FR-448 | 跟 AI 聊着改提示词，每轮拿当前提示词当底稿 |
| FR-449 | 「不指定画风」成为一等选项；自由出图默认就是它 |
| FR-450 | 左栏按因果顺序编号，意图 / 画风 / 提示词收进同一个创作台 |
| FR-451 | 「不指定画幅」成为一等选项，由立意按画面内容挑并显示它选了什么 |
| FR-452 | 图片查看器默认「适应」，可缩到适应以下，百分比按原图真实像素算 |
| FR-453 | 左栏分组界线从「设置类型」改成「画什么 vs 怎么发」，画幅归入前者 |

## 3. 仍然成立的口径

> [!warning] 「不在乎 token」不等于「不告诉用户在花钱」
>
> 出图这一步的用量与档位照旧显示（BR-120：2K 与 high 必须显式选择并在按钮上标出档位）。
> 变的是**不再为了省调用而牺牲交互**，不是取消知情。
>
> 界面上的成本文案相应降调：去掉「贵档」「便宜得多」这类劝阻性说法，
> 保留「本次调用 N 次 · 1K / medium」这类事实。

以下不受本次变更影响，继续有效：

- **BR-110 不伪造**：解读、遗漏、对话回复都必须来自模型真实返回，
  拿不到就如实报错，不编内容。`missing` 尤其明确禁止「为了显得有用而编造遗漏项」。
- **不做自动优化开关**（§11.2）：改写只在显式操作时发生。
  自动重写不违反这条——它的触发条件是用户**主动换了画风**，且只覆盖机器自己生成的那份，
  用户手写或聊出来的内容一律不动。
- **BR-100 语义别名**：新增的两条通路都走 `explain-standard`，业务代码里没有模型名。
