# CR-014 本地开发一键启动完善

- **提出**：scholar，2026-09-03
- **状态**：已实现
- **基线**：`d1ba1e6`
- **影响模块**：本地启动器、Electron 开发壳、开发档运行拓扑

## 1. 问题

根目录的一键启动文件使用中文名称，不利于终端输入、跨平台调用和文档引用。启动器默认优先打开 `/Applications/NEXUS.app`，会让开发者误以为正在测试当前源码。它只校验 API 和 Web 的 HTTP 存活，worker 或 Electron 启动后立即退出仍可能显示启动完成；启动中途失败时也会留下半套进程。

## 2. 决策

| 编号 | 决策 |
| --- | --- |
| D-1 | macOS 双击入口为 `Start NEXUS.command`，终端入口为 `start-nexus.sh`，Windows 入口为 `start-nexus.bat`，Python 入口为 `tools/launch_nexus.py` |
| D-2 | 默认开发拓扑已被 CR-017 替代为 desktop + SQLite；PostgreSQL、Redis/Arq 改为 `--mode developer` 显式选择 |
| D-3 | 本地开发启动不构建签名包，不默认打开已安装包；`--installed` 作为显式选项保留 |
| D-4 | API 与 Web 校验 HTTP 健康，worker 和 Electron 校验进程存活；任一必需服务失败则整体启动失败 |
| D-5 | 整体启动失败或被中断时，回收本轮 API、worker、Web 和桌面壳进程，PostgreSQL 与 Redis 容器保留以缩短下次启动 |
| D-6 | CR-016 后启动器不再检查或启动 Jarvis App Server、Codex、CuaDriver 与唤醒进程 |
| D-7 | 源码 Electron 壳只在 TypeScript 源码、构建配置或产物集变化时重新编译；未变更时直接复用 `desktop/dist` |

## 3. 验收

- 四个新入口名称均可正常调用，仓库不再引用旧文件名。
- 默认命令启动 desktop SQLite、API 内置任务消费者、Vite Web 和源码 Electron，不调用任何签名流程。
- worker 或 Electron 立即退出时返回失败，启动中途异常后无本轮残留进程。
- `--browser`、`--no-open`、`--installed`、`--mode docker`、`--status` 和 `--stop` 保留明确语义。
- 启动器不将退场的执行引擎视为依赖；桌面壳产物未过期时不运行 `tsc`。

## 4. 实施记录

- 启动器对 API、Web、worker 和 Electron 补齐存活检查，桌面壳编译或启动失败不再静默降级为浏览器。
- 默认路径直接编译并打开源码 Electron；已安装包改为显式 `--installed`。
- 整体启动在失败和中断路径上统一回收开发进程。
- CR-016 退场后删除执行引擎前置检查，日常启动不再要求 `interpreter`、`agent-browser` 或 `cua-driver`。
- 增加 Electron 产物新鲜度判断：源码、`package.json`、`tsconfig.json` 与 `dist` 产物集对齐时跳过 `tsc`，变更或删除源文件后会重编。
- 启动器 Ruff 与 8 条行为测试通过；Electron TypeScript 编译通过。
- 真实运行 `./start-nexus.sh --timeout 180` 退出码为 0；PostgreSQL / Redis 健康，Alembic 升级到当前版本，API、worker、Web 和源码 Electron 进程均存活，`/healthz` 返回 `status=ok`。
- 未变更桌面源码的实际重启输出“复用未过期的 `desktop/dist`”，未运行签名或打包，全套开发服务在 9.63 秒内完成重启。

## 5. Windows 源码启动（2026-09-10）

- `start-nexus.bat` 通过 uv 准备 Python 3.12，启用 UTF-8，使用脚本自身目录，双击失败时保留提示。
- Windows 直接运行 Electron 原生 exe；pnpm 的 npm/Corepack 安装通过 Node 入口执行，避免批处理转义和中文路径问题。
- 依赖安装使用锁文件；默认仍是 SQLite + Web + Electron，公开内容包按已有机制初始化。
- `.github/workflows/windows-launch.yml` 检查 Windows 批处理入口、API 健康、Web 响应和 Electron 进程，失败保留日志。
- 本地启动器 13 条测试通过；Windows 实机结果以该工作流为准，不用 macOS 测试代替。
