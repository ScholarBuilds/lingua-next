## 1. 变更背景

CR-004 立项后交付了 M1~M5（v1 MVP），随后 codex 又交付了一版扩展（commit `cc99aaa`，
26313 行）。用户实测两版后给出的判断是：**功能没有全量集成，画布的交互与观感明显不如蓝本**。

用户逐条点出的差距：

| # | 用户原话要点 | 事实核对结果 |
| --- | --- | --- |
| 1 | 画布分普通/智能两种，我们只有一种 | 属实。蓝本 `canvas.js`（16 类节点）与 `smart-canvas.js`（5 类节点）是两套并行实现，画布 JSON 里 `kind` 字段区分 |
| 2 | 连线的丝滑性、便捷性、显示效果都不如原项目 | 属实。蓝本每条连线配一条 `stroke-width:14` 的透明命中路径 + 中点删除按钮 + 端点圆点，我方 React Flow 默认边无此结构 |
| 3 | 并发应该不限制 | 属实。蓝本 `smartCascadeParallelLimit()` 硬编码上限 6（ComfyUI 时取实例数），我方无此概念 |
| 4 | 循环和并发应该是一个节点 | 属实。蓝本 `smart-loop` 用 `mode: serial \| parallel` 一个字段切换，我方无循环节点 |
| 5 | 选中图片头上要出现对应工具 | 属实。蓝本节点悬浮工具条（预览/裁剪/扩图/遮罩/画笔/宫格切分/下载），我方无 |
| 6 | 右键菜单要有基础项 | 属实。蓝本有 `createMenu`/`linkCreateMenu`/`nodeInputMenu`/`nodeOutputMenu`/`imageNodeMenu` 五套菜单 |
| 7 | 连线动效可开关 | 蓝本已有 `conn-reduce-motion`，我方无 |
| 8 | 默认生图质量应全局 high | 属实。蓝本画布 `settings.quality = "auto"`，我方亦非 high |
| 9 | LiteLLM 别名要和上游模型名一致 | 与既有铁律冲突，见 §3.4 |

## 2. 反转项：许可证约束

### 2.1 原裁决（CR-004 · BR-149）

> 蓝本 Infinite-Canvas **只允许功能复刻不允许搬代码**（许可证禁商用 + 二开传染开源）。

依据是蓝本 README 的声明：

- 已申请著作权，禁止商业用途
- 根据代码二次开发的软件必须保持开源并注明来源作者

### 2.2 新裁决

用户在本轮明确两次：本项目是**个人自用项目**，不封装成产品、不分发、不商用，
因此上述两条约束在本场景下均不触发。**允许直接移植蓝本实现**。

### 2.3 仍然保留的义务（不因自用而取消）

| 义务 | 做法 |
| --- | --- |
| 来源登记 | 移植来的文件在文件头注明蓝本路径与函数名；`server/resources/*/INFINITE_CANVAS_SOURCE_LICENSE.txt` 保留 |
| 作者署名 | 开源清单记作者 wuli大雄 与仓库地址 |
| 边界提醒 | 若将来要商用或分发，必须先重新评估本条 |

> [!note] 为什么仍要登记
>
> 登记的成本是几行注释，而「哪些代码是抄来的」这个事实一旦丢失，将来任何形态变化
> （开源、分享、商用）都要重新逐文件考古。这与许可证是否强制无关。

## 3. 新增与修订裁决

### 3.1 画布实现选型：放弃 React Flow，自研 DOM+SVG 内核

**裁决**：新建 `web/src/features/studio/canvas-core/`，移植蓝本的渲染与交互语义；
移除 `@xyflow/react` 依赖；现有 `CanvasPage`/`CanvasNodes`/`canvasStore` 全部重写。

**依据**（读蓝本 `static/canvas.html` + `smart-canvas.js` 得出）：

```text
#board                       视口层：拖放遮罩、框选框、选择中枢、五套菜单
  └ #world                   变换层：transform: translate(x,y) scale(s)
      ├ <svg id="links">     连线层：三次贝塞尔 path
      ├ #linkControls        连线控件层（HTML）
      └ #nodes               节点层（HTML div）
  └ #minimap                 缩略导航
```

蓝本**没有用 Canvas 或 WebGL**，就是 DOM + SVG。这意味着：

- 移植不存在技术障碍，React 重写这套结构是直译；
- React Flow 的限制（边渲染依赖 ResizeObserver、命中区不可控、节点外壳被框死）在自研内核里全部消失；
- 我方仓库已记录「React Flow v12 在内嵌浏览器面板里永远画不出边」这条坑（ResizeObserver 不回调），自研内核顺带解决。

**连线手感的三个具体来源**（必须逐条复刻）：

| 元素 | 作用 |
| --- | --- |
| `.conn-line` | 主路径，可带流动动效 |
| `.conn-hit` | `stroke-width:14` 透明路径，**这是"好点中"的全部原因** |
| `.conn-end` + `.conn-cut` | 端点圆点、中点删除按钮（悬浮显形） |

### 3.2 双画布形态

**裁决**：保留普通画布与智能画布两种形态，画布记录加 `kind` 字段。

| 形态 | 蓝本来源 | 节点模型 | 定位 |
| --- | --- | --- | --- |
| **智能画布** `smart` | `smart-canvas.js` | `smart-image`、`smart-loop`、`smart-prompt`、`smart-group`、`smart-minimax` | 生成能力**内置在图片节点里**，一个节点即容器即生成器，上手快 |
| **普通画布** `normal` | `canvas.js` | image/output/prompt/generator/llm/loop/comfy/rh/minimax/midjourney/msgen/video/ltxDirector/group/promptGroup/workflow | 每种能力一个专用节点，可编排复杂链路 |

两种形态**共用同一个 canvas-core 内核**（视口、连线、选择、快捷键、菜单），只在节点注册表上分叉。

### 3.3 循环/并发节点规格（用户要求吃透原理）

**结论**：蓝本的循环与并发**是同一个节点的两个模式**，不是两个节点。

`smart-loop` 节点字段（实测自蓝本 `data/canvases/*.json`）：

| 字段 | 语义 |
| --- | --- |
| `mode` | `serial`（循环）/ `parallel`（并发） |
| `count` | 轮数 |
| `loopStart` | 起始计数，默认 1 |
| `showPrompt` | 开启提示词变量模式 |
| `variablePrompt` / 多个提示词字段 | 每轮取第 index 条 |
| `imageInput` | 开启图片切片模式 |
| `imageBatchSize` | 每轮取几张上游图（1~100） |

**它是一个驱动器**：本身不产图，而是驱动下游链路跑 N 轮。三种用法：

1. **变量计数**：提示词里插 `《计数》`/`《总数》`/`《进度》` token，每轮替换成序号
   → 「第 1 张…第 N 张」这类序列图
2. **多提示词字段**：写 N 条不同提示词，循环 N 轮各出一张，共享同一条上游参考图
   → **一组卖点图、一套 App 登录界面**（一致性来自共享参考图，差异来自各轮提示词）
3. **图片切片**：`imageInput` 开启后按 `loopStart + imageBatchSize` 切上游图片列表，每轮喂不同的图
   → **把一个界面的所有 UI 切图逐个处理成透明切图**

用户对这个节点的三处理解，与蓝本实现**完全吻合**，可直接按此实现。

**升级项（超过蓝本）**：

| 项 | 蓝本 | 本项目 |
| --- | --- | --- |
| 并发上限 | 硬编码 6（`smartCascadeParallelLimit`） | 不设上限，改为可配置（全局默认 + 节点覆盖），仅按供应商速率限制自动退避 |
| 模式说明 | 只有两个按钮，无解释 | 每个模式配一句话说明用途 + 一个典型场景示例 |
| 变量 token | `《计数》`/`《总数》`/`《进度》` | 保留全部，另加日期、随机种子、上游文件名等，并做成可点选插入的 chip |
| 图片切片 | 数字输入 | 快捷选项（1/2/3/4/6/8/10）+ 自定义，并实时预览「这一轮会喂哪几张」 |

### 3.4 模型别名：双层策略

**冲突**：用户要求「LiteLLM 别名必须和上游模型名一致，方便识别」，
与既有铁律「业务代码禁止硬编码供应商模型名，只走语义别名」（CLAUDE.md 核心原则 5）冲突。

**裁决**：两层并存，各司其职。

| 层 | 别名形态 | 谁用 | 例 |
| --- | --- | --- | --- |
| 语义层 | 业务语义名 | 业务代码（翻译、讲解、封面…） | `translate-fast` → 上游 `gpt-5.4` |
| 直通层 | **与上游同名** | 配置中心展示、工坊里用户手选模型 | `gpt-image-2` → 上游 `gpt-image-2` |

配置中心**同时显示别名与真实上游模型名**。换供应商时业务代码不动（语义层解耦仍然成立），
工坊里用户看到的永远是真名（识别需求满足）。

### 3.5 全局生图质量默认 high

**裁决**：全产品默认 `quality = high`，不再是 `auto`。

- 全局默认值落配置中心，一处可改；
- 各工具/节点可在其上微调，微调不写回全局；
- 蓝本画布 `settings.quality` 默认 `"auto"`，此项**高于蓝本**。

### 3.6 连线动效开关

**裁决**：连线流动动效默认开启，提供显式开关（画布工具栏 + 全局偏好两处可关）；
同时尊重系统 `prefers-reduced-motion`（蓝本已有 `conn-reduce-motion` 类，行为一致）。

### 3.7 节点悬浮工具条

**裁决**：节点选中/悬停时头部浮出工具条，与蓝本一致：
预览 · 裁剪 · 扩图 · 遮罩 · 画笔 · 缩放 · 宫格切分 · 下载。

图片编辑器七个模式（`preview`/`crop`/`expand`/`mask`/`brush`/`resize`/`grid`）全部要有；
宫格再分 `split`（切分）与 `join`（拼接）两个子模式。

### 3.8 右键菜单

**裁决**：复刻蓝本五套菜单并统一成一套上下文菜单系统：

| 菜单 | 触发 |
| --- | --- |
| 创建菜单 | 双击空白 / 右键空白 |
| 连线菜单 | 右键连线（删除、插入节点、改类型） |
| 节点输入菜单 | 从输入端口拖到空白处松手 |
| 节点输出菜单 | 从输出端口拖到空白处松手 |
| 图片节点菜单 | 右键图片节点 |

### 3.9 API 配置引导

**裁决**：配置中心每个供应商都要有**授权引导卡**，包含：

- 这个平台是什么、能提供哪些能力（生图/聊天/视频）；
- 逐步骤的配置指引，**每一步都带一个跳转按钮直达该平台官方页面**（注册页、控制台、
  Key 管理页、计费页）；
- 字段级说明（Base URL 要不要带 `/v1`、Key 前缀长什么样）；
- 配好后一键测试连通性，失败时给原文错误 + 修复建议。
