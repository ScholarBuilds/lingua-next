# CR-002 开放 4K 与画风库

- **提出日期**：2026-08-20
- **决策人**：scholar
- **涉及需求**：CR-001 的画质档决定（反转）、FR-442 ~ FR-443（新增）
- **触发**：用户指出左侧参数栏功能不足——画风要多、比例要能预览、要支持 4K、
  每个配置都该点开成弹窗、整体 UI 要重做
- **状态**：已实现（2026-08-20）

## 1. 反转项

| 编号 | 原口径 | 新口径 | 理由 |
| --- | --- | --- | --- |
| CR-001 画质档 | 「1K 为主，2K 按需，**不开 4K**」 | **开放 4K**，长边 3840 | 原理由是两条：一没有超分模型，二贵且未验证。用户明确说明「gpt 中转是我自己的账号，token 完全足够」——**第二条前提没了**。第一条仍然成立，所以 4K 是上游直出而非本地放大，且保持显式选择、不做默认 |

> [!danger] 后续实测：**这个中转根本不认分辨率档**（2026-08-20 标定）
>
> 8 比例 × 3 档共 24 次真实调用，结果是三档返回的**像素量完全一样**（约 1.57MP）。
> 请求 3840×3840 回来 1254×1254，请求 1024×1024 回来**也是** 1254×1254——
> 只有画幅比例被精确遵守。也就是说本条「开放 4K」在当前供应商上**不产生任何效果**。
>
> 没有回滚这条决定：档位是**供应商的属性不是产品的属性**，换个认分辨率的供应商重跑
> 标定就生效。做法是让标定数据驱动界面——`tiers_effective` 为 false 时照实告诉用户
> 「这个网关不认档位」，而不是留一个选了没用的控件不吭声。明细见
> [需求说明 §14.7](../02.功能需求/16.生图与视觉资产/需求说明.md)。

> [!warning] 「能出」与「上游保证出得好」是两回事
>
> 上游文档把 2560×1440 以上标注为实验性分辨率。这条事实没有变，变的是我们怎么处理它：
> 以前是 `validate_size()` **直接拒绝**，现在降级成 `is_experimental()` 的**事实标注**，
> UI 照实标出来但不拦人。硬约束（宽高须为 16 的倍数、比例 1:3~3:1、单边不超 3840）
> 仍然在 `validate_size()` 里拦。

## 2. 新增项

| 类别 | 内容 | 需求编号 |
| --- | --- | --- |
| 画风库 | 从 5 个扩到 **111 个**（自制 5 + 导入 106），分 9 类，全部有中文名与一句话说明 | FR-442 |
| 自定义画风 | 用户可增删改自己的风格，与内置同一命名空间、撞名即拒 | FR-442 |
| 参数形态 | 摊开的侧栏 → **设置行 + 弹窗**：画风、比例、高级、提示词各一个弹窗 | FR-443 |
| 比例选择 | 可视化预览全部 8 个比例 × 3 档，标出实验性与实测值 | FR-443 |
| 高级参数 | 输出格式、背景（含透明底）、压缩率、审核强度，每项配一句人话解释 | FR-443 |
| 生成态 | 真实管线节点步骤条 + 骨架特效 + 流式中间图 | FR-443 |

## 3. 画风库的来源与取舍

| 项 | 结论 |
| --- | --- |
| 取自 | **twri/sdxl_prompt_styler（MIT）** 的 `sdxl_styles_sai.json`(17) + `sdxl_styles_twri.json`(89) = 106 条 |
| 没取 | Fooocus 聚合的另外 101 条（`diva` 79 + `mre` 22）。Fooocus 本体是 **GPL-3.0**，而那 101 条只存在于它那里。同样的东西能从 MIT 上游拿，就没有理由去拿 GPL 的 |
| 不是照搬 | 原提示词是给 SDXL 那类 CLIP 条件扩散模型调的，塞满「8K / masterpiece / highly detailed / trending on artstation」质量咒与 `(word:1.4)` 权重语法。gpt-image-2 是指令跟随模型，这些词不提升画质、只稀释真正的风格描述，导入时统一清洗 |
| 中文名 | 106 条的中文名与一句话说明由 LLM 一次性生成后落盘（BR-111 要求面向用户的枚举必须有中文标签），产物提交进仓库，不在运行时调模型 |
| 可复现 | `scripts/import_image_styles.py`，幂等；已命名过的不重复花钱 |

## 4. 影响评估

| 维度 | 影响 |
| --- | --- |
| 数据库 | 新增 `image_style` 表（自定义画风）；`image_job` 加 `options` JSONB（高级参数整包） |
| 后端 | `StylePreset` 加 `category` / `tags` / `source`；`validate_size` 放开实验性阈值；`render_images` 支持任意高级参数透传 |
| 跨进程 | 自定义风格存库、注册表在内存，API 与 worker 各一份 → 凡渲染提示词处必须先 `ensure_loaded`，有源码级不变式测试守着 |
| 前端 | 参数栏重写为设置行；新增 4 个配置弹窗与 1 个生成态组件；改用本仓既有的 shadcn/radix 组件 |
| 成本 | 4K 单张更贵更慢，但需用户显式选择，且档位会在按钮上标出 |

## 5. 明确保留的约束

- **BR-110 不变**：只展示后端能证明的东西。生成态的步骤条画的是**管线真实节点**
  （立意/写提示词/出图/入库/应用，各自的状态与耗时），不是编造的百分比；拿不到节点
  信息时只做「活着」的动效与已跑秒数，**不显示任何百分比**。
- **BR-111 不变**：111 个风格全部有中文名，有测试逐条校验不是裸英文。
- **不做提示词自动优化开关**：静默改写用户输入会让「改了词但出图没变」无法归因。
