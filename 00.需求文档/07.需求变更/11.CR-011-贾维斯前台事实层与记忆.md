# CR-011 贾维斯前台事实层、两层记忆与待唤醒档

- **提出**：scholar，2026-09-03（「总感觉这个不是我想要的最佳本体贾维斯，结合开源项目和业内最佳实践帮我看看到底是哪里没做好」）
- **状态**：已被 [CR-016](./16.CR-016-贾维斯功能退场.md) 替代（2026-09-03）
- **影响模块**：20 语音助理、21 电脑操控、22 扩展与例程（例程播报）
- **不改**：CR-010 的执行内核、门代理、三档开关与打包链路一条没动；本 CR 只补它上面缺的那层

## 1. 诊断（实测，不是感觉）

CR-010 交付的是一套扎实的执行管道，缺的是让它像个「本体」的那几件事。证据：

| 指标 | 实测 | 基线目标 | 出处 |
| --- | --- | --- | --- |
| 引擎首个 delta | **3307 ms** | ≤1500 | `data/logs/jarvis-latency-20260902-153457.json` |
| 审批卡出现 | **3159 / 9863 / 11708 / 16874 ms** | ≤200 | 同上 + 15:09 / 15:16 两次 |
| 急停 | **835 ms** | ≤100 | 同上 |
| 打断 ack | 19.8 ms | ≤300 | 同上（唯一达标项） |

六条根因，全部有代码位置：

1. **前台是个瞎子**：全双工语音模型只有 `computer_task` 一个工具（`jarvis_voice.py` `COMPUTER_TASK_TOOLS`），于是「现在几点」「今天怎么样」「刚才那件事做完没」都要启动 Open Interpreter，日常问句一律 3.3 秒起步。工作台里成套的只读能力一个都没给它。
2. **没有记忆**：`thread/start` 每次新建线程且全仓没有一处 `thread/resume`，系统提示词是常量。API 一重启，昨天说过什么、你纠正过它什么全部归零——它认识"一台 Mac"，不认识 scholar。
3. **唤醒词是死代码**：`LocalVadProvider.start()` 把打分函数写成 `lambda _frame: 0.0` 且 `set_continuous(True)`，编排器里 grep `wake` 零命中。ALWAYS-ON 下麦克风全程流给字节，且 `_route_utterance` 对任何完整话无条件提交——**你在房间里说的每句话都是指令**。
4. **AEC 判据自相矛盾**（CR-010 已修，本 CR 复核）：`direct` 残留 −12.1 dB、`control`（不放音）−11.9 dB，两者只差 0.2 dB，说明回声已压到本底噪声、物理上测不出更低；而判据要求 ≤−30 dB，是本底达不到的门槛。
5. **它从不先开口**：`routines.speak` 字段在，但服务端没有任何地方向语音会话推送；唯一的播报是今天页上一个手动按钮。早报到点跑完只是写进数据库等人去看。
6. **审批卡挡在最慢的地方**：门本身不慢（打断 ack 19.8 ms 证明席位是快的），慢的是它挂在代理循环末端——要等引擎想完、决定动作、发出请求。

## 2. 决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D-1 | **前台装只读工具**：`domain/jarvis_facts.py` 收八个不改状态的事实函数（时间 / 今天一眼 / 到期词 / 任务 / 最近几步 / 找书 / 未读邮件 / 今天日程），与 `computer_task` 一起作为全双工会话的 function tools | 入选判据只有一条「这次调用会不会改变任何状态」，源码扫描守着（`test_no_fact_tool_writes`）。业内做法（OpenAI Realtime、LiveKit Agents、Pipecat）都是给语音模型一批廉价只读工具，重代理只在真要动手时启动 |
| D-2 | **两层记忆**：稳定层 `data/jarvis/profile.md` 人手写，情节层 `user_pref['jarvis.memory']` 每轮落一条「他说了什么 → 结果」，滚动保留 60 条；开线程时拼「档案 + 最近 8 条 + 与开场白撞词的 4 条」进 `developerInstructions` | 不额外调模型做摘要——用户原话本身就是最好的索引，为一句摘要再等一次 LLM 会把省下的延迟赔回去。不走 `thread/resume`：上下文无限长还要配 compaction，本机单人用量下这套便宜得多 |
| D-3 | **ALWAYS-ON 分两态**：待唤醒（`WakeGate` 在本机跑 openWakeWord，麦克风一帧不上行）→ 叫到名字才连云端；`jarvis_wake_idle_s` 秒没说话且不在忙就断开回到待唤醒 | 一次解决隐私、费用、误触发三件事。档位读后端真源（`GET /jarvis/mode`）而不是页面的 hello，页面说了不算 |
| D-4 | **AEC 判据改成「误触发 0 且落到本底 +3 dB 内」**，ALWAYS-ON 保持全双工 | 残留 dB 不可能低于本底噪声，固定 −30 dB 是个永远达不到的门槛。真实信号是：AEC 关时 6 次误触发，开时 0 次 |
| D-5 | **主动播报**：例程产出先交给在线语音会话念（`offer_announcement`），没人接得下就发一条 hub 广播事件，页面转成壳通知 | 只会应答的助理是个命令行。插在半句话中间比不说更糟，所以「正在念 / 正在做事 / 待唤醒」一律不插嘴，改走通知 |
| D-6 | **审批前移**：`danger.classify_utterance` 在他说完话那一刻判危险意图，命中就先弹一张 `kind=intent` 的卡；点过头的风险类在同一轮里覆盖引擎的第一次同类请求 | 卡片从 3–17 秒变成即时。判据宁可漏报——误判会让每句带「删」的话都弹卡，比晚几秒更烦人，所以问句、否定句、说过去的事一律放行 |

## 3. 契约

| 面 | 变化 |
| --- | --- |
| 全双工 `session.tools` | 由 `jarvis_voice.front_desk_tools()` 给出：`jarvis_facts.function_tools()` + `computer_task`，末位固定是 `computer_task` |
| 语音 WS 下行 | 新增 `tool.call{callId, name, elapsedMs}`（只读工具）与 `announce{text}`；`agent.state` 多一档 `armed` |
| 语音 WS 上行 | 新增 `wake{}`：待唤醒时手动叫醒（刘海按钮 / 页面按钮），不必真喊名字 |

| 文件 | `data/jarvis/profile.md`（人设档案，人手写，改完下一次开线程生效） |

## 4. 实施记录（2026-09-03）

### 4.1 D-1 前台事实层

- `domain/jarvis_facts.py`：八个只读函数 + `FactTool` 注册表 + `function_tools()` / `call_fact()`。`call_fact` 对未知名字与坏参数回成结果而不是抛——语音链路不该因为一次工具调用断掉。
- `domain/assistant.py` 的 `review_status` / `inbox_summary` / `calendar_today` / `running_tasks` / `current_time` 改为委派，同一份实现两处用。
- `VoiceOrchestrator._on_function_call` 分流：名字在事实表里就本地执行（一次数据库查询），否则才是 `computer_task`。未知工具的错误信息把有哪些工具列出来。
- 守卫 `tests/test_jarvis_facts.py::test_no_fact_tool_writes` 用 AST 扫每个 handler 的源码，出现 `add` / `commit` / `update` 这类写操作就失败（`calendar_today` 的 `commit` 是刷新 OAuth 令牌的访问副作用，显式豁免并写明理由）。

### 4.2 D-2 两层记忆

- `domain/jarvis_memory.py`：`load_profile()` / `remember()` / `recall()` / `compose_instructions()` / `build_instructions()`。撞词检索去掉中文停用词，没有词对得上就一条都不给——不相干的旧事进提示词比不进更糟。
- `JarvisHandle.prompt` 记这一轮用户原话，`_end_turn` 收尾时连同结果落一条情节。
- **落库位置排在 `turn_done.set()` 之后**：早一行就会和等它的请求会话互相等死（CLAUDE.md 记过的同一族死锁，这次又踩了一次）。
- `data/jarvis/profile.md` 给了初版模板（他是谁、在做什么、常用什么、怎么跟他说话），人手改，下一次开线程生效。

### 4.3 D-3 待唤醒档

- `WakeGate`：openWakeWord 加载放线程，加载完之前用一个永远打不开的假打分器——宁可这几百毫秒叫不醒，也不能把音频先送上云。
- `_main` 分两条起点：待唤醒只挂事件循环，`_bring_up()` 连供应商的那段被两条路共用；`_wake_up()` / `_sleep_again()` 在两态之间来回。
- 空闲判据要同时看「有没有在忙」和「上次说话多久了」，正在念 / 正在做事一律不睡。
- 前端 `VoiceState` 与 `AgentState` 加 `armed`，HUD 显示「等你叫我」；`voiceClient` 加 `sawAgentState` 守卫，免得连接完成那一下把服务端报的 `armed` 盖成 `listening`。

### 4.4 D-4 AEC 判据

- CR-010 收口时已把判据改成「残留 ≤ −30 dB **或** 落到本底 +3 dB 内」，本 CR 用 2026-09-02 那次真实设备数据复算确认：`direct` / `loopback` 均为 `full_duplex_ok`，陈旧的 `half_duplex` 结论已在 `data/logs/aec-probe-2026-09-02.json` 就地更正并标注 `verdict_note`。
- 代码里没有任何地方按半双工降级（grep `half_duplex` 在 server / web / desktop 下零命中），ALWAYS-ON 本来就是全双工。

### 4.5 D-5 主动播报

- `VoiceOrchestrator.offer_announcement()` 只做「接不接得下」的同步判断并入队，真正念在主循环里（三路事件串行的约束不破）。
- `app/routers/jarvis_voice.announce()` 找第一个接得下的会话；`routines.speak_result()` 在没人接时发 hub 广播。
- SSE 多路复用 0 号广播位：`asyncio.wait` 同时等自己那条队列与广播队列，取消未完成的 getter（`asyncio.Queue.get` 的取消是安全的，不会吞掉元素）。
- `ShellBridge` 收到 `announce` 就调 `shellNotify`——服务端只在没人念得出来时才发这条事件，收到就等于该弹通知，不需要再判一次。

### 4.6 D-6 审批前移

- `danger.classify_utterance()` + `spoken_risk()`：**口语与命令行是两套写法**，说的是「删掉」「发出去」「付一下」，命令行里才是 `delete` / `send` / `pay`，所以另配一份正则而不是复用命令那几条（复用的话「把桌面的 test.txt 删掉」一条都命不中，实测）。
- `JarvisManager.submit()` 命中就起后台任务等裁决并返回 `accepted_as: "intent"`：**不能在请求里等**，单连接会被这一等锁死（第三次踩同一族坑）。
- `ApprovalBroker.confirm()` 认 `handle.preapproved`：同一轮里同一风险类的第一次请求直接过并记一条 note，第二次照样弹卡。沿用模块 21 旧执行器的 `preapproved_step` 范式。
- 假件加了 `改一下文件` 别名指向 `patch-delete` 剧本：原来那句话本身带删除动词，会先被意图门拦下，要单独测引擎侧的 `file_change` 卡就得用不带危险动词的说法。

## 6. 留给 scholar 的真机验收

1. 问「现在几点」「今天怎么样」——应当亚秒作答，`/jarvis` 页看不到引擎启动。
2. 改 `data/jarvis/profile.md` 写点它该记得的事，重启 API 再问它认不认识你。
3. 常听档下不说话时看 HUD 是不是「等你叫我」，喊「Hey Jarvis」再看它连不连云端。
4. 说「把桌面的 test.txt 删掉」——卡片应当立刻出来而不是等三秒；点拒绝后引擎一步都不该走。
5. 早报到点时人不在语音会话里，看壳通知弹不弹。
6. `pnpm probe:aec` 开扬声器重跑一次，把结论回填 §4.4。
