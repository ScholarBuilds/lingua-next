# CR-008 常听与唤醒词

- **提出**：scholar，2026-09-02（「套壳以后是不是客户端了，贾维斯是不是能做了」）
- **状态**：已被 [CR-016](./16.CR-016-贾维斯功能退场.md) 替代（2026-09-03）
- **影响模块**：20 语音助理（加常听）、P7 壳（图标与显示名）、侧栏（壳里去 logo）
- **前置**：CR-007 P4 的回合制助理与 P7 的壳

## 1. 背景

CR-007 把助理做成「按住 ⌥Space 说一句」的回合制，唤醒词按 ADR-014 推迟。壳落地之后麦克风权限、
常驻进程、全局快捷键都有了，常听的门槛只剩两件：识别在本机（D5 第 6 条），以及别让它听见自己念的话。

## 2. 决策

| 编号 | 决策 | 默认 |
| --- | --- | --- |
| D1 | 唤醒词用 openWakeWord 预训练的 `hey_jarvis_v0.1`（Apache-2.0，onnx 随包，不用下载），端点检测用它自带的 Silero VAD | 词是 Hey Jarvis，不自训 |
| D2 | 音频在页面用 `getUserMedia` 采（壳里权限已给），AudioWorklet 抽样成 16 kHz PCM16、80 ms 一帧，经 WebSocket 推到本机 API；识别全在本机进程 | 不上传任何音频到云，转写仍走已绑定的 ASR |
| D3 | 状态机三段：idle 等唤醒词 → awake 等人开口（6 秒没声回去）→ speaking 攒段，静音 700 ms 收段；段交给现有转写 + 助理代理（`take_turn`，与 HTTP 回合同一函数） | 阈值见 `ListenConfig` |
| D4 | 念回复时不开门（麦克风会听到自己），**念完页面叫一声 follow_up** 再进 awake 几秒，追问不用再喊；念的中途喊唤醒词 = 打断（页面停 TTS） | 不做全双工 |
| D5 | 常听是开关（HUD 头部与助理页），偏好存本机，下次打开自动接上；失败（没麦克风 / 模型缺）明说，不静默 | 默认关 |
| D6 | 产品显示名与图标换成 NEXUS（蓝色连接小精灵）：窗口标题、Dock、托盘提示、favicon、README 首行；代码标识（`lingua` / `LINGUA_*` / 数据库 / 包名）不动 | 只改显示层 |
| D7 | 壳里侧栏顶格不放 logo（标题栏与 Dock 已有图标），改成窗口拖动区，标题栏 `hiddenInset` | 浏览器里照旧 |

## 3. 实施记录（2026-09-02）

- `domain/listening.py`：`ListenSession` 状态机（纯函数注入打分器，单测不碰 onnx）、`load_detectors`（进程内加载一次）、wav 封装。
- `routers/assistant.py`：`take_turn` 从 HTTP 端点抽出来共用；`WebSocket /assistant/listen`（二进制帧 + JSON 控制：hello / context / wake / follow_up / cancel / stop；事件：ready / wake / speech_start / thinking / reply / empty / timeout / idle / error）。
- `web/src/features/assistant/listenClient.ts`：采音、抽样、推帧、收事件；`assistantStore` 加 `listening` / `wakeState`，事件驱动 HUD；`ListenToggle` 放在 HUD 头部与助理页。
- 实测：用 edge 音色合成「Hey Jarvis, what time is it」喂给检测器，唤醒分 0.999、VAD 抓到 19 帧语音；协议由 `tests/test_listening.py` 用 Starlette TestClient 走通（唤醒 → 开口 → 收段 → 回复 → follow_up → 取消）。
- 依赖：`openwakeword`（Apache-2.0，含 Silero VAD onnx，MIT）登记进开源复用清单。

**留给 scholar**：真人对着麦克风喊一句（自动化里没有麦克风）；误唤醒率与 700 ms 收段线按体感调 `ListenConfig`。

## 4. homerail 参考结论（2026-09-02，scholar 给的 [xiaotianfotos/homerail](https://github.com/xiaotianfotos/homerail)）

看了它的语音面（`agent-ui/src/components/agent/AgentVoiceCockpit.vue` 一万行、`agent-ui/src/agent/codex-live-voice-client.ts`、`homerail_manager/src/server/voice.ts` 与 `ark-voice.ts`）：

- **全量搬不动**：TypeScript / Vue / Node 栈，「Live Voice」是 OpenAI Realtime 经 Codex appserver 走 WebRTC（`RTCPeerConnection`），服务端 VAD 与 `commentary` 播报频道都是那条链路给的，换成我们的供应商就没有。它的普通路径（浏览器采音 → VAD 静音 → 整段 ASR → TTS）与本仓 CR-008 同构，且**没有唤醒词**。
- **抄了三点**：① VAD 静音窗口交给人调（他们 `omni.voice.vadSilenceMs.v1` 存浏览器，我们存 `user_pref`，连唤醒后等待与唤醒灵敏度一起做成 `GET/PUT /assistant/listen-settings`，助理页三条滑杆）；② AI 在说时「点按停止」（HUD 状态行点一下停，常听开着就顺手开门等追问）；③ 状态词汇（listening / user-speaking / manager-working / assistant-speaking）与我们的四态对齐，不改。
- **留作下一步的**：`ark-voice.ts` 里火山 openspeech v3 的 `tts/bidirection` 双向流式 TTS 与 `sauc/bigmodel` 流式 ASR 的帧封装（gzip、sequence、事件号）写得完整，要把首字延迟再压下去时照它接；我们现在是整段 flash ASR + 整段 TTS。
- 许可证 MIT，登记为思路参考。
