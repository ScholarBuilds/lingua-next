# CR-022 全局默认模型与统一换模型弹窗

- 提出：scholar，2026-09-06
- 状态：已落地
- 影响：模块 17（创作工坊）、配置中心、阅读器、修复代理

## 1. 起因

scholar 在设置 · 模型服务里截图反馈三件事：

> 当前这个弹窗不行，而且我觉得没必要全局设置里面分这么多场景吧，全局模型里面设置一个全局都用的模型，
> 然后在使用的时候可以去换模型，并且换模型的弹窗弄的布局和 ui 都好看一点，可以分厂商区分等等

## 2. 现状盘点（2026-09-06 实测）

**设置页太碎，而且碎得没有道理**。模型服务 tab 平铺八张一模一样的能力卡，实测他自己的库里
七条绑同一个模型（`deepseek-v4-flash`）、只有修复代理单独绑了 `deepseek-v4-pro`。更糟的是其中两条是死绑定：
`companion` 的代码里写的是 `COMPANION_ALIAS = "explain-standard"`，`summary` 没有任何调用点。
`explain-standard` 反倒被十几个模块引用，事实上早就是全局默认了。

**弹窗按凭据分组等于不分组**。`provider_type` 记的是接入协议不是厂商，五个凭据里四个都是
`openai_compatible`，而同一个中转后面同时挂着 OpenAI / DeepSeek / GLM / Qwen / Kimi / MiniMax 六家。
`deploymentChoices` 按凭据名排序、组内按模型名字母排，于是打开弹窗第一眼看到的是「个人中转」的
`embedding-3` —— 一个连对话都不能做的嵌入模型。宽度写死 280px，46 条模型没有可用的搜索
（`placeholder` 写着「手输模型名后回车」，但回车的判据是候选总数为 0，在模型下拉里永远不成立）。

**换模型的 UI 有四套**：设置页的 `Sel`、工坊对话页手写的两列 `.sgc-model-pop`、画布的 `PillPicker`、
修复代理的 `ActionPicker`。其中两套把 `chat-general` / `image-free` 这种路由键摆在「模型」位上（违反核心原则 6）。

**学习侧根本换不了模型**。`domain/llm` 的四个入口早就带 `deployment_id` 形参，但只有 studio / images /
repair / realtime / llm_admin 五处把它开到了 HTTP，阅读器那条链一个都没有。

## 3. 决策

| 编号 | 决策 |
| --- | --- |
| D-1 | 新增能力 `default-llm`（全局默认模型）。八条 LLM 能力没有自己的主部署时跟随它。它进 `ALL_CAPABILITIES` 与 `MODEL_CAPABILITIES`，但**不进** `LLM_CAPABILITIES`——进了会被 `/bindings/legacy` 当成待改绑挂红点，测试桩也会自动给它绑上，让「没配默认」这条分支永远测不到 |
| D-2 | 候选顺序 `explicit → binding → binding.fallback → default`。默认**只在这条能力自己没有主部署时**参与：绑了模型但那条部署停用了照旧报错，不把配置事故静默换成另一个模型出结果 |
| D-3 | 新增 `DELETE /config/bindings/{capability}` 表示「改回跟随默认」。`PUT` 做不到——它要求 `credential_id` 或 `deployment_id` 必填，传 null 会 400 |
| D-4 | 不做自动迁移。已有的八条绑定原样留着，用户在设置页自己点「跟随全局默认」收敛。偷偷改写他一条条选过的配置，他看到的是「我的配置丢了」 |
| D-5 | 弹窗按**厂商**分组，判据只认模型名前缀（`web/src/lib/model-vendor.ts`），不认 `provider_type`。嵌入 / 转写这类非对话模型单列一组、默认折叠、搜索时照常出 |
| D-6 | 换模型弹窗全产品收敛成一个 `components/model-picker/ModelPicker.tsx`，走 `Overlay` 不走 radix Dialog（Dialog 不进浮层栈，页面级快捷键不会让路） |
| D-7 | 使用处换模型是 per-call 覆盖，只影响这一次调用，绝不静默改绑定。选择记在 localStorage |
| D-8 | `deployment_id` 必须进缓存寻址（`provider` 加 `#d<id>` 后缀）。不进的话换了模型仍旧命中上一个模型的结果，接口 200、日志干净，用户看到的是「换了没反应」 |

## 4. 落地

**后端**

- `domain/model_catalog._candidate_specs` 收第三个参数 `default_binding`，新增 `source="default"`；
  `resolve_model_candidates` 只对 `LLM_CAPABILITIES` 里的能力查默认那条（生图与音色各有各的默认，
  混进来会让一条 `media_types=['image']` 的部署被语法分析静默捡走——这条路径不校验 media_types）
- `domain/credentials.DEFAULT_LLM_CAPABILITY`；`app/routers/config.CAPABILITY_META` 加一条，
  `LEGACY_SCAN_CAPABILITIES` 排除它；绑定视图新增 `follows_default` 与 `known` 两位
- `DELETE /config/bindings/{capability}`：只允许跟随者，删整行（`params` / `fallback` 一起走——
  模型都不指定了，采样参数留着只会在下次改绑时悄悄复活）
- `app/routers/analyze.py` 七个 Body 加 `deployment_id`，`_generate_llm` 透传并分槽；
  `/analyze/translate` 经 `domain/translate.py` 三个函数透传，机翻降级档不参与
- 顺手修掉过时文案：`LLM 网关未配置或不可用` 改 `str(exc)`。网关 2026-08-23 就删了，
  这句会让人白查一遍

**前端**

- `lib/model-vendor.ts`（新）：19 家厂商的模型名前缀规则、圆标色与缩写、版本号排序（新版本在前）
- `components/model-picker/`（新）：`groupModels.ts` 纯逻辑 + `ModelPicker.tsx` 视图 + `modelPicker.css`
- 设置页：全局默认单独一张卡，八个用途收进折叠区（标题写清有几个是单独指定的），
  目录外的遗留绑定（`computer-use` / `jarvis-voice`，当前代码零消费者）另起一段
- 工坊对话页：拆掉手写两列弹层与它的点外面关 / Esc / 按凭据分栏三套逻辑；顶栏与触发器改显示真名
- 修复代理：`ActionPicker` 换成 `ModelPicker`（46 个选项终于能搜）
- 词卡：元信息行的 `llm:explain-standard` 改成「词语解释 · deepseek-v4-flash」，可点换模型，
  钉了模型时标「临时换的」
- 修掉 `.wc-ai .wc-ai-meta` 这条后代选择器：SentencePanel 与 PhrasePanel 里这个类没有 `.wc-ai` 祖先，
  整条声明不生效、退成一行裸文本，而且不报错

## 5. 验证

后端 `uv run ruff check . && uv run pytest -q` 全绿（含新增 `tests/test_default_model.py` 21 条）。
前端 `tsc --noEmit`、`pnpm test`、`check:css` / `check:scroll` / `check:jsx` / `check:select` 全过，
新增 `model-vendor.test.ts` 28 条与 `groupModels.test.ts` 15 条。

真浏览器实测：设置页设默认 → 快速翻译改跟随 → 运行时解析 `source=default` 且模型正确；
词卡换成 `kimi-for-coding` 真的重算并落进独立缓存槽（`llm:explain-standard#d50`），
点「跟随全局默认」回到原槽命中缓存、localStorage 清空。

## 6. 已知取舍

- 画布生图页（`OnlineImagePage`）的模型选择是带平台切换与分页的内联面板，不是弹窗，本轮不动
- `companion` 与 `summary` 两条死绑定保留：删能力要动 `seed_config.py` 与库里的残留行，
  且 jarvis 那套代码不在当前 checkout，留着不影响使用
- 全局默认只覆盖对话类能力。生图、音色、翻译链各有各的默认，合并会丢能力
