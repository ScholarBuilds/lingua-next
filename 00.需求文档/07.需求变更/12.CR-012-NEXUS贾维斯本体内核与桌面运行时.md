# CR-012 NEXUS 贾维斯本体内核与桌面运行时

- **提出**：scholar，2026-09-03
- **状态**：已被 [CR-016](./16.CR-016-贾维斯功能退场.md) 替代（2026-09-03）
- **基线**：`cf34119`
- **影响模块**：20 语音助理、21 电脑操控、22 扩展与例程、17 StudioFlow、桌面壳、模型与凭据

## 1. 目标

NEXUS 的文字、语音、主动任务和电脑执行共享同一个身份、会话、上下文、记忆和策略。多步骤任务在进程退出后可恢复，所有状态变化有持久事件；官网 DMG 在干净的 Apple Silicon macOS 14+ 设备上不依赖源码目录、Python、uv、Docker、PostgreSQL 或 Redis。

## 2. 决策

| 编号 | 决策 |
| --- | --- |
| D-1 | 建立 Jarvis Kernel，持久化 conversation、turn、mission、command、event、memory、announcement |
| D-2 | StudioFlow 是唯一持久 DAG；App Server 保留为快速执行器和节点内执行器 |
| D-3 | 工具依次优先结构化业务 API、正式 API/MCP、浏览器 DOM、macOS Accessibility、视觉 CUA |
| D-4 | 语义事件先落库再发布；音频和 token 增量只携带持久对象标识与基础 cursor |
| D-5 | 长期记忆先建议后确认；执行 journal 自动记录但不冒充用户偏好 |
| D-6 | 默认分级审批；口头预授权必须绑定目标、单次消费并限时 |
| D-7 | 桌面档使用 SQLite WAL 与数据库队列；开发/服务器档继续支持 PostgreSQL 与 Redis/Arq |
| D-8 | 官网发布采用 Developer ID、公证 DMG、自托管 HTTPS 更新和完全 BYOK |
| D-9 | 熟人内测允许独立生成 ad-hoc、未公证 DMG，附手动放行与权限重授说明；不得标记为正式发布包 |
| D-10 | 桌面档凭据主密钥使用 Application Support 内的 0600 文件；启动令牌经限定回环地址的请求头注入，不依赖 Keychain 或持久 Cookie |

## 3. 实施顺序

1. 修复 CR-011 的预授权、唤醒预卷、播报竞态、音频乱序和 AEC 降级。
2. 建立持久模型、统一身份、事件日志与兼容 API。
3. 将多步骤执行提升为 Mission，并接入 StudioFlow checkpoint 与本地队列。
4. 统一工具能力、风险、数据范围、幂等和证据输出。
5. 完成长记忆确认、注意力策略与语音可观测性。
6. 打包本地 sidecar、SQLite 基线、数据迁移和首次启动向导。
7. 完成签名、公证、更新、SBOM 与干净 Mac 验收。

## 4. 验收

- 同句唤醒命令不丢失；待唤醒音频只在本机处理。
- 口头确认仅覆盖目标匹配的第一个动作，第二个动作重新审批。
- 主动播报必然进入语音、系统通知或带原因的失败状态。
- API、worker 或 App Server 重启后，任务从最后 checkpoint 恢复且外部写入不重复。
- 语音 100 轮无回答率低于 1%，明确停止漏停为 0，停止音频 P95 不超过 250ms。
- 干净 Mac 可完成安装、BYOK、权限申请、真实执行、重启恢复和升级。

## 5. 兼容与边界

- `/jarvis/sessions` 与 ComputerSession 保留一个兼容版本，再由新对象投影替换。
- `data/jarvis/profile.md` 只用于现有开发数据迁移，不进入公开安装包。
- 首版不支持 Intel Mac、Mac App Store、托管模型账号或 ChatGPT 订阅转 API。
- Developer ID、公证、外部更新源和干净设备验收需要发布凭据与独立设备，代码门禁不能替代。

## 6. 实施记录

### 6.1 CR-011 稳定化

- 预授权改为带目标 token 与过期时间的一次性 grant，不再只按风险类放行。
- WakeGate 保存有限本地预卷；命中后才交给语音供应商，并在首个终稿剥离唤醒短语。
- 主动播报经领域 broker 投递，语音席位排队后变忙会明确降级为壳通知。
- MP3 解码按到达顺序串行；AEC 不可用时常听降为回答期间暂停收音的半双工。
- 本地 RMS 只报候选，收到供应商 speech-start 后才取消当前回答。
- 邮件和日历事实工具声明敏感数据范围；日历明确标记 OAuth 刷新副作用。

### 6.2 统一 Kernel 与持久事件

- 增加 profile、conversation、turn、mission、command、event、memory 和 announcement 的持久模型与 Alembic 迁移。
- App Server 每轮开始前写入 JarvisTurn，步骤和结局写入全局游标事件；流式事件携带 trace、conversation、turn 和基础 cursor。
- 增加 `POST /jarvis/turns`、`GET /jarvis/conversations/current` 和 `GET /jarvis/events?after=`，保留旧 session API。
- 开发档案首次读取后迁入 JarvisProfile；语音前台、普通助理和 App Server 共用该身份，不再硬编码开发者名字。
- 定向验证通过：Kernel、App Server、审批门、语音、普通助理和旧记忆兼容共 118 条测试。

### 6.3 Mission 与恢复队列

- 助理交付、例程和多步指令自动提升为 Mission，并与 ComputerSession、JarvisTurn、StudioFlowRun 和 StudioTask 关联。
- 本地队列使用 lease owner、lease expiry、generation 和幂等键；旧 worker 在 generation 变化后不能继续写 checkpoint。
- 增加暂停、继续、取消、转向、补充信息和审批命令，命令先持久化再尝试影响当前 App Server。
- 启动恢复不再将带 Mission 的会话统一标记失败；已知副作用正在执行的 checkpoint 转人工确认，其余进恢复队列。
- SQLite 运行时启用外键、WAL 和 5 秒 busy timeout；StudioFlow 重试与恢复保留 mission_id。
- 定向验证通过：Mission、StudioFlow 和 App Server 共 35 条测试。

### 6.4 工具分层与数据边界

- 增加可查询的 capability contract，统一输入 schema、执行层级、风险、数据范围、幂等要求、超时和证据类型。
- 执行优先级固化为工作台事实工具、浏览器 DOM、macOS Accessibility 和视觉 CUA；视觉层要求动作前后截图和幂等键。
- 邮件与日历默认不把结果回传云端语音模型；未授权时返回可识别的 authorization_required，不泄露内容。

### 6.5 长期记忆

- 长期记忆新增 proposed、active、superseded 和 deleted 状态；模型只能提议，用户确认后才生效。
- 修正会创建新版本并保留 supersedes_id，删除写 tombstone 和时间，避免旧摘要再次召回。
- `GET/POST /jarvis/memories` 提供建议、确认、修正和删除接口。

### 6.6 桌面本地运行时与迁移

- 打包态由 Electron 启动内置 PyInstaller onedir sidecar，随机绑定回环端口并注入单次启动令牌；API 拒绝异源 Origin。sidecar 异常退出后指数退避重启，前端窗口会切到新端口。
- Web 静态产物、SQLite 当前 schema 基线、openWakeWord 资源、Open Interpreter standalone 和必要策略文件进入 `Contents/Resources/runtime`；开发者个人 profile 不进包。
- 桌面队列使用独立 SQLite WAL，实现 lease、generation fencing、attempt 和幂等 job id；本地 worker 与定时器随 sidecar 生命周期运行。
- 迁移工具支持 PostgreSQL/SQLite 源数据 dry-run，执行前保留 PostgreSQL dump 和目标库备份，导入后对账表数、外键与媒体 SHA-256，可解密凭据重新加密后使用桌面本地 `vault.key`。
- 首次启动指引依次收集称呼、BYOK 模型绑定、macOS 权限和常听/长期记忆/主动通知的独立选择；撤回常听授权会立即降到待命。

### 6.7 语音时序与断线恢复

- 生产语音帧统一携带 frame sequence、trace、conversation、turn、mission 和持久 cursor；每轮记录唤醒、ASR、路由、首模型增量、TTS、首帧播放、underrun、cancel 与 provider 切换的单调时钟时序。
- 播放器将首帧与 underrun 回传给同一轮次；MP3 降级按 item 串行解码，provider 切换时不向旧 item 继续写入。
- 工作台启动时从服务端全局 cursor 追平持久事件，浏览器本地保存最后 cursor，不再用进程内 hub 猜任务状态。

### 6.8 发布工程与本地产物

- `electron-builder` 产出 arm64/macOS 14+ DMG 和 ZIP，开启 Hardened Runtime 与 Electron fuses。本机 Apple Development 验证产物为 1.4 GB `.app`、485 MB DMG 和 492 MB ZIP；DMG checksum、ZIP 完整性、挂载后深度签名与运行时 manifest 均通过。
- 构建时生成运行时 SHA-256 manifest、CycloneDX 1.6 SBOM 和第三方许可清单。官网发布脚本强制检查 Developer ID Application、App Store Connect API 凭据、HTTPS 更新源与 Ed25519 更新密钥。
- 更新客户端先校验 Ed25519 清单与 `latest-mac.yml` SHA-512，再由 Squirrel.Mac 校验应用签名。
- CuaDriver 不改变上游签名身份；已验证固定 0.23.2 包的 SHA-256、bundle id、Team ID 和 Gatekeeper `Notarized Developer ID`。
- 本机尚无 Developer ID Application 证书，而 Apple Development/Distribution 不能代替官网分发身份。公证上传、staple、干净 Mac 与升级/回滚验收保留为发布门，不以本地构建代替。

### 6.9 安装包执行链路修复与实机证据

- 桌面凭据 rekey 对 9 条记录完成检查并迁移 7 条记录、8 个密文字段，重跑结果为零变更，迁移前 SQLite 已留备份。桌面档最终密钥来源为 Application Support 内的本地文件。
- 安装包的内部 MCP 精确路径只由回环地址与独立 Bearer 守卫处理，不再被 Electron 启动令牌提前拒绝；额外路径仍返回 401。
- CuaDriver 门代理使用已解析的绝对二进制路径和单次 stdio 连接；capability manifest 到期或空闲超时后自动轮换私有 daemon，运行日志只写 `Application Support/NEXUS/logs`，不再改动签名包内容。
- Open Interpreter standalone 的 `interpreter` 与 `codex-code-mode-host` 必须成对入包。后者使用 JIT/unsigned executable memory entitlement 单独签名，避免 Hardened Runtime 下 V8 `CodeRange` 启动失败。
- `/Applications/NEXUS.app` 的会话 83 实际调用 `desktop.launch_app` 打开 `com.bytedance.douyin.desktop`，随后两次取得抖音可见窗口并完成回复；动作后应用仍通过 `codesign --verify --deep --strict`。
- 最终本地验证产物 SHA-256：DMG `628e9d51e08e0d8e4f8d1ae8b2e43d40cf986a4a8ea215d252b574b5bcf6d9dd`，ZIP `bbfbada734ae0473937e1bef3519cc73ec839dd6381b7456ca298b9c41f989c6`。

### 6.11 熟人内测分发

- `dist:mac:friends` 生成独立的 ad-hoc、未公证 DMG 和 ZIP，不要求开发者证书或公证凭据，也不覆盖本机验证与官网发布产物。
- 产物目录包含安装说明，明确首次手动放行、权限申请和升级后可能重新授权；正式发布脚本继续强制 Developer ID、公证与签名更新清单。
- 实际构建产物的外层标识为 `com.lingua.nexus`、`Signature=adhoc`、无 Team ID；挂载后的应用通过深度严格签名校验，JIT helper 保留 allow-jit、allow-unsigned-executable-memory 与 library-validation 例外。
- DMG 为 481 MB，SHA-256 `9e226c5b8f593f40bcd65de83c169e99634beae5e4e1431e032ebc1b4d3b367c`；ZIP 为 488 MB，SHA-256 `85ca5b7fb462a35477e19b1de609cfa9e59109222da8f04fb59fb2469ac38fd9`。DMG、ZIP、校验清单与 29 条 Electron 测试均通过。

### 6.12 桌面密钥与启动令牌

- 桌面 sidecar 固定使用 `~/Library/Application Support/NEXUS/vault.key`，创建后文件模式为 0600；开发和服务器档仍可按配置使用环境变量或系统密钥服务。
- Electron 不再保存启动 Cookie，而是只向当次随机回环地址注入 `X-Nexus-Startup-Token`；sidecar 只接受请求头，不接受 Cookie 降级。
- 打包关闭 Electron Cookie 加密 fuse，桌面 sidecar 排除 Python `keyring` 模块，NEXUS 运行不再具备 Keychain 访问路径。本机迁移前 SQLite 已备份，9 条凭据的 8 个密文字段使用本地文件主密钥验证通过。
- App Server stdio 单帧上限调整为 32 MiB，避免截图和工具证据超过 asyncio 默认 64 KiB 后读循环退出。SQLite 文章列表在打包运行时使用 `json_array_length`。
- 新的熟人内测 DMG SHA-256 为 `b56ba98919783ccff6af77fea8ab0e0bfa57d7daa6423746a8f9b50a45d33cad`，ZIP 为 `57cec00b8866049db2a1cf4c70717d541ce561446b126fbe1eb16c4f128990b2`。Electron fuse 实测 `EnableCookieEncryption is Disabled`，包内 keyring 路径为 0，DMG、应用深度签名和安装后 sidecar 健康检查通过。
- 回归验证为后端 Ruff 全量、pytest `2363 passed`、Electron `29 passed`；实机轮次成功恢复模型凭据、调用工具并打开原生应用，新 sidecar 无凭据解密、长帧读取或 traceback 错误。

### 6.13 唤醒设置与语音能力反馈

- 「设置 · 贾维斯」成为首次设置的长期入口，集中管理用户称呼、助理名字、模型绑定、本机权限、隐私选择、运行模式和唤醒方式；执行现场只显示缺项摘要并跳转，不再承载横向表单。
- 唤醒方式同时支持包内 openWakeWord 预训练词、按钮/快捷键与任意自定义短语。自定义短语在 macOS 本机 Speech 框架内匹配，待机音频不上传；命中后才启动云端语音会话。
- 常听在 AEC 不可用时显式进入半双工，回答期间暂停麦克风、播放结束后恢复；页面分别显示连接中、待唤醒、正在收音、收到声音和半双工状态，不再用 WebSocket 在线冒充正在收音。
- 待唤醒状态下再次点击麦克风、刘海或快捷键会发送明确的 `wake` 控制帧；本机麦克风电平不经过服务端，仅用于确认采集链路是否收到声音。
- 定向验证为后端 Ruff 与语音/唤醒测试 `80 passed`，Web TypeScript、UI 约束检查及 Vitest `1520 passed`；四个随包唤醒模型均完成实际加载。

### 6.14 执行期语音隔离

- PCM 播放首帧预留 120 ms 抖动缓冲；发生 underrun 后以 180 ms 重建连续队列，避免命令执行或网络抖动引发连续断音。
- App Server 超过 256 KiB 的 JSON 帧在工作线程解析，截图证据不再长时间占用 API 主协程。
- 命令控制台增量只走页面 SSE，语音 WebSocket 不再重复转发；完成步骤仍保留在两条通道中用于断线兜底。
- 定向验证为后端语音与 App Server `64 passed`，Web 播放、语音、Store 与执行现场 `48 passed`。
- 本轮全量回归为后端 Ruff 通过、pytest `2370 passed`，Web Vitest `1520 passed`、TypeScript、UI 约束与生产构建通过，Electron `29 passed`。

### 6.15 自定义唤醒、3D 舞台与 Codex 执行子进程

- 自定义唤醒短语不再被 openWakeWord 的预训练模型名限制。macOS 独立 Speech 帮助进程只做本地识别，命中后才通知页面建立语音会话；「唤醒词 + 命令」的同句尾部直接送入当轮。
- 设置新增唤醒开场白、模型生成变体与随机播报。开场白经同一 TTS 队列播放，不旁路创建第二个播放器。
- 行动控制台的装甲形象由 Three.js WebGL 渲染为有视差、环形景深、粒子与状态光强的 3D 舞台，并在 WebGL 失败时保留图像兜底。
- 执行子进程从 Open Interpreter Rust 0.0.40 迁到官方 Codex CLI 0.149.1；安装包只携带 Codex arm64 vendor 运行时，开发档保留显式旧引擎回落。详见 [CR-015](15.CR-015-自定义唤醒与Codex执行内核.md) 与 [ADR-017](../../01.项目文档/02.架构/ADR/ADR-017-贾维斯执行内核迁移到Codex-App-Server.md)。
