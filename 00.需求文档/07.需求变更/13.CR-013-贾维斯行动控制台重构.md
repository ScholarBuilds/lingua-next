# CR-013 贾维斯行动控制台重构

- **提出**：scholar，2026-09-03
- **状态**：已被 [CR-016](./16.CR-016-贾维斯功能退场.md) 替代（2026-09-03）
- **基线**：`5852096`
- **影响模块**：贾维斯执行现场、执行证据、审批、桌面 Web 资源

## 1. 问题

现有执行现场把系统状态、中央反应堆、对话和原始工具输出硬分成三栏。工具输出或截图变长后，右栏会撑破视口且无法回到关键操作；中央主体被推到视口下方。原始 MCP JSON 与 Shell 输出默认展开，也让用户对话和当前任务失去主次。

## 2. 决策

| 编号 | 决策 |
| --- | --- |
| D-1 | 页面改为顶栏加三段式行动区，所有中间轨道显式使用 `min-height: 0`，只有轨道内部滚动 |
| D-2 | `jarvis-codex` 的透明装甲形象作为中央状态主体，运行状态只驱动克制的亮度、呼吸和扫描反馈 |
| D-3 | 对话、执行和证据统一为活动时间线；用户与贾维斯消息直接显示，代码、工具原文和控制台输出默认折叠 |
| D-4 | 截图显示缩略图并可进入统一 Overlay 大图；长字符串必须换行或在局部容器横向滚动，不得扩大页面宽度 |
| D-5 | 顶栏固定承载返回、新会话、打断和紧急停止；输入区固定在中央轨道底部，执行过程中仍可插话 |
| D-6 | 标准桌面三栏、紧凑桌面两栏、窄窗口单列；任何档位都保留状态、输入、审批和急停 |
| D-7 | 界面正文使用产品 UI 字体，等宽字体只用于协议值、代码和控制台输出 |

## 3. 验收

- 1280×720、1440×900、1920×1080 和半屏窗口下无页面级横向溢出。
- 右侧有长 JSON、长命令、连续截图时只在活动轨道内部滚动，顶栏和输入区保持可达。
- 原始执行证据默认收起，展开、收起和截图预览均可用键盘操作。
- 等待审批时审批动作位于活动轨道顶部，内容再长也不遮住急停。
- `prefers-reduced-motion` 下不运行扫描、漂浮或呼吸动画。

## 4. 资产与许可证

中央形象原文件为 `Big-Guan/jarvis-codex@bf32925` 的 `public/assets/jarvis-character-v2.png`，未修改复制，来源仓库以 GPL-3.0 发布。仓内同时保留来源说明和 GPL-3.0 文本；未来改变分发或商业策略时重新评估该资产。

## 5. 实施与验收记录

- 顶栏固定引擎状态、会话、新会话、打断和急停；中央输入区在运行中始终可达。
- 右侧将对话、命令、MCP 证据和截图按时间统一投影；原始输出默认折叠，截图可在 Overlay 中查看原图。
- 1440×900 真实 35 步历史会话中，页面 `scrollWidth = clientWidth = 1440`，活动区 `clientHeight = 777`、`scrollHeight = 2843`；滚动被限制在右栏。
- 1280×720 截图预览中，Overlay 为 1100×672，页面仍无溢出；另验证 1920×1080、960×720 与 720×780 响应式布局。
- 开发态直接使用 Vite 与源码 API 验收，本批次不构建、不签名、不覆盖 `/Applications/NEXUS.app`。
