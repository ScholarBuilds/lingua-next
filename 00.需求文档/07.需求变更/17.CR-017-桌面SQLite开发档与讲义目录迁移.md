# CR-017 桌面 SQLite 开发档与讲义目录迁移

- 提出：scholar，2026-09-03
- 状态：已实现
- 影响：本地启动器、桌面运行时、凭据保险箱、讲义库、设置

## 1. 决策

1. `./start-nexus.sh` 默认使用 `desktop` 档：SQLite、数据库任务队列、FastAPI、Vite 和源码 Electron；任务消费者在 API 进程内运行。
2. PostgreSQL + Redis/Arq 不再是日常开发前置条件，通过 `--mode developer` 显式启动；`--mode docker` 继续提供全容器拓扑。
3. 源码桌面档数据统一放在 `data/desktop/`，不进入 Git；安装包仍使用 `~/Library/Application Support/NEXUS`。
4. 首次没有 SQLite 时按当前模型和唯一 Alembic head 创建基线。已有数据库版本不匹配时停止启动并保留旧库，不静默重建。
5. 讲义库使用桌面档托管目录 `data/desktop/grammar`。用户可在“设置 · 数据管理”或讲义库空状态选择旧 Markdown 目录并导入副本。
6. 导入不删除源目录，不跟随文件符号链接，跳过隐藏目录和既有归档目录；同名同内容跳过，同名不同内容报告冲突且不覆盖。
7. `LINGUA_VAULT_KEY_BACKEND=file` 时忽略 `server/.env` 中的旧环境密钥，凭据只使用桌面数据目录的 0600 主密钥文件，避免钥匙串提示和密钥来源串档。

## 2. 迁移结果

- PostgreSQL dry-run：4,237,007 条记录、9 组凭据、2696 个媒体文件。
- 迁移后的 SQLite 表计数与源库一致，`PRAGMA foreign_key_check` 通过。
- 迁移前 PostgreSQL custom-format 备份保存在 `data/desktop/backups/`；原 PostgreSQL 卷未删除。
- 9 组凭据中 7 行、8 个敏感字段已重新加密到桌面文件保险箱。
- 旧 Obsidian 目录发现并导入 57 篇有效讲义，无冲突；源目录未改动。

## 4. 回退

使用 `./start-nexus.sh --mode developer` 可随时回到 PostgreSQL + Redis/Arq；SQLite、迁移清单、媒体副本和原 PostgreSQL 数据互不覆盖。
