## 1. 目标

1. 像 Codex 实时语音那样随时打断：用户开口 ≤200ms 内停声；执行中插话按「补充 / 叫停 / 排队」分流，不重跑任务。
2. 能操作电脑：浏览器（agent-browser）、第三方原生 App（cua-driver）、代码与文件（引擎自身），三条路都过同一个审批席位。
3. 不卡顿：引擎输出逐字流式；热路径不阻塞事件循环；页面用 SSE 不轮询。
4. 一键开关三档：OFF（手动打开面板才对话）/ STANDBY（常驻托盘 + ⌥Space + 刘海，按键说话）/ ALWAYS-ON（常听）。
5. 壳打包并本机签名（`/Applications/NEXUS.app`），TCC 授权与开机自启从此稳定。

## 2. 决策

| 编号 | 决策 | 理由 |
| --- | --- | --- |
| D-1 | **语音前台火山为主，分两步**：第一步旧协议 `volc.speech.dialog`——引擎输出分句后用 `500 ChatTTSText` 让同一会话念，`450 ASRInfo` 当抢话信号，**麦克风全程不关**；第二步迁全双工 Seeduplex 3.0（`v3/duplex/realtime/dialogue`，model 1.2.6.1：原生 function calling 把引擎注册成 `computer_task`，`response.cancel` 协议级打断，`speech_text_buffer.replacement` 指定念什么）。interpreter 内置 `thread/realtime/*` 只做半小时探针不实施（握手写死 OpenAI 形状，需自研翻译层） | 500 官方明说「播报中被新 query 中断时无需再发 end 包」，等于协议自带打断；不引入新供应商；scholar 拍板 |
| D-2 | **唯一打断裁决者 = 服务端 `VoiceOrchestrator`**（`domain/jarvis_voice.py`）。火山 450 / 459、本地 Silero、duplex 的 speech_started 一律只上报信号；供应商经 `VoiceProvider` 接缝可换（VolcDialog → VolcDuplex → LocalVad 兜底）；前端只认一份 `/jarvis/voice/ws` 帧契约（§3）。分句流式 TTS，**已念出口的句子才进记录**；假打断按 LiveKit 三件套恢复（`min_interrupt_chars≥2`、2s 内无达标终稿续念） | 两个打断真相源会分叉（Pipecat #2431）；供应商可换要求打断逻辑不建在供应商语义上 |
| D-3 | **分级审批三层**：引擎侧 `approval_policy=on-request` + `default_permissions=jarvis` 自定义 permission profile（替代 `sandbox_mode`，受保护路径 `server/.env`、`data/vault.key`、钥匙串、`~/.ssh`、`**/.env` 一律 deny）；客户端 `ApprovalBroker` 对每个 `requestApproval` 按风险分级答复（低风险 `accept`（turn 级，**永不自动 `acceptForSession`**）、五类动作走 `kernel.approval` 席位弹卡、命中受保护路径 `decline`、**未知服务端请求 fail-closed**）；驱动器经 fastmcp 门代理（`/mcp/desktop`、`/mcp/browser`）过同一席位，cua-driver 跑 API 进程私有 `bounded + capability manifest` daemon；语音只认「拒绝」，放行必须点卡；语音路径硬禁 `thread/shellCommand`、`process/*`、`command/exec*`、`fs/*`、`plugin/*`、`marketplace/*`、`remoteControl/*` | 现状 9 条无门路径叠加、未知请求回 `{}` 等于新审批点自动放行；cua-driver `standard` 对 click/type 默认静默放行，只有 bounded 是模型绕不过的天花板 |
| D-4 | **执行中插话三分法**：停词（停/别弄了/算了/取消/stop/cancel）→ `turn/interrupt`；其余 → `turn/steer`（被拒 `activeTurnNotSteerable` → `thread/queue/add` → 引擎队列不可用退本地队列）；idle → `turn/start`。拒绝语不再交给 TTS。`say()` 改 `submit(policy)`，超时 / 打断统一 `_end_turn` 收尾且开新 turn 前清 `last_spoken` | 引擎协议三条方法现成；现状 busy 抛错被念出来，超时还会把上一轮的话当本轮结果播 |
| D-5 | **一键开关三档**，唯一真源 `GET|PUT /jarvis/mode`（`user_pref` 键 `jarvis.mode`，不进 localStorage / prefStore 整包）；壳启动先读它，托盘与设置页任一端改动先 PUT 再经 IPC 广播；`powerMonitor`（锁屏 / 休眠 / 电池 / 热降频 serious+critical / speed-limit<100）只改「生效档」不改「存储档」；急停后 ALWAYS-ON 自动降 STANDBY 并记审计。OFF 保留托盘与 ⌘⇧Esc，撤掉 ⌥Space、刘海、overlay、审批窗；浏览器（无壳）只读档位 | 服务端唯一真相；现状偏好散在 localStorage 且被 teardown 反向抹掉；ChatGPT / Raycast 默认就是「常驻但不常听」 |
| D-6 | 壳增加三个辅助窗：刘海按 opendex 参数重做（`'screen-saver'`、`display.bounds` 贴顶、`roundedCorners:false`、`setHiddenInMissionControl`、`movable:false`、内容驱动补间、hover/pin）；点击穿透 overlay（执行中横幅 + 急停，在任何 App 之上）；独立审批弹窗。三窗共用 SPA bundle，CSS 按 `data-window` 作用域化并只用 tokens | 急停三处入口里最弱的是「贾维斯干活时前台是别的 App」；`jarvis-notch.css` 无层规则正在污染整个 SPA |
| D-7 | **本期打包 + 本机签名**：electron-builder，`appId com.lingua.nexus`（定死）、`productName NEXUS`、hardenedRuntime、entitlements（无 XML 注释）、`CSC_NAME` 用本机 Apple Development 证书，**禁 ad-hoc**；装到 `/Applications/NEXUS.app`，旧 `/Applications/Lingua.app`（ad-hoc）提示后移除；`tools/launch_nexus.py --dist` 构建 / 签名 / 安装，`start_desktop` 优先 `open -a NEXUS`；开机自启只在 `app.isPackaged` 时启用并回读；PATH 用 fix-path 补 | 未签名壳注册登录项静默失败；TCC 绑签名身份，ad-hoc 每次重建都是新身份；scholar 拍板；日常启动优先安装包的行为已被 CR-014 替代 |
| D-8 | 引擎输出流式：delta 只进内存 `JarvisEventHub`，`item/completed` 才落 `computer_step`；页面走 SSE `GET /jarvis/sessions/{id}/events?after=N` 替代 500ms / 1s 轮询；语音编排器订阅同一个 hub | `_record` 每条 item 开一个 DB session，delta 落库会把 PCM 转发挤出时间片 |
| D-9 | 旧 Playwright 电脑操控退场（`domain/computer_use.py`、`routers/computer.py`、`/computer` 页）：先把 `detached_session`、`DANGER_WORDS`、`purge_old_screenshots`、`_step_view` 与 12 条审批测试上提到贾维斯侧，再删；`data/engines/open-interpreter`（AGPL venv）与 `server/engine_runner/` 一并删除 | 两个 manager 抢同一张表；D5-2 的行为契约不能随文件消失 |
| D-10 | 文档：执行内核从 ADR-014 决策 3 拆出独立 [ADR-015](../../01.项目文档/02.架构/ADR/ADR-015-贾维斯执行内核选型.md)；ADR-005 补修订 2、ADR-010 补修订；CR-007 D5 六条安全铁律提成 STD-SEC-001..006 提案，另提 STD-BUILD-001；质量属性基线新增「语音执行助理」六要素指标 | 贾维斯是安全面最大的功能却零条 STD-SEC；ADR-010「不配 token 不挂载」已被静默推翻 |

## 6. 实施记录

### 6.1 M0 契约与探针（2026-09-02）

- codex 版基线提交 `2383e09`；本文、ADR-015、CR 登记表、CR-009 横幅、ADR-014 指针、ADR-005 修订 2、ADR-010 修订 1、七份 STD 提案（`02.项目规范/00.规范治理/提案/`）落地。
- `server/tests/fake_app_server.py`：12 个剧本的假 app-server（stream / danger / benign / patch-delete / netperm / secret / elicit / unknown-request / unsteerable / slow / slow-interrupt / crash），服务端请求带独立 id、停在那一步等客户端答复。
- `server/scripts/jarvis_probe.py` 对真二进制 `interpreter 0.0.40` 的探针结论（`data/logs/jarvis-probe-20260902-*.json`）：
  - 枚举是 **kebab-case**：`approvalPolicy` 取 `untrusted | on-request | granular | never`（`onRequest` 被 -32600 拒）；`sandbox` 取 `read-only | workspace-write | danger-full-access`。
  - thread/start 传 `permissions: ":workspace"` **真实生效**（返回 `activePermissionProfile`，`sandbox.type = workspaceWrite`），没有 `falling back` 字样；`permissionProfile/list` 只有三个内置档，自定义档靠 `-c permissions.<id>.*`。
  - `experimentalFeature/list` 回 `{"data": [...]}`（114 条），`steer=True`，没有叫 `queue` 的特性；`turn/steer` 必须带 `expectedTurnId`；`thread/queue/add` 在 ephemeral 线程上被拒、在落盘线程上可用且空闲时立刻出队。
