> CR-006 把产品收成一个无账号的壳；本 CR 把壳里装的东西从「英语学习」扩成「我这台电脑上的工作台」。

> 本 CR 把「操作电脑」以另一种形态拉回范围：不是自己做原生客户端，而是给 Web 壳配一个本机代理进程。

## 1. 背景

### 1.1 scholar 的原话（2026-09-01）

> 不想要什么前台和后台，不想要什么用户的登录体系了……除了目前我们有的这些学习功能，我还需要做：如果还能管理我所有的 google 账号，google 邮箱，并且还能记住那些凭证……实时语音如果有那种贾维斯的效果就更好了，我希望这个工作台也能拥有 codex 那种 computer-use 控制电脑的能力……我这个工作台应该有很强的扩展能力，未来可以加很多其他的功能。

### 1.2 已有基础（事实核对）

| 要做的事 | 仓库里已经有的 | 出处 |
| --- | --- | --- |
| 扩展系统 | 可撤销注册的插件内核、模型插件目录、工具运行时（pre → guard → approval → around → post）、审批内核、工作流引擎、统一事件流、MCP 出口 | `domain/plugin_runtime.py`、`model_plugins.py`、`kernel/tool_runtime.py`、`kernel/approval.py`、`studio_flows`、`task_event_stream.py`、ADR-010、[全能力打通调研 §5](../02.功能需求/17.创作工坊/全能力打通调研-2026-08-22.md) |
| 记住凭证 | LLM 供应商凭据加密落库、不回显；YouTube 登录态（`login_profile`，用前现导 cookies） | `ProviderCredential`、`domain/video_source.py`、`domain/youtube_login` |
| 贾维斯式语音 | 火山实时对话（首响 710 ms 实测，可打断）、用户侧文本注入 ChatTextQuery(501)、TTS seed-tts-2.0、ASR 极速版 | ADR-005、ADR-012、`domain/volc_realtime.py` |
| 电脑操控 | Playwright 已用于本仓验证；yt-dlp 登录流已经会开浏览器 | `.playwright-mcp/`、`domain/youtube_login` |
| 命令面板 | `cmdk` 已是依赖，`components/ui/command.tsx` 已在 | CR-006 D6 |
| 助理化身（可选） | 看板娘 mascot（pixi） | `features/mascot/` |
| 任务中心 | StudioTask / FlowRun / PipelineRun 已折成一份列表一条事件流（M61） | CR-006 D4 |

结论：五件新事里没有一件要从零起。最大的一块缺口是**浏览器给不了的系统能力**（全局快捷键、唤醒词常听、屏幕捕获、输入注入、钥匙串），见 D4。

### 1.3 不做的事（先划线）

- 不做完整邮件客户端：第一版只有统一收件箱、搜索、读、回、归档、发送（需确认）；无过滤器、无标签管理、无线程折叠规则。
- 不做密码管理器替代品：保险箱只存这个工作台自己要用的凭据，不做浏览器自动填充扩展、不做跨设备同步。
- 不做通用桌面 Agent 产品：电脑操控是助理的一只手，不是独立产品；范围默认浏览器窗口。
- 不做扩展市场：扩展来自本地目录、MCP 服务器、声明式 YAML 三种来源，没有商店、没有签名分发。

## 2. 裁决（提案）

### D1 产品定义改写

一句话愿景改为：**一个装在自己电脑上的工作台——学英语、管账号和邮件、用嘴指挥、让它替我操作电脑，能力按扩展加。** 学习四主链路（词库、精读、视频、对话）原文保留为「学习」分组。

### D2 信息架构

在 CR-006 D3 的「今天 · 学习 · 创作」之上加两组，底部加「扩展」：

| 分组 | 入口 | 路由 |
| --- | --- | --- |
| — | 今天 | `/` |
| 学习 | 阅读 · 视频 · 词汇 · 语法 · 对话 | `/read` `/video` `/vocab` `/grammar` `/talk` |
| 创作 | 工坊 | `/studio/*` |
| 助理 | 语音助理 · 电脑操控 | `/assistant` `/computer`、`/computer/:sessionId` |
| 账号 | 邮件 · 账号与凭据 | `/mail`、`/mail/:messageId`、`/accounts` |
| 底部 | 任务 · 扩展 · 设置 · 主题 · 收起 | `/tasks` `/extensions` `/settings/:section?` |

全局常驻两样东西，不占导航：**⌘K**（CR-006 D6，命令分组加「让助理」）与**助理 HUD**（底部居中一枚药丸，按住 ⌥空格 或说唤醒词展开；它不是浮层，不进浮层栈，但 Esc 先关浮层再收它）。

### D3 新模块

| 编号 | 模块 | 做什么 | 复用什么 | 关键约束 |
| --- | --- | --- | --- | --- |
| 18 | 邮件与 Google 账号 | 多个 Google 账号 OAuth 授权（桌面应用类型客户端 + PKCE，刷新令牌进保险箱）；Gmail 统一收件箱、跨账号搜索、读、回、归档、发送；Calendar 今日事件读进「今天」；邮件一键「收入阅读」（走 articles 导入，点词可查） | Gmail / Calendar API 官方 Python 客户端；`domain/imports.py` 的文章导入 | 发送必须经审批（D5）；令牌只存保险箱；同步用 `historyId` 增量，不全量拉 |
| 19 | 凭据保险箱 | 把 `ProviderCredential` 泛化为 `credential(kind ∈ api_key / oauth / password / cookies / bearer / totp)`；主密钥由 macOS 钥匙串持有（`keyring`），库里只有密文；两种授权：**填充**（值不经模型、只作为动作参数注入输入框或请求头）与**读出**（人看，记台账）；导出文件再加一道口令 | 现有 `credential` 表与设置页凭据区；`kernel/approval.py` | 设置 · 模型服务的凭据一栏改为「从保险箱里挑」，不再自己存一份；YouTube `login_profile` 迁进 `cookies` 类 |
| 20 | 语音助理 | 在火山实时对话上加「助理模式」：中英混说、持有工作台上下文（当前页、选中对象）、经 ToolRuntime 调工具、结果念出来；HUD（听 → 想 → 做 → 完四态、转写、动作卡、内联审批）；例程（arq cron 触发工作流，结果 TTS 念出或塞进「今天」，首个是 07:30 早报） | ADR-005 实时链路、`ChatTextQuery` 文本注入、`kernel/tool_runtime.py`、`studio_flows` 触发器、`/api/events` | 唤醒词用本机 KWS（openWakeWord，音频不出本机），常听与全局快捷键都要 D4 的本机代理；学习模式（对话）与助理模式是同一条链路的两套系统提示与工具集，UI 上分开 |
| 21 | 电脑操控 | 两级范围：**浏览器**（默认，Playwright/CDP 驱动一个专用 Chrome 实例，稳定可回放）与**桌面**（macOS 辅助功能 + 屏幕录制权限；执行器候选 `cua` 的 computer-server 或 pyautogui + Quartz）；模型侧经能力名 `computer-use` 绑定（Anthropic computer use tool 或 OpenAI CUA，按 `capability_binding` 选）；会话页 = 屏幕预览 + 计划 + 动作日志 + 审批卡 + 接管；每步截图落盘 7 天 | `kernel/approval.py`、任务中心、事件流、保险箱的「填充」 | 发送 / 付款 / 删除 / 安装 / 提交表单前必问，清单只增不减；单会话上限（步数与时长）；模型只看得到限定窗口的截图 |
| 22 | 扩展与例程 | 把调研 §5.2 的四类合同升格为**贡献点**清单：导航页、⌘K 命令、助理工具、画布节点、设置项、后台任务、例程触发器、数据表、凭据类型；三种来源：本地目录（`manifest.yaml`，声明式热装、含 worker 代码重启生效）、MCP 服务器（`mcp` SDK 客户端，它的工具立刻进助理与画布）、例程（YAML 工作流 + 触发器）；扩展页列每个扩展贡献了什么、状态、缺的权限 | `plugin_runtime.py` 注册内核、调研 §5.8 的插件包发现与设置命名空间、ADR-010 的 MCP 出口反向 | 内置模块也按同一份 manifest 登记（扩展页里「阅读」「视频」和「Claude Code」同一张表）；权限四类：网络、凭据、屏幕与输入、文件 |

### D4 本机代理进程

浏览器标签页做不到：全局快捷键、页面不在前台时常听唤醒词、屏幕捕获、输入注入、读钥匙串、系统托盘与通知。Web SPA 不变（ADR-001 不推翻），新增一个本机常驻进程提供这些能力，候选：

| 方案 | 做法 | 代价 |
| --- | --- | --- |
| **Tauri 2 壳（推荐）** | 把现有 SPA 装进 Tauri 窗口；用官方插件 global-shortcut / tray / notification / os；屏幕捕获与输入注入仍由 Python 侧执行器做（server 已是 Python，执行器与 API 同进程或 sidecar） | 多一层 Rust 构建；SPA 同时保留浏览器可开 |
| Python 菜单栏守护 | rumps + pynput + sounddevice，纯 Python，与 server 同栈 | 无窗口，SPA 仍在浏览器里；全局快捷键与麦克风权限归这个进程 |
| Electron | 同 Tauri 思路 | 体积与内存明显更大，没有换来更多能力 |

执行器一律放 Python 侧，壳只做「系统入口」；这样换壳不换执行器。

### D5 安全铁律（写进规范，编号待 STD-*）

1. 默认范围是浏览器窗口；桌面范围要显式开且系统权限齐全。
2. 发送、付款、删除、安装、提交表单前必问，清单只能加不能减；审批经 `kernel/approval.py`，缺席即拒绝。
3. 保险箱的值不进模型上下文：助理与电脑操控只有「填充」权；任何「读出」记台账。
4. 每步截图与动作落盘 7 天可回放；单会话步数与时长有上限，超过停下来问。
5. API 只绑本机；局域网访问是显式开关（CR-006 D2）。
6. 唤醒词识别在本机；不常传音频到云端，只在按下或唤醒后开流。

### D6 UI 与交互

- 原型 `design/mockups/workbench.html`，令牌直接读 `web/src/styles/tokens.css`，无新色相：助理 HUD 用壳色，状态用现有 `--accent / --warn / --ok`；AI 生成内容沿用「sparkle + accent-soft」身份（邮件草稿、早报）。
- 表格类页面（账号、保险箱、扩展）共用 `.tbl`，行悬停才露操作；状态一律 chip + 文字，不靠颜色单独表意。
- 邮件三栏；「收入阅读」切换到 Literata 阅读排版并点词可查，是本产品独有的邮件用法。
- 电脑操控页：屏幕预览带真实几何（屏幕、分辨率、预览帧率、延迟），计划 / 动作日志 / 审批卡在右列，接管按钮常驻。
