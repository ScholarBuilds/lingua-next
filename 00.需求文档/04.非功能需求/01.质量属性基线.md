# 质量属性基线

> [!warning] 元规则
>
> 所有数值均为 ASSUMPTION，用于推动原型与验证，未经真实测量不得当作 SLA 承诺。默认统计口径 P95（延迟类另给 P50），按供应商与网络环境分别统计，不用全局均值掩盖差异。

## 1. 性能目标

| 场景 | 目标 | 测量口径 |
| --- | --- | --- |
| 已缓存点词/分析结果 | **P95 100ms**（服务端查询）/ 300ms 内关键字段可见（端到端） | 点击 → 音标与核心释义可见 |
| 在线点词关键字段 | P95 1.5s | 本地词典即时先展示，AI 字段流式后补 |
| AI 释义/语法分析首字 | P95 2s | SSE 首 token |
| 短句翻译核心译文 | P95 3s | 按供应商分别统计 |
| 整篇翻译（300 段内） | 视口段落首批译文 2s；全文后台完成 | 视口优先、按需分批 |
| TTS 单句朗读起播 | P95 1.5s | 点击 → 音频可听 |
| 整篇朗读句级跟随高亮 | 高亮偏差 ≤ 1 句 | |
| 实时语音对话首音频 | **P50 1s / P95 2s** 开始播放 | 用户停止说话 → AI 出声，真实网络实测 |
| 语音打断生效 | 200ms 内 AI 停声 | |
| 视频字幕点击跳转 | 100ms 内完成 seek 起播 | 本地媒体流 |
| 10 分钟视频入库（下载完成后） | 转写 + 入库 < 5 分钟（CPU int8 档） | 按硬件档位标定 |
| 300 页 epub 解析入库 | < 60s | |
| 词库列表滚动 | 万级词条 60fps | 虚拟滚动硬约束 |
| 动态配置传播 | 60s 内对新请求生效 | LLM 别名/翻译引擎切换 |

## 2. 可靠性与恢复

- 外部供应商失败不得丢失已获得的输入、译文或学习记录。
- 错误必须分型：超时、限流、鉴权失败、网络中断、格式错误各有独立状态与文案，不允许统一"出错了"。
- 有副作用的操作（收藏、导入、任务提交）携带幂等标识；重试不产生重复条目、重复计费。
- 长任务（下载/转写/整篇翻译）可断点续传：已完成句子不重算，任务粒度记录进度。
- 非官方端点（translators/edge-tts/DLX）失效自动降级到下一档并标注实际使用的服务，不静默失败也不伪造结果。
- 取消只承诺停止尚未开始或可中止的工作；已发出的第三方请求按其能力处理。

## 3. 隐私与安全

- 供应商密钥只存服务端（litellm/api 配置库），不进前端包、日志与分析事件。
- 实时语音使用 ephemeral token，不得复用于其他能力。
- 日志用请求 ID + 结构化错误，不记录完整原文、音频或图片内容。
- 单用户本地部署仍保留删除与导出能力：学习资产可全量导出（JSON + Markdown），删除按"结构化记录/原始媒体"分别执行并说明影响范围。
- 原始录音默认保留 30 天，结构化转写与学习资产保留到手动删除；两者生命周期解耦。

## 4. 前端架构硬约束（Web 化新增）

- 长文档渲染必须虚拟化：300+ 段落、万级词条列表不允许全量 DOM。
- 重计算（正则预处理、分词标注、字幕解析）放 Web Worker，主线程不做 > 50ms 的同步计算。
- 限额与配额校验一律服务端强制，前端展示值仅供参考（前端可被随意篡改）。
- 浏览器基线：Chrome/Edge 最近两个大版本优先，Safari 尽力兼容；WebRTC 与 MediaRecorder 能力检测后降级提示。

## 5. 可访问性

- 点词、展开学习卡、播放发音、收藏不依赖精确鼠标点击（键盘可达）。
- 颜色不作为状态的唯一标识。
- 播放控件有可读标签、播放状态与停止能力；音频内容有文本等价物。
- 目标基线 WCAG 2.1 AA（尽力项，不作为里程碑门禁）。

## 6. 成本可归因

- 每次外部调用记录：供应商、能力、模型、计费单位、估算费用、缓存命中与否。
- LLM 用量集中在 LiteLLM 统计；翻译/TTS/ASR 用量在 `analysis_result` 与任务表可聚合。
- 缓存命中率是一级指标：点词与翻译的命中率月度可查（ADR-006 的收益验证）。
- 预算控制：LiteLLM 预算上限 + 应用层供应商日限额，超限拒绝新增付费调用并给出可执行替代（切免费档/本地档）。

## 7. 新指标验证门槛

任何新增质量目标必须补齐六要素才算正式目标：目标设备与硬件档位 / 网络条件 / 数据规模与输入上限 / P50、P95 或错误率口径 / 监控来源与未达标处理 / 依赖的配置版本与供应商条件。

## 8. 语音执行助理（贾维斯，CR-010）

> [!warning] 全部数值为 ASSUMPTION，直到 M86 实测回填
>
> 六要素按 §7 补齐；测量脚本与口径以本节为准，实测数字进 [CR-010](../07.需求变更/10.CR-010-贾维斯可打断语音与常驻开关.md) §6 与治理基线 M86。上限类（turn / 启动 / 恢复次数）由配置项承载，不是分位数。

### 8.1 六要素

| 要素 | 取值 |
| --- | --- |
| 目标设备与硬件档位 | macOS arm64（Apple Silicon）。**Electron 壳**（签名安装的 `/Applications/NEXUS.app`：三档全开、全局 ⌥Space、刘海 / overlay / 审批窗）与**浏览器**（`http://127.0.0.1:8080`：只读档位、无 ALWAYS-ON、⌥Space 仅页面有焦点时）分列统计，不合并 |
| 网络条件 | 火山实时 / TTS / ASR 走外网（`openspeech.bytedance.com`，国内直连不经代理；shell 带 `all_proxy=socks5` 时需 `httpx[socks]`）；执行内核（stdio 子进程）、三个 MCP 门代理（`/mcp`、`/mcp/desktop`、`/mcp/browser`）与语音 WS `/jarvis/voice/ws` 全在回环，不计外网抖动 |
| 数据规模与输入上限 | 单轮 ASR 终稿 ≤ 4000 字；单 turn 内步骤 ≤ 999（`computer_step.ordinal`）；上行 PCM16 16k mono 40ms/帧（duplex 20ms）；语音会话 TTL 1500s 在静音期轮换（`LINGUA_JARVIS_VOICE_SESSION_TTL_S`） |
| 统计口径 | 延迟类 P50 + P95；按供应商（`volc.speech.dialog` / Seeduplex 3.0 / LocalVad 兜底）与承载体（壳 / 浏览器）分别统计，不用全局均值 |
| 监控来源与未达标处理 | `server/scripts/measure_voice_latency.py`（喂 WAV 打点：用户停顿→459、459→turn/start、首句→首音、450→tts.flush；`--scenario barge_in`；出 P50 / P95 JSON）、`server/scripts/jarvis_latency_probe.py`（打断 ack、急停、首 delta、审批卡出现；写 `data/logs/jarvis-latency-<时间>.json`）、结构化日志 `jarvis.turn`（`first_delta / interrupt_ack / approval_wait / turn_total`）、`GET /jarvis/sessions/{id}/metrics`。未达标：打断类先查 `VoiceOrchestrator` 是否唯一裁决点、再跑 AEC 实测（`desktop/scripts/probe-aec.mjs`），都不行 ALWAYS-ON 降半双工带抢话、STANDBY 一律 PTT，**不退回关麦**；引擎类先重跑 `jarvis_probe.py` 看协议分支 |
| 依赖的配置版本与供应商条件 | `interpreter 0.0.40`（Rust app-server；`turn/steer` / `thread/queue` / permission profile 全标 experimental）、`cua-driver 0.23.2`（私有 bounded daemon）、`agent-browser 0.36.0`（`mcp --tools core`）；火山 `volc.speech.dialog`（`dialog.model` 1.2.1.1，QPM 60 / TPM 10w）→ M6 起 Seeduplex 3.0（`v3/duplex/realtime/dialogue`，model 1.2.6.1）；`computer-use` / `realtime-voice` / `tts-assistant` 三个能力已绑定（M6 起可另绑 `jarvis-voice`） |

### 8.2 指标

| 场景 | 目标 | 测量口径 | 状态 |
| --- | --- | --- | --- |
| 用户开口 → 停声 | ≤ 200ms | 450 ASRInfo 到播放器静音，壳内本机时钟 | §1 既有「语音打断生效」，模块 07 BR-01 同口径 |
| 450 → `tts.flush` 发出 | 服务端 P95 ≤ 100ms | 编排器收到 speech_started 到 flush 帧写出 | ASSUMPTION |
| 用户停顿 → ASR 终稿 | P50 ≤ 600ms | 最后一帧有声 PCM → 459 / final transcript | ASSUMPTION（`end_smooth_window_ms=500` 是下限） |
| 首句切出 → 首音 | ≤ 800ms | `SentenceSplitter` 切出首句 → 首个下行音频帧 | ASSUMPTION |
| 用户停顿 → 首音（含引擎首 token） | ≤ 1.5s | 459 → 首个下行音频帧 | ASSUMPTION |
| `turn/interrupt` ack | P95 ≤ 300ms | 发出 interrupt → `turn.completed{interrupted}` | ASSUMPTION |
| 急停生效 | ≤ 100ms | `POST /jarvis/emergency-stop` 响应 | ASSUMPTION（CR-009 实测约 15ms，见 8.3） |
| 审批卡出现 | ≤ 200ms | `requestApproval` 到 `approval.requested` 帧到达前端 | ASSUMPTION |
| 假打断恢复 | ≤ 2.5s | 误触发 flush → `tts.resume` 续念（2s 窗口 + 一次分句） | ASSUMPTION |
| 单 turn 上限 | 300s | 超时先 `turn/interrupt` | 配置项，硬阈值 |
| 引擎启动 | ≤ 20s | 拉起子进程 → `initialize` 应答 | 配置项，硬阈值 |
| 自动恢复 | ≤ 2 次 | 内核不响应 / 异常退出 → 重启并重建 thread，超过即 failed | 配置项，硬阈值 |

### 8.3 对照：CR-009 已记录的实测

CR-009 链路（Python sidecar + 实时桥 + 整段单向 TTS，2026-09-02，治理基线 M83 与 CR-009 §5）：急停 API 约 15ms；实时桥建链约 3.0s；建链后约 0.7s 出现第一段回复；约 7.5s 收到引擎结果并触发第二段语音。这四个数是重做前的基线，不是目标：建链的 3.0s 落在 STANDBY 唤起之前（会话 TTL 内复用，不计入每轮）；0.7s / 7.5s 对应「整段回复再念」，CR-010 改分句流式后按 8.2 的口径重量。
