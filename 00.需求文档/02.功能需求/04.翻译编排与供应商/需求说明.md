# 翻译编排与供应商

## 1. 模块目标

统一接入所有可接入的翻译能力——免费网页端点（必应/Google/有道等）、官方 API（DeepL/微软/有道智云）、AI 翻译（任意 LLM）——按场景路由、失败降级、结果可对比、来源可解释、成本可归因。

## 2. 供应商目录（三档）

| 档位 | 供应商 | 接入方式 | 定位 |
| --- | --- | --- | --- |
| 免费档 | 必应、Google（网页端点）、有道、百度等 | translators 库聚合 | 零成本默认档，稳定性不承诺 |
| 官方档 | DeepL（免费额度 50 万字符/月）、微软 Translator、有道智云 | 官方 SDK/API | 稳定高质量档 |
| AI 档 | 任意 LLM（经 LiteLLM 别名 `translate-fast` / `translate-quality`） | OpenAI 兼容协议 | 语境理解最好，支持语气偏好 |
| 自托管档（可选） | DLX（原 DeepLX） | 自托管容器 | 个人加餐，随时可降级 |

## 3. 功能需求

- FR-01 能力注册表：每个供应商声明能力（文本翻译/文档翻译）、语言方向、计费单位、配置状态；每家提供可执行的连通性探针（真实小额请求，不用假响应判定），探针结果（耗时/失败原因/时间）在设置页可见。
- FR-02 场景默认路由（明确规则，不做不可解释的"AI 自动最优"）：
  - 单词/短语 → 本地词典优先（不走翻译供应商）
  - 句子点译 → 用户当前选定引擎（默认免费档首选）
  - 整篇翻译 → 用户选定引擎批量执行，AI 档展示预估消耗
  - AI 语境释义/语法 → LLM 别名路由（见 10 模块）
- FR-03 引擎切换：翻译结果面板可切换引擎重译并对比（并列展示，标注引擎与生成时间）；每个场景记住上次选择。
- FR-04 降级链：所选引擎失败自动按"同档其他 → 下一档"降级，结果标注实际使用的引擎；用户可对单个引擎设"禁止自动回退"。
- FR-05 译文语气全局偏好（自然/正式/简洁/保留原文风格），对 AI 翻译档全链路生效。
- FR-06 每次调用记录：供应商、能力、延迟、估算费用、缓存命中、成败与错误类型（超时/限流/鉴权/网络/格式分型）。

## 4. 业务规则

- BR-01 所有翻译结果按 ADR-006 指纹落库：同句同引擎不重复调用；换引擎产生新缓存行，天然支持多引擎对比。
- BR-02 免费档标注"免费通道，稳定性不保证"，失效不阻塞主流程（自动降级 + 状态提示）。
- BR-03 密钥只存服务端；签名鉴权类（百度/腾讯/阿里/有道）签名在服务端计算。
- BR-04 幂等标识防重试重复计费；自动重试有上限。
- BR-05 英中/中英方向分别维护质量与可用性记录。
- BR-06 适配完成、探针通过、启用是三个独立状态；未过探针的引擎在 UI 中可见但标注不可用原因。

## 5. 实现方案

| 部件 | 方案 | 开源参考 |
| --- | --- | --- |
| 免费档聚合 | translators 库（GPL，个人项目直用），包一层适配器 + 熔断 | UlionTse/translators |
| 官方档 | deepl-python 官方 SDK、有道智云 REST | 官方文档 |
| AI 档 | LiteLLM 别名，prompt 模板含语气偏好与术语保护 | ADR-004 |
| 引擎抽象 | 参考 Pot/Easydict 的引擎插件模型：`translate(text, from, to) -> {text, alternatives?}` 统一契约 | pot-app/pot-desktop |
| 熔断降级 | 适配器内简单熔断（连续 N 次失败挂起 M 分钟），状态入 Redis | - |
| DLX | 自托管容器（可选 profile，Compose 内注释提供） | OwO-Network/DLX |

## 6. 验收要点

- AC-01 免费档全部失效时句子点译仍可用（降级到官方/AI 档并标注）。
- AC-02 同一句换 3 个引擎重译，三条结果并列展示且各自落库，二次访问全部缓存命中。
- AC-03 探针页能真实区分"网络不通/密钥无效/配额耗尽"三类失败。
- AC-04 用量页按"供应商 × 能力"聚合展示次数、延迟分位、估算费用。

# v2 修订：翻译带素材语境（2026-08-18，真实使用反馈驱动）

## 7. 领域词歧义与语境注入

### 7.1 问题实证

逐句翻译不带任何语境，LLM 只能按最常见词义翻。15 号视频（伦敦一日游）的
`The tube has arrived` 被译成「**管子**到了」——tube 在英式生活语境里指地铁。
同类风险词还有 quid（英镑）、the Underground、black cab、chuffed 等。

讽刺的是语境本来就在库里：该视频的 AI 摘要明确写着"穿插介绍英式表达，如 tube、
queue、quid"，只是从没喂给翻译。

### 7.2 需求

- FR-07 翻译接受可选 `context`（素材背景），拼进 system prompt 指导选词：
  视频取「中文标题 + 主题标签（前 3 个）+ 摘要节选（120 字）」，
  文章取「书名 + 篇名」，即时翻译由前端透传。
- FR-08 语境只对 LLM 档生效；免费机翻引擎不接受语境（这也是降级链里 llm 优先的又一理由）。
- BR-07 语境进 `analysis_result.context_hash` 位分槽缓存：换语境即换缓存槽，
  不会命中旧的无语境译文（ADR-006 双指纹寻址）。
- BR-08 摘要截断到 120 字、主题取前 3 个：语境是给 LLM 定调的，过长反而稀释注意力并抬高每句开销。

### 7.3 实测

| | 译文 |
| --- | --- |
| 无语境 | 管子到了，管子到了，我们正在下车，现在我们正在下车。 |
| 带语境 | 地铁到了，地铁到了，我们要下车了，现在我们要下车了。 |

语境串：`视频《跟着博主逛伦敦学英语》；主题：旅行、生活、英语学习；内容简介：…`

## 8. v2 验收要点

- AC-07 15 号视频 `the tube` 译为「地铁」而非「管子」。
- AC-08 同一句在不同语境下产生不同译文且各自独立缓存，互不覆盖。
- AC-09 语境缺失（无标题无摘要）时行为与改造前一致，不报错不空转。
