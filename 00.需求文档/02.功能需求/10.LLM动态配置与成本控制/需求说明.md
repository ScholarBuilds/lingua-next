# LLM 动态配置与成本控制

## 1. 模块目标

运行时增删任意 LLM 供应商（OpenAI/Anthropic/Google/DeepSeek/通义/Kimi/豆包/硅基流动/Ollama 本地/自定义 OpenAI 兼容端点），按能力绑定模型，预算可控、用量可查、切换不改代码。

## 2. 功能需求

### 2.1 供应商与模型管理

- FR-01 供应商 CRUD：类型（原生/OpenAI 兼容）、Base URL、密钥、可用模型列表（支持 `/models` 自动拉取或手填）；保存即生效，无需重启。
- FR-02 语义别名路由：`translate-fast`、`explain-standard`、`grammar-deep`、`companion-long`、`summary-long` 等别名映射到具体"供应商+模型"，应用内"模型设置"页可视化改绑。
- FR-03 每条别名可配 fallback 链（主失败自动切备）与超时/重试参数。
- FR-04 能力测试：每条绑定提供"测一下"按钮——跑该能力的真实调用（含 schema 校验），返回延迟与一小段样例输出；"连得上但守不住 JSON schema"必须能被测出。测试结果与时间入库展示。
- FR-05 本地模型：Ollama 端点作为一等供应商接入（零成本档）。

### 2.2 预算与限额

- FR-06 两层限制：部署级绝对上限（环境变量，动态配置不可突破）+ 运行时预算（月度总额、单供应商日额、实时语音单独日额，应用内可调）。
- FR-07 预算耗尽行为：拒绝新增付费调用并给可执行替代（切免费翻译档/本地模型/仅读缓存）；不允许无限重试绕过。
- FR-08 预警：用量达阈值（默认 80%）应用内提示，不在耗尽瞬间才告知。

### 2.3 用量可观测

- FR-09 用量页两视图分离："还剩多少预算"（额度视图）与"慢在哪里/贵在哪里"（分析视图，按 供应商×能力×模型 分组，调用最多排前，延迟给 P50/P95）。
- FR-10 每次调用记录：别名、实际供应商与模型、token 数、估算费用、延迟、缓存命中、成败分型；缓存命中费用记 0。
- FR-11 配置变更审计：谁（单用户场景记录来源界面）、何时、改了什么、可回滚到上一版本。

## 3. 业务规则

- BR-01 密钥只存服务端（LiteLLM 配置库），前端只见掩码；密钥不进日志与导出。
- BR-02 业务代码只引用语义别名，禁止硬编码供应商模型名（规范红线）。
- BR-03 能力声明按协议判定（openai 兼容/原生），不按供应商名硬编码分支；每家差异用显式配置表达。
- BR-04 配置读取失败用最后已知正常版本；超过陈旧窗口按安全默认值拒绝高费用能力，不解释为无限额度。
- BR-05 实时语音（Realtime）预算独立于文本 LLM 预算，分别设限分别显示。

## 4. 实现方案

> [!info] 网关决策见 [ADR-004](../../../01.项目文档/02.架构/ADR/ADR-004-LLM网关采用LiteLLM动态配置.md)

| 部件 | 方案 | 说明 |
| --- | --- | --- |
| 网关 | LiteLLM Proxy 容器 + PostgreSQL 配置持久化 | 供应商/模型/密钥/预算/fallback 全部其内置能力 |
| 应用内设置页 | api 封装 LiteLLM 管理 API（增删供应商、改别名映射、查用量），前端一个设置面板搞定 | scholar 不离开产品界面 |
| 能力测试 | api 按 kind 取真实 prompt 模板 + schema 跑一次小样本 | 结果落库 |
| 用量数据 | LiteLLM spend 表 + 应用侧 `analysis_result`/调用日志聚合 | 双源对账 |
| 部署级上限 | Compose 环境变量 `LLM_HARD_BUDGET_MONTHLY` 等，api 启动读取，动态配置校验不得超过 | 两层限制模型 |

## 5. 验收要点

- AC-01 新增一个 DeepSeek 供应商并把 `translate-fast` 改绑过去，全程不重启服务，60s 内新请求生效。
- AC-02 主模型故障时 fallback 链生效，结果标注实际模型。
- AC-03 预算耗尽后 AI 调用被拒且提示替代路径；缓存读取不受影响。
- AC-04 能力测试能区分"连通失败/超时/schema 不通过"三类结果并展示样例。
