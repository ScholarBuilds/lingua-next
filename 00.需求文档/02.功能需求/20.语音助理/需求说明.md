# 语音助理

CR-007 立的模块 20，CR-010 重做。对外只有一个名字「贾维斯」：耳朵与嘴是火山实时会话
（`volc.speech.dialog`，第二步迁全双工 Seeduplex 3.0；供应商经 `VoiceProvider` 接缝可换），
脑子是 ADR-015 的执行内核（`interpreter app-server`），工作台技能（找书、开页、复习、邮件、日历、任务）
经 `domain/assistant.py` 的工具层与回环 Lingua MCP 提供。打断、插话、假打断恢复由服务端
`VoiceOrchestrator`（`domain/jarvis_voice.py`）一处裁决，前端只认 `/jarvis/voice/ws` 的帧契约。

> [!info] 决策只按 CR-010 编号引用
>
> 本模块从回合制（CR-007 P4）→ 常听（CR-008）→ 引擎语音桥（CR-009）走到可打断语音（CR-010），
> 前三轮的决策已被 [CR-010](../../07.需求变更/10.CR-010-贾维斯可打断语音与常驻开关.md) §0 逐条作废或改写。
> 下面两张表里标「已废」的条目只留编号占位，避免旧文档引用失联；
> 帧契约、REST、壳 IPC、配置键见 CR-010 §3，不在这里复制。

| BR-20-14 | （已废，见 BR-20-15 / BR-20-16）常听不再是本机开关，是三档模式之一，偏好真源在服务端 |

| BR-20-17 | 打断验收口径：用户开口 ≤200ms 停声（与模块 07 BR-01 同口径，`scripts/measure_voice_latency.py` 量）；执行中插话三分——**barge-in** 只停播（`tts.flush`）、**steer** 追加进在飞 turn（`turn/steer`，被拒退 `thread/queue/add` 再退本地队列）、**abort** 才 `turn/interrupt`（停词：停 / 别弄了 / 算了 / 取消 / stop / cancel，且短句）；假打断按 LiveKit 三件套恢复：`min_interrupt_chars ≥ 2`，2s 内无达标终稿从断句处续念（`tts.resume`） |
| BR-20-18 | 常听可见性（STD-SEC-006）：ALWAYS-ON 时菜单栏橙点常亮且可见；锁屏 / 休眠 / 电池 / 热降频自动退回待命并在刘海 / HUD 明示原因（「常听 · 锁屏降级」）；隐藏窗口后不得无提示地继续上行 |
| BR-20-19 | 麦克风全程不关（作废 CR-009 D12）：念的中途麦克风照常上行，火山 `450 ASRInfo` 是唯一抢话信号，裁决只在 `VoiceOrchestrator`；供应商侧的 VAD（450 / 459 / duplex `speech_started` / 本地 Silero）一律只上报信号不动作 |
| BR-20-20 | 语音只能表达拒绝（不要 / 别 / 拒绝 → `deny`），放行必须点审批卡；语音里说「可以」「允许」对审批不生效（`test_voice_only_expresses_rejection`） |

## 3. 不做的

- interpreter 内置的 `thread/realtime/*`（Codex 实时语音）：握手写死 OpenAI 形状，只做探针（ADR-015 决定 6）。
- 菜单栏模式（`accessory` / LSUIElement）：本期不做（CR-010 §5）。
- 浏览器（无壳）里的 ALWAYS-ON：不允许，只读档位；⌥Space 在浏览器里只在页面有焦点时有效。
- 长期记忆 / 用户画像：上下文只活在引擎 thread 里，不跨会话。
- 保险箱 fill-only 的原生执行者：要先修 ADR-010（BR-21-05）。

## 4. 实施记录（2026-09-02，CR-007 P4 回合制链路；历史，链路已被 CR-010 替换）

**后端**

- `domain/assistant.py`：PydanticAI `Agent[AssistantDeps, str]`，模型复用修复代理的 `build_model`（每次模型请求单独记账）；工具各自开 session（`AssistantDeps.session_factory`），测试里由 `conftest._detached_session` 接管到内存库，**不要在工具里直接引 `SessionFactory`**（第一版就是这么写的，`draft_reply` 在测试里查真库、返回「没有这封邮件」、待确认为空，而接口 200）。
- `domain/briefing.py`：`compose_morning_brief` 四段拼一段口语；`routine_run` 表（迁移 `a5b6c7d8e9f0`）；`latest_run(today_only=True)` 按本机时区取「今天」。
- `domain/gmail.upsert_from_meta`：搜索结果落成本地行，读正文与回复都要本地 id。
- `routers/talk.list_sessions` 与 `routers/home._continue_talk` 排除 `mode=assistant`。
- **助理的声音要自己一档**：回复中文为主，而「整句朗读」绑的是火山英文音色 `en_female_dacey_uranus_bigtts`，喂中文返回「未返回音频」，路由再兜到 edge `en-US-AriaNeural` 同样不出声，接口 502「TTS 暂不可用」——英文音色对中文不是读得差，是一个字不出。加了场景 `assistant`（`tts-assistant`），没绑定时直接用 edge `zh-CN-XiaoxiaoNeural`，出错兜底也用它；其它场景没绑定仍是 503，不悄悄换音色。
- `httpx[socks]`：本机 shell 带 `all_proxy=socks5://` 时 httpx 没有 socksio 直接 `ImportError`，接口回 502「助理没答上来」。加了这个 extra 之后同一条请求正常。修复代理、生图、任何直连远端上游的 httpx 客户端都受此影响，之前没显形只是因为起服务的那个 shell 没导出 `all_proxy`。

**前端**

- `lib/recorder.ts`：从对话页抽出 `useRecorder` / `pickRecordMime` 共用。
- `features/assistant/assistantStore.ts`：zustand，HUD 与助理页同一份运行态；TTS 用 `playUrl(ttsUrl(text,'assistant'))`，`ended/error/pause` 回 idle。
- HUD 在 `/assistant` 上返回 null（页面自己渲染输入条，⌥Space 跟着输入条走），动作执行的 effect 仍在 HUD 里跑。

**门禁**：ruff 0 · pytest 2105 全绿（+9 `tests/test_assistant.py`；`test_plugin_runtime::test_repair_agent_logs_every_pydantic_model_request` 那条长期失败随 socksio 装上一起转绿——它一直是同一个 SOCKS 代理 ImportError）· tsc 0 · vitest 1440 · check:css 通过（67 文件）· 迁移已在本机库执行 · playwright：助理页打字「帮我打开任务」→ 真实模型（`chat-general` 回落）调 `open_page` → 页面跳到 `/tasks`、回复「打开了」；早报「现在生成」实测文案「早上好。任务都空着。词汇有 72 张到期。」（没连 Google 账号时邮件与日程两段不出现）。

| 位置 | 用法 | 落点 |
| --- | --- | --- |
| OFF 档的离线唤醒 | OFF 档不常驻采集；手动打开面板后，面板内的语音入口沿用本机唤醒 / VAD 收段，不建常驻火山会话。openWakeWord 锁版本（0.4，`hey_jarvis_v0.1.onnx` 与 `silero_vad.onnx` 随包自带，`download_models` 在这个版本不存在） | `domain/listening.py`，M7 后并入 `jarvis_voice.LocalVadProvider` |

## 7. 前台事实层、记忆与待唤醒档（CR-011，2026-09-03）

CR-010 把语音管道修好了，但前台只有 `computer_task` 一个工具、引擎线程每次都是新的、常听档全程上云。这一轮补的是这三件事，决策与实测数字在 [CR-011](../../07.需求变更/11.CR-011-贾维斯前台事实层与记忆.md)。

**BR-20-24 前台自己答得了的不惊动引擎**：全双工语音模型的工具带是 `jarvis_voice.front_desk_tools()` = `jarvis_facts.function_tools()`（八个只读事实：时间 / 今天一眼 / 到期词 / 任务 / 最近几步 / 找书 / 未读邮件 / 今天日程）+ `computer_task`，末位固定是后者。入选判据只有一条「这次调用会不会改变任何状态」，会改的（开始复习、起草回信、跳页面）不在这里。日常问句因此不再等引擎那 3.3 秒。
