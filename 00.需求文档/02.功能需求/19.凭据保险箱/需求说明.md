# 凭据保险箱

CR-007 立的模块 19，是邮件（18）、语音助理（20）、电脑操控（21）的共同前置：它们都要拿凭据，
而凭据只能有一个家。

> [!info] 表没换，泛化的是它装什么、怎么拿出去
>
> `provider_credential` 本来就是「加密 config 的凭据表」（模块 11）。这轮不另起一张 `credential`，
> 只加三个通用秘密类型（`password` / `bearer` / `cookies`，`kind=secret`）、一张访问台账、
> 两种授权方式和带口令的导出导入。模型供应商的凭据仍在设置 · 模型服务里加与测——那边有探测、
> 拉模型、试连，保险箱页只把它们列出来、能读出、能看记录。

## 1. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-19-01 | 库里只有密文。主密钥来源按序：环境变量 `LINGUA_CONFIG_KEY`（Docker / CI）→ 系统钥匙串 → 本地文件 `data/vault.key`；一个都没有时自动生成并优先写进钥匙串（`domain/vault_key.py`） |
| BR-19-02 | 主密钥不随导出走。换机器用「导出保险箱」带口令导出再导入；口令派生密钥（scrypt），口令不存任何地方 |
| BR-19-03 | 两种授权：**读出**（reveal）是人看，值回到浏览器；**填充**（fill）是执行器拿去用，值不经模型上下文。两种都记一行 `credential_access`；供应商调用（LLM / TTS）不记 |
| BR-19-04 | 只有秘密字段（`SENSITIVE_FIELDS`）能读出 / 填充；明文列（用户名、站点）不走这条路 |
| BR-19-05 | 停用的凭据拒绝填充；删除凭据保留台账（外键置空，名字快照在行里） |
| BR-19-06 | 编辑时密码框留空 = 不改；不回显明文 |
| BR-19-07 | 导入按 `(provider_type, name)` 去重，跳过而不覆盖 |
| BR-19-08 | 秘密类型由供应商类型推出（`vault.secret_kind`），不在每个类型上再写一遍：字段里有 cookies_text 就是 cookies，有 api_key 类字段就是 api_key，本机 CLI 是 login，没有秘密字段是 none |

## 2. 功能需求

| 编号 | 需求 | 落点 |
| --- | --- | --- |
| FR-19-01 | 账号与凭据页列全部凭据：名称、秘密类型、谁在用、状态、上次访问 | `web/src/features/vault/VaultPage.tsx`，`GET /vault/credentials` |
| FR-19-02 | 新建 / 编辑 / 停用 / 删除通用秘密，字段由 `GET /vault/secret-types` 驱动 | `POST/PATCH/DELETE /vault/credentials` |
| FR-19-03 | 读出：选一个秘密字段，明文只在弹窗里出现，可复制 | `POST /vault/credentials/{id}/reveal` |
| FR-19-04 | 访问台账可查 | `GET /vault/credentials/{id}/access` |
| FR-19-05 | 导出带口令的保险箱文件；导入 | `POST /vault/export`、`POST /vault/import` |
| FR-19-06 | 页面显示主密钥来源；在 .env 的可一条命令迁进钥匙串 | `GET /vault/status`，`scripts/vault_key_to_keychain.py` |
| FR-19-07 | 填充接口留给电脑操控（模块 21）：`vault.fill(session, credential_id, field, purpose)` | `domain/vault.py` |

## 3. 不做的

- 不做浏览器自动填充扩展、不做跨设备同步（CR-007 §1.3）。
- OAuth 令牌类型（Google 账号）随模块 18 进来，`SECRET_KINDS` 已留位。
- 台账不记供应商调用：模型调用已有自己的台账（`model_invocation`）。
