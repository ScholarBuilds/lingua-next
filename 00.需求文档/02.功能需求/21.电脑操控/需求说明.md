# 电脑操控

CR-007 立的模块 21，CR-010 改成引擎侧口径。执行内核是 [ADR-015](../../../01.项目文档/02.架构/ADR/ADR-015-贾维斯执行内核选型.md)
选定的本机 `interpreter 0.0.40 app-server --stdio`（Apache-2.0，只用协议不含源码）；浏览器走 agent-browser、
第三方原生 App 走 cua-driver，两者都不直连内核，而是经 Lingua 的 fastmcp 门代理（`/mcp/browser`、`/mcp/desktop`）挂成 MCP，
每次工具调用过同一个 `kernel.approval` 席位。范围不再由「浏览器窗口 / 桌面」二分，而由引擎 permission profile
与 cua-driver 的 capability manifest 划定。会话与步骤仍是 `computer_session`（`scope=desktop`）/ `computer_step` 两张表。

> [!info] 审批的态度：不推翻 CR-007 D5-2，改为分级必问
>
> CR-009 §6 的「完全接管、不逐步审批」自 CR-010 起失效。删除 / 清空、发送（邮件 · 消息 · 表单提交）、
> 支付 / 下单、系统设置、对外写接口（非 GET 的 HTTP、git push）、安装、kill 非自启进程、浏览器 download / eval / auth
> 必问；其余自动执行。补偿控制是 cua-driver `bounded` 天花板 + 每步落库 + 急停。规则编号见
> [STD-SEC-001..006 提案](../../../02.项目规范/00.规范治理/提案/)。

## 1. 业务规则

| 编号 | 规则 |
| --- | --- |

| BR-21-09 | API 重启后启动对账分 scope：`scope=desktop` 由 `domain/jarvis.reconcile_on_startup` 判 `failed`；`scope=browser` 的历史会话由旧执行器判，M7 删除旧执行器后一并归贾维斯侧 |

## 3. 不做的

- 视觉模型看截图：bounded 下截图只给人看（`kind=image` 步骤）；原生 App 靠 AX 树、网页靠 `snapshot @ref`，canvas 类页面再评估 computer-use 兜底。
- 录屏回放：cua-driver 的 `start_recording / replay_trajectory` 不接，每步截图 + `computer_step` 够回放。
- 菜单栏模式与 Developer ID 公证：CR-010 §5 本期不做，环境变量预留。
- 保险箱 fill-only 的原生执行者：先修 ADR-010（BR-21-05）。
- 任务中心「在跑」行里列贾维斯会话：现场在 `/jarvis` 与 overlay，不再进 `useRunningRows`。

- （已删除，2026-09-02 M7；审批语义上提到 `tests/test_jarvis_gate.py`）测试 `tests/test_computer_use.py`（14 条，假驱动 + FunctionModel 编脚本）：审批放行 / 拒绝、凭据不进模型上下文、上限暂停与续跑、提问回答、停止、主动审批覆盖下一个危险动作、危险词清单、工具目录、启动对账、截图清理。

**踩坑**

- **测试内存库单连接 + 后台运行器 + 页面轮询 = 两种假失败**：轻则轮询的 GET 会话一关把后台刚 `execute` 未 `commit` 的 UPDATE 连带回滚（回答写回了、行还是 awaiting），重则两个 session 同时碰一条连接抛 `IllegalStateChangeError`、后台任务无声死掉（状态永远 queued）。生产是连接池没这回事；测试里让请求会话与后台会话经一把**按任务可重入**的锁轮流用（`tests/jarvis_harness.py`），可重入是因为 `create_session` 在请求任务里就调 `manager.start`（它自己也开一个后台会话）。同时每个测试结束把 `manager.runs` 里没跑完的任务等完，否则会话 id 每个测试都从 1 起、上一个测试的收尾会写进下一个测试的库。
- **模型会为同一个提交问两遍**：它先 `request_approval` 主动问，执行器在 `click` 上又拦一次。加 `preapproved_step`：主动问过并获准，紧接着的那一个危险动作直接放行并记「已在第 N 步点头」。
- **模型看到 JSON 结果页会以为没提交成功再来一遍**（httpbin 实测提交了两次）：系统提示词明写「看到结果页就算完成，不要回去再提交」。

**门禁**：ruff 0 · pytest 全绿（+14）· tsc 0 · vitest 1440 · check:css 通过（68 文件）· 迁移已在本机库执行 · **真实链路**：`https://httpbin.org/forms/post` 填 Customer name / Telephone / 选 Large → 点「Submit order」被拦、`POST /approve` 放行 → 提交 → `finish` 总结，18 步 46 秒，每步有截图；会话页在 playwright 里看过（截图预览、计划、动作日志、结果）。

**留给 scholar**：`computer-use` 能力还没绑模型（目前走 `chat-general`）；带登录与上传的真实流程（CR-007 P5 验收原话）要一个真站点与保险箱里的账号，代码路径（`list_credentials` → `fill_credential`）已由单测覆盖。

## 5. 桌面范围：贾维斯执行内核（CR-009 → CR-010）

「桌面」这一档不再自己写执行器，接 Open Interpreter Rust App Server（`interpreter 0.0.40 app-server --stdio`，Apache-2.0，本机预编译二进制，仓库不含其源码）当内核：
写代码、管文件、开软件、看屏幕、控制第三方软件都由它做，我们负责模型配置、审批门、门代理、落库、界面与急停。
步骤种类多了 user / message / code / console / image / note / ask / question。入口是全局贾维斯按钮、`/jarvis` 页、刘海、
⌥Space 与技能层的 `computer_task`。选型与退路见 [ADR-015](../../../01.项目文档/02.架构/ADR/ADR-015-贾维斯执行内核选型.md)，决策与契约只按 [CR-010](../../07.需求变更/10.CR-010-贾维斯可打断语音与常驻开关.md) 编号引用。

CR-010 口径下的桌面规则：

- 审批装在内核协议上：`approval_policy=on-request` + `default_permissions=jarvis` 自定义 permission profile（替代 `sandbox_mode`）；客户端 `ApprovalBroker` 对每个 `requestApproval` 按风险分级答复（BR-21-02 / 03）。CR-009 的 `full_control=true` 默认、`approvalPolicy=never`、`danger-full-access`、`auto_run` 别名全部作废；`/full-control` 与 `/auto-run` 端点只作 deprecated 别名。
- 驱动器不直连内核：agent-browser（浏览器）与 cua-driver（原生 App）经 fastmcp 门代理挂成 `/mcp/browser`、`/mcp/desktop`，cua-driver 跑 API 进程私有的 `bounded + capability manifest` daemon；启动脚本检测到用户级 `standard` daemon 时警告并提示 `cua-driver stop`（它会让私有 bounded 边界失效）。
- macOS TCC 不能被应用绕过：Electron 只申请麦克风；辅助功能与屏幕录制授权对象是 `CuaDriver.app`，HUD 从 `cua-driver permissions status --json` 读组合状态并可调起 `permissions grant`；备份 App 或其他客户端的开关不代表 CuaDriver 已授权（CR-009 D13 保留）。签名壳装到 `/Applications/NEXUS.app` 后麦克风要重授一次（STD-BUILD-001）。
- 同一时间只有一个全局贾维斯会话（`POST /jarvis/session/ensure` 并发安全）；忙碌时新指令按三分法处理（FR-21-03），不再拒绝、也不把拒绝语念出来。
- 引擎输出逐字流式：delta 只进内存 `JarvisEventHub`，`item/completed` 才落 `computer_step`；页面与语音编排器消费同一个 hub（SSE，不轮询）。
- 每个 turn 300s 上限，超时先 `turn/interrupt`；内核不响应或异常退出自动重启并重建 thread，最多恢复 2 次；崩溃时在飞 item 以 `failed` 落库。
- 语音只采集麦克风（`getUserMedia({audio})`），不捕获系统音频；回答由火山会话经 `500 ChatTTSText` 念（模块 20 BR-20-19）。

**旧 Playwright 执行器的去向**：`domain/computer_use.py`、`routers/computer.py`、`features/computer/*` 与 `/computer` 页已于 2026-09-02（CR-010 M7）删除，连同 Python 0.4.3 的 AGPL venv 与 `server/engine_runner/`；删除前把 `detached_session`（conftest 接管名不变）、`DANGER_WORDS`、`purge_old_screenshots`、`_step_view`、`ACTIVE_STATUSES` 与 12 条审批语义测试分别上提到 `domain/jarvis.py`、`domain/danger.py`、`domain/computer_steps.py` 与 `tests/test_jarvis_gate.py`；`data/engines/open-interpreter`（AGPL venv）与 `server/engine_runner/` 一并删除。§4 保留为浏览器范围首版的历史记录。

## 6. 审批前移（CR-011 D-6，2026-09-03）

**BR-21-10 危险意图在他说完话那一刻就问**：`danger.classify_utterance()` 扫用户原话，命中就先弹一张 `kind=intent` 的卡，不等引擎跑到那一步（实测卡片原来要 3159–16874ms 才出现，基线是 ≤200ms）。裁决在后台等，`POST .../say` 立刻回 `accepted_as: "intent"`——在请求里 await 会把单连接锁死。

**判据宁可漏报**：误判会让每句带「删」的话都弹卡，比晚几秒更烦人。问句（「能不能删掉」）、否定句（「不要删」）、在说过去的事（「刚才删掉的那个」）一律放行。口语与命令行是两套写法，`spoken_risk()` 另配一份正则——复用命令那几条的话「把桌面的 test.txt 删掉」一条都命不中。

**BR-21-11 点过头的不问第二遍**：意图卡放行后，同一轮里引擎的第一次同类风险请求直接过并记一条 note（沿用旧执行器的 `preapproved_step` 范式），第二次照样弹卡；换了风险类、或进了下一轮，重新问。引擎侧与门代理侧的门一条没少。
