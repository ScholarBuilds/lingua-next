# 精读阅读器与点词学习卡

## 1. 模块目标

在安静的阅读界面逐句精读：点词出学习卡（音标/释义/例句/AI 语境义）、点句出翻译与语法分析、拖选词组可查、双语对照可切换、批注与进度自动保存。这是产品核心差异化主链路。

## 2. 功能需求

### 2.1 阅读器布局

- FR-01 三栏：左目录（句子级定位，标题作分组行）/ 中正文（视觉重心，字号行距行宽可调）/ 右学习面板（可折叠，折叠后学习内容改为浮动卡片形态）。栏宽可拖拽并记忆，分隔条键盘可调。
- FR-02 学习内容双形态共存（用户偏好切换）：锚定弹卡（Floating UI 定位在被点内容旁）/ 右侧常驻面板（内容替换式）。两形态共用同一数据模型与加载状态机。
- FR-03 正文虚拟化渲染，段落组件按稳定 key 记忆化（key 含段落 id + 文本指纹 + 词组区间指纹 + 批注指纹 + 字号 + 开关状态），只在输入真变化时重建。

### 2.2 点读交互

- FR-04 点词：高亮 + 朗读该词 + 学习卡；点句（行号区/句边距）：高亮 + 朗读该句 + 句子面板（译文、语法、精讲入口）。点选与朗读联动作为一个动作整体变化。
- FR-05 学习卡两级模型：主卡 + 替换式速查小卡（卡内点词替换小卡自身，不叠层）；Esc 分级关闭（先小卡后主卡）。
- FR-06 学习卡首屏顺序固定：单词与原文词形 → 音标（点击可播）→ 整词发音 → 当前句核心释义 → 词性与原形；展开区：其他义项、词形变化、搭配、例句（成对含译文）、语法作用、收藏/标熟。
- FR-07 重复点击同一词/句只重新朗读，不重建面板；换句时丢弃上一句的语法分析展示。
- FR-08 词组：拖选连续词元或点击系统标记的搭配；词组点击区间盖在内部词元之上；整篇词组离线拆解（本地多词词条匹配，保留判据：含罕见词或动词+小品词，全功能词组合丢弃），标记开关默认关、关闭仅不画线仍可点。
- FR-09 右键菜单自建（`contextmenu` + preventDefault）：按对象分层（词/词组/选区 → 句子 → 通用）；跨句选区不出现"加入生词本"（按句末标点判定）；代码块只给复制。
- FR-10 选中即译：任意选区浮层出译文，带出处可转为学习目标；不写入历史。

### 2.3 双语对照与整篇能力

- FR-11 三种正文模式：仅原文 / 原文+译文 / 仅译文；切换即时生效且保持滚动位置与面板状态。
- FR-12 译文按句或按段插入，样式可配（无标记/下划线/虚线/背景块/模糊悬停显示、颜色、相对字号、粗细、换行或同行），全应用共用一份译文样式配置 + 实时预览。
- FR-13 整篇翻译：显式触发并预估消耗；从视口段落开始分批提交流式回填；按句断点续传，已完成句不重复计费；失败句单独标记重试。
- FR-14 整篇朗读：从当前句连续朗读，当前句高亮 + 自动滚动；手动滚动后暂停跟随并提供"回到朗读位置"；上一句/下一句/倍速控制。
- FR-15 批注：任意字符区间多色高亮 + 文字批注，锚定"段落 ID + 字符区间"；可筛选可导出 Markdown。

## 3. 业务规则

- BR-01 词典事实 / 上下文推断 / AI 生成三分，署名跟内容走；查不到不伪造，无结果给候选词形与说明。
- BR-02 AI 字段（语境义、语法作用、精讲）显式触发生成、按 ADR-006 落库；卡片打开时并发取回已存结果直接展示，只读结果只覆盖 AI 字段，不洗掉词典事实。
- BR-03 查词链路顺序固定：内存缓存 → 本地词典 → AI 补充；本地命中不发外网请求。
- BR-04 例句与译文成对存取，不分别截断（防静默错位）。
- BR-05 多词查询用剥掉首尾标点的原文整体（`mother-in-law` 不得拆开）；客户端不自行 percent-encode 路径参数。
- BR-06 朗读队列单例：点词/点句/整篇朗读抢同一扬声器，新请求先停旧队列，不允许多路音频重叠。
- BR-07 高亮体系分层不冲突：朗读句（底色+下划线）、选中词（底色+加粗）、批注色、词组虚线、生词标记（单一虚下划线，不为"已掌握"加第二种线型）。
- BR-08 已收藏未掌握的词正文轻标记；已标熟的词不再标记。

## 5. 验收要点

- AC-01 已缓存点词二次打开 P95 < 100ms（服务端）；本地词典即时可见，AI 字段流式后补且不闪替词典内容。
- AC-02 5000 词文章滚动流畅；点词不引起版面抖动、不丢滚动位置。
- AC-03 三种正文模式切换保持滚动位置；整篇翻译中断后续传，已译句不重复计费。
- AC-04 整篇朗读句级高亮跟随，偏差 ≤ 1 句；点词打断后旧队列停止。
- AC-05 批注在重新导入同一文章后不漂移（依赖 02 模块解析一致性）。

## 6. v10 词卡数据补全（2026-08-18）

### 起因：查库查出来的两个硬缺口

词卡的中文释义、考纲标签、词频与柯林斯星级全部来自本地 ECDICT（MIT，340 万词条）。
按词频段实测覆盖，常用词其实很扎实：

| 词频段 | 有音标 | 有英释 | 有柯林斯 |
| --- | --- | --- | --- |
| 最常用 3k | 99.4% | 99.9% | 94.6% |
| 常用 10k | 97.1% | 99.7% | 81.4% |
| 全库 340 万 | 10.4% | 5.2% | 0.4% |

长尾极薄但学习者点不到，**够用**。真正的问题是另外两条：

**① 一条例句都没有**——表里根本没这个字段。

**② 多音词只存一个音标，而且常是少数派读音。** 查库实证：

| 词 | ECDICT 存的 | 词性分布 | 问题 |
| --- | --- | --- | --- |
| `use` | `ju:s`（名词） | v:81 / n:19 | 81% 场景是动词 /juːz/ |
| `record` | `ri'kɒ:d`（动词） | n:77 / v:21 | 77% 是名词 /ˈrekɔːd/ |
| `object` `contract` `present` `produce` `refuse` `wind` `close` | 单读音 | — | 另一读音缺失 |
| `live` `lead` `tear` `bow` `minute` | `liv.laiv` / `li:d. led` | — | 两读音塞一个字段用 `.` 分隔，前端原样显示 |

音标编码也不是标准 IPA（用 `ә` 而非 `ə`，`kɒ:d` 是畸形串）。

### 需求

- FR-129 **例句**：新表 `dict_enrich` 按词缓存 dictionaryapi.dev 的结果（释义与例句源自
  Wiktionary，CC BY-SA），每词至多 6 条，带词性与该义项英文释义。查不到的词记
  `status='miss'` 负缓存，不反复打网络。
  **与 `/dict/{word}` 分成两个接口是有意的**：本地词典要瞬间出卡，补全要打外网，
  合并会让每个新词首次开卡都多等几百毫秒——前端并行拉、后到后补。
- FR-130 **多音词读音修正**：外部源给出的多个读音（标准 IPA，部分带口音标注）优先展示；
  ECDICT 的音标**仅在外部源什么都没给时**兜底——它是非标准转写，与标准 IPA 并列会让
  同一个读音出现两种写法（`live` 会同时显示 `lɪv` 和 `liv`）。ECDICT 单字段里的
  多读音按 `.` / `,` 拆分；**这套拆分规则只对 ECDICT 用**，dictionaryapi.dev 的 IPA
  拿 `.` 作音节分隔符（`/ˈtʃæl.əndʒ/`），同一规则会把一个读音劈成两半。
- FR-131 **英美双读**：卡片头部下方给「英 / 美」两个按钮。有真人录音先试录音
  （服务端落盘代理，避免外站挂掉时哑火），失败静默落回 TTS 显式音色
  （`edge:en-GB-SoniaNeural` / `edge:en-US-AriaNeural`）。
  **TTS 是主档不是兜底**：真人录音覆盖不齐（实测 challenge 只有美音、schedule 有澳音
  美音没英音），且 dictionaryapi.dev 的媒体站实测**整体 502**（challenge/schedule/
  record/hello 全部拉不到）。没有口音标注的其余读音只列不读——光给一个词无法让合成器
  挑对读法，标出来让学习者自己对照比读错强。
- FR-132 **外部查词**：底部三个跳转，只放本地词典与 AI 语境释义补不了的：
  **Linguee**（真实语料双语例句）/ **Cambridge**（学习型释义 + 英美真人发音）/
  **Google 图片**（具象词图像记忆）。
  Google 翻译、Bing、有道一律不放——它们给的东西本地和 AI 已经给了，七个彩色圆点是噪音。

### 验收与实测（2026-08-18）

| 验收 | 实测 |
| --- | --- |
| AC-06 例句 | `challenge` 3 条、`use`/`record`/`live` 各 6 条，带词性与义项释义；点例句朗读整句，句中词仍可点查 |
| AC-07 多音词 | `record` 由 1 个读音（动词）变 4 个（含名词 `ˈɹɛkɔːd` 与动词 `ɹɨˈkɔːd`）；`live` 出 `lɪv`/`laɪv`；`challenge` 不再并列 ECDICT 旧转写 |
| AC-08 双读降级 | 英音无录音 → 直接 `edge:en-GB-SoniaNeural`；美音有录音 → 先试 `/dict/challenge/audio?accent=us` → 媒体站 502 → **自动落回** `edge:en-US-AriaNeural`。降级链在真实故障下验证通过 |
| AC-09 外链 | 三个链接 `target=_blank rel="noreferrer noopener"`，URL 模板正确 |
| 质检 | ruff 全过、196 测试全绿、tsc 全绿 |

**已知未解**：`use` 这类词外部源没给音标，仍只有 ECDICT 的名词读音 `ju:s`，
而 81% 用法是动词。要彻底解决得让 LLM 按语境判读音（已有语境释义链路可挂），列为后续。

### v10.1 调整（2026-08-18，scholar 实际体验后拍板）

- **FR-131 英美双读下线**：dictionaryapi.dev 媒体站不可用导致降级链有感知延迟
  （先试真人录音失败再落 TTS），体验卡顿。UI 移除；`dict_enrich` 表、
  `/dict/{word}/enrich`、`/dict/{word}/audio` 与 `playWordAccent` 全部保留待复用。
- **FR-129 例句区下线**：AI 语境释义已按当前句给例证，Wiktionary 例句与其重复。
  数据链路同样保留。
- **FR-133b AI 语境释义带读音**：`word_explain` 输出新增 `phonetic_in_context`
  （该词在本句读法的 IPA），渲染在词性旁。这直接收掉 FR-130 的遗留——
  实测 "You can use my phone" 语境下 AI 给 **/juːz/**（ECDICT 只存名词 /juːs/），
  连 memory_hint 都自发带读音说明。旧缓存无此字段，条件渲染不回填。

## 7. v11 阅读器工具箱（2026-08-19）

> [!info] 这一版的取舍
>
> 工具栏此前只有「视图三态 + 批注 + 朗读 + 陪读」四件，其余能力散落在快捷键与右栏里，
> 用起来要靠记。本版按 Readest / Koodo Reader / foliate 的工具栏基线补齐，
> 并把最常被误伤的一条纠正过来：**翻译不再进双语就自动跑**。

### 7.1 翻译显式化（FR-374）

- FR-374a 整篇翻译只由用户点按钮触发；`翻译` 按钮的下拉里显示 `已翻译 N/M 句`。
- FR-374b `进入双语自动翻译` 开关默认 **关**；开了才恢复"进双语即翻"的旧行为。
- FR-374c 没触发过翻译的章节不轮询译文接口——显式化之后干等没有意义。
- FR-374d 翻译进行中按钮呈脉冲态，覆盖满自动收；部分已翻译时按钮角上有提示点。

> 翻译是有成本的动作，默认替用户花钱是反模式，业内阅读器一律给按钮。

### 7.2 排版与纸张（FR-375）

| 项 | 取值 | 默认 |
| --- | --- | --- |
| 字体族 | 衬线 / 无衬线 / 等宽 / 易读体（OpenDyslexic） | 衬线 |
| 字号 | 14-34 px | 19 |
| 行距 | 1.3-2.6 | 1.9 |
| 栏宽 | 520-1200 px | 760 |
| 段距 | 0.4-2.6 × | 1.0 |
| 字距 | -0.3-2 px | 0 |
| 两端对齐 | 开/关（开时自动启用连字符） | 关 |
| 纸张 | 跟随 / 纸白 / 米黄 / 护眼 / 夜间 / 高对比 | 跟随 |

- FR-375a 全部落 `prefStore.reader`，服务端整包持久化，换设备仍在。
- FR-375b 改动实时生效，不做"确定/取消"二段式；实现上走 CSS 变量，调滑杆是纯样式重算。
- FR-375c 纸张主题独立于全局深浅色；高对比纸张下点词标记与小译浮字一并提亮。

### 7.4 全局音色弹窗（FR-372~373）

- FR-372 音色选择器上收为 `components/VoicePicker.tsx`，词库场景本 / 阅读器 / 后续视频共用一个。
  调用方只给标题、当前值、试听例句；`onClear` 可选，给了才出「跟随全局设置」。
- FR-373 阅读器音色存 `prefs.reader.voice`，`null` 表示跟随配置中心的场景绑定。

### 7.7 本轮修掉的四个自造缺陷

1. **下拉开不出来**：打开下拉的那次 click 还在冒泡，`useEffect` 注册的 window listener
   立刻收到它并把刚打开的面板关掉。改为 `mousedown` + 按 `.tb-wrap` 归属判定。
2. **搜索计数与可见高亮不符**：ProseView 会跳过与标题重复的首段 heading，而搜索遍历了
   全部段落——计数 2、页面 1，且「下一个」会跳到不存在的锚点。抽出 `visibleParagraphs`
   统一口径，搜索/书签/统计共用。
3. **右键高亮静默失败**：复用了 `createAnn`，而它读的是选区工具条状态 `selTool`，
   右键路径下为空。改为独立的 `createAnnAt`，区间显式传入。
4. **小译样式被覆盖**：`.prose .w { padding: 0 1px }` 与 `.prose .w-lens` 同特异性且后加载，
   `padding-top` 被吃掉（computed 0px）。选择器提到 `.prose .w.w-lens`。

以及一条说到没做到的：快捷键表里写着「Esc 关闭浮层」，而这张表自己没接 Esc；
`J/K` 标的是「下一段/上一段」，实现却是滚固定像素。两处都按文案改到实处。
