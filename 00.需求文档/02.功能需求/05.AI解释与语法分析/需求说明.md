# AI 解释与语法分析

## 1. 模块目标

对单词给出当前句语境释义，对句子给出"谁做了什么、什么时态、哪些从句"的可理解分析与精讲；所有 AI 产物一次生成、永久缓存、显式重析，跨模块（书库/字幕/词库）共享命中。

## 2. 功能需求

### 2.1 分析类型（kind 枚举）

| kind | 输入 | 输出结构 |
| --- | --- | --- |
| word_explain | 词 + 上下文句 | 语境释义、词性判断、近义辨析、语气色彩、记忆提示 |
| grammar | 句子 | 三级结构：快速理解（主干+自然中文+难点一句话）/ 结构展开（成分、从句修饰关系、时态语态）/ 深度解释（歧义候选、相似句型、可替换表达、常见错误） |
| sentence_deep | 句子 | 精讲：逐块翻译对照、搭配与固定结构、文化背景 |
| phrase_explain | 词组 + 上下文 | 整体含义、字面与引申、使用场景 |
| summary | 整篇/章节 | 摘要、难度评估、核心词汇表 |

### 2.2 交互与展示

- FR-01 AI 分析必须显式触发（点按钮），不随点词自动调用；已有缓存则打开时直接展示，无需再点。
- FR-02 生成过程流式展示（SSE），可中途取消；结构化字段完整后校验落库。
- FR-03 "重新分析"常驻弱化按钮：新建版本并置为当前；可选切换模型后重析（不同模型结果并存可对比）。
- FR-04 语法分析结果与原文词元关联：点击分析中的成分标注定位回原文片段。
- FR-05 歧义句给候选解释而非唯一答案，措辞用"可能/候选"。
- FR-06 AI 陪读快捷提问（见 07 模块）产生的解释同样落库，与点按生成共享缓存。

## 3. 业务规则

- BR-01 持久化寻址遵循 ADR-006：`(scope, content_hash, context_hash, kind, provider, lang_pair)`；缓存命中费用记 0 并标 `cached=true`。
- BR-02 读写端点分离：GET 只读未命中 404 不触发生成，POST 才生成——防止"浏览时看看分析过没有"变成每次付费。
- BR-03 LLM 输出必须过 JSON Schema 校验，失败自动重试一次，仍失败进"部分成功"状态并保留原始文本输出。
- BR-04 AI 结果只覆盖 AI 字段，不写回词典事实层；与词典冲突时并列展示不静默覆盖。
- BR-05 用户修改原文（文章重导入）后旧分析按内容指纹自然失效（hash 不再匹配），不需要主动清理。
- BR-06 每种分析 kind 可单独绑定 LLM 别名（翻译要快、语法要守 schema、精讲要强模型）；绑定失效退回默认别名但保留绑定配置。
- BR-07 分析用的 prompt 模板版本化入库，结果记录 prompt 版本 + 模型名，可解释可回溯。

## 4. 实现方案

| 部件 | 方案 | 说明 |
| --- | --- | --- |
| 结构化输出 | LLM JSON mode / tool-call 强制 schema，Pydantic 校验 | 语法分析 schema 按三级展示结构定义 |
| 流式 | FastAPI SSE，前端边收边渲染，完整后整体校验入库 | 流式展示与结构化落库分离：流式给用户看，落库存校验后的结构 |
| 路由 | LiteLLM 语义别名：`explain-standard`（词/词组）、`grammar-deep`（语法/精讲）、`summary-long`（整篇） | ADR-004 |
| 辅助校验 | spaCy 词性/依存作为交叉参考（可选，标注分歧不裁决） | - |
| Prompt 参考 | Easydict/沉浸式翻译的词典式 prompt 结构 | 参考其字段组织 |

## 5. 验收要点

- AC-01 同一句语法分析第二次打开直接展示（P95 < 100ms），用量记录 cached=true 费用 0。
- AC-02 换模型重析后两个版本可切换查看；当前版本标识明确。
- AC-03 schema 校验失败时用户看到原始文本输出 + "结构化失败"标识，不看到空白卡。
- AC-04 书里某句分析过，同句出现在字幕中点击直接命中缓存。
