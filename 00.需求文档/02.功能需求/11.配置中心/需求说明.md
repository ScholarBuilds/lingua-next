# 配置中心

## 1. 模块目标

把项目中一切可配置项收拢到一个设计精良的设置中心：供应商凭据全部入库（加密）、上游模型/音色动态拉取、能力与场景的默认绑定可视化管理。当前单用户，但数据模型按"未来每个用户配自己的密钥"设计（本期不做用户体系）。**开发期不留兼容代码**：.env 密钥路径迁移入库后移除。

## 2. 信息架构（设置页左侧子导航，6 类）

| 分类 | 内容 |
| --- | --- |
| **模型服务** | LLM 供应商凭据 CRUD（官方/OpenAI 兼容/Ollama）、动态拉取上游模型列表、五个能力别名绑定（含 fallback 链）、能力测试 |
| **语音服务** | TTS 供应商凭据（火山/edge/Azure/OpenAI/Kokoro）、音色目录动态刷新与试听、五个朗读场景默认音色绑定；实时语音凭据（火山 AppID/AccessKey）与会话参数；ASR 档位（whisper 模型） |
| **翻译引擎** | 引擎启停与优先级排序（拖拽）、默认引擎、各引擎凭据（DeepL 官方/有道智云预留位） |
| **阅读与外观** | 现散落 localStorage 的偏好服务端化：主题三态、阅读排版、跟随滚动、右栏点词、自动发音、看板娘（开关/模型/位置）、双语译文样式 |
| **用量与预算** | 现有 /settings 用量双视图与预算迁入本分类 |
| **数据管理** | 学习资产导出（CSV/Anki/JSON）、缓存清理（TTS 音频/分析缓存统计与清理）、词典重导入口 |

## 3. 核心数据模型（本项目 PostgreSQL，凭据加密）

```
provider_credential                      -- 供应商凭据（未来加 user_id 即多用户）
├── id, name(用户命名，如"DeepSeek 官方")
├── kind          -- llm | tts | realtime | translate | asr
├── provider_type -- deepseek | openai | openai_compatible | ollama | volc_speech | edge_tts
│                    | azure_speech | openai_tts | kokoro | google_web | deepl | youdao ...
├── config JSONB  -- {api_base?, api_key※, app_id?, access_key※, region? ...} ※字段 Fernet 加密存储
├── enabled, status(untested|ok|failed), status_detail, last_tested_at
├── models_cache JSONB   -- 最近一次拉取的上游模型/音色列表 + 拉取时间
└── created_at, updated_at

capability_binding                        -- 能力/场景 → 凭据+模型/音色
├── id, capability   -- llm: translate-fast|explain-standard|grammar-deep|companion|summary
│                    -- tts: tts-word|tts-sentence|tts-chapter|tts-vocab|tts-video
│                    -- realtime: realtime-voice · translate: translate-chain(JSONB 存序)
├── credential_id FK, target(模型名或音色 id), params JSONB(语速/温度等)
├── fallback JSONB   -- [{credential_id, target}] 有序降级链
└── updated_at

user_pref(key unique, value JSONB)        -- 阅读与外观偏好（前端读服务端，localStorage 仅离线缓存）
```

**执行层职责不变**：LLM 仍经 LiteLLM 网关执行（STD-AI-001）——本库是唯一事实源，保存绑定时经管理 API 同步到 LiteLLM；TTS/实时语音/翻译适配器改为从凭据库读取（替换 server/.env 路径）。加密密钥 `LINGUA_CONFIG_KEY` 走环境变量（基础设施密钥，不入库）。

## 4. 功能需求

### 4.1 供应商凭据（FR-01~06）
- FR-01 凭据 CRUD：按 kind 分区展示卡片（名称、类型 logo、掩码密钥 `sk-53…{尾4}`、启用开关、状态点）；新增走类型选择器（预置类型带说明与所需字段表单，"OpenAI 兼容"只需 base+key）。
- FR-02 **动态拉取**：LLM 凭据"刷新模型"调上游 `/v1/models` 缓存展示（数量+时间）；火山/edge/Azure TTS"刷新音色"拉全量音色目录（名称/语种/性别/试听）。
- FR-03 连通测试：真实小请求探测，结果分型（连接失败/密钥无效/超时/正常+延迟），状态与时间落库。
- FR-04 密钥安全：入库 Fernet 加密；任何 API 响应只回掩码；编辑时留空=不修改。
- FR-05 停用凭据时提示受影响的绑定清单；有绑定引用时删除需二次确认并给出改绑引导。
- FR-06 一次性迁移种子：现 LiteLLM 内三别名的凭据、server/.env 火山键、新 DeepSeek 官方 key 首启导入。

### 4.2 能力绑定（FR-07~10）
- FR-07 LLM 五能力绑定矩阵：每行 = 能力（中文说明+用途）→ 凭据下拉 → 模型下拉（来自该凭据 models_cache，可手填）→ 高级参数（温度/reasoning_effort 开关）→ 测一下（真实调用含 schema 校验，展示延迟+样例）。
- FR-08 fallback 链：每能力可加多级降级（拖拽排序）。
- FR-09 TTS 五场景绑定：查词/句子/整篇/背单词/视频字幕各自默认音色（凭据+音色+语速），试听按钮；**朗读处仍可临时切换，但默认取此处配置**。
- FR-10 翻译链配置：引擎卡片启停 + 拖拽排序即降级顺序；实时语音参数（最长时长/空闲超时/难度默认）。

### 4.3 偏好与迁移（FR-11~13）
- FR-11 阅读与外观偏好服务端化（user_pref），前端启动拉取、变更即保存；localStorage 仅作离线兜底。
- FR-12 用量预算、数据管理迁入对应分类（复用现有接口）。
- FR-13 移除 .env 密钥读取与旧 /llm 直连 LiteLLM 的散配置路径（不留兼容层）。

## 5. 业务规则

- BR-01 绑定保存即生效（LiteLLM 同步/适配器热读），失败回滚并报因。
- BR-02 每个能力必须始终有一个有效绑定：改绑失败不清空旧绑定；凭据停用后该能力自动走 fallback，无 fallback 则标红警示。
- BR-03 探测一律真实请求（继承 BR-MEDIASVC-007）；模型/音色列表过期（>7 天）UI 提示可刷新，不自动轮询。
- BR-04 配置变更写审计行（改了什么、旧值摘要、时间），设置页可见最近 20 条。
- BR-05 前端任何位置的"临时切换"（如朗读音色）只影响本次会话，不写回默认配置。
- FR-14 全局默认对话模型（`default-llm`，CR-022）：模型服务页最上面一张卡设「平时用哪个模型」，
  八条 LLM 用途默认跟随它，按用途单独指定收进折叠区，标题上写清有几个是单独指定的。
  「改回跟随默认」经 `DELETE /config/bindings/{capability}`。
- FR-15 换模型弹窗全产品统一（`ModelPicker`，CR-022）：按厂商分组（判据只认模型名前缀，
  不认 `provider_type`——同一个中转后面挂着六家的模型）、组内新版本在前、非对话模型单列折叠、
  搜索同时匹配模型名 / 厂商 / 账号、↑↓ 与回车全流程、底部一档「跟随全局默认」并显示它当前的真名。
- FR-16 使用处换模型（CR-022）：词卡 AI 释义、工坊对话与出图、修复代理都能临时换模型，
  只影响这一次调用，界面上标「临时换的」，一键回到跟随。
- BR-06 全局默认只在一条能力**自己没有主部署**时参与解析。绑了模型但那条部署停用了照旧报错，
  不把配置事故静默换成另一个模型出结果。
- BR-07 使用处换模型绝不写回绑定；`deployment_id` 必须进缓存寻址，否则换了模型仍命中旧结果而接口 200。
- BR-08 「模型」位一律显示上游真名；要同时说清能力就写 `<中文能力名> · <真实模型名>`，
  路由键（`chat-general` / `explain-standard`）不许露给用户。

## 6. 开源参考与实现基座

| 部件 | 方案 |
| --- | --- |
| UI 形态 | **LobeChat 供应商设置页**（业内最佳参考：凭据卡+启用开关+动态模型获取+检查按钮）；Cherry Studio / Open WebUI 同型佐证 |
| 表单 | react-hook-form + zod（既定选型），凭据类型 schema 驱动动态表单 |
| 加密 | cryptography.Fernet（Python 标准方案） |
| LLM 执行 | LiteLLM 网关不变，凭据库→管理 API 单向同步 |
| 拖拽排序 | dnd-kit（MIT，业内默认） |

## 7. 验收要点

- AC-01 新增 DeepSeek 官方凭据→刷新出模型列表→把 translate-fast 绑到 deepseek-chat→测一下通过→阅读器句子翻译立即走新绑定（全程不碰终端）。
- AC-02 火山 TTS 凭据刷新出全量音色→试听→把"整篇朗读"默认音色改为另一音色→阅读器整章连读生效；朗读条临时换音色不影响默认。
- AC-03 停用某凭据→受影响能力自动降级并在设置页警示。
- AC-04 重启全栈后所有配置仍生效（.env 中已无业务密钥）。
- AC-05 审计列表可见最近变更。
- AC-06 模型服务页设一次全局默认→把「快速翻译」改为跟随→运行时解析出的正是默认那条模型
  （台账 `source=default`）；把默认那条部署停用→「快速翻译」报「模型部署已停用」而不是换一个模型出结果。
- AC-07 词卡上把这次分析换成另一家的模型→真的重算并显示新模型真名与「临时换的」→点「跟随全局默认」
  回到绑定模型并命中原缓存槽；设置页的绑定全程未变。
