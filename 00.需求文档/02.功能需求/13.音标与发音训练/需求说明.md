# 音标与发音训练

## 1. 模块目标

把「读不准」这件事从模糊的自我感觉变成可定位、可训练、可复查的具体音位。

两条腿：**输入侧**用最小对立对听辨重塑音位范畴（听得出才可能读得对），**输出侧**用声学模型给出词级与音素级诊断。两侧共用同一套音位卡片与 FSRS 调度。

> [!warning] 这个模块的精度天花板要先说清楚
>
> 词级误读标注的 precision 约 **20%**（五个红标里四个是误报），recall 约 70%；
> 训练过的 SOTA 系统在音素级的 PCC 天花板是 **0.612**，句子级 0.742；
> 开源最强英文 IPA 音素模型在带口音语音上的 PER 约 **19%**。
>
> 这不是实现得好不好的问题，是这个粒度本身就不可靠。**所有 UI 分寸由此推导**（见 §6）。

## 2. 现状盘点（2026-08-19 核实）

| 已有 | 状态 |
| --- | --- |
| ECDICT 音标 | 353,134 条，但 **28% 含西里尔字符**（schwa 写成 `ә` U+04D9 而非 `ə` U+0259），34% 用 DJ 冒号长音、仅 4% 用 IPA `ː`；抽查 20 个 th- 词有 1 处真错（`this → θis`） |
| ctc-forced-aligner | 每词已输出 `score`，但现有代码只取时间戳丢掉了它 |
| 火山豆包 TTS + Edge TTS | 可用，Edge 有 22 个英文音色 |
| 跟读工作台 | 录音、词级 diff、AI 流式点评、历史记录已完整（模块 09） |
| FSRS 调度器 | `domain/srs.py` 已用于单词 |
| 真人录音链路 | `dict_enrich`（dictionaryapi.dev → Wikimedia Commons），TTS 兜底 |

**缺口**：无音素级数据、无最小对立对词表、无音位教学内容、无发音评分。

> [!note] 一条实测数据
>
> 用库里那条真实跟读录音（accuracy 90%）实测 `ctc-forced-aligner` 的 score：
> 对齐**正确文本**归一化均值 **−0.661**，对齐**无关文本** **−1.825**，差 2.8 倍。
> 而正确文本里分数最低的 `challenge`、`failure`，正对应那 10% 没读对的部分。
> **词级发音置信度几乎零成本可得**——只要不丢那个字段。
>
> 注意 `score` 是区间求和不是均值，长词天然高分，**必须按帧数归一化**才能当质量分用。

## 3. 数据地基（FR-390）

### 3.1 不修 ECDICT，新建 word_phoneme 表

35.3 万条 IPA/DJ 混排，清洗性价比为负。已验证归一化的边界：

| 转换 | 可靠性 |
| --- | --- |
| 西里尔 `ә`→`ə`、`є`→`ɛ` | ✅ 无损 |
| DJ 冒号 `:`→`ː`、重音 `'`→`ˈ` | ✅ 无损 |
| DJ 元音体系 → IPA | ❌ **有歧义**：`in` 该是 `ɪn`，而 `bi:` 里同一个 `i` 是长音，同字符两个音，简单替换必错 |

- FR-390a 新建 `word_phoneme(word, ipa_us, ipa_uk, arpabet, syllables, stress, source)`。
- FR-390b 主档取 **ipa-dict**（MIT，en_US 12.6 万条，单一 IPA 记法，无需自写映射表）。
- FR-390c 重音与音节数取 **CMUdict**（BSD-2，ARPAbet 带重音数字 `AA1/AA0`）——这一列顺手就是「音节重音」题库。
- FR-390d 英音列取 ipa-dict 的 `en_UK`（CMUdict 只有美音）。
- FR-390e OOV 用 **g2p_en**（Apache-2.0，纯 Python 无 GPU）兜底，`source='g2p'` 标注来源。
- FR-390f ECDICT 的 `phonetic` 降级为兜底展示，主展示改读新表；现有 `split_ecdict_phonetic()` 不动（它处理的是老数据）。

> [!danger] 展示链路与评测链路必须用不同的音素体系
>
> 这不是冲突，是分工：
>
> - **展示**（音标学习）用 ipa-dict / CMUdict —— 自主可控、避开 GPL
> - **评测**（发音打分）必须用 **espeak-ng** 生成参考序列 —— 因为音素识别模型就是
>   espeak G2P 训练的，符号体系不同源会造成**系统性误报**
>
> 两条链路各自成立，不要试图统一成一套。

### 3.2 中国学习者难点：算出来，不抄清单

- FR-391 下载 **speechocean762**（CC BY 4.0，OpenSLR 101），**只解析标注文件不跑音频**，
  统计每个音素的低分率，生成 `phoneme_difficulty` 表。

该数据集说话人**全部是普通话母语者**（125 成人 + 125 儿童），带逐音素 0/1/2 专家标注，
与本项目用户画像正好对口。这张表驱动出题顺序与「薄弱音位雷达图」，是本模块的差异化点。

## 4. 音位卡片（FR-392）

- FR-392a 44 个英语音位手写一份 JSON：符号 / 发音部位 / 发音方法 / 例词 ×3 / 常见错读 / 剖面图文件名。
- FR-392b 总览页按 IPA 官方图表排布（元音四边形：横轴唇形、纵轴开口度），署名 CC BY-SA 4.0。
  44 个格子自绘比引任何组件都快，没有值得引入的开源件。
- FR-392c 辅音配 **drammock/phonetics-teaching-assets** 的中矢面 SVG（**CC0-1.0**，公共领域无署名义务，
  51 个文件）。缺 `/l/ /w/ /tʃ/ /dʒ/`，其中 l 和 w 恰是中国学习者痛点，需自己补画。
- FR-392d 元音**不用剖面图**，用 IPA 元音四边形上的定位点——元音本来就不该用剖面表达。
- FR-392e 例词发音复用现有 `dict_enrich`（真人录音优先、TTS 兜底），这条链路已在跑，一行不用改。
- FR-392f 关键发音部位（舌尖 / 舌背 / 软腭）加 CSS class 上色高亮——这是 Mayer 的 signaling 原则，
  比任何动画都便宜且有效。
- FR-392g **例词按音素在词中的位置分组**：词首 / 词中 / 词尾各给 1-2 个。
  同一个音素在不同位置的发音难度不同（`/l/` 的 light L 与 dark L、词尾浊辅音清化），
  合成一组会把这个区别抹掉。这条抄 iSpeakerReact 的音素页组织方式。

### 4.1 示范音频的音素级时间戳（离线，FR-392h）

要做「例词播放时逐音素高亮」，需要音素级时间边界。这件事**是离线一次性的**，
不进运行时链路，所以对工具的约束完全不同：

- FR-392h 用 **Montreal Forced Aligner**（MIT）在内容生产期为示范音频生成 word/phone 边界，
  产物落库；运行时只读时间戳，不跑对齐。
- conda 安装的代价在离线脚本里可以接受（不必进 api 镜像），MFA 纯 CPU 且极快
  （Buckeye 上 RTF 52–194× 实时）。
- **它的定位是对齐不是评分**——不要拿它的对齐置信度当发音分用。

> [!note] 这条修正了本文档 §9 的一项排除
>
> 初稿把 MFA 整个排除掉了，理由是「conda 装、只给 TextGrid 不给音素后验」。
> 那个理由只对**运行时评测**成立；离线内容生产恰恰只需要 TextGrid，而且不在乎装机成本。
> 排除的粒度错了，现改为「不进运行时链路，可用于离线内容生产」。

## 5. 听辨训练（FR-393）

### 5.1 题型：identification，不是 discrimination

> [!info] 元分析给出的效应量差距
>
> **identification**（听一个音，从两个词里选）**g = .95**
> **discrimination**（判断两词是否相同）**g = .57**
>
> 主力题型只做前者。

- FR-393a 二选一强制选择，逐题即时对错反馈。
- FR-393b 答错时并排回放两个词、高亮 IPA 串里不同的那一位、弹出对应剖面图。
- FR-393c 词对由 `pronouncing`（BSD-3，CMUdict 封装）离线跑音素编辑距离 = 1 生成，
  落 `minimal_pair` 表，再用 ECDICT 已有的 `bnc`/`frq` 字段过滤到高频词。
- FR-393d 按对比组分桶：`θ/s`、`θ/f`、`ð/d`、`ð/z`、`v/w`、`l/n`、`n/ŋ`、`s/ʃ`、
  `iː/ɪ`、`æ/e`、`æ/ʌ`、`ɒ/ɔː`、词尾 `s/z`。
- FR-393e **高变异是 HVPT 的核心**：每题从 edge-tts 的 22 个英文音色里随机抽 ≥6 个，重点词用豆包 TTS 出高质量版。
- FR-393f 调度直接接现有 FSRS：把「对比组 × 音位」当 card，答错降 ease，**不为音标另写一套**。

### 5.2 结业进度条

- FR-394 元分析显示总训练 **400 分钟**后收益趋平。把它做成模块的结业进度条，
  比无限刷题诚实，也给用户一个「练到什么时候算完」的答案。

> [!tip] 题型不在本模块自研
>
> 听辨题、看音标选词等所有练习题走
> [组件：练习引擎](../../../01.项目文档/02.架构/C4模型/组件-练习引擎.md)——
> 题目 Schema、Widget 注册、评分与渲染分离由那一层统一提供，本模块只出内容与判分规则。

### 5.3 其余题型

| 编号 | 题型 | 说明 |
| --- | --- | --- |
| FR-395 | 看音标选词 / 看词选音标 | 数据就是 `word_phoneme`，零额外成本；练的是「音标符号认读」，这是国内学习者的实际短板，听辨题练不到 |

## 6. 发音评测（FR-398）

> [!warning] 第 1/2 层（音素识别 + GOP）已于 2026-08-30 下线
>
> **状态**：FR-398d/e/f/g、FR-398i、FR-399a~c 作废；FR-398a~c（第 0 层）与 FR-398j（LLM 叙述）在线。
> BR-90 与 BR-91 随之失去约束对象，BR-92 仍生效（第 0 层的词级 score 照样按帧数归一化）。
>
> **原因**：把本地推理外包给 API。ASR 换成了火山大模型录音文件识别，
> 强制对齐（CTC / MMS-300M）保留，而音素后验**没有对应上游**——
> 任何 ASR API 都不返回逐帧音素概率，而 §6.6 那个校准模型的 31 个特征
> （`gop_*` / `top1_*` / `margin_p10` / `entropy_mean` / `per` / `sub_del_ins_rate`）
> 几乎全建在它上面，换供应商等于整层重做，不是换个 provider 的事。
>
> **代价，如实记**：ρ(accuracy)=0.687（按说话人聚类自助 CI [0.626, 0.741]），
> 高于专家 vs 同行共识的人类天花板 0.651。这个分数是真的被放弃了。
> 现在 `accuracy` 退回词级 CTC 置信度均值，未经人工标注校准，只能自己跟自己比。
>
> **存档**：`归档/2026-08-30-发音评分模型下线/`（`calibration.json`、`phoneme_asr.py`、
> `pron_features.py`、两个校准脚本，以及 `phoneme_ipa/` `phoneme_demo/` 的 tar——
> 后两者不在 git 里且不可再生）。要接回来需重下 speechocean762 约 500MB
> 并重跑约 45 分钟特征抽取。
>
> 下面 §6.2/§6.3/§6.5/§6.6 保留原文作为决策依据，不再是待办。

每层都能独立上线。

### 6.1 第 0 层 · 零新依赖

Azure 的四维里 **Completeness 与 Fluency 不需要发音模型**：

- FR-398a 完整度 = 已有 `diff_words` 的词级比对（漏读/多读词数比）。
- FR-398b 流利度 = `ctc-forced-aligner` 已产出的词级时间戳算停顿分布。
- FR-398c 停顿落在从句边界是正常，落在名词短语中间是 `UnexpectedBreak`，
  该有的边界停顿缺失是 `MissingBreak`（依赖模块 14 引入的 spaCy）。

这两维的信号质量**比音素级高得多**（句子级 PCC 0.742 vs 音素级 0.612），却一行模型代码都不用写。
先做这层，它单独就能让跟读从「AI 写段评语」升级为「有结构的诊断」。

### 6.2 第 1 层 · 音素识别

新增件只有两样：

| 件 | 规格 |
| --- | --- |
| `onnx-community/wav2vec2-lv-60-espeak-cv-ft-ONNX` 的 `model_int8.onnx` | **318 MB**，Apache-2.0，391-token IPA 词表 |
| Docker 里 `apt-get install espeak-ng` | 生成参考音素序列 |

- FR-398d 与已跑通的 MMS-300M **完全同架构**（wav2vec2-large，`inputs_to_logits_ratio=320`），
  单例加载照抄 `domain/alignment.py` 的 `_get_aligner` 模式。
- FR-398e 参考侧在句子导入期用 phonemizer/espeak 预生成 IPA 落库，运行时零开销。
- FR-398f 比对用 Needleman-Wunsch，替换代价按发音特征距离加权（送气/清浊/元音松紧），
  不用等权编辑距离。这段逻辑抄 **OpenPronounce**（MIT）的置信度调整规则。
- FR-398g 多语言词表含其他语言声调标记，英文推理时要把非英文 token 从 argmax 候选里屏蔽，
  否则会出现 `i1`/`i5` 之类的伪音素。

延迟按 ADR-007 实测的 RTF 0.215 估算：5 秒录音约 1 秒（M1）/ 2-4 秒（x86 单核）。

### 6.3 第 2 层 · 真 GOP

最划算的一步。`get_alignments(emissions, tokens, tokenizer)` 的词表来自 `tokenizer.get_vocab()`，
**把 IPA 模型的 tokenizer 传进去就能对参考音素做强制对齐**，无需改库代码。

- FR-398h `GOP(p) = log P(p|frames) − max_q log P(q|frames)`。emissions 已是 log_softmax，
  帧区间由对齐给出，实现约 50 行。
- FR-398i 第 1 层给「说成了什么」，第 2 层给「说得有多不确定」，两个信号交叉验证压低误报。

### 6.4 第 3 层 · LLM 叙述

- FR-398j **不让 LLM 打分**。分数由前三层的确定性算法给，LLM 只负责把 `/ɪ/` vs `/iː/`
  翻译成「你把 ship 读成了 sheep，舌位放松、别拖长」，并关联到对应音位卡片。
- FR-398k 评分与叙述分离，评分才可回归测试。

### 6.5 编排参考

四层跑起来之后是多个模型并行（音素识别、Whisper 转写、音高、韵律），
编排形状可参考 [PronounceAI](https://github.com/vikranthreddimasu/PronounceAI)（MIT，Python/FastAPI）：
`pipeline.py` 做并行调度 + 缓存 + 预热 + 降级，`fusion.py` 把音素准确度、语调、节奏、
元音质量分维度算再融合。技术栈与本项目一致，是目前找到的最贴近的全栈实现。

> [!danger] 这个项目 ★0，只抄结构不抄数值
>
> 零社区验证（2026-05-13 最后推送）。可以看它怎么组织并行推理与结果结构，但：
>
> - GOP 阈值是经验值，必须用 speechocean762 自己标定（§6.5 校准）
> - 综合评分权重是它的产品选择，不是通用结论
> - **对齐失败后均匀切分音频的降级方式不能用于正式评分**——那会产出看起来正常实则无意义的分数
> - 它自己的评测目录也自我定位为轻量检查，不是公开基准

### 6.6 校准

- FR-399a 从 speechocean762 抽 200-500 条带专家分的语料拟合评分映射系数
  （OpenPronounce 用 500 条拟合出 ρ=0.65，这是可复现的锚点）。
- FR-399b 可用 Azure 免费层（每月 5 小时音频，约 3600 句/5 秒）跑 100-200 条自己的录音做一次交叉校准，
  之后不再依赖。
- FR-399c **跳过校准，打分就是玄学**——这一步不是可选项。

## 9. 明确不做

| 不做 | 理由 |
| --- | --- |
| **WebGL / 3D 口腔舌位建模** | Massaro & Light (2003) 实验：11 名日语母语者练 /r/-/l/，「透明脸看舌头」相对普通正面视图**无显著优势**。three.js 178.5 KB gzip 是 wavesurfer 的 15 倍，花 15 倍 bundle 买一个已发表的 null result |
| **SVG path morph 补间** | 51 张 CC0 图 path 结构不一致，morph 要重画全部资产；Höffler & Leutner 的 d=0.37 来自**表征性动画 + 程序性知识**，不是补间平滑度。一个音配 2-3 张图做离散切换就吃到了这个效应 |
| 自研 GOP 声学模型 / Kaldi 路线 | 无 GPU 单机上要编译 Kaldi + 训 DNN 对齐模型，工程量是整个模块的数倍 |
| 自己训练或微调发音评测模型 | wav2vec2 微调需 GPU-days |
| 清洗 ECDICT 的 phonetic 字段 | 35.3 万条混排，性价比为负，见 §3.1 |
| Montreal Forced Aligner **进运行时评测链路** | 只能 conda 装、塞进现有镜像代价大，且给的是 TextGrid 边界不是音素后验（算 GOP 还得再接 Kaldi）。**但它可以用在离线内容生产**，见 §4.1 |

> [!note] 「不做动画」不等于「不要动画」
>
> Mayer 的 coherence 原则与 Rey (2012) 元分析说明：与教学目标无关的炫技视觉对记忆有小到中等**负效应**、
> 对迁移有中等负效应。**炫技是负分不是零分**。该做的动画（离散切换的发音步骤）要做，
> 不该做的（3D 实时口腔）一帧都不做。

### 14.2 两处需求与现实不符

**ð/z 的最小对立对数量是语言事实，不是实现问题。**
按初版的词频门槛（两词都在 COCA 前 6 万）只能生成 **14 组**——breathe/breeze、
clothing/closing、seethe/seize、with/whiz 那一批就是英语里全部的常用 ð/z 对立对。
处理方式是给对比组加 `scarce` 标记，含该音素的词放宽词频门槛（放宽只对这一组生效），
拿到 37 组。**没有靠降低 AC 标准来"达标"**，也没有把不相干的词凑进去。

**第 1 层实际用 fp32 而不是 int8。**
§8 的实现方案表写 ONNX int8（318MB）。实测 fp32（1.26GB）与 int8 **同速**
（RTF 0.11，M1，5 秒音频约 0.55 秒）且解码结果一致——既然不快，就没有理由用有损版本。
代码优先加载 `model.onnx`，只下了 int8 时照样能跑。

| 环节 | 耗时 | 备注 |
| --- | --- | --- |

### 14.4 校准：它当场推翻了第一版的准确度算法

`scripts/calibrate_pronunciation.py` 拿 speechocean762 测试集跑完整链路，
输出各维度 Spearman ρ 与线性映射系数，落 `data/phonetics/calibration.json`。

**第一轮（300 条）的结果是坏消息**：

| 维度 | ρ |
| --- | --- |
| accuracy | **0.246** |
| fluency | 0.521 |

对照锚点 OpenPronounce 的 0.65 差得远。按 FR-399c 的原则，这时该改**特征**不该改常数。
拆开看两个信号才发现问题在哪：

| 信号 | ρ（seed 42 / seed 99） |
| --- | --- |
| 仅 CTC 对齐置信度 | 0.154 / 0.229 |
| 仅 GOP 均值 | **0.591 / 0.608** |

第一版的 accuracy 只用了 CTC 对齐置信度——**那个量衡量的是「音频与参考文本对不对得上」，
不是「每个音读得有多像」**。后者是 GOP 的事，而第 2 层早就把 GOP 算出来了，只是没用进分数里。

改用 GOP 后 ρ 升到 0.59。中间试过 GOP 0.65 / 0.79 两档加权融合，
两轮里**融合分都低于单用 GOP**（0.572 vs 0.591、0.595 vs 0.608），
所以句子级准确度最终只用 GOP；CTC 留在它确实有用的两处——
词级置信度展示与音素级提示的交叉验证（FR-398i）。

四轮实测全记录（每次权重改动都有对应的这一行）：

| 轮次 | 样本 | 仅 CTC | 仅 GOP | 上线口径 |
| --- | --- | --- | --- | --- |
| 初版（只用 CTC） | seed 42 / 300 | — | — | **0.246** |
| 融合 GOP 0.65 | seed 42 / 150 | 0.154 | 0.591 | 0.572 |
| 融合 GOP 0.79（留出验证） | seed 99 / 150 | 0.229 | 0.608 | 0.595 |
| **仅 GOP（当前上线）** | seed 42 / 200 | 0.258 | 0.588 | **0.586** |

对照 OpenPronounce 的 0.65（500 条）仍有差距，但 0.246 → 0.586 这一段**全部来自换特征，
一个常数都没调**。差距要继续缩，方向是给 GOP 加特征（音素时长、重音位置），不是改系数。

### 14.4.1 第二轮：全量校准把 ρ 推到 0.687

第一轮结束时留下的方向是「给 GOP 加特征，不是改系数」。第二轮照着做，
全量 2500/2500 条、跨说话人评估，结果：

| | ρ(accuracy) | 说明 |
| --- | --- | --- |
| 首版（仅 CTC 置信度） | 0.246 | 特征选错了 |
| 第一轮（仅 GOP，n=200） | 0.586 | 换特征，一个常数没调 |
| **第二轮上线口径（n=2500）** | **0.687** | 95% CI [0.626, 0.741]（按说话人自助） |

参照系有两个，第二个才是有意义的那个：

- 标签并列给的 ρ 天花板是 0.959，达成 72%
- **单个人类专家预测另外四人的共识只有 ρ=0.651**——模型已经在人的水平上

第二个数是自己算的：官方论文只写「五位专家独立打分」没报一致性，
但每位专家的原始分随数据集发在 `resource/scores-detail.json` 里。
取单个专家 vs **不含他自己**的四人共识，正是模型所处的位置
（拿专家 vs 发布标签会虚高到 0.71-0.76，因为他自己就在标签里）。
`calibrate_pronunciation.py --report` 里的 `human_ceiling` 字段记着这组数。

#### 加了什么特征

| 特征组 | 单独的 ρ | 为什么它带新信息 |
| --- | --- | --- |
| 归一化 GOP | 0.592 | /θ/ 的 GOP 天然比 /ɑː/ 低，绝对阈值把「音素难」判成「读得差」。按音素做 z 分数把身份从质量里剥出来 |
| 帧级后验（top1/margin/entropy） | 0.573 | GOP 只看最强的一个竞争者；这组看整个竞争格局 |
| 自由解码编辑距离（PER/替换率） | 0.573 | GOP 走强制对齐问「按这个文本对齐后每个音多像」，这组走自由解码问「不告诉它文本，它听成了什么」。两条路独立 |
| 时长 | 0.487 | 长短元音不分、词尾吞音、辅音簇加音 |
| 重音 | 0.106 | **不进模型**，见 §14.4.2 |

全量消融（test，n=2500）：

| 特征组 | ρ(accuracy) |
| --- | --- |
| 仅 GOP | 0.555 |
| 仅归一化 GOP | 0.592 |
| 仅词模型聚合 | 0.625 |
| GOP + 时长 | 0.633 |
| GOP + 时长 + 形态 | 0.643 |
| **上线口径（去重音）** | **0.687** |

三级模型各自的成绩要配天花板看，否则会误读：

| 级 | 样本 | ρ | 并列上限 | 达成 |
| --- | --- | --- | --- | --- |
| 音素 | 35,674 | 0.371 | 0.677 | 55% |
| 词 | 13,102 | 0.379 | 0.522 | 73% |
| 句 | 2,500 | 0.687 | 0.959 | 72% |

词级 82-89% 的标注是满分，并列把它的上限压到 0.522——「词级 0.379」不是比句级差一半。

#### 走过的三个弯路

**`lpp` 加了等于没加**。参考音素的平均对数后验 = `gop + conf`，
线性模型自己就能凑出来。真正独立的是 top1 计数、逐帧裕度、后验熵这类非线性量。

**帧级统计不排除 CTC blank，量到的是「峰有多尖」**。CTC 把 token 压在 1-2 个峰值帧上，
铺满区间里多数帧的最优是 `<pad>`。首版没排除，一个读得完全正确的 7 帧元音也只有
1/7 的帧「认对」，竞争者恒为 `<pad>`——这个量随语速和峰型漂移，与发音质量无关。

**抽取按 `wav.scp` 顺序截断 = 只拿到好学生**。它按说话人排序，中途停掉的运行
只覆盖前几十个人，而那批人恰好偏好：截断子集里 accuracy ≤5 只占 1.7%，全量是 13.8%。
在这种子集上统计基准表、拟合权重、报 ρ 全都是偏的。现已加固定种子 shuffle。

#### 三处方法学修正

| 问题 | 后果 | 修法 |
| --- | --- | --- |
| 在 test 上挑 alpha 与模型形态，再报同一个 test 的 ρ | 报出来的是**挑出来的**数 | 选型移到从 train 按说话人切出的验证集，test 只在最后跑一次 |
| Fisher-z 置信区间假设 2500 条独立 | 125 人 × 每人 20 句强聚类，区间窄了 **2.8 倍** | 改按说话人自助 600 次 |
| 折外堆叠按列表跨步分折 | 同一人的语料散进所有折，「留出」从没留出过说话人 | 按说话人分桶 |

最后一项定稿时没用上：折外堆叠在验证集上 0.718、基线 0.716，差值在噪声内。
「秩 + 二次项」变体验证集 0.733 最高，但 test 上 0.690 vs 基线 0.687——
**CI 大面积重叠，不拿可解读性换这 0.003**。上线的是基线线性，
输出直接是专家 0-10 刻度换算的百分数。

### 14.4.2 重音特征算但不进模型

speechocean762 的词级 stress 标注 **2097/2102 都是满分**——这份语料里几乎没有重音错误，
拿它拟合重音权重等于在 5 个样本上学。消融实测 GOP+重音（0.558）低于纯 GOP（0.555）
的差异也在噪声内，全量下仅重音的 ρ 只有 0.106。

所以重音保留计算与展示（界面要能说「重音落在了第二个音节」），但不进评分模型。
理由写在 `pron_features.STRESS_NOTE` 里，换语料后可以重新评估。

### 14.4.3 校准的第二个作用：把内部分换成看得懂的分

模型现在**直接预测专家会打多少分**（0-10 刻度），所以显示值是可解读的，
不再是「只有我们自己看得懂的内部值」。首版不是这样：同一条录音的原始分 34.3
看着像不及格，换算到专家刻度其实是 6.85——中等偏上的带口音朗读。

`Assessment.accuracy_source` 记着这个分是怎么来的：`model` = 三级校准模型，
`heuristic` = 没跑校准时的兜底，界面明说「这个数只能自己跟自己比」。

> [!warning] 版本不匹配宁可不出分
>
> `PHONE_FEATURE_NAMES` 从 18 项涨到 22 项又加了音素身份 one-hot。
> 旧的 `calibration.json` 套上去不会报错，只会让 `predict_phones` 静默返回空表、
> 聚合项退回中性值——线上跑一个比报告 ρ 更弱的模型且无人知晓。
> 所以 `model_accuracy` 校验 `refs` 存在，不匹配就整体退回启发式并在 notes 里说明。

### 14.4.4 completeness 这一维没有校准

校准脚本喂给评测的是「参考文本自比」，所以 completeness 恒为 100、**无方差**，
它的 ρ 不可解读（第一轮报的 0.0 是这个原因，不是「我们的完整度与专家无关」）。
要校准这一维得先跑 whisper 拿真实转写，那会把转写误差混进来，是另一件事。
报告里已把这一维单独说明并移出表格。

### 14.5 FR-392h 没有引 MFA

需求 §4.1 说逐音素时间戳要用 Montreal Forced Aligner 做离线内容生产。**实际没引**——
第 2 层算 GOP 时本来就在对参考音素序列做强制对齐（CTC Viterbi），
同一条路径顺手就给出每个音素的帧区间。再装一套 conda 环境只是把已有能力重做一遍。

落地形态是 `/phonetics/word/{word}/timings`：TTS 现合成示范音频 → 对齐 → 时间戳与音频
一起按内容指纹落缓存，二次访问零计算（与 ADR-006 同口径）。首次约 4 秒。
阅读器点词面板里的「逐音素跟读」用它做卡拉OK式高亮。

一处必要的后处理：CTC 把每个 token 压在一两个峰值帧上，中间全是 blank，
直接拿原始区间做高亮每个音只亮 20ms 就灭。按相邻音素的中点把区间铺满，
这是 CTC 对齐做可视化的标准处理。
