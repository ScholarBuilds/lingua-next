# 邮件与 Google 账号

CR-007 立的模块 18。它是「账号」这一组的第一个真实连接器，也是助理（20）第一批工具的来源。

> [!info] 不做完整邮件客户端（CR-007 §1.3）
>
> 第一版只有：统一收件箱（最近 50 封元数据）、Gmail 语法搜索、读正文、回复、归档、标已读、
> 今天的日程、把一封邮件当阅读材料。没有过滤器、标签管理、线程折叠、草稿箱。
> 官方 SDK 也没引：用到的六个端点 httpx 二十行就够，官方库为此要拖进几十个包和一套发现文档机制。

## 1. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-18-01 | 一个 OAuth 客户端（桌面应用类型，`provider_type=google_oauth_client`，存保险箱）服务全部账号；每个账号授权后各自的刷新令牌存成一条 `kind=oauth` 的凭据，秘密类型 `oauth` |
| BR-18-02 | 授权走 PKCE（S256）+ `access_type=offline` + `prompt=consent`；回调落在 API 自己身上（`LINGUA_GOOGLE_REDIRECT_BASE` + `/google/oauth/callback`），state 与 verifier 只活在发起进程里、十分钟作废、一次性 |
| BR-18-03 | 访问令牌只在内存缓存；`invalid_grant` 把账号标 `reauth` 并说明原因（同意屏幕仍在测试状态时刷新令牌 7 天过期），不静默重试 |
| BR-18-04 | 收件箱只缓存元数据（From / To / Subject / Date / 标签 / 摘要），正文点开时再取并缓存；搜索走 Gmail 自己的 `q`，结果不落库 |
| BR-18-05 | 发送必须带 `confirm=true`（D5 铁律 2）；这个端点是人点按钮的路径，助理经工具发信走审批内核；每次发送记 `config_audit` |
| BR-18-06 | 归档 = 去掉 INBOX 标签；标已读 = 去掉 UNREAD；都同步到 Gmail |
| BR-18-07 | 「收入阅读」把正文按空行切段进 `article`（`source_kind=mail`），邮件行记 `article_id`；再点直接打开那篇 |
| BR-18-08 | 移除账号显式逐层删（缓存 → 账号 → 凭据），不靠外键级联（内存 SQLite 不开外键约束） |
| BR-18-09 | 邮箱地址统一小写；同一邮箱重新授权只覆盖令牌，不多一条账号 |

## 2. 功能需求

| 编号 | 需求 | 落点 |
| --- | --- | --- |
| FR-18-01 | 账号页配置 OAuth 客户端：引导卡（步骤与链接来自 `provider_onboarding`）+ 两个字段 | `features/vault/GoogleAccounts.tsx`，`POST /vault/credentials` |
| FR-18-02 | 添加账号：系统浏览器里授权，页面轮询账号列表等它出现 | `POST /google/oauth/start`，`GET /google/oauth/callback` |
| FR-18-03 | 账号表：邮箱、已授权范围、令牌状态、上次同步；同步 / 重新授权 / 移除 | `GET/DELETE /google/accounts`，`POST /google/accounts/{id}/sync` |
| FR-18-04 | 邮件页三栏：账号（全部 + 各账号未读数）/ 列表 / 正文 | `features/mail/MailPage.tsx`，`GET /google/mail/inbox` |
| FR-18-05 | 搜索：Gmail 语法，跨账号 | `GET /google/mail/search` |
| FR-18-06 | 读正文、标已读、归档、回复（发送前再问一次） | `GET /google/mail/messages/{id}`、`/read`、`/archive`、`POST /google/mail/send` |
| FR-18-07 | 收入阅读（点词可查） | `POST /google/mail/messages/{id}/import` |
| FR-18-08 | 今天页显示当天日程 | `GET /google/calendar/today`，`TodayPage` 右列 |
| FR-18-09 | 主导航不展示邮件、账号与凭据、扩展及空分组；既有页面与 ⌘K 入口保留 | `App.tsx`，`commandItems.ts` |

## 3. 不做的

- 增量同步（`historyId`）先只记不用：第一版每次拉最近 50 封元数据，量小；量大了再接 `history.list`。
- 附件下载、写新邮件（非回复）、多收件人、HTML 正文渲染（正文一律剥成文本）。
- 早报例程里念邮件——那是模块 20 的事，这里只提供数据。

## 4. 实施记录（2026-09-02，CR-007 P3）

- 服务端：`domain/google_oauth.py`（PKCE、换令牌、刷新、userinfo、客户端与账号令牌）、`domain/gmail.py`（六个端点、元数据解析、HTML 剥文本、RFC822 组装、日历）、`app/routers/google.py`（14 个端点）、`GoogleAccount` / `MailMessage` 模型与迁移 `f3c4d5e6a7b8`；`credentials.py` 加两种类型并把 `client_secret / refresh_token` 列进秘密字段；`provider_onboarding.py` 加 Google Cloud 四步引导（链接由 `check_provider_links.py` 探活）。
- 前端：`/mail` 三栏页、账号页上半的 Google 账号区、今天页日程卡、侧栏与 ⌘K 项。外链走 `openExternal`（STD-UI-013）。
- 门禁：`test_google_mail.py` 11 条（PKCE 参数、无客户端 409、回调落令牌与重复授权、同步 upsert 与正文缓存、标已读 / 归档、收入阅读、发送 confirm 与审计、搜索与日历、invalid_grant → reauth、移除级联、HTML 剥文本）。**真实账号未测**：需要 scholar 在 Google Cloud 建一个桌面类型 OAuth 客户端并填进账号页（引导卡列了四步），那一步只能由账号主人做。
