## 1. 目标、边界与完成定义

创作工坊升级为 lingua-next 的 **AI 创作中心**。Infinite-Canvas 当前可运行的每项能力
都必须满足以下三种处置之一，并在能力矩阵中有唯一编号：

1. 原生实现：沿用 lingua-next 的 React、FastAPI、PostgreSQL、任务队列和统一资产库；
2. 等价替代：入口和数据结构可以重构，但用户能完成的动作、输入参数、结果质量、恢复能力不得下降；
3. 兼容适配：LiteLLM 不支持时新增直连 adapter、CLI bridge 或 workflow adapter，不能以“不支持”为由删除。

“全量完成”同时满足：能力矩阵无 `缺失/部分`；蓝本快捷键和外部粘贴全部通过；
所有生成任务跨路由持续运行且可从任务中心返回上下文；提示词与工作流完成带来源导入；
配置中心覆盖蓝本协议；自动化测试和人工对照测试均通过。只完成工具首页或画布 MVP 不算完成。

本模块**允许直接移植蓝本实现**（CR-005）。本项目为个人自用，不封装为产品、不分发、不商用，
蓝本「禁商用 + 二开传染开源」两条约束在本场景下不触发。

仍然保留的义务，与许可证是否强制无关：

- `server/resources/*/INFINITE_CANVAS_SOURCE_LICENSE.txt` 保留上游许可证原文；

## 3. 总体架构规则

| 编号 | 规则 |
| --- | --- |
| BR-170 | Infinite-Canvas 可运行能力不得因技术栈不同或 LiteLLM 缺失而被裁剪。 |
| BR-171 | `upstream_model_id` 必须保存并展示上游真实模型名；LiteLLM `model_name`/别名也使用该真实名称，不再用 `image-cover`、`chat-general` 等业务语义伪装成模型。 |
| BR-172 | 业务能力名与模型名分离。`image.generate`、`image.edit`、`video.generate` 等 capability binding 指向 provider + upstream model + adapter，工具只选能力或真实模型。 |
| BR-173 | 以 LiteLLM 为通用 adapter，不支持的协议使用 direct adapter；所有 adapter 统一实现提交、查询、取消、错误归一化、能力描述和参数 schema。 |
| BR-174 | 所有异步操作先创建持久化任务，再调用上游。页面卸载、刷新、断网或服务重启不丢任务；轮询和恢复由服务端 worker 负责。 |
| BR-175 | 工坊产物统一进入媒体资产库，保留原始文件、缩略图、来源、任务、模型、参数、提示词、参考资产和父子血缘。不得把视频强塞进仅支持图片的 `image_asset`。 |
| BR-176 | 画布文档态与任务运行态分离，通过 task id 关联；恢复时以服务端任务结果合并画布，不在浏览器内孤立轮询。 |
| BR-177 | 密钥加密存储、只回传掩码；CLI 登录态只在受控本机 bridge 使用；插件采用短期令牌和明确 CORS，不能沿用 `*` + 无鉴权。 |
| BR-178 | 所有直接迁移的代码、提示词、工作流和图标登记 provenance；保留上游许可证与作者署名。 |
| BR-179 | 工具参数由 capability schema 驱动，供应商专属字段可以扩展，不能用最小公分母抹掉上游能力。 |
| BR-180 | 自动保存、跨标签冲突合并、撤销重做、任务恢复都必须有确定性测试；禁止依赖 localStorage 作为唯一持久化。 |
| BR-181 | 旧版接口保持兼容到迁移完成；新增 adapter 和任务底座后逐工具切换，不能一次性推翻已可用功能。 |

### 3.1 模型、供应商与能力数据关系

```text
ProviderCredential ──< ProviderEndpoint ──< ModelDeployment
                                              │
                                              ├── upstream_model_id（真实上游名）
                                              ├── adapter_type + protocol options
                                              └── capability schema
CapabilityBinding ────────────────────────────┘
ToolRun/StudioTask ──> capability + deployment snapshot + source_context
```

同一模型在多个供应商存在时，UI 显示“真实模型名 · 供应商”；内部用 deployment id 区分，
不会篡改真实模型名。任务必须保存调用时的部署快照，随后修改全局配置不能改变历史任务或重试语义。

### 4.2 RunningHub 与 ComfyUI

RunningHub 支持在线选择 Model API 或粘贴运行路径创建 AI 应用/工作流卡片，积分 Key 与
Enterprise-Shared Key 分流，读取远端 schema、节点图预览、

### 4.3 模型别名：语义层与直通层并存

用户要求「LiteLLM 别名必须和上游模型名一致，方便识别」，与既有铁律「业务代码禁止硬编码
供应商模型名，只走语义别名」冲突。裁决是**两层并存，各司其职**（CR-005 §3.4）：

| 层 | 别名形态 | 谁用 | 例 |
| --- | --- | --- | --- |
| 语义层 | 业务语义名 | 业务代码（翻译、讲解、封面…） | `translate-fast` → 上游 `gpt-5.4` |
| 直通层 | **与上游同名** | 配置中心展示、工坊里用户手选模型 | `gpt-image-2` → 上游 `gpt-image-2` |

配置中心的模型列表**同时显示两列**：别名与真实上游模型名。换供应商时业务代码不动
（语义层解耦仍然成立），工坊里用户看到的永远是真名（识别需求满足）。

同一真名在多个供应商存在时，直通别名加供应商后缀区分（`gpt-image-2@yuzhi`），
但界面显示仍是「真名 · 供应商」两段，不把后缀当成模型名的一部分展示。

### 4.4 授权引导

每个供应商都要有**授权引导卡**，不是一行「请填写 API Key」。必需内容：

| 区块 | 内容 |
| --- | --- |
| 这是什么 | 平台定位、提供哪些能力（生图/聊天/视频/工作流）、计费方式 |
| 分步指引 | 注册 → 实名/充值（如需） → 创建 Key → 复制 Key → 回来粘贴；**每一步配一个跳转按钮直达该平台官方页面** |
| 字段说明 | Base URL 要不要带 `/v1`、Key 的前缀形态、区域/项目怎么填 |
| 验证 | 一键测试连通性；失败给**上游原文错误** + 针对该错误的修复建议 |
| 能力探测 | 拉取模型列表并按 image/chat/video 自动归类，让用户确认后入库 |

官方页面链接必须逐条真实可打开，验收时逐个点开核对（CR005-I）。链接失效按外部资源
处理：不硬编码猜测，配置里可改。

不能静默丢失。

## 6. 无限画布全量要求

### 6.0 实现选型与双画布形态

#### 6.0.1 放弃 React Flow，自研 DOM+SVG 内核

蓝本画布**不是 Canvas 也不是 WebGL**，就是 DOM + SVG：

```text
#board                       视口层：拖放遮罩、框选框、选择中枢、五套上下文菜单
  └ #world                   变换层：transform: translate(x,y) scale(s)
      ├ <svg id="links">     连线层：三次贝塞尔 path
      ├ #linkControls        连线控件层（HTML）
      └ #nodes               节点层（HTML div）
  └ #minimap                 缩略导航
```

因此**移植不存在技术障碍**，用 React 重写这套结构是直译。裁决（CR-005 §3.1）：

- 新建 `web/src/features/studio/canvas-core/` 承载视口、连线、选择、快捷键、菜单、缩略图；
- 移除 `@xyflow/react` 依赖；现有 `CanvasPage` / `CanvasNodes` / `canvasStore` 全部重写；
- 已入库的画布数据必须迁移可用，不允许丢弃。

放弃 React Flow 的三条实证理由：

| 理由 | 事实 |
| --- | --- |
| 边渲染依赖 ResizeObserver | 本仓已记录「React Flow v12 在内嵌浏览器面板里永远画不出边」，RO 一次都不回调；自研内核不依赖 RO |
| 命中区不可控 | 蓝本连线好点中的**全部原因**是每条线配一条 `stroke-width:14` 的透明命中路径，React Flow 默认边给不了 |
| 节点外壳被框死 | 蓝本节点头部悬浮工具条、端口拖拽菜单、组内吸收都要求完全掌控节点 DOM |

#### 6.0.2 双画布形态

保留普通画布与智能画布两种形态，画布记录带 `kind` 字段（蓝本同名字段）。

| 形态 | 蓝本来源 | 节点模型 | 定位 |
| --- | --- | --- | --- |

### 6.4 一致性与生成质量

参考图次序和用途不能只转成文字描述。图像编辑请求必须原字节上送参考图，并支持多参考排序、
主体/风格/构图角色；默认带参考时 `input_fidelity=high`（供应商支持时）、尺寸
跟随参考比例；无参考时不伪造 edit。批量张数拆成可独立恢复的子任务。节点可固定模型和参数，
历史任务重试使用原始快照，避免旧 worker 默认值造成配置漂移。

#### 6.4.1 全局生图质量默认 high

**全产品默认 `quality = high`**，不是 `auto`。此项高于蓝本（蓝本画布 `settings.quality`
默认 `"auto"`）。

| 层 | 行为 |
| --- | --- |
| 全局 | 配置中心一处设定，所有工具与画布节点的初始值来自它 |
| 工具/节点 | 可在其上微调，**微调不写回全局**，两者不冲突 |
| 供应商不支持 high 时 | 按该供应商的最高档降级，并在参数区照实标注降到了哪一档，不静默 |

新建节点、新建任务、模板套用一律取全局默认；读历史任务用任务自己的快照（BR-179），
不因为改了全局默认就改变历史任务的重试语义。

### 6.5 循环/并发节点（同一个节点的两个模式）

> [!important] 循环与并发不是两个节点
>
> 蓝本 `smart-loop` 用 `mode: serial | parallel` 一个字段切换。本项目照此实现，
> 不拆成两个节点类型。

**它是驱动器不是生成器**：本身不产图，而是驱动下游链路跑 N 轮。

| 字段 | 语义 | 蓝本默认 |
| --- | --- | --- |
| `mode` | `serial`（循环）/ `parallel`（并发） | `serial` |
| `count` | 轮数 | 1 |
| `loopStart` | 起始计数 | 1 |
| `showPrompt` | 开启提示词变量模式 | false |
| 提示词字段（可多条） | 每轮取第 index 条 | 空 |
| `imageInput` | 开启图片切片模式 | false |
| `imageBatchSize` | 每轮取几张上游图（1~100） | 1 |

#### 6.5.1 三种用法（必须全部支持并各留一条实测记录）

| 用法 | 配置 | 产出 | 典型场景 |
| --- | --- | --- | --- |
| **变量计数** | `showPrompt`，提示词插 `《计数》`/`《总数》`/`《进度》` token | 每轮把 token 替换成当前序号 | 「第 N 张」这类带序号的序列图 |
| **多提示词字段** | `showPrompt` + 写 N 条提示词 | 每轮取第 index 条，**共享同一条上游参考图** | 一组卖点图、一套 App 登录界面——一致性来自共享参考图，差异来自各轮提示词 |
| **图片切片** | `imageInput` + `imageBatchSize` | 按 `loopStart + imageBatchSize` 切上游图片列表，每轮喂不同的图 | 把一个界面的所有 UI 逐个处理成透明切图 |

三种可叠加：切片喂图 + 每轮不同提示词 + 计数变量同时生效。

#### 6.5.2 相对蓝本的升级项

| 项 | 蓝本 | 本项目 |
| --- | --- | --- |
| 并发上限 | 硬编码 6（`smartCascadeParallelLimit`，ComfyUI 时取实例数 1~6） | **不设上限**，全局默认 + 节点覆盖；只按供应商速率限制自动退避，不在客户端卡死 |
| 模式说明 | 只有两个按钮，无解释 | 每个模式一句话说明 + 一个典型场景示例，鼠标悬停即见 |
| 变量 token | `《计数》`/`《总数》`/`《进度》` | 保留全部，另加日期、随机种子、上游文件名；做成**可点选插入的 chip**，不靠用户记语法 |
| 图片切片 | 数字输入框 | 快捷选项（1/2/3/4/6/8/10）+ 自定义，并**实时预览「这一轮会喂哪几张」** |
| 失败处理 | 整链停止 | 可选「跳过失败继续」/「停在失败处」，失败轮可单独重试 |
| 进度 | 只有运行中标记 | 第 k/N 轮、每轮耗时、剩余预估 |

### 6.6 连线交互规格

每条连线渲染四个元素，逐条复刻蓝本：

| 元素 | 作用 | 关键参数 |
| --- | --- | --- |
| `.conn-line` | 主路径，三次贝塞尔 | 可带流动动效 |
| `.conn-hit` | **透明命中路径** | `stroke-width: 14`——这是「好点中」的全部原因，必须有 |
| `.conn-end` | 终点圆点 | r=3.5 |
| `.conn-cut` | 中点删除按钮 | 悬浮显形，点击断开 |

其余要求：

- **连线动效可开关**：默认开，画布工具栏与全局偏好两处可关；同时尊重系统
  `prefers-reduced-motion`（蓝本 `conn-reduce-motion` 同款行为）；
- **切线擦除**：按住修饰键拖拽划过连线即切断，带擦除轨迹视觉反馈（蓝本
  `connection-erase-trail`），松键退出；
- **端口拖到空白**：松手弹出可创建节点菜单，只列与该端口类型兼容的节点；
- **连线运行态**：级联执行时，正在跑的那一段连线高亮并显示流向；
- **贴边吸附**：拖近端口时吸附，不要求像素级对准。

### A.1 v1 背景与定位

两边用的是**同一个中转、同一个模型**（`ai.whyuz.com.cn` / `gpt-image-2`，实测出图
像素上限同为 ≈1.57MP），差距全部来自**调用方式与迭代循环**——参考图锚定的对话式
出图、原话直达、auto 尺寸、画布上并排比较。

据此立项：在 lingua-next 内建一个**工具中心**，命名「**创作工坊**」（导航标签
「工坊」，路由 `/studio`），把 Infinite-Canvas 的功能按 lingua-next 的技术栈**复刻**

>
> Infinite-Canvas 的许可证：**禁止商业用途；二次开发必须保持开源并注明来源作者；
> 已申请著作权**。直接搬代码会把这些义务带进本仓。
> 且其实现为 19k 行单文件 Python + 944K 无测试 vanilla JS，与本仓
> React 18 + FastAPI + PostgreSQL 完全不接。
>
> 所以本模块**只复刻功能与交互设计，不复制任何代码**。许可证事实已登记

- **BR-140 资产同源**：工坊任何工具产生的图一律经模块 16 的 ingest 落 `image_asset`（指纹去重、血缘、用量、缩略图自动生效），禁止另建文件级存储。
- **BR-141 生成同路**：出图只走既有生图端点与 LiteLLM 语义别名；工坊新增后端只做**编排与持久化**，不做第二条生成通路。
- **BR-142 复刻不搬运**：不从 Infinite-Canvas 复制任何代码/资源文件；交互与算法按调研清单重新实现。
- **BR-143 文档态与运行态分离**：画布/会话的持久化结构里不存 pending/running 等瞬时字段；运行态由任务查询接口现算。
- **BR-144 参考图按资产 id 引用**：画布与对话引用已入库的图时传 `ref_asset_ids`，服务端从存储直读字节，禁止前端下载再上传的绕行（蓝本因无资产库只能上传文件路径，这里必须做得更好）。

### A.4 v1 功能需求

#### A.4.1 工坊首页（FR-460）

`/studio`：工具格子（图标 + 名称 + 一句话 + 里程碑徽标），点击进入各工具；
未交付的工具显示「即将上线」不可点。导航栏「工坊」项插在「生图」之后。

#### A.4.2 无限画布（FR-461 ~ FR-469）

蓝本最核心的资产，完整复刻其节点模型与交互语义，实现层用 `@xyflow/react`
（本仓已依赖，管线 DAG 在用）+ zustand。

##### FR-461 节点模型

四类节点（蓝本五类，`smart-minimax` 视频时间线裁剪，见 §7）：

| 类型 | 内容 | 说明 |
| --- | --- | --- |
| `image` | `items[]`（每项 `asset_id` 或外部 `url`、kind、宽高）、`prompt_draft`、`run_settings` | 唯一可生成落点；多图时网格排布 |
| `prompt` | `text`、`split_separator`、LLM 扩写配置 | 给下游供提示词；可按分隔符拆成多条供循环轮取 |
| `loop` | `count(1~50)`、`mode(serial/parallel)`、`variable_prompts[]` | 级联执行的轮次控制，占位符《计数》《总数》《进度》 |
| `group` | `member_ids[]`、吸收的 `items[]` | 画布中的画布：图片拖入被吸收成网格；整组可当参考运行 |

每节点自带 `run_settings`（模型别名、画幅、质量、张数），优先级：节点 > 画布默认。

##### FR-462 连线三语义

`connections = [{from, to, kind}]`，kind ∈ `input`（参考输入：上游图作下游生成的
参考）/ `flow`（生成血缘：系统自动补）/ `history`（历史归档：灰虚线，不参与取参、
不参与级联）。缺省按 `flow` 读（兼容不变式）。拖节点出口到空白处自动新建空图节点并连线。

##### FR-463 单节点生成

选中图节点 + 提示词 → 汇总参考（自身图 > input 上游图 > 手动参考，去重、上限 10）→
有参考走 `/images/edit`（`ref_asset_ids` 直引资产），无参考走 `/images/jobs`。
节点已有图时**分支式生成**：右侧新建 pending 输出节点连 `flow` 边，原图保留；
新图落回时旧图移入自动创建的「历史分组」（`history` 边）。张数 N 拆成 N 个并发
单张任务（蓝本经验：比一次 n=N 更易恢复）。失败回滚删掉空分支节点，错误原样展示。

##### FR-464 级联执行

从链尾（或 loop 节点）一键沿 `input+flow` 拓扑逐节点生成；loop 控制轮数与
串/并行（并行上限 4）；同源多下游时第一个真正生成、其余复用同批输出；连线按
wait/active/done 三态着色。执行中可停止（当前任务收尾后中断）。

##### FR-465 @提及与手动参考

提示词框输入 `@` 弹出选择器（两个来源：上游链路图 / 素材库），选中插入不可编辑
token；构建请求时 token 编号为「图N」，prompt 前拼映射表。参考行「+」可追加常驻
手动参考（不进提示词正文）。

##### FR-466 画布编辑器（纯前端，不花钱）

节点浮动菜单进入：裁剪、扩图（原图贴大白底画布 + 提示词预置 "Remove white area
and fill the scene"，`outpaint_size` 联动下次生成尺寸）、遮罩涂抹（黑白 mask 随参
考上送）、宫格切分/拼接。产物经 `/images/local` 入库（source=local 不计用量）。
与模块 16 已有 MaskCanvas/Filerobot 能力复用，不重写。

##### FR-467 持久化与多端

`studio_canvas` 表：`nodes/connections/viewport` JSONB + `updated_at` 乐观锁。
450ms 防抖全量保存；409 时**本地在跑节点完全本地优先、图片取并集、宁可复活不丢
结果**的合并策略（蓝本协作不丢数据的关键，原样复刻）；软删 + 30 天回收站；
meta（标题/图标/颜色/置顶/项目）单独更新且**不刷 updated_at**（否则打个标签就把
画布顶到列表最前）。

##### FR-468 视口与整理

滚轮以光标为锚缩放、拖空白平移、minimap、一键整理（拓扑分层 + 分组原子折叠，
选中单节点先扩散为连通簇）。缩放时图片按视口远近懒切清晰度（近用原图远用缩略）。

##### FR-469 画布列表与项目

`/studio/canvas`：画布卡片（标题/图标/9 色/置顶/负责人）、项目分组（默认项目
不可删，删项目画布迁回默认）、回收站、导出/导入选中子图为 Lingua 或
Infinite-Canvas 兼容 JSON/带资源 ZIP，并可资产化到工作流库。

#### A.4.3 对话生图（FR-470 ~ FR-473）

蓝本「在线生图 + GPT 对话」的合并复刻，是「参考图锚定循环」的一等入口。

- **FR-470 会话**：`studio_chat` 表，turns JSONB（user: text + ref_asset_ids；
  assistant: asset_ids + 耗时 + 错误）。会话可改名、删除、置顶；打开恢复上次会话。
- **FR-471 生成循环**：每轮默认以**上一轮产图为参考**（可撤掉/换参考/加素材库图）；
  尺寸默认 **auto**（带参考时跟随参考比例——这正是蓝本一致性的来源）；短中文原话
  直达，不经立意改写。质量 auto/low/medium/high 四档。
- **FR-472 提示词尺寸解析**：原话里的「竖版/横版/方形/16:9/4K/高清」等按模块 16
  六轮的立意规则解析（复用，不重写一套）。
- **FR-473 图上继续**：任何一轮的图可「送去画布」「送去控制台改」「设为参考继续聊」；
  模块 16 结果查看器的「对话编辑」入口指到这里。

#### A.4.4 细节增强（FR-474，M2）

单图增强：上传/选资产 → 强度档（轻/中/强，映射为增强指令强度）→ 走 `/images/edit`
增强指令模板 → 前后**拖拽对比滑块**展示。蓝本的 ComfyUI 双阶段超分（2x/4x）无本地
ComfyUI 时不可用，本仓通过中转无超分模型——**照实标注**「增强改善细节与清晰度，
不放大像素」（BR-110 不伪造），超分留待接入超分供应商后开放（见 §8 M4）。

#### A.4.5 角度控制（FR-475，M2）

蓝本最亮的交互，完整复刻：上传图贴到 3D 平面，旋转/俯仰/距离三滑杆实时预览机位，
机位自动翻译成中文指令（「将相机向右旋转 35 度，俯视 20 度，使用广角镜头」）
**原位写入提示词**（只替换以「将相机」或「保持原机位」开头的那一行，保留用户手写的
其它内容），生成走 `/images/edit`。距离 >4 广角、<2 特写、其余标准。

> [!note] 3D 预览改用 CSS 3D，不引 three.js（M2 实施时的取舍）
>
> 需求初稿写的是 `@react-three/fiber`（照抄蓝本）。实施时改成
> `perspective() + rotateY/rotateX + translateZ`：**单个贴图平面绕相机旋转，与
> 相机绕平面旋转在数学上等价**，CSS 3D 的投影结果与三维引擎一致，而代价是
> 少两个依赖、不碰 WebGL 上下文（本仓有 pixi 销毁丢 context 的旧账），
> 且在 playwright 里可量可验。实测 distance 3/6/1.5/8 的绘制宽度
> 215/107/429/80 px，与 P/(P−z) 的理论值吻合。
>
> M4 的 360 全景预览是真的需要球面渲染，到时再引 three.js。

> [!danger] GPT 断流落库：写着 finally 却根本不生效
>

> **客户端断开时两种断法都是 `turns: 0`**：请求作用域的 session 这时已经在拆，

> （shield 的外层 await 被取消时内层照样跑完）；② 开头就把 `chat.id` 取成普通 int
> ——finally 里再读 ORM 属性会触发隐式懒加载，异步下直接 MissingGreenlet
> （本仓 onupdate 列那次是同一个坑）；③ 正文改成**增量累加**，断在半路的字也留得住。
> 另在 conftest 里把 `detached_session` 指到内存库，否则这条路测试根本覆盖不到。

> 1. 模型回 `enough:true` —— 系统提示词里那条「宁可少问」在这一轮要让位（服务端）；
> 2. 前端按 id 去重 —— 模型每轮都从 `q1` 编起，第二轮整批被当成重复丢掉；
> 3. 已问未答的题目没回传 —— 它不知道自己问过什么，把「参考图照着哪一面来」
>    换成「参考图借哪一面」又问一遍。
>
> 第 2 条是这轮唯一靠**实测**才发现的：单看代码它是一条正确的去重。


### 12.7 P3 第七批：画幅「自动」、骨架比例、画布图清晰度（2026-08-21）

用户报的三条，根因各不相同，但前两条同源。

#### 「同一个提示词，原项目出竖版手机页，我们出横版三联 banner」

不是模型不听话，**是我们明确命令它画一张超宽 banner**。实际发出去的提示词：

```
出一个 移动端 app 的登录页面，场景是语聊房

Canvas: 1536x608, aspect ratio 2.53:1. Compose for this exact shape.
```

画幅选的是「自动」，`size_req` 却是 `1536x608`（2.53:1）。那个数是
`Tunable("size", …, "1536x608")` 的默认值，当初给单词卡横幅调的。

根因与画风那个 `NO_STYLE` 的坑**完全同构**：`None`/`""` 同时表示「没说」和
「自动」，被 `size or 默认` 一路吞掉。修法也一样——加一等选项：

| 值 | 含义 | 行为 |
| --- | --- | --- |
| `None` / `""` | 没说 | 回落该用途默认（词卡那条链不变） |
| `"auto"` | 明确不指定 | **不传 size 给上游，也不补画布句**，由模型自己判断 |
| `"1024x1536"` | 用它 | 传 + 补画布句（上游按提示词里的比例出图，不看 size 参数） |

覆盖到每一个消费点：`validate_size` 放行、`parse_size` 显式拒绝（不静默返回数字，
否则调用方会拿它去算比例）、`ensure_canvas` 不补句、`build_structure` 不写
`layout.canvas`、`render_images` / `edits` / `image_stream` 不放进请求体、
Gemini adapter 整个 `imageConfig` 不下发（它走 `parse_size`，不分流就是 500）。

#### 顺带发现：立意挑画幅从来没生效过

`pinned_size = chosen("prompt","size", job.size)` 在没选尺寸时回落 Tunable 默认，
于是 `aspects=None if pinned_size else …` 恒为 `None`——**立意那一步从来没被问过
该用什么画幅**。而代码注释与本文档都把"不指定时由立意按画面内容挑"当既定行为。

Tunable 默认改为留空后实测：需求「一张竖版的手机 app 启动页」→ 立意挑 `576x1024`
→ `layout.canvas: 576x1024 (0.56:1)` → 出图 941×1672。改之前会掉进
1536x608，方向完全相反。

#### 「骨架模态是横的长方形，项目是竖的」

`.scv-skeleton { height: 150px }` 固定高、跟着节点宽铺满 = 永远一条 2.8:1 的横杠。
改成跟着**预期出图比例**（`pendingAspect`），三级判据与出图时真正生效的规则一一对应：

1. 钉了画幅 → 就是它；
2. 没钉但有图可参考（自身 / 附件 / 上游）→ 跟随参考（生成条上写的「尺寸跟随参考」）；
3. 都没有 → 1:1。**不猜**——猜横的正是这个 bug 的成因。

实测：有参考图时骨架 352×626（0.563 = 参考图比例），与蓝本一致；空节点 420×420。

#### 「画布上的图都是模糊的，点进去才清楚」

`src` 钉死 `display` 变体，而 display 只有 768px 宽。Retina 屏上一个 637px 宽的
节点需要 1274 物理像素——放大 1.66 倍就是肉眼可见的糊，把画布放大更糊。
蓝本读本地原图，所以它任何缩放下都清楚。

改用 `srcset` + `sizes` 让浏览器自己挑，而不是自己按 `scale × dpr` 算变体：
它会考虑 DPR、只下载选中的那一档、且**放大后不会降级**回小图。

两个容易写错的细节：

- `sizes` 必须把画布缩放乘进去。`transform: scale()` 不改变布局尺寸，
  浏览器算 srcset 时看不见它——不乘的话放大到 2× 仍按原尺寸挑图，越放大越糊，
  而那正是最想看清的时候。缩放值**量化成 1/2/4 档**再进 memo 比较，
  传原始值会让缩放的每一帧把全部节点重渲染一遍。
- 描述符必须是那个 URL **真正**返回的宽度。服务端 `_resize_webp` 在原图本来
  就更窄时不放大、直接回原图，所以一张 420 宽的图 `/display` 拿到的是 420；
  标成 `768w` 的话浏览器会以为它够铺 700px 的位置——还是糊，而且比原来更难查
  （srcset 明明"生效"了）。

实测：`sizes` 420px 时选 `/display`（768w，1.83× 超采样）；把画布放大到 4 档、
`sizes` 变 1680px 后自动升到 `/full`（941w）。

> [!warning] 这一批的验证卡在"改完 worker 没重启"上，第二次栽同一个坑
>
> API 已经接受 `auto` 了，前端仍然弹 `PromptError: 尺寸格式应为 宽x高，收到 'auto'`。
> 出图跑在 arq worker 里，而它是八小时前启动的旧进程——`parse_size` 还是老版本。
> CLAUDE.md 早就记着这条铁律，这次仍然只重启了 uvicorn。

### 12.8 P3 第八批：下拉统一、悬浮交互与说明小字清理（2026-08-21）

三件事一条主线：把输入框和全项目的浮层交互对齐蓝本，再把界面上解释性小字清干净。

#### 统一 picker 组件（STD-UI-009）

蓝本的 `.smart-control` 体系是**悬浮即开**（`:hover`/`:focus-within`/`.pinned`，
加 8px 悬浮桥伪元素防止斜穿关闭），不是点击下拉。第一版误用 Radix Select
（点击开）返工重做，最终形态四件套，全部在 `web/src/components/ui/picker.tsx`：

| 组件 | 底层 | 交互 | 用途 |
| --- | --- | --- | --- |
| `PillPicker` | DropdownMenu + `useHoverOpen` | 悬浮开、140ms 延迟关 | 生成条药丸（质量/数量/模型） |
| `Picker` | Radix Select | 点击开 | 表单里的常规选择 |
| `PopoverPicker` | Popover + `useHoverOpen` | 悬浮开 | 复合内容浮层（尺寸三 tab） |
| `ActionPicker` | DropdownMenu | 点击开、无选中态 | 动作菜单 |

全项目替换 44 处原生 `select`/自制下拉，`pnpm check:select` 守卫防回流。

踩的坑，都记这里：

- **Radix Select 的空串值是保留字**（表示"清除"），`''` 选项必须映射成具名值
  （`'none'`/`'all'`/`'global'`/`'default'`），否则运行时抛错。
- **Radix Select 无法悬浮开**（listbox 强占焦点），悬浮语义只能建在
  DropdownMenu + 受控 `open` 上；`DropdownMenuRadioGroup` 自带单选/方向键/首字母。
- **替换引入过一个真回归**：快捷键的 `isEditable` 原来靠 `tag === 'SELECT'`
  判"焦点在输入类控件"，换成 Radix 后触发器是 `<button role="combobox">`，
  焦点落在下拉上按 Delete 会直接删节点。改为按 role 集合判定
  （`combobox/listbox/option/menu/menuitem*/spinbutton` + 祖先 `[role="menu"]`）。
- 尺寸浮层的 tab 会**弹回**：自定义填 1024×1024 恰好等于 `1:1 · 1K` 预设，
  `scope` 若纯由 value 推导就跳回系统参数。修法是 `pickedScope` 状态 +
  `mine` ref 区分"自己改的 value"与"外部塞进来的 value"。

#### 输入框收外部文件 + 文档预览

- `MentionInput` 支持粘贴/拖入图片与文件：paste 时**先查 `clipboardData.files`
  再查文本**（很多来源两者都带，先文本会把文件吞成路径字符串）；drop 加
  `stopPropagation`，否则画布把文件抢去建节点。
- 附件预览按类型分流：PDF 走浏览器内建 viewer（iframe），markdown 走
  react-markdown+remarkGfm，表格（xlsx/csv）服务端 openpyxl/csv 解析成行列，
  文本走 `<pre>`，二进制给下载。服务端 `document_preview` 统一编码探测
  （utf-8-sig → gb18030 → lossy）。

#### 说明小字清理（STD-UI-010）

悬浮浮层里的解释性 tips 全项目普查（469 条候选），判 30 删 / 8 收敛 / 2 保留：

- 节点菜单 16 条 hint 收到 4 条，只留标签讲不清的（「细节增强 · 不放大像素」）；
- 图片编辑器 7 条顶部说明条全删（同一句话在 7 个模式里重复 6 次）；
- 约束不删语义：自定义尺寸的"16 倍数、≤3840"改由控件表达
  （`step/min/max` + 出错才显示的一行红字）；
- 删掉一条**说反了的**快捷键说明（写着"下拉不算输入框"，实际行为相反）——
  错的说明比没有说明更坏；
- JSX 不解析 markdown：界面上真的显示过 `**原图真实像素**` 字面星号。加
  `pnpm check:jsx` 守卫，当场又抓出 5 处，全改 `<b>`。
