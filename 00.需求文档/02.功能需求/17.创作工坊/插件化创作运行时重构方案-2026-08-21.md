# 插件化创作运行时重构方案

> 日期：2026-08-21  
> 状态：实施中  
> 范围：模型、工具、工作流、全局任务、画布实时恢复，以及 Infinite-Canvas F001-F134 全量迁入

## 1. 结论

Lingua 不直接移植 DeepSeek Harness，也不继续围绕 LiteLLM 增加条件分支。目标架构是：

1. 一个具备可撤销注册、版本和代际的插件内核；
2. Chat、图片、视频、音频、工作流分别使用类型化能力合同；
3. 所有执行先解析并冻结模型/插件/配置快照，再提交任务；
4. 用户任务、模型调用、调用尝试和领域事件分层持久化；
5. 工具、Agent Tool、画布节点和工作流节点从同一份 schema-first 清单派生；
6. 画布 UI 是持久执行状态的投影，刷新或页面关闭不影响服务端继续执行和最终落图；
7. LiteLLM 保留为一个可选插件，不再是全局运行前置条件。

## 2. DeepSeek Harness 参考边界

参考仓：`参考项目/deepseek-harness`  
参考提交：`b150a551b8d465e31e418e1b2eaf5e79bbb7d28e`

采用的思想：

- 所有注册均由插件持有，并返回可撤销句柄；
- 服务定义、提供者和消费者分离；
- 调用绑定到准确的插件代际，运行中替换不改变既有调用；
- 持久事件是恢复、审计和 UI 投影的事实源；
- 模型适配、工具注册、会话日志和执行循环均位于可替换边界；
- telemetry 从持久台账派生，不取代业务审计。

当前对应实现：

| Harness 边界 | Lingua 实现 | 当前性质 |
| --- | --- | --- |
| Service Definition | `ModelPlugin` 定义媒体、操作、Provider Type 和声明式 ready 状态 | 目录定义 |
| Service Provider | `ChatRouteProvider` / `ImageRouteProvider` / `VideoRouteProvider` / `AudioRouteProvider` / `WorkflowRouteProvider` + 各能力可撤销注册表 | 真实运行时实现 |
| Consumer | `PreparedChatRoute` / `PreparedImageRoute` / `PreparedVideoRoute` / `PreparedAudioRoute` / `PreparedWorkflowRoute` | 冻结路由和准备时 Provider 后执行 |
| Effect disposal | `RegistrationHandle.dispose()` | 替换实现卸载后恢复前一代 |
| Generation freeze | `plugin_generation` + `runtime_generation` | 旧 prepared call 继续使用准备时的 Provider |
| Model-visible logging | `PreparedChatCall` 调用前创建 `ModelInvocation` | 成功、失败、取消和遗弃都有终态 |

`/config/model-plugins` 同时返回模型插件的 `ready_operations` 和真实挂载的
`chat/image/video/audio/workflow_provider_operations` 与各自 `runtime_generation`，界面与调试不再把
“声明已支持”误当成“运行时已装载”。路由快照会绑定模型插件代际、媒体
Provider 代际与真实模型或工作流定义；Chat 额外递归冻结协议配置和端点，图片/视频冻结已解析的
`ResolvedModelRoute`，音频冻结合成配置，工作流冻结定义、凭据和提交协议。配置或 Provider 热更新不会污染已准备调用。

明确不照搬：

- 不移植 Cordis 和 TypeScript 元编程机制；
- 不用一个聊天 token stream 合同强行统一图片、视频、音频和工作流；
- 不允许用户代码直接加载到 API 进程；
- 不让插件任意挂 FastAPI 路由或绕过权限、幂等、日志和错误归一化；
- 不用内存/JSONL 作为多用户任务与画布事务事实源；
- 不用控制台日志或 OpenTelemetry 替代可查询的调用台账。

DeepSeek Harness 和其 vendored Cordis 均使用 MIT 许可证。当前实现只重建架构合同，没有复制其实现源码；若以后复制实质代码，必须在第三方声明中保留对应版权和许可文本。

## 3. 当前根因

### 3.1 模型层

- 配置允许保存非 LiteLLM 的 Chat deployment，但 `domain.llm` 原先永远调用 LiteLLM alias，形成“可配置、不可执行”的死配置；
- adapter 名单、图片 allow-list、视频分支和工作流分支是多份事实源；
- 新 `ModelDeployment` 路由没有继承旧凭据 fallback；
- 解密后的整份凭据配置在多个调用对象中传播，统一日志若直接序列化会泄密；
- LiteLLM 用量、图片资产 usage、任务结果和管线 metrics 无法还原一条跨协议调用链。

### 3.2 任务与画布恢复

- 自动分支生成的 `pending` 节点保存时被整节点过滤，但任务的 `source_context.node_id` 正指向该节点；刷新后恢复逻辑找不到节点而跳过；
- 同一节点 `n > 1` 会产生多条任务，恢复逻辑按 `node_id` 去重，只回收最新一条；
- `StudioTask` 没有严格迁移表、追加事件、SSE cursor、租约、检查点和取消合同；
- worker 启动恢复不扫描 `queued`，不可恢复任务也缺统一插件恢复策略。

### 3.3 工具与工作流

- `STUDIO_TOOLS` 是前端导航元数据，不是可执行插件注册中心；
- GPT tools、CanvasNode、worker 函数和 React 页面各维护一份静态合同；
- `StudioWorkflow` 的目录、schema、ComfyUI/RunningHub 执行已收编到可撤销 `WorkflowRouteProvider`；公共提交、恢复和等待边界不再按 Provider 写静态分支；
- 工作流节点缺少统一的输入输出类型检查、权限、超时、取消、幂等、检查点和补偿语义。

## 4. 目标分层

| 层 | 责任 | 禁止事项 |
| --- | --- | --- |
| PluginManager | 包发现、manifest/config 校验、生命周期、健康、代际和 drain | 不保存明文密钥，不允许未跟踪后台任务 |
| CapabilityRegistry | 模型、工具、工作流的不可变注册快照和可撤销句柄 | 不做业务选路，不直接改任务状态 |
| CapabilityRouter | deployment/能力绑定/fallback/权限/配额解析，冻结执行快照 | 不把解密凭据放入公开快照 |
| ExecutionRuntime | invoke/stream/submit/resume/cancel、超时、幂等和错误归一化 | 插件不能绕过该入口直接改 `StudioTask` |
| InvocationLedger | 每次调用和 attempt 的状态、用量、耗时、上游请求、脱敏错误 | 不保存密钥、媒体字节、data URL 或签名参数 |
| DomainEvent + Outbox | 任务/画布追加事件、顺序、事务发布和 SSE cursor | 不先广播再提交数据库 |
| Projection | 全局任务中心、画布运行态、产物落点和恢复视图 | 不把浏览器内存当事实源 |
| Profile/Preset | 工作区、用户、工作流、节点覆盖和不可变执行预设 | 只保存 secret reference，不执行任意代码 |

## 5. 模型插件合同

每个插件至少声明：

- `plugin_id`、版本、API 合同版本和代际；
- 支持的 `provider_types`、凭据类型和媒体类型；
- 准确操作：`chat.complete`、`chat.stream`、`image.generate`、`image.edit`、`image.stream`、`video.generate`、`audio.synthesize`、`asr.transcribe`、`realtime.session`、`workflow.run`、`midjourney.generate`、`midjourney.action`、`midjourney.poll`；
- 是否支持流式、异步恢复、取消、模型发现；
- 协议参数 schema、权限和健康检查；
- `resolve/prepare/invoke/resume/cancel` 实现。

选路优先级固定为：

1. 节点/任务显式 `deployment_id`；
2. 工作流绑定；
3. 画布/会话执行预设；
4. 用户/工作区 profile；
5. 能力主绑定；
6. 有序 deployment fallback；
7. 迁移期旧 LiteLLM alias。

任务接受时冻结 requested route、served route、真实模型名、插件 id/版本/代际、配置修订和预设修订。排队期间修改设置，不得静默改变既有任务。

## 6. 模型调用台账

`StudioTask` 是用户可见的业务执行；`ModelInvocation` 是一次逻辑模型调用；后续 `ModelInvocationAttempt` 记录重试和 fallback。三者不能合并为一张表。

调用台账至少可查询：

- 任务、画布、节点、工作流和父调用关联；
- capability、operation、requested/resolved deployment；
- 插件 id、版本、代际、供应商、真实模型和上游 request id；
- created/running/streaming/succeeded/failed/cancelled/abandoned；
- 总耗时、首 token/首 preview、用量和可核算成本；
- 脱敏后的参数摘要、响应摘要和错误；
- 资产 id，不保存短期 URL 和二进制。

密钥字段、Authorization、`x-goog-api-key`、data URL、媒体字节和带凭证 query 的签名 URL 必须在入库前删除；日志失败不得导致模型调用失败。

## 7. 任务、事件与画布投影

一期状态建议：

`accepted -> queued -> leasing -> running/waiting_external/waiting_input/recovering -> succeeded|partial|failed`

取消使用：

`queued|running|waiting_* -> cancel_requested -> cancelling -> cancelled|failed`

终态不可回退；重试始终新建子执行，并通过 parent/attempt 串起历史。

`StudioTaskEvent` 使用 `(execution_id, seq)` 唯一单调序号，事件与任务投影在同一数据库事务提交。SSE 支持 `Last-Event-ID`/cursor，先补历史再进入实时；GET 仅保留为低频降级。

画布另建可索引执行投影：`canvas_id`、source/target node、output slot、规划几何、group、latest seq、landed version。多图使用父执行和多个子执行聚合，产物落图以 `(execution_id, artifact_id, target_node_id)` 幂等。页面关闭后由服务端 projector 完成落图。

## 8. 工具与工作流插件合同

工具 manifest 是服务端、Agent、画布和工作流的唯一事实源，至少包含：

- id、版本、显示信息和 runtime kind；
- input/output/config JSON Schema；
- 权限、超时、并发键、幂等模式和 resume policy；
- 声明式 UI 贡献：home card、route、canvas node、toolbar action、inspector；
- `validate/start/resume/cancel/healthcheck`。

同一个工具执行入口必须服务 REST、Agent Tool、画布动作和工作流节点。工作流连线只有在上游 output schema 与下游 input schema 兼容时成立；图片资产转 URL、文件上传等使用显式 converter plugin。

首批包装现有五条真链路：`image.generate`、`image.edit`、`video.generate`、`workflow.comfyui`、`workflow.runninghub`。

## 9. 实施顺序

### 阶段 A：插件与调用底座

- 通用注册表、模型插件清单、版本/代际；
- 模型调用持久台账、脱敏和日志 API/UI；
- LiteLLM Chat 兼容门面；
- OpenAI-compatible 直连 Chat 插件和 deployment/fallback 路由。

### 阶段 B：模型全链路收编

- 翻译、视觉理解、图片对话和 Agent；
- 图片 generate/edit/stream；
- 视频 submit/resume/poll/download；
- ComfyUI/RunningHub；
- TTS、实时语音、本地 ASR；
- 禁用 LiteLLM 后仍有直连 Chat、图片和本地模型可运行。

### 阶段 C：任务与实时恢复闭环

- 严格状态机和 `StudioTaskEvent`；
- SSE cursor 与全局单例客户端；
- canvas execution projection；
- 修复 pending 分支、多图聚合和孤儿产物；
- 级联/循环/套图迁入 worker DAG/checkpoint；
- 通用 cancel/retry/clone/open-context。

### 阶段 D：工具与工作流内核

- ToolPluginRegistry 和执行中间件；
- Agent/REST/Canvas/Workflow 共用 manifest；
- 类型化 DAG、版本、暂停/人工输入、补偿、分支、聚合和 checkpoint 恢复；
- 插件包安装、签名、权限、隔离和资源限额。

### 阶段 E：Infinite-Canvas 全量迁入

以《Infinite-Canvas能力差异调研-2026-08-21.md》的 F001-F134 为唯一清单，按以下域逐项关闭：

- D01-D05：应用外壳、项目、经典/智能画布、节点、生成与编排；
- D06-D10：媒体编辑、独立工具、GPT、多模型设置、ComfyUI；
- D11-D13：素材、模板、日志、任务历史与恢复；
- D14-D16：Chrome、Photoshop、CLI、启动、更新与备份。

既有 Lingua 超集能力（资产内容寻址、加密凭据、持久任务、版本冲突、学习资产回写）继续保留；只重构执行和交互薄弱部分。

## 10. 本轮已经落地

- `PluginRegistry`：可撤销注册、可逆覆盖、优先级能力解析和代际；
- `ModelPlugin`：后端自描述适配器目录，替代静态 `ADAPTER_TYPES`；
- Chat 已完成 Service Definition / Provider / Consumer 的第一条纵向链路：LiteLLM、OpenAI 兼容直连、Codex CLI 和 Gemini CLI 由可撤销 `ChatRouteProvider` 提供，消费者不再按插件 id 分支建客户端；
- `PreparedChatRoute` 冻结模型插件代际、Provider 运行时代际、传输和递归不可变协议配置；`PreparedChatCall` 只允许一次 dispatch，自动建立台账、关闭客户端，未写终态时自动记为 `abandoned`；
- 模型实验台从插件 API 动态读取适配器、供应商映射和已接入能力；
- 创建 deployment 时校验插件真实声明的媒体能力；
- `ModelInvocation` 增量表、Alembic migration、任务/画布上下文传播；
- 调用输入输出、用量、上游 request id、模型、插件版本/代际、耗时和错误的脱敏持久记录；
- `domain.llm` 的 JSON/Text 完成和流式调用接入统一 Chat 路由与台账；
- 翻译、视觉反推/提示词扩写已移除固定 LiteLLM 客户端，可按能力绑定或显式 deployment 直连，并记录调用；
- 图片 generate/edit/stream/probe 与视频 submit/wait 已经进入同一 `ModelInvocation` 台账，二进制输入只记文件名、字节数和首帧耗时；
- GPT 创作对话每一个 Agent round 都使用冻结的 Chat route 并单独记账；发送区可对本轮的对话模型和工具出图模型分别选 deployment；
- PydanticAI 修复 Agent 的每次内部 model request 已经过可观测 OpenAI-compatible adapter 执行，不再在 `build_model` 里固定 LiteLLM；换模型重试可显式选任意启用的 Chat deployment，并把选择固化到新会话；
- Edge TTS、火山流式 TTS 和火山端到端实时会话已进入模型插件目录与调用台账；缓存命中不伪造新上游调用；
- TTS API 可显式选 audio deployment；实时语音场景页可选已启用的火山 audio deployment，并把快照固化到会话后再建 WebSocket；
- Faster Whisper 本地 ASR 已作为 `execution=local` 的模型插件登记；修复语音、回合制对话录音和视频管线转写都记录文件摘要、真实模型名、输出统计和错误；
- 音素 ONNX 对齐、发音评测与校准已作为本地模型调用记账，记录音素/单词统计、评测层级、准确率、提示数和失败信息；
- ComfyUI/RunningHub 工作流的提交与等待分别进入调用台账，并关联持久任务、画布节点、工具、工作流和上游任务 ID；产物只记录类型、大小及脱敏来源；
- Chat 能力绑定到 `adapter_type=openai` 的 deployment 后会绕过 LiteLLM，使用真实 Base URL 和 `upstream_model_id`；各兼容函数也接受显式 `deployment_id`，未指定新 deployment 时继续走旧 alias；
- 直连 HTTP 客户端按真实上游地址判断本机代理，结构失败后的重试显示为独立调用；
- `/config/model-plugins` 与 `/config/model-invocations`；
- 模型实验台“模型调用日志”列表，5 秒刷新并可展开请求、响应、用量和上下文。
- `StudioTaskEvent` 追加事件表、严格终态迁移、全局 cursor SSE 和 `Last-Event-ID`/本地 cursor 断点续传；
- `StudioTask` 增加可索引的 `canvas_id`/`node_id`/`execution_group_id`，worker 启动对账也通过状态机追加事件；
- 画布恢复改为按 `canvas_id` 查询，不再按节点丢弃多任务；图片分支节点快照和执行组跟随任务持久化，刷新后可重建运行落点、续接进度并幂等落图。
- `ToolPluginRegistry` 已登记 ST-01~ST-20 的服务端 manifest，包含能力、路由、界面贡献、运行时类型、输入输出 schema 和恢复策略；工坊首页与任务中心已删除前端静态业务清单，改读同一目录。
- `domain/tool_execution.py` 已成为 REST、图片、视频、Canvas 与 Workflow 的统一执行入口，负责 manifest 操作校验、输入 schema、冻结快照、领域任务创建、队列映射、入队失败归一化和重试映射。
- 工作流输入已统一为图片、视频、音频、文件 typed reference；界面选择、REST 提交和执行器解析使用同一合同。
- `StudioFlow` / `StudioFlowRun` 与 DAG 编排器已落库：定义做无环和直接依赖校验，运行冻结版本快照，按就绪节点并行启动，节点 checkpoint 持久化，并支持重试、取消、成功 checkpoint 续跑、子任务收养与 worker 启动恢复。一次性 inline run 允许画布冻结当次拓扑而不制造用户可见的永久工作流。
- DAG 输入表达式已有 `$incoming/$concat/$coalesce/$replace/$artifacts`，可把异构任务结果归一成图片、视频、音频和文件引用；`image.auto` 延迟到输入解析后再选择生成/编辑。同一运行内解析后请求签名相同的图片节点共享一个任务，但保留逐节点 checkpoint 与画布落点。
- 工坊已增加 DAG 编排页面，可编辑插件/操作节点、输入引用与边，启动后轮询 checkpoint，并执行重试或取消。
- Infinite-Canvas JSON/ZIP adapter 已能识别两类源格式，把打包资源按 SHA-256 重建为 portable ref，转换源节点与连接，同时对保留的 `source_payload` 做密钥脱敏。
- 跨工具 `asset` 接续、画布 `⌘X`、视频抽帧页面和 Infinite-Canvas v2.1 的 10 条提示词模板已经补齐；迁入模板通过接口和 UI 保留来源。
- 画布项目实体、默认项目、CRUD/计数/删除回迁、按项目筛选、跨项目剪切粘贴和 `classic/smart` 类型已经落库；CanvasBoard 按类型使用源项目的两套框选/切线键位。
