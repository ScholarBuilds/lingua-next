# 扩展与例程

CR-007 立的模块 22。工作台的可扩展性落成三件事：**一份 manifest** 说清一个扩展贡献了什么、
要什么权限；**一张表**把内置模块、本地目录扩展、MCP 服务器、例程列在一起；**一个滴答**让
时间表进库、扩展能声明自己的定时任务。

> [!info] 本期是声明式扩展，不是代码包
>
> 本地扩展只认 `manifest.yaml`（命令、页面、MCP 服务器、例程），改完点「重新扫描」就生效。
> 带 worker 函数的代码包（调研 §5.8「两级」里的第二级）没做：现在没有第一个真实需求，
> 先把合同与页面立住。内置模块也按同一份 manifest 登记，扩展页里「阅读」和「示例扩展」是同一张表。

## 1. 业务规则

| 编号 | 规则 |
| --- | --- |
| BR-22-01 | 贡献点九类（`CONTRIBUTION_POINTS`）：导航页、⌘K 命令、助理工具、画布节点、设置项、后台任务、例程触发器、数据表、凭据类型；权限四类（`PERMISSIONS`）：网络、凭据、屏幕与输入、文件 |
| BR-22-02 | 内置模块的贡献数从真实登记处取（助理技能层的 `TOOL_CATALOG`、内置例程数），不手抄；手写的数字只允许出现在没有登记处的项上（节点、后台任务、数据表）。旧电脑操控执行器的 12 个工具随 CR-010 M7 退场，内置清单里的「电脑操控」改指贾维斯——引擎侧工具经门代理 MCP 提供，不在助理目录里计数 |
| BR-22-03 | 本地扩展缺一项权限就不就绪（`needs_permission`），页面上点一下授予；内置模块不用授 |
| BR-22-04 | 坏的 manifest 也要列出来（`invalid` + 原因），不能让一个坏文件藏起整个目录 |
| BR-22-05 | MCP 工具集只来自**就绪**的扩展，惰性连接（跑代理时才起进程 / 建连接）；工具名带扩展 id 前缀免撞名；连不上的扩展跳过，不拖垮整轮对话。这里说的是**助理侧**扩展 MCP（PydanticAI `MCPToolset`）；贾维斯引擎侧的 MCP 是另一套——`/mcp`（Lingua）、`/mcp/desktop`（cua-driver）、`/mcp/browser`（agent-browser）三个门代理由 `build_engine_config` 注入引擎，不走扩展清单（CR-010 D-3）。助理的 `computer_task` 只把目标交给全局贾维斯会话并排队，不另开会话 |
| BR-22-06 | 例程按 key upsert：标签 / 类型 / 提示词 / 来源跟声明走，**时间表与开关一旦入库归人管**；声明里消失的扩展例程标停用而不删（产出还在） |
| BR-22-07 | 到点判定：上一次该触发的时刻晚于 `last_run_at`；从没跑过的只补 5 分钟内错过的一次，不把几天前的都补跑 |
| BR-22-08 | 例程失败也记一条产出（`last_status=failed`，文案带原因），页面看得见 |
| BR-22-09 | 扩展页里的「测试」只做连接与列工具，不调用任何工具 |

## 2. 功能需求

| 编号 | 需求 | 落点 |
| --- | --- | --- |
| FR-22-01 | `GET /extensions`（清单 + 状态 + 贡献点与权限字典）、`POST /extensions/rescan`、`PATCH /extensions/{id} {enabled, granted}`、`POST /extensions/{id}/test` | `app/routers/extensions.py` |
| FR-22-02 | `GET /routines`、`PATCH /routines/{key} {enabled, schedule, speak}`、`POST /routines/{key}/run`、`GET /routines/{key}/runs`；助理页沿用的 `/assistant/routines*` 转到同一份 | 同上、`routers/assistant.py` |
| FR-22-03 | manifest 模型（`ExtensionManifest`：id / name / kind / version / description / contributions / permissions / mcp / routines / default_enabled）；本地目录 `data/extensions/<id>/manifest.yaml` | `domain/extensions.py` |
| FR-22-04 | MCP：`mcp.transport ∈ stdio / http`，经 PydanticAI `MCPToolset`（fastmcp 传输）挂进助理代理 | `domain/extensions.mcp_toolsets`、`domain/assistant.run_turn(toolsets=)` |
| FR-22-05 | 例程表 `routine`（kind `brief` / `prompt`，schedule `HH:MM` 或五段 cron）；worker 每分钟 `run_due_routines`：同步声明 + 跑到点的；早报改走这里 | `domain/routines.py`、`worker/tasks.py` |
| FR-22-06 | 扩展页 `/extensions`：扩展栏（分类筛选、贡献 chip、权限 chip 可点授予、状态、启停、测试、三张「怎么加」卡）；例程栏（时间表可改、开关、念出来、现在跑、上次产出可念） | `features/extensions/ExtensionsPage.tsx` |
| FR-22-07 | 导航「助理」组加「扩展」；⌘K 页面「扩展」与「例程与时间表」 | `App.tsx`、`commandItems.ts` |
| FR-22-08 | 示例扩展 `data/extensions/example/manifest.yaml`（默认关着，演示命令 / 例程 / MCP 三段写法） | 仓库内 |

## 3. 不做的

- 代码包扩展（带 worker 函数、需要重启）：等第一个真实需求。
- 画布节点 / 设置项 / 数据表由扩展贡献：合同里留了计数位，运行时还没有装载点。
- MCP 出口（把工作台工具给别的客户端）不在这里：那是 ADR-010 的 `app/mcp_server.py`，早就有；贾维斯引擎的三个门代理同理（ADR-010 修订 1）。

## 4. 实施记录（2026-09-02，CR-007 P6）

- `domain/extensions.py`：manifest pydantic 模型、内置清单、目录扫描、状态合并、MCP 工具集、探活。
- `domain/routines.py`：`cron_of` / `describe` / `is_due` / `sync` / `run_routine` / `run_due`；`RoutineSpec` 供内置与扩展声明共用。
- 依赖：`pydantic-ai-slim[mcp]`（带来 `fastmcp-slim`，Apache-2.0）、`croniter`（MIT）显式声明；两者登记在开源复用清单。
- 表 `extension_state` / `routine`（迁移 `c7d8e9f0a1b2`）。
- 测试 `tests/test_extensions.py`（10 条）：manifest 解析与拒绝、目录合并与状态、权限门、例程跟随扩展就绪与人改优先、时间表解析与到点、滴答跑早报与提示例程、失败记录、MCP 工具集形状、助理代理接 toolsets、探活失败报错。

**踩坑**

- **croniter 的 `get_prev` 取严格早于基准的那一次**：基准正好落在整分（07:30:00）时拿到的是昨天的 07:30，判成「早已错过、不补」。基准加一秒。worker 滴答在每分钟第 5 秒跑本来不会撞上，但手动触发与单测会。
- **例程端点在表还没同步时 404**：worker 没跑过、扩展页没打开过，`routine` 表是空的；助理页「现在生成」直接打 `/routines/morning_brief/run` 就找不到行。取行的地方先同步一次再找。

**门禁**：ruff 0 · pytest 全绿（+10）· tsc 0 · vitest 1440 · check:css 通过（69 文件）· 迁移已在本机库执行 · 浏览器看过扩展页两栏（8 个内置 + 1 个示例，示例缺权限 / 已停用两种状态都显示）。

**留给 scholar**：真实 MCP 服务器一个都没接（示例里的 filesystem server 是注释掉的写法）；接的时候把 manifest 的 `mcp:` 段放开、在扩展页授网络权限、点「测试」看工具数，然后直接对助理说话就能用。
