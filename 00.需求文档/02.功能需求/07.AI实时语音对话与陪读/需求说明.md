# AI 实时语音对话与陪读

## 1. 模块目标

提供对标 ChatGPT 语音模式的英语陪练：亚秒级首响、随时打断、自由话题与场景对话；阅读文章时 AI 持有全文上下文，随口提问语法词义即时应答；会话内容沉淀为学习资产。

## 2. 功能需求

### 2.1 实时对话

- FR-01 会话准备：选模式（自由话题/预设场景/角色扮演）、难度（词汇复杂度与语速）、双语辅助强度（纯英/关键处中文/双语）；展示预计供应商与预估费用级别。
- FR-02 实时交互：自动回合检测（VAD）+ 可选按键说话；用户可随时打断（barge-in），打断后 AI 200ms 内停声且旧回合输出不覆盖新输入。
- FR-03 实时字幕：双方语音增量转写显示；可选逐句中文提示、关键词标注、口语纠错提示（不打断对话流，会后汇总）。
- FR-04 会话控制：最长时长与空闲超时（默认 30 分钟/3 分钟，可配）；到点提醒并安全结束；网络抖动显示重连状态，超恢复窗口安全结束。
- FR-05 会话结束四项清理：关麦克风、停音频、失效 ephemeral token、关远端会话；随后生成结构化记录。

### 2.2 AI 陪读

- FR-06 阅读器内唤起陪读：建立会话时注入当前文章全文（超长取当前章节 + 摘要）与阅读位置；阅读器滚动经 data channel 增量同步位置。
- FR-07 陪读提问模式：语音或文字问"这句什么语法/这词什么意思/这段讲了什么"，AI 基于全文上下文回答；产生的单词/语法解释按 ADR-006 落库，与点按分析共享缓存。
- FR-08 陪读可切换纯文字模式（不开麦克风，打字问答，流式回复）。

### 2.3 学习沉淀

- FR-09 会后结构化记录：完整转写（双方分轨）、重点词组、口语纠错汇总（语法/用词/表达三类）、可复听的关键片段；生词一键入词库。
- FR-10 会话历史可回放浏览；可删除整次会话或仅删原始音频（转写保留，生命周期解耦）。

## 3. 业务规则

- BR-01 打断语义硬约束：用户开口即打断，旧语音立即停止，服务端丢弃未播放的旧回合音频。
- BR-02 ephemeral token 由 api 签发、单会话有效、不复用于其他能力；长期密钥不到达浏览器。
- BR-03 断线重连不产生重复会话与重复计费（会话 ID 幂等）。
- BR-04 会话必须有服务端强制的时长与费用上限；达上限提醒后停止新回合，不静默续费。
- BR-05 纠错反馈标识为 AI 生成；不提供音素级发音评分（明确超出范围，不由通用模型臆测）。
- BR-06 选择的模式不可用时（如 Realtime 网络不通）明说原因并给替代（文字陪读/降级管线），不静默降级。

## 4. 实现方案

> [!info] 双轨制详见 [ADR-005](../../../01.项目文档/02.架构/ADR/ADR-005-实时语音对话方案.md)

| 部件 | 方案 | 说明 |
| --- | --- | --- |
| 主路径 | OpenAI Realtime API（gpt-realtime / gpt-realtime-mini），浏览器 WebRTC 直连 | 延迟最优；mini 档约 $10/$20 每百万音频 token，常规对话 $0.05-0.10/分钟 |
| 会话签发 | api 服务 `POST /talk/sessions`：注入场景 prompt、难度指令、陪读上下文，返回 ephemeral token + SDP 配置 | instructions 模板版本化 |
| 转写回传 | Realtime 转写事件经 data channel 收集，会话结束 api 落库 | - |
| 备选管线 | pipecat：Silero VAD + faster-whisper 流式 + LiteLLM 任意模型 + TTS | 触发条件见 ADR-005 |
| 场景库 | 首批 10 个场景（问候/点餐/问路/酒店/面试/会议/机场/购物/就医基础用语/电话），YAML 数据化，含角色设定、目标任务、关键句 | 内容规则见 08 模块 |
| 前端 | `RTCPeerConnection` + 音频可视化（说话状态指示）；连接状态机（准备/连接中/聆听/AI说话/重连/结束） | 状态机继承旧版 |

## 5. 验收要点

- AC-01 中国大陆网络实测：首响 P50 < 1s、P95 < 2s；打断生效 < 200ms（不达标则触发 ADR-005 备选评估）。
- AC-02 连续对话 10 轮无中断故障；断网 10s 内重连恢复，会话不重复计费。
- AC-03 陪读模式下询问当前段落语法，回答与所指段落一致（上下文注入正确）。
- AC-04 会后记录含完整分轨转写与纠错汇总；删除音频后转写仍在。

# v2 修订：陪读上下文显式化与驻页化（2026-08-17，真实使用反馈驱动）

> [!info] v2 触发背景
>
> scholar 使用中提出两点：① 视频页「AI 陪读」跳转到自由话题页，应当像文章页一样驻页；
> ② 点句同时触发朗读与 AI 感知，"我想听这句"和"我想问这句"被绑成一个操作。
> 排查后确认后者是隐式上下文收集，与业内已收敛的显式范式相悖，一并重做。

## 6. 陪读上下文显式化（v2 核心）

### 6.1 问题实证

`useInlineVoiceCompanion` 订阅 `readerStore.selection`，只要选中变为句子就把该句发给 AI。
而「点句」这一个操作同时承担三件事：

```
点句 ──┬─→ 定位 / 朗读        （只想听）
       ├─→ 右栏出句面板        （只想看翻译）
       └─→ 悄悄注入 AI 上下文   （并没想问）  ← 问题所在
```

后果：AI 被无关句子刷屏（3 秒节流只是缓解）；用户无从知道 AI 此刻"看着"哪句，也无法撤回。

### 6.2 业内范式

| 产品 | 上下文加入方式 |
| --- | --- |
| VS Code Copilot | 选中代码 → **Add to Chat**，以引用卡显示在输入框上方，可移除 |
| JetBrains AI / Trae | 右键菜单 / 高亮后 "Add to chat" |
| Contexty（arXiv 2604.11067） | @-mention 或显式 "Add to Chat" 引入记忆 |

共识：**上下文的加入必须显式、可见、可移除**；隐式收集（implicit context gathering）是公认反模式。

### 6.3 需求

- FR-11 点句只做定位与朗读，不再自动注入 AI 上下文；移除 selection 订阅链路（不保留开关，隐式收集本身即反模式）。
- FR-12 每个学习句（视频）/ 句子（文章）的操作行新增**「问 AI」按钮**，点击即把该句显式加入陪读上下文；陪读未开启时先起会话再加入。
- FR-13 陪读面板顶部显示**上下文引用卡**：列出当前已加入的句子（带序号与时间戳/段落号），每张可单独移除，支持叠加多句（对比两句用法）。
- FR-14 正文与字幕支持**拖选任意文本 → 浮动工具条**（问 AI / 查词组 / 收藏），覆盖半句、跨句与任意片段（Kindle / Readwise 同范式）。
- BR-07 引用卡是上下文的唯一事实来源：AI 收到的就是卡里列出的内容，不多不少；清空引用即回到全文级泛聊。

## 7. 视频页驻页陪读

- FR-15 视频学习页右栏新增**「AI 陪读」模式**（与现有八模式并列成为第九个），切过去即陪读面板，不跳转 `/talk`。
- FR-16 陪读面板含实时字幕（复用文章页 `CompanionPanel` 的语音链路与顶部字幕区），视频页不带看板娘。
- FR-17 会话建立时注入 `video_id`：全片字幕（按语法句拼装）+ AI 摘要 + 当前学习句位置（已由 FR-34 后端支持）。

## 8. 陪读增强（v2 增补）

- FR-18 **快捷追问芯片**：AI 回答后给出三个一键追问（"再简单点"/"举个例子"/"这词还有别的意思吗"），降低口语组织成本。
- FR-19 **问答留存与回顾**：语音陪读的双方转写落库，会话可回看；单条 AI 讲解可一键存为该句笔记（与阅读器批注同一体系）。
- FR-20 **生词联动**：陪读回复中的英文词可点，一键入 FSRS 生词本并带上视频/文章出处（出处字段已具备）。
- FR-21 **AI 主动检验**：连续学完 N 句后 AI 主动发起一次检验（问刚讲过的词组，或让学习者复述该段），可在陪读面板关闭。
- FR-22 **跟读点评接入陪读**：跟读比对结果（`POST /study-units/{id}/shadow` 的漏读/错读词）交给陪读 AI，由它口头点评并给纠正建议。
- BR-08 主动检验不打断正在进行的问答，仅在用户空闲且未播放时发起。
- BR-09 陪读中产生的词汇与语法解释按 ADR-006 落库，与点按分析共享缓存（FR-07 不变）。

## 10. 陪读语音优先化（v11.2 · scholar 实测反馈）

三处陪读原本长得不一样：文章页是「输入框打字 + SSE 流式回答」外挂一块语音字幕，视频页是语音优先，
场景短文页直接复用了文章页那套。既然叫陪读，就该开口说话——**输入框整块去掉**，
文字通道只保留快捷提问，经同一条 realtime 会话下发（`ChatTextQuery`），与语音共享上下文。

- FR-282 陪读面板收敛为单一实现 `features/companion/VoiceCompanion`，文章 / 场景短文 / 视频三处共用，差异只有绑定对象、空态文案与快捷问法。
- FR-283 **去掉输入框**。文章页原有的 SSE 文字问答链路（`createCompanionSession` / `askCompanion`）连同 `.cp-*` 样式一并下线，不再维护第二条问答通道。
- FR-284 空态是一次邀请而非一行灰字：居中大按钮（点它即开说）+ 学习对象名 + 该页取词方式说明 + 3 个开场问题 + 往次记录折叠。
- FR-285 **开场问题从空态就能点**：点了先建会话，连上后自动补发该问题，用户不必先点开始再想问什么。
- FR-286 会话中底部常驻快捷追问芯片（FR-18 的落地形态），标签写「说不出来时点一下」——它存在的理由就是口语卡壳。
- FR-287 大按钮外环随 AI 下行音量涨落（`getVoiceLevel`），静态图标看不出 AI 是否真的在出声。
- FR-288 会话结束后字幕留在原地并给「再聊一会」，不清空、不跳走。

## 11. 引用不抢答（v11.3 · scholar 实测反馈）

点一句话，AI 立刻开讲——用户根本没问。根因在协议语义：火山的 `ChatTextQuery(501)`
就是「用户说了这句话」，模型收到必答；而前端把引用卡的新增直接当成 ChatTextQuery 发了出去。
FR-293 让阅读位置自动进引用卡之后，这个问题从「点句偶发」变成了「读到哪响到哪」。

- FR-311 **加引用不发送**。引用只是「AI 待会儿要看的」，攒在客户端；随下一次用户提问一并送出，送出后标记 `sent`，不重复带上。
- FR-312 引用卡上标出状态：未发出的写「待随提问发出」，已发出的写「已发给 AI」并转灰。卡在面板里 ≠ AI 已经知道了，这件事必须可见。
- FR-313 引用区给一键问法（「这句什么意思」「拆一下这句的语法」「这句怎么读才自然」），省掉「我说的是哪句」这一步。
- BR-10 只有用户真的在提问时才向上游发 `ChatTextQuery`；任何「让 AI 知道点什么」的需求都不得借用这条通道。

> [!warning] 语音提问带不上引用
>
> 语音走的是音频上行，前端没有插入文本的时机——用户开口时模型已在处理。
> 所以**引用只在文字通道（快捷问法、引用区一键问法）生效**；纯语音提问时 AI 只有会话建立时注入的全文，
> 不知道「这句」指哪句。UI 因此把一键问法放在引用卡旁边，作为语音之外的指定入口。

## 9. v2 验收要点

- AC-05 点句不再触发 AI 感知；点「问 AI」后引用卡出现该句，AI 的回答确与该句一致。
- AC-06 引用卡可移除；移除后追问该句，AI 不再持有该上下文。
- AC-07 视频页右栏「AI 陪读」不跳转，实时字幕可见，AI 开场白引用本视频标题。
- AC-08 拖选半句 → 浮动工具条问 AI，回答针对所选片段而非整句。
- AC-09 跟读比对结果交给陪读后，AI 点评点名具体的漏读/错读词。
- AC-10 陪读面板不含任何输入框；文章、场景短文、视频三页的面板结构与交互一致。
- AC-11 空态点开场问题 → 会话建立 → AI 直接回答该问题，无需二次操作。
- AC-12 会话中点快捷追问，AI 的回答针对该问题，且与语音在同一条会话里连续。
- AC-13 陪读会话进行中连点多句，AI 不产生任何回答，引用卡随之更新为最后点的那句。
- AC-14 点引用区的一键问法，AI 的回答针对该句，卡片转为「已发给 AI」。

## 实时对话数字人

- 实时对话中央默认显示本地 VRM 骨骼人物，可切换简洁模式；不使用静态肖像。保持现有会话、音色、模型服务和右侧学习辅助，不新增数字人云服务，不额外上传音频。
- 口型从实际播放输出采样，不从麦克风、字幕字数或排队音频估算。打断后闭嘴，静音时不持续张嘴；通过音量和频谱驱动元音表情，不宣称逐音素同步。
- 人物提供眨眼、轻微呼吸、倾听/思考表情、有限视线跟随和头发物理；遵循减少动态效果偏好，隐藏页面暂停渲染。
- 数字人与简洁模式可切换并记住选择。切换不重建语音连接，不清空字幕；关闭时释放渲染器、纹理及帧循环。
- 资源或 WebGL 失败时显示明确提示和重试入口，语音与字幕仍可继续。人物、字幕和右栏各自保持有界布局。
- 仅随包携带已确认可分发的模型，固定来源提交及校验和；非商用演示资源不进入安装包。

验收覆盖实际模型渲染、合成音频驱动与打断、资源故障、装卸清理、减少动态效果和不同窗口尺寸。真人麦克风与云端模型回合需单独进行声音验收，不由视觉测试代替。
