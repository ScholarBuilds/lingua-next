# 目标用户与核心旅程

## 1. 目标用户

首位且唯一验证用户是 scholar 本人：开发者背景、英语阅读与口语提升需求、自部署能力强、对工具的响应速度与可解释性敏感。产品验证成立后再考虑多用户化。

## 2. 核心旅程

### 旅程 A：读一本书

打开书架继续上次进度 → 逐句精读，生词点一下出卡（音标秒出、AI 语境义流式补充）→ 难句点行号看语法结构 → 顺手收藏生词 → 读完一章合上，进度自动保存 → 次日复习队列出现带原句的生词。

### 旅程 B：看一条 YouTube 视频

粘贴 URL → 后台下载转写（进度可见）→ 双语字幕跟着视频走 → 听不清的句子点字幕回跳重听 → 生词点击暂停查卡收藏 → 逐句精听模式过一遍难段。

### 旅程 C：跟 AI 练口语

选"机场值机"场景 → 语音对话，AI 扮演地勤 → 说错被温和继续（纠错会后汇总）→ 随时打断改问"刚那句怎么说更地道" → 结束后看纠错汇总，生词一键入库。

### 旅程 D：背单词

打开考研词表 → 看词识义三档反馈 + 拼写练习 → FSRS 排明日队列 → 从书里、字幕里收藏的词混入队列，卡片带原句能跳回出处。

## 3. 旅程对体验的硬要求

- 点词秒出（本地词典先行），AI 慢字段流式补充，不阻塞阅读节奏。
- 查过的东西永远不用等第二次（持久化缓存）。
- 语音对话打断要跟真人对话一样自然（< 200ms 停声）。
- 后台长任务（下载/转写/整篇翻译）不打断前台学习，进度可见可重试。
