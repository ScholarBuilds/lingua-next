# 核心业务规则与状态机

> [!info] 继承说明
>
> 状态机与全局规则继承自旧版 `03.业务规则与状态机`，删除 macOS 专属项（签名分发、屏幕权限、划词取词），按单用户 Web 形态改写。任何实现都必须能表达进行中、部分成功、失败、取消和重试，不能只用一个成功布尔值。

## 1. 全局业务规则

- BR-G-001 原文、词典事实、供应商翻译、AI 解释、用户笔记必须保留内容类型与来源标识，UI 上可区分，不把 AI 推断冒充词典事实。
- BR-G-002 一次操作触发多个外部调用时，界面显示整体状态和子能力状态（如：词典已出、AI 释义生成中、TTS 失败可重试）。
- BR-G-003 自动重试有上限，且不产生重复计费、重复收藏、重复导入（幂等标识）。
- BR-G-004 AI 输出结构校验失败或与词典事实冲突时进入部分成功，不静默覆盖可靠数据。
- BR-G-005 所有 AI/翻译产物按 ADR-006 指纹寻址持久化；同一寻址键不重复调用供应商，除非用户显式重析。
- BR-G-006 供应商配置（LLM 别名、翻译引擎、TTS 音色）数据库化、版本化；配置缺失或校验失败时使用安全默认值，不解释为"全部开放"。
- BR-G-007 预处理（清洗、断行合并）只作用于提交给供应商的文本；展示与落库使用未经预处理的原文，保证点词偏移不错位。
- BR-G-008 英中两个方向分别维护供应商能力与质量记录。
- BR-G-009 删除操作区分结构化记录与原始媒体，说明影响范围；原始媒体到期删除不连带删除结构化学习资产。
- BR-G-010 客户端不持有长期供应商密钥；实时语音短期凭据不复用于其他能力。
- BR-G-011 **可见状态必须能由 URL 复现**：用户看到的是哪个页面、哪个本、哪个页签、哪组筛选，刷新后应原样回来。视图状态放组件局部 state 等于「刷新即丢」，是缺陷不是取舍。
- BR-G-012 **深链进入的页面必须给返回上级的入口**。浏览器后退在深链首屏无处可退（history 里没有上一页），页面自身要提供去处。
- BR-G-013 **写操作换来的会话数据在客户端持久化**：像「领取一批新词」这种一调用就落库、重调只会换来新数据的接口，其结果必须存进 `sessionStorage`，否则刷新就把已领取的批次丢在半路。

## 1.1 交互与呈现通则

> [!warning] 这些规则本来散在各功能模块里
>
> BR-G-014 起的这批，最初写在 09 视频模块（BR-73~86）与 01 词库模块（BR-55~57 等）的文档里。
> 但它们讲的是「产品里任何地方都该这样」，写在单个模块下等于**做别的模块时翻不到**——
> 词库、阅读器、管线各自重新踩一遍。凡是不依赖某模块领域概念的规则，一律升到这里。

### 朗读与播放

- BR-G-014 产品内**任何位置**出现的英文句子都可朗读、词都可点查；在弹窗里不降级成纯文本。可朗读文本块的热区是**整块**，不是那个小喇叭图标。
- BR-G-015 播放/暂停控件的语义是**续播**而非重播，除非用户点的是明确的「重播 / 从头」。
- BR-G-016 播放类按钮必须有**播放态**且可暂停——图标变了就得真能停。
- BR-G-017 播放"某一句"一律走**片段机制**（播到句尾即停），不用裸 `play()` 让它一路往下播。
- BR-G-018 **浮层关闭即停止它触发的一切播放**。常驻型浮层（栈空只 `return null`、组件从不卸载的那种）按**打开态**判定，只挂卸载清理等于没挂。
- BR-G-019 与媒体时间轴绑定的效果（逐词高亮等）必须复用**该媒体自身的时间戳**，不另起音源——另合成一段音频时间轴对不上，效果必然漂。

### 浮层与提示

- BR-G-020 被其他层唤起的浮层（如词卡）层级必须**高于唤起它的那一层**。新增弹层对照全局层级表（见 [设计系统](../../01.项目文档/03.UI设计/01.设计系统.md)），不各写各的 z-index。
- BR-G-021 交互提示走**全局委托**：写 `title` 即得即时提示，不要求每处改用专门组件，也不依赖原生 title 那一两秒的延迟。图标型操作同时给 `aria-label`。

### 内容呈现

- BR-G-022 AI 生成的文本一律经**统一 Markdown 渲染器**输出；不再有第二套解析实现，也不用纯文本兜底（`**粗体**` 会原样露出来）。
- BR-G-023 嵌进既有版面的新区块**跟随宿主的表达方式**：文字流里就用排版，不要突然插一排带框控件。
- BR-G-024 同一份信息不在同一屏出现两次。

### 前端实现约束

- BR-G-025 依赖 `requestAnimationFrame` 的持续效果要配事件兜底（如 `timeupdate`）：页签不可见时 rAF 被浏览器整体冻结，只挂 rAF 会直接停摆。
- BR-G-026 逐项推进的异步循环必须带**中断标志**：用户的新操作压不住旧循环，除非显式检查。
- BR-G-027 覆盖既有类的样式要带上被覆盖类**提高特异性**（`.overlay-card.ss-card`），不依赖 CSS 导入顺序决胜。
- BR-G-028 快捷键方案**照抄业内既有键位**（Anki / Quizlet 等），键盘注册用成熟库，不手搓全局 keydown。


## 2. 状态机清单

### 2.1 分析任务（点词/句子分析/翻译共用）

```
空闲 → 提交 → 缓存命中? ──是──→ 结果可用
              └─否──→ 本地词典即时展示 → 远程生成中(流式) → 结果可用 / 部分成功 / 失败可重试
任何进行中状态 → 已取消
结果可用 + 用户重析 → 远程生成中(新version)
```

- `结果可用`只表示核心内容可读，词典/AI/音频字段可分批到达。
- `部分成功`：词典命中但 AI 失败、翻译成功但 TTS 失败等，失败子项单独标识、单独重试。

### 2.2 长任务（视频入库/书籍入库/整篇翻译/整篇朗读合成）

```
已创建 → 排队中 → 执行中(阶段进度: 下载→抽音→转写→入库) → 完成 / 部分完成 / 失败可重试
执行中 → 已取消（停止未开始的阶段，保留已完成产物）
失败可重试 → 从最近完成的阶段断点续跑
```

- 阶段进度经 Redis 发布，前端 SSE 订阅；每阶段产物独立落库（下载完成的视频不因转写失败而丢弃）。

### 2.3 实时语音会话

```
空闲 → 会话准备(选场景/角色/难度) → 签发凭据 → 连接中 → 聆听 ⇄ 用户发言 ⇄ AI发言 → 正常结束
异常 → 重连中 → 超恢复窗口 → 异常结束
任何结束路径 → 四项清理：关麦克风、停音频播放、失效短期凭据、关远端会话 → 会后落库(转写/生词/纠错)
```

- 用户打断后旧 AI 语音必须停止，旧回合输出不得覆盖新输入。
- 会话必须配置最长时长与空闲超时，到点提醒并安全结束。

### 2.4 点词学习

```
未选择 → 词元已选择 → 词典即时可见(+缓存AI字段) / AI生成中 → 学习卡完整 / 部分可用 / 无结果
学习卡任意可用态 → 用户主动收藏 → 进入生词本(带原句语境)
生词本 → 完成学新词 / 主动加入学习计划 → 初始化FSRS卡 → 进入复习队列
```

- 点词本身不自动收藏；无结果时说明原因并给候选词形。
- 收藏和调度是两个独立操作。新收藏的 `fsrs_card` 和 `due_at` 均为空；已有调度记录不因再次收藏而重置。
- 同一单词可保留多个来源语境。同一内部来源指纹幂等；定位信息只保存文章、句子、视频、字幕、会话、轮次、词书、词条、训练和题目等稳定内部标识，不保存任意外部 URL。

### 2.5 复习调度（FSRS）

```
新词 → 学习中 → 复习中(FSRS间隔) → 已掌握(长间隔维持)
复习中 --遗忘--> 重新学习 → 复习中
任意状态 → 已暂停(用户挂起) / 已移除
```

- 评分档位与调度参数遵循 py-fsrs 默认，复习日志全量保留（未来参数优化的训练数据）。

### 2.6 词库导入

```
待选择来源 → 解析中 → 待确认(展示新增/重复/失败统计) → 导入中 → 完成 / 部分完成 / 已取消
```

- 用户确认前不写库；重复词条默认合并不覆盖学习进度。
