## M36 局域网联调与麦克风安全上下文（2026-08-19）

- ✅ vite `server.host: true` 开放局域网访问。后端不跟着暴露：前端一律走相对路径 `/api`，由 vite 代理转发到回环地址上的 8100，WebSocket 同理（`ws: true`），少开一个对外端口。实测局域网直连 8100 不通。
- ✅ `LAN_HTTPS=1` 开关启用 `@vitejs/plugin-basic-ssl` 自签证书。做成开关是因为自签证书每换一个浏览器都要点一次「继续前往」，平时本机开发没必要吃这个成本。
- ✅ 新增 `lib/mic.ts` 统一取麦克风入口，四处调用点收敛过去。

> [!warning] 局域网 http 下麦克风必然失败，且原提示会把人带偏
>
> 浏览器只在**安全上下文**（https 或 localhost）挂载 `navigator.mediaDevices`，`http://<IP>` 不算。
> 非安全上下文下它是 `undefined`，取 `.getUserMedia` 抛的是 **TypeError 而不是 DOMException**——
> 而 `MicCapture.start` 的 catch 只认 `NotAllowedError` / `SecurityError` / `NotFoundError`，
> TypeError 落进兜底分支提示「麦克风启动失败，请检查设备与浏览器设置」，
> 测试的人会去翻设备和权限，那边根本没问题。已改为先判断 `isSecureContext` 并直接说明真实原因与出路。

> [!note] 沙箱内 curl 走 HTTP 代理，https 到局域网 IP 会假失败
>
> 验证时 `curl https://<IP>:5173` 返回 000，但 `openssl s_client` 到同一地址能拿到证书、
> `https://localhost` 也是 200——是 curl 经代理 CONNECT 隧道后 TLS 握手超时。
> 测局域网地址一律加 `--noproxy '*'`，否则会误判成服务端问题。

### 决定性的实测与数据

| 事实 | 影响 |
| --- | --- |

### WebGL 的结论：不上

Massaro & Light (2003) 实验：11 名日语母语者练 /r/-/l/，「透明脸看舌头」相对普通正面视图
**无显著优势**。three.js 178.5KB gzip 是 wavesurfer 的 15 倍——花 15 倍 bundle 买一个已发表的 null result。

但不等于不要动画：Höffler & Leutner 的 d=0.37 来自**表征性动画 + 程序性知识**，
一个音配 2-3 张 CC0 剖面图做离散切换就吃到了；而 Mayer coherence 原则 + Rey (2012) 说明
**炫技视觉是负分不是零分**（对迁移有中等负效应）。

### 校准当场推翻了准确度算法的第一版

这是这一轮里最值得记的一件事：**校准不是走过场的最后一步，它当场证伪了一个算法选择**。

第一版的 accuracy 用 CTC 对齐置信度，speechocean762 300 条实测 ρ = **0.246**，
远低于 OpenPronounce 的 0.65 锚点。按 FR-399c 该改特征不该改常数，拆开信号才看清：

| 信号 | ρ（两轮） |
| --- | --- |
| 仅 CTC 对齐置信度 | 0.154 / 0.229 / 0.258 |
| 仅 GOP 均值 | **0.591 / 0.608 / 0.588** |

CTC 对齐置信度衡量的是「音频与参考文本对不对得上」，不是「每个音读得有多像」。
后者是 GOP 的事，而第 2 层早把 GOP 算出来了，只是没用进分数。
**上线口径（仅 GOP，n=200）ρ=0.586**，从 0.246 起步，这一段全部来自换特征。

中途试过 0.65 / 0.79 两档加权融合，**两轮里融合分都低于单用 GOP**，
于是句子级准确度只用 GOP，CTC 留在词级置信度展示与音素级交叉验证这两处它确实有用的地方。
权重的每一次改动都有对应的实测行，没有一个数是调出来的。

顺带发现界面上显示的是内部原始分：34.3 看着像不及格，按拟合系数换算到专家刻度是 6.85/10。
现在 `accuracy`（原始，校准脚本拟合用）与 `accuracy_calibrated`（显示用）分开，
换算在**读取时**做不落库——系数会变，原始分不会。

### 一条被数据验证的预判

需求 §2 记过一条实测：用库里那条 accuracy 90% 的真录音跑 ctc-forced-aligner，
分数最低的 `challenge` 与 `failure` 正对应那 10% 没读对的部分。

需求里那句「词级发音置信度几乎零成本可得，只要不丢那个字段」是对的。

## M50 发音评分校准到人的水平 + 语法概念专栏（2026-08-19）

### 发音准确度 ρ 0.586 → 0.687

全量 2500/2500 条、跨说话人（官方划分说话人零重叠）。95% CI [0.626, 0.741]，
按说话人自助算——Fisher-z 的 iid 假设在 125 人 × 每人 20 句的语料上不成立，窄了 2.8 倍。

**参照系是自己算出来的**：官方论文只写「五位专家独立打分」没报一致性，
但每位专家的原始分随数据集发在 `resource/scores-detail.json` 里。
单个专家 vs **不含他自己**的四人共识 ρ=0.651，这正是模型所处的位置。
所以 0.687 的含义是「判卷跟一位人类考官一样准」，不是一个孤立的数。

四组新特征，每组都独立于 GOP：

| 组 | 单独 ρ | 独立在哪 |
| --- | --- | --- |
| 归一化 GOP | 0.592 | 把音素身份从质量信号里剥出来 |
| 帧级后验 | 0.573 | GOP 只看最强竞争者，这组看整个竞争格局 |
| 自由解码编辑距离 | 0.573 | 强制对齐 vs 自由解码，两条独立的路 |
| 时长 | 0.487 | 长短元音、吞音、辅音簇加音 |

三个弯路（细节在模块 13 §14.4.1）：`lpp` 线性可导等于没加；帧级统计不排除
CTC blank 量到的是「峰有多尖」；抽取按 `wav.scp` 顺序截断只拿到好学生。

三处方法学修正：选型从 test 移到 train 切出的验证集；CI 换按说话人自助；
折外堆叠改按说话人分桶。定稿时「秩+二次项」验证集最高（0.733），
但 test 上 0.690 vs 基线 0.687，CI 大面积重叠——**没拿可解读性换这 0.003**。

原规则要求「解析把握不足的构式命中不指概念」。实现完一测：
**2,376 条真实命中里 0 条低于门槛**，构造的各种脏输入也全在门槛之上。

### tag-question 规则重写，误报降了 89%

原规则「ROOT 是 AUX 且有代词 nsubj」两头都错：漏掉 `do you?`（do 被标成 VERB），
又把 `What a beautiful day it is!` 当成命中。真正的判据是**位置**——
附加部分的主语在助动词之后，主句在助动词之前。

还有第二个挂法：主句一复杂 tag 就从 ROOT 变成 conj，
所以 `build_matcher` 扩成一个 key 支持多个候选子图。

22 条正反例进单测。全语料重扫后，tag-question 命中 **20,209 → 2,241**，差掉的是误报。

### 两条被 agent 纠正的误判（记下来免得重复踩）
量化探针会把两类**设计使然**的情况报成缺陷，判据要先排除：
- `.cvc-node` 的 `scrollWidth > clientWidth` 不是内容溢出：output 节点多出的 8px 正是 `.cvc-port-out { right: -8px }` 的端口圆点，image 节点多出的 41px 是居中悬浮工具条两侧各探出的量（418/2 + 500/2 = 459，严丝合缝）。给 `.cvc-node` 加 overflow 只会把端口切成半圆、把工具条整条剪掉。**要量节点内容溢出请量内层 `.scv-node`。**

## M67 画布对齐蓝本：真比例显示 · 落点避让 · 分组 · 提示词库 · 编辑器重构（2026-08-23）

### 图片按真实长宽比完整显示
根因是 `object-fit: cover` + item 缺 w/h 时先摆成方框——竖图先被压成方块再被裁掉头尾，所以非得双击开弹窗才看得到全图。改 `contain` + 比例走 `itemAspect`（文档 w/h 优先，回落 onLoad 量到的）。多图网格列数由 `gridColumns` 内联（`repeat(N, minmax(0,1fr))`——`1fr` 的最小值是 min-content，图会把自己那列顶宽从而溢出节点）。
**量到的尺寸只留比例、不写回文档**，两条理由：① `naturalWidth` 在 srcset 场景返回的是**密度校正后的 CSS 尺寸**不是原图字节尺寸，写回 `item.w` 会毒到 `itemSrcSet` 的 full 档描述符，浏览器从此不再取原图、画布反而更糊；长宽被同一系数缩放，所以**比例是这里唯一量得准的东西**。② BR-143：写回等于打开旧画布图一加载完就产生脏改动与自动保存。
浏览器实测：14 个图节点渲染比与原图比逐一吻合（1.50/0.67/0.80/0.56），`object-fit: contain`。

### 生成时落点避让（蓝本没有这一层，新写）
蓝本建产出节点一律 `rect.x + width + 240`，谁在那儿都压上去；我方原来更糟——`generateFrom` 的分支节点恒落 `source.x + w + 80`，**同一节点连点两次出图，两张坐标完全一样、后一张把前一张盖死**。新增 `freeSpotFor` / `freeSpotsFor`（`PLACE_GAP=28`、`PLACE_BACKWARD_COST=1.6`）：**只挪新节点，一个已有节点都不动**——没有拿 `arrangeByConnections` 当避让用，那个会把整条链重排，用户正看着某处时整条链跳走是很糟的体验。
连带修：`landImageTask` 落 items 时补算节点宽度（协调方补的，见下）。

### 一键整理
顶栏按钮，选中链路上任一节点即可把整条链按连线排成从左到右的列。链路用 `clusterOf` 取（**历史归档边不算链路**——算进去的话整理一条跑过十几轮的链会顺手把十几个历史节点摊上来），排版复用 `arrangeByConnections`。禁用时 tooltip 说明前提而不是神秘置灰。

### 分组（抄蓝本并升级）
分组小菜单五动作照蓝本 `smartGroupToolbarHtml:8289`：整理排列 / 预览 / 宫格拼接 / 批量下载 / 解散分组，enabled 判据照抄（拼接要 >1 张）。预览与宫格拼接接编辑器，按组内顺序左右切换。
**并发出图收进分组做成默认关 + 画布上可勾**，理由记在 `batchGroupEnabled` 上：① 收进分组后图是 104px 缩略格，而留在产出节点里是 `mediaGridBox` 的 ≤220px 格——自动开等于把「让图都能看清」反着做；② 吸收是删原节点搬图、血缘边改接到分组，默默替用户做这个不可见重排、撤销一次未必回得来。**这一条与项目主人「人家并发生成是放到一个分组里」的观察不同，需要他确认要不要改成默认开。**

### 编辑器弹窗
- **AI 扩图双向对称**：`symmetric` 为真时两侧同时等量扩展。没照抄蓝本的「重新居中」——那样会把一键比例预设留下的不对称留白抹平。

- **切图到头停住不回绕**：回绕会让「一直按右」悄悄从最后一张跳回第一张，用户以为还在往后翻实际在看重复的图。
- **宫格拼接实装**：7 个纯函数 `joinAutoDims` / `joinCellSize` / `buildJoinLayout` / `joinCanvasSize` / `joinDropTarget` / `swapInOrder` / `joinOutputScale`，支持拖拽换位、来源可以是单节点或整个分组。
- 八个页签浏览器实测：预览/裁剪/画笔/遮罩重绘/AI 扩图/缩放/宫格切分七个都渲染出真实主操作；宫格拼接在单图节点上置灰是**正确判据**（`items.length > 1`，与蓝本 `imageCount > 1` 一致）。

D1 报了 blocker 但 D2 与门禁都没接：`landImageTask` 只加 items 不重算 `w`，空建的图片节点 `w` 恒为 `EMPTY_NODE_W`(420)，一张 9:16 的图撑成 420×747——比例是对的但节点过分高大、更容易压到邻居（蓝本 `singleImageLayout:1673` 是等比装进有界框）。补了 `widthForLandedItems`：**判据是「宽度还等于空态默认值」而不是「有没有 w」**，用户拖过缩放手柄的宽度是他自己定的，重算会冲掉。

## M69 输入框生成模式收口 · 三个弹窗重构（2026-08-23）

### 输入框：三个入口收成两个正交选择
收口前「出几张」这件事散在三处且互不知道对方存在：参数行的数字框（并发 N 张）、画布上的循环节点（串行）、动作行的「成套」按钮（AI 规划张数）。用户要出一套图得先在画布上画一个循环节点再连线。
现在输入框上只有两个选择：**出几张**（`1` / `多张 N` / `自动`）× **怎么跑**（`并发` / `串行`，**只在张数 > 1 时出现——隐藏不是禁用**，1 张时这个选择没有意义，摆一个点不动的控件只会让人猜为什么）。
三条链路**全部复用既有能力，一条都没重新实现**：并发 = `generateFrom` 的张数 N；串行 = `runSetPlan` 的 `intent:'consistent'`（上一张产物排进下一张参考）；自动 = 成套弹窗 → 同一个 `runSetPlan`。
关键发现：**串行不需要 loop 节点**——`runSetPlan` 的 consistent 语义与 loop `mode:'serial'` 是同一件事，而且它自带槽位复用（`slot_of`/`slot_round`）、服务端 checkpoint 续跑、失败轮重试。循环节点按项目主人要求原样保留，一行没动。
另加四项：出图前的预告行（几张 / 怎么跑 / 落在哪 / 带几张参考 / 大概多久——**预计用时只在有 ≥2 次本节点实测样本时才出现，取中位数，少了就不写，不编数字**）、参考图顺序可见（顺序影响出图）、跑图期间「排下一条」、失败单张单独重试。

**顺手修的真 bug**：`BulkComposer` 的「统一张数」原来只写 `run_settings.n`。加 `count_mode` 之后，批量设成 4 再单选那个节点，界面按旧 `count_mode` 显示「1 张」而运行时读 `n=4`——两边各说各的且都不报错。同族约束：`countModePatch` 必须连 `n` 一起写，因为 `generateFrom` 只读 `rs.n`（CLAUDE.md 那条「UI 上能改的参数必须回头确认运行时真的读它」）。

**兼容**：`CanvasRunSettings` 只加两个可选字段，旧画布按 `n` 反推模式（n>1 → 多张·并发），无迁移、无后端改动。
