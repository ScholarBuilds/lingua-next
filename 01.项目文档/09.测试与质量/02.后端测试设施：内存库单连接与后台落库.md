# 后端测试设施：内存库单连接与后台落库

> [!danger] 结论
>
> `tests/conftest.py` 的测试引擎是 `sqlite+aiosqlite://` + `StaticPool`：**所有 session 共用同一条 DBAPI 连接**。
> 任何在请求期间并发跑、自带 session 落库的后台任务（台账事件写入器、断流落库……），
> 都必须被 autouse fixture `_detached_session` 接管成"攒着、显式 flush 再写"，
> 否则它提交后归还连接触发的 rollback-on-return 会把请求会话刚 flush、还没 commit 的行一起回滚。

## 1. 现象

| 用例 | 表现 |
| --- | --- |
| `test_studio_m3.py::TestGptStream::test_error_keeps_generated_images` | 稳定失败：SSE 已回 `asset_id=1`，`session.get(ImageAsset, 1)` 却是 `None` |
| `test_tool_call_generates_and_ingests_image` | `-n 4` 下约一半次数同样丢行 |
| `test_image_stream.py` / `test_gemini_image.py` 若干用例 | teardown 阶段 ERROR：`engine.dispose()` 里 `do_terminate` 吃到 `CancelledError`，随后 pytest-timeout 120s |
| `test_image_tool_failure_does_not_kill_the_turn` | `SAWarning: Identity map already had an identity for ModelInvocationEvent (4,)` |

触发点：`ModelInvocationSpan.record_event` 经 `InvocationEventWriter` 入队，消费者任务在任意 `await` 点醒来，
`detached_session()` 开新 session 批量 `add_all` + `commit`。

## 2. 根因：归还连接时的 rollback-on-return 打在别人的事务上

SQLAlchemy 引擎日志的顺序**不可信**——它在语句排队进 aiosqlite 线程之前就打印。开 `aiosqlite` DEBUG 看真实执行顺序：

```text
executing commit@Connection            ← 事件写入器提交
POOL being returned to pool
executing execute@Cursor INSERT INTO image_asset …   ← 请求会话 flush（隐式 BEGIN）
POOL rollback-on-return
executing rollback@Connection          ← 写入器归还连接的 reset，把 image_asset 一起回滚
executing fetchall@Cursor              ← 请求会话取回 RETURNING id=1（行已不存在）
executing commit@Connection            ← 请求会话 commit，无事可提交
```

生产 PostgreSQL 每个 session 各占一条池连接，互不影响；只有单连接的测试引擎有这个问题。
`SAWarning` 同源：写入器批量插入被别的 reset 回滚后，SQLite 无 `AUTOINCREMENT` 关键字的 rowid 回退，下一批拿到同样的 id。
teardown ERROR 同源：消费者任务还挂在这条连接上，`engine.dispose()` 与它抢连接。

单独写脚本复现不出：`b.commit()` 自身就会归还连接，`a.flush()` 排不进 `commit` 与 `rollback` 两次 aiosqlite 操作之间；
只有并发任务才会把语句插进这条缝里。

## 3. 解法

`tests/conftest.py` 的 `BufferedEventWriter`：`append` 只攒内存，`flush` 时用原 `_write` 一次落库；
autouse fixture `_detached_session` 把 `model_invocations.event_writer` 换成它。
事件测试断言前显式 `await flush_invocation_events()`（`test_invocation_events.py` 的 `_events` 助手已如此）。

不选 `pool_reset_on_return=None`：写入器的 `commit` 仍会把请求会话的半截事务提前提交、请求会话的 `rollback` 会吞掉写入器已 flush 的事件，
时序依旧不确定；teardown 抢连接也没解决。

## 4. 预防规则

- 新增任何"自带 session 的后台落库"（`detached_session`、`asyncio.create_task` 里开 session），同步在 `_detached_session` fixture 接管：
  指向测试引擎，且不得在请求进行中并发写库。
- 调查这类丢行问题直接看 aiosqlite 层日志（`logging.getLogger("aiosqlite").setLevel(DEBUG)`），
  `sqlalchemy.engine` 的 INFO 要先放开 `sqlalchemy` 根 logger（它默认钉在 WARN）。
- xdist 下的 teardown ERROR 优先怀疑"还有任务挂在测试引擎的连接上"，不是用例本身。
