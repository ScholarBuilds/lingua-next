# UI 设计系统

> [!info] 基调决策
>
> scholar 已确认（2026-08-26 二次改版）：**清岩**双轨。工具壳（rail/topbar/appbar）冷岩灰 + 编辑蓝点缀；阅读与学习画布近白。深色模式为冷黑，壳层再深一档。令牌的唯一事实来源是 [web/src/styles/tokens.css](../../web/src/styles/tokens.css)（design/mockups/tokens.css 是它的镜像，改令牌先改 web 侧再同步镜像与此文）。

## 1. 色彩体系

### 1.1 表面（三层纵深）

| 令牌 | 浅色 | 深色 | 用途 |
| --- | --- | --- | --- |
| `--bg-shell` | #EAEDF0 | #0E1013 | 工具壳：rail、顶栏、appbar（清岩浅壳，比内容再浅一档，靠 1px 描边分界；不进内容区） |
| `--bg-sunken` | #E9EBED | #101318 | 下沉：输入槽、统计底 |
| `--bg-app` | #F4F5F6 | #15171B | 内容区底：侧栏、面板 |
| `--bg-paper` | #FBFBFA | #1B1E24 | 阅读画布（近白/冷墨） |
| `--bg-surface` | #FFFFFF | #22252C | 浮起：卡片、弹层、控制条 |

层级规律：浅色下外壳比内容区再浅一档（对比度最高的地方是书不是导航），越浮起越亮；深色下壳最暗、越浮起越亮。阅读画布只出现在内容页正文区。壳上图文有独立令牌组（`--ink-shell*`、`--border-shell`、`--bg-shell-*`），强调色用亮铜 `--accent-shell`（铜金主色在墨石底上对比度不足）。

### 1.2 墨色与主色

- 文字四档：`--ink`（暖黑正文）→ `-secondary` → `-muted` → `-faint`，浅色模式最低用 muted 档做正文辅助文字（对比度 ≥ 4.5:1），faint 只做装饰性标签。
- 主色 `--accent` 编辑蓝（浅 #1D4ED8 / 深 #8FB0FF）：只用于交互与状态（按钮、选中、进度、当前项），**不用于大面积装饰**——版面上的克制是这套设计的核心。

### 1.3 正文标记体系（五层不打架）

正文同时存在五类标记，各占一个视觉通道，任何两层叠加仍可辨认：

| 层 | 视觉通道 | 令牌 |
| --- | --- | --- |
| 生词（已收藏未掌握） | 琥珀**点状**下划线 | `--mark-vocab` |
| 词组搭配 | 青色**虚线**下划线 | `--mark-phrase` |
| 朗读当前句 | 淡蓝**底色洗** + box-decoration-break | `--wash-reading` |
| 选中词 | 深一档底色 + 加粗 | `--wash-select` |
| 批注高亮 | 四色**背景块**（黄绿粉蓝） | `--hl-*` |

规则：已掌握的词零标记；下划线一律 `text-decoration-skip-ink: none` + `text-underline-offset`（词组线不能被 g/p/y 下伸笔画切断）；不为"已掌握"设计第二种线型（旧版教训：第四层线会让页面变花）。

## 2. 字体体系

| 角色 | 字体 | 用途 |
| --- | --- | --- |
| 阅读正文 | **Literata**（Google Play Books 御用电子书衬线，可变字重）→ Georgia → Songti SC | 书籍/文章/字幕英文、学习卡单词、闪卡 |
| UI | **Inter** → 系统 → PingFang SC | 全部界面 chrome、中文译文与解释 |
| 等宽 | JetBrains Mono | 音标、时间戳、数字对齐 |

- 阅读正文默认 19px / 行高 1.9 / 行宽 ≤ 660px（约 68 字符），用户可调 16-24px；**阅读排版三项（字号/行距/行宽）独立于界面字号**。
- 中英混排原则：英文原文用衬线（阅读感），中文译文/解释用无衬线（工具感）——视觉上天然区分"原文 vs 辅助内容"，与来源三分原则呼应。

## 3. 几何与动效

- 圆角三档：6 / 10 / 14px；胶囊 999px（chip、朗读条）。
- 阴影三档，暖色调阴影（`rgba(30,25,15,…)`）配纸感；深色模式加深。
- 动效：150ms（悬停）/ 220ms（面板、主题切换），`cubic-bezier(0.25,0.8,0.35,1)`；只动 opacity/transform/background；尊重 `prefers-reduced-motion`。
- 悬停不得引起布局位移（禁 scale 引发的挤压）；可点元素一律 `cursor: pointer` + 可见反馈。

## 4. 组件规范（shadcn/ui 基底）

- 实现基底：shadcn/ui 组件源码进仓库，按本令牌重皮；图标统一 **Lucide**（stroke 1.5-2，禁 emoji 当图标）。
- 已定义的原型级组件类：`.btn`（ghost/primary/soft 三态）、`.icon-btn`、`.seg`（分段切换）、`.chip`（含 accent/ok/warn 语义）、`.card`、`.rail-item`、播放条 `.player`、学习卡 `.wordcard`。
- 学习卡宽 360px，锚定弹出（Floating UI），箭头指向锚点词；内部分区：词头（词+音标+发音）→ 标签 chips → 词典释义 → AI 语境释义（accent-soft 底突出"AI 生成"身份）→ 例句（成对含译文）→ 操作脚。
- AI 生成内容的统一视觉身份：**sparkle 图标 + accent-soft 底色块**，词典事实永远白底/surface 底——来源三分在视觉层的落实。

## 5. 深浅色

- 双主题从令牌层解决，组件不写死颜色即自动双色；深色为**冷黑**（#15171B 系）非纯黑，壳层（#0E1013）再暗一档，纸面仍比内容区亮一档。
- 三态切换：浅 / 深 / 跟随系统（`prefers-color-scheme`），全部界面同步生效不出现混色。

## 5.1 层级表（z-index）

> [!warning] 新增弹层前对照本表，不要各写各的
>
> 词卡曾经是 `z-index: 95`，低于通用弹层的 100——从语法弹窗里点词，卡片弹在弹窗底下，
> 看着像点了没反应。这类问题只在"某层从另一层里被唤起"时才暴露，写的时候很难想到。

| 层级 | 用途 | 说明 |
| --- | --- | --- |
| 10-11 | 页内定位元素 | 粘性头、浮动角标 |
| 40-90 | 页内浮层 | 选区工具条、播放器浮层、看板娘 |
| 100 | `.overlay` 通用弹层 | 语法分析、跟读工作台、音色选择、全文等 |
| 120 | 词卡 `.wm-backdrop` | **被其他层唤起**，必须压在通用弹层之上 |
| 130 / 140 | 删除确认 alert-dialog | 破坏性操作，压在词卡之上 |
| 150 | tooltip / 全局即时提示 `.itip` | 永远在最顶 |

**定层原则**：一个浮层能被哪些层唤起，它就必须高于其中最高的那层；能唤起它的层越多，位置越靠上。破坏性确认永远高于内容型浮层。

## 5.2 提示（tooltip）

全产品的交互提示走**全局事件委托**（`lib/useInstantTooltip.ts`）：组件里照常写 `title`，
悬停即刻浮出，不必改用专门组件。实现上悬停时把 `title` 摘到 `data-tip`（避免与原生提示打架），
离开时原样放回，DOM 上始终留着 `title` 给读屏与外部工具。

图标型操作除 `title` 外还要给 `aria-label`（BR-G-021）。

## 6. 可访问性底线

- 正文对比 ≥ 4.5:1（两主题均验证）；颜色不是任何状态的唯一标识（下划线样式/图标/文字并行）。
- 全部交互键盘可达；点词目标最小命中区含字符 padding；焦点环可见。
- 播放控件有加载/播放/暂停/失败四态与可读标签。
