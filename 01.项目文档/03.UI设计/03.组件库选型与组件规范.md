# 组件库选型与组件规范

> [!info] 核实状态说明
>
> 标 ✅ 的条目经 2026-08 实时核实；标 ⚠ 的按 2026 年初已知信息 + 逻辑判断给出，动工装依赖时用 `npm view <pkg> time` 花一分钟复核最新版即可。所有选择服从既定原则：组件源码可进仓库随意改（DEC-NEXT-002）、消费 tokens.css 同一套令牌、深浅色自动成立。

## 1. 分层策略

```
第 4 层  成熟实现参考 —— asbplayer / qwerty-learner / LiveKit 示例（抄交互与组件代码）
第 3 层  专项组件库 —— 播放器、波形、图表、虚拟滚动、命令面板（各找业内最佳）
第 2 层  shadcn/ui —— 通用组件（按钮/弹层/表单/菜单），源码进仓库按令牌重皮
第 1 层  无头基座 —— Base UI / Radix primitives（可访问性与交互逻辑）
```

选型铁律：**通用组件不自研、专项组件先找库、库不满足再参考开源实现二开**；所有第三方组件进仓库后统一走 `tokens.css` 变量，禁止组件自带主题色泄漏。

## 2. 基座层决策

| 库 | 状态 | 结论 |
| --- | --- | --- |
| shadcn/ui | ✅ 仍是 React + Tailwind 生态默认选择 | **采用**。CLI 拉组件源码进 `web/components/ui/`，按 tokens 重皮 |
| Base UI（@base-ui-components/react，MUI+前Radix团队） | ✅ shadcn 官方文档已提供 base 变体（`docs/components/base/*` 已上线） | **优先**：新拉组件选 Base UI 变体 |
| Radix UI Primitives | ⚠ 2025 后维护放缓（团队转向 WorkOS） | 兼容备选；个别组件 Base UI 未覆盖时用 |
| React Aria | 稳定（Adobe） | 不引入，避免第三套交互语义 |

| 候选 | 状态 | 结论 |

## 4. 按钮体系规范（已落 tokens.css + components.html）

### 4.1 层级（六档，同屏至多一个 Primary）

| 层级 | 类名 | 用途 | 示例 |
| --- | --- | --- | --- |
| Primary | `.btn-primary` | 页面唯一主动作 | 继续阅读、开始对话、导入 |
| Soft | `.btn-soft` | 强调但不夺焦的高频操作 | AI 陪读、收藏、朗读本句 |
| Outline | `.btn-outline` | 次级但需边界感 | 收藏句子、导出 |
| Ghost | `.btn` / `.btn-ghost-sm` | 低频轻操作 | 标熟、重新分析、倍速 |
| Danger | `.btn-danger`（轻）/ `.btn-danger-solid`（实） | 破坏性操作；实底仅用于二次确认框 | 结束会话 / 确认删除 |
| Icon | `.icon-btn` | 纯图标工具钮，必须带 title/aria-label | 词组开关、搜索 |

### 4.2 尺寸与状态

- 尺寸三档：sm 26px / 默认 32px / lg 40px（`.btn-sm`/`.btn-lg`）；图标钮 30px，触屏语境放大至 44px。
- 状态全集：default / hover（背景或亮度变化，无位移）/ active / **focus-visible（统一 2px accent 外环）** / disabled（opacity 0.45 + 禁点）/ **loading（spinner 替换图标，文案改进行时，禁点）**。
- 异步操作必须走 loading 态（防重复提交），完成或失败后由 toast 反馈结果。
- 破坏性操作永远不用 Primary 色；确认弹窗中确认钮在右、取消在左。

### 4.3 映射到实现

shadcn Button 的 variant 映射：`default→primary`、`secondary→soft`、`outline→outline`、`ghost→ghost`、`destructive→danger`；size 映射 `sm/default/lg`。cva 变体定义只引用 tokens 变量。

## 5. 视觉验收基准

`design/mockups/components.html` 是组件层的视觉验收基准：按钮六层级 × 状态、seg/输入框/开关/滑杆、chips 语义色、正文五层标记、toast/骨架屏、表面层级色板，深浅色均已实测。开发实现与样张不一致时，以样张 + tokens.css 为准。
