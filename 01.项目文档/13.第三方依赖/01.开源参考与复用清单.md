> [!note] 主题词表数据源的调研结论
>
> imsky/wordlists、eranimo/wordlists、lpmi-13/machine_readable_wordlists 这类"按主题分类的英文词表"**不适用于本项目**：它们面向密码生成与文字游戏，分类维度是动物/颜色/形状，不是点餐/问路/面试这种语言学习场景，且无中文释义与难度分级。场景词表改由 LLM 生成 + ECDICT 校验，学术界同款做法（LLM 候选 → 难度词表过滤 → 不足则补轮）。

## 7.4 实际引入后的版本与踩坑（2026-08-19 落地）

| 件 | 落地版本 | 引入方式 |
| --- | --- | --- |
| spaCy | 3.8.15 + `en_core_web_sm` 3.8.0 | 模型作为 URL 依赖写进 `pyproject.toml`，不靠 `spacy download`——那种装法 `uv sync` 会抹掉 |
| ERRANT | 3.0.2 | 自带一份 spaCy 实例，与 `domain/syntax` 各一份。12MB 的模型不值得为共享去动 errant 的初始化 |
| pronouncing | 0.3.0 | 只在 seed 脚本里用 |
| g2p_en | 2.1.0 | 只在 seed 脚本里用。它依赖的 nltk 语料要单独落盘，见下 |
| harper.js | 2.7.0 | 前端动态 import |
| onnxruntime | 1.28.0 | 已随 ctc-forced-aligner 装好，无需新增 |

> [!danger] 四处实际踩到的坑
>
> 1. **多语言词表的掩码不能把 CTC blank 一起屏蔽**。音素模型词表里混着别的语言的声调 token
>    （`i1`/`i5`），推理时要屏蔽。但 `<pad>`（id 0）是 CTC 的 blank，它在静音帧上概率接近 1.0——
>    一起屏蔽掉，每一帧都被迫吐一个真音素，解码结果从 `ʃ iː s ɛ l z` 变成
>    `n t k t ʃ j iː i s j ɛ l d z`。看上去像模型不准，其实是掩码写错了。
> 2. **NumPy 2 的弱标量规则会把回溯变量降成 int8**。GOP 的 Viterbi 回溯里
>    `s -= bp[t, s]`（bp 是 int8 数组）会让 `s` 变成 np.int8，序列一长就
>    `OverflowError: Python integer 148 out of bounds for int8`。显式 `int()` 转回来。
> 3. **Vite 预打包会打断 harper.js 的 wasm 定位**。它用
>    `new URL('harper_wasm_bg.wasm', import.meta.url)`，被 esbuild 预打包后这个相对 URL
>    指向 `.vite/deps/` 下不存在的路径，dev server 按 SPA 回落返回 `index.html`，
>    浏览器报 `expected magic word 00 61 73 6d, found 3c 21 44 4f`（那是 `<!DO`）。
>    解法是 `optimizeDeps: { exclude: ['harper.js'] }`。
> 4. **nltk 自带的 downloader 在受限网络下不可用**（它解析出的 CDN 地址会被 SSRF 守卫拦）。
>    改成直接拉 `raw.githubusercontent.com/nltk/nltk_data` 的 zip，解到 downloader 同样的落盘路径。
