# ADR-013：单人本地工作台，无账号体系

- 状态：accepted（2026-09-02）
- 日期：2026-09-02
- 决策人：scholar（按 [CR-006](../../../00.需求文档/07.需求变更/06.CR-006-撤销用户体系改为单人本地工作台.md) §6 默认值全部拍板）
- 修订：撤销 2026-08-25 提交 `c4c1379` 引入的用户账号、RBAC、会话、CSRF、邀请码、审计与内容发布门禁（那一批没有对应 ADR）；重申 [产品愿景](../../../00.需求文档/00.产品总览/01.产品愿景与范围.md) §3 FACT「单用户优先」与 DEC-NEXT-003「首版不做注册，账号体系留扩展点」

## 背景与约束

产品自 2026-08-25 起分成三个 SPA 入口（运营后台、learning-core、学习前台）与一套服务端身份层。代价见 CR-006 §1.2：身份层 2,192 行、前台 1,550 行、后台管理页 341 行、learning-core 843 行，40 个 router 挂门禁，16 条正则白名单决定学习者能碰哪些接口。每加一个功能都要先回答「学习者能不能用、发布了没有、走哪个壳」三个与学习无关的问题。

使用者只有 scholar 一人；局域网设备（手机、平板）偶尔用，也是同一个人。

## 决策

1. **一个入口、一个壳**：只保留 `web/`；删除 `learner-web/`、learning-core 双入口与后台管理页。没有登录、注册、发布。
2. **无登录，owner 是常量**：`app/owner.py` 的 `OWNER_ID = "owner"` 经 `CurrentOwner` 依赖注入路由；学习状态表的 `user_id` 列**保留**，值统一改写为该常量。这就是 DEC-NEXT-003 说的扩展点：将来真要多用户，是在这个依赖前面加一层鉴权、把 id 换成登录者，不是重新加列。
3. **删掉的表**：`user_account role permission user_role role_permission auth_session verification_token invite_code audit_event content_publication user_preference user_resource_progress user_word_state`。偏好回到单用户的 `user_pref`；目录投影表由学习真相表（`reading_progress`、`video_study_progress`）直接服务。
4. **多账号数据**：迁移 `d3f1a7c2e9b4` 发现任何学习表里有第二个账号就拒绝执行；先跑 `scripts/archive_other_accounts.py --apply` 把非 owner 记录导出到 `归档/` 再删。执行前 `pg_dump` 到 `server/data/backups/`（gitignored）。
5. **局域网访问**：保留为显式开关；开时可选一个共享口令（一个环境变量，浏览器首次输入后存 cookie），不建账号。参考同类本地工具：Open WebUI `WEBUI_AUTH=false`、Stirling-PDF `SECURITY_ENABLELOGIN`、ComfyUI `--listen`、AUTOMATIC1111 `--gradio-auth`。
6. **信息架构**按活动分组，不按角色（CR-006 D3–D6）：今天 / 学习 / 创作，任务与管线合一，⌘K 命令面板。这部分在 P2 落地。

## 后果

- 好：新功能不再需要回答权限与发布问题；少一个镜像、一个 nginx、一个端口；测试夹具不必再造管理员会话。
- 坏：「给别人用」这条路的前台形态彻底放弃；安全模型退到「API 只绑本机 + 局域网可选口令」，与数据库只绑 `127.0.0.1` 是同一姿态。
- 迁移不可逆：`downgrade` 直接抛错，回退只能从备份恢复。
