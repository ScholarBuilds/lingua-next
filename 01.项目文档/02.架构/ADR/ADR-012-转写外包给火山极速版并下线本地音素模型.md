# ADR-012：视频转写外包给火山极速版 ASR，本地音素模型下线

- 状态：accepted（2026-08-30）
- 日期：2026-08-30
- 决策人：scholar
- 修订：[ADR-007](ADR-007-视频字幕ASR管线选型.md) 的转写一环；影响 [ADR-011](ADR-011-音位示范音取自Commons录音与强制对齐切段.md) 的双元音切段路径

## 背景与约束

起因是部署成本：这套东西要跑起来需要三个本地模型常驻，把服务器配置顶到了不合理的高度。

| 模型 | 体积 | 职责 |
| --- | --- | --- |
| faster-whisper large-v3 (int8) | 权重 2.9GB，峰值 RSS 3.4GB | 视频转写 |
| ctc-forced-aligner (MMS-300M ONNX) | 1.2GB | 词级时间戳 |
| wav2vec2-lv-60-espeak (ONNX) | 目录 1.5GB | 发音评分的音素后验与 GOP |

scholar 的要求是「改成外包给 API 的模型」。三个并不等价，先查了能不能接：
四个已配的 LLM 中转（DeepSeek 官方、智谱中转、gpt 中转、个人中转）现拉模型清单，
**一个语音模型都没有**——没有 whisper、没有 transcribe、没有 audio。
而火山语音凭据（`provider_credential` id=5）已经在库里，实测账号已开通
大模型录音文件识别（`volc.bigasr.auc` 返回 `20000000 OK`）。

## 实测（7 条视频 / 46 分钟音频 / 5654 个同词配对，脚本 `server/scripts/compare_asr.py`）

| | whisper large-v3 int8 + CTC 对齐 | 火山极速版 |
| --- | ---: | ---: |
| 转写 46 分钟音频 | 2035s（实时率 0.739×） | 93s（0.034×） |
| 常驻内存 | 3.4 GB | 0 |
| 句末标点 | 780 | 658 |
| 逗号 | 447 | 546 |
| 零宽词跨度 | 333（占总词数 5.4%） | 0 |

词序列一致度中位 **97.7%**（范围 89.9%–100%）。速度差随时长放大：31 秒的片子
23s vs 4s，32 分钟的 video 28 是 **24 分钟 vs 58 秒**——火山耗时几乎与音频长度无关。

词级时间戳对标 CTC 强制对齐（ADR-007 里量过的声学基准，中位跨度 0.120s）：

```
绝对偏移中位  50ms（带符号 −20ms，火山一致偏早）
±50ms  内  53% ｜ ±100ms 内 79% ｜ ±200ms 内 92%
```

比 CTC 松，但**零宽跨度一个都没有**，而 whisper+CTC 那侧有 333 个
（video 28 单条 273 个，占 6.3%）——零宽跨度是渲染不出来的死数据，词高亮直接没法用。

顺带查出两件事：

- **video 10 的字幕轨整条是威尔士语。** whisper large-v3 把 213 秒英式英语误判语言，
  转出 111 条 cue、609 个词的威尔士语，而 `status` 是 `ready`，管线健康检查不查语言。
  全库 23 条 whisper 轨只有这一条坏。火山那侧是正确英文。
- **最小对立对上两边都不可靠。** video 25 讲 "Accept vs. Except"，正确文本
  "Accept, except."：whisper 写成 "Accept. Accept."、火山写成 "Except, except."，
  中间那句 "**Except** means excluding" 两边都写成了 "Accept"。既有问题，不是切换引入的。

## 决策

**一、转写默认走火山极速版，本地 whisper 保留为回落。**

选路在 `domain/transcribe.prepare_preferred_asr_route`：查到可用的 `volc_speech`
凭据就走火山，凭据缺失/被禁/解密失败一律静默落回本地。转写是整条视频管线的第一步，
不该因为一条凭据没配就整片跑不动。视频管线重跑时显式指定 `whisper_model` 视为
「我就要本地这一档」，跳过火山。

不删 faster-whisper：它是离线可用的唯一一条路，而且这次的对比脚本要靠它做对照。

**二、CTC 强制对齐保留。**

火山的词级时间戳够用但比它松（绝对偏移中位 50ms）。对齐是增强项，失败即回落，
1.2GB 换 50ms 的稳定精度值这个价——而且第 0 层发音评测的流利度与词级置信度
全靠它，删了那一层也没了。

**三、本地音素模型下线，发音评分只留第 0 层。**

这是三个里唯一**没有对应上游**的：任何 ASR API 都不返回逐帧音素概率，
而 `data/phonetics/calibration.json` 的 31 个特征（`gop_*` / `top1_*` /
`margin_p10` / `entropy_mean` / `per` / `sub_del_ins_rate`）几乎全建在那上面。
Azure 发音评估 / 讯飞 / Speechace 那类返回的是**它们自己的分**，不是音素后验——
换过去不是换 provider，是把整个评分层连同校准重做一遍。

代价如实记：ρ(accuracy)=0.687，按说话人聚类自助 CI [0.626, 0.741]，
**高于专家 vs 同行共识的人类天花板 0.651**。这个分数是真的被放弃了。
现在 `accuracy` 退回词级 CTC 置信度均值，未经人工标注校准，
界面上明说「只能自己跟自己比」。

支撑这个取舍的三件事实：

1. 前端音标模块入口已于 2026-08-23（commit 3f89807）撤下，这个模型今天唯一的
   用户可见消费方就是跟读页的「发音诊断」折叠区。
2. 它在容器里**从来没跑通过**：`.dockerignore` 排除 `data/`、`Dockerfile` 没装
   `espeak-ng`，删掉不改变任何已部署行为。
3. 存量数据一行（`pronunciation_assessment`，layer≥1）。

## 后果

**不可再生的东西，删之前存档。** `归档/2026-08-30-发音评分模型下线/` 收了
`calibration.json`、`phoneme_asr.py`、`pron_features.py`、两个校准脚本，
以及 `phoneme_ipa/` + `phoneme_demo/` 的 tar。后两者不在 git 里
（`.gitignore` 排除 `server/data/media/`）且**不可再生**：8 个双元音的音位示范音
Commons 上不存在，唯一来源是 TTS 合成 + 该模型强制对齐切段（ADR-011）。
44/44 已落盘，运行时走缓存不受影响，但从此是资产不是缓存。

要接回来：重下 speechocean762 约 500MB，重跑约 45 分钟特征抽取，再拟合。

**API 形状变了。** `/shadow/{id}/assess` 的响应去掉 `phonemes` / `layer` /
`gop` / `accuracy_source` 四个键。留着永远为空的键比去掉更糟——
前端会为一个永不触发的分支保留 UI，读接口的人以为那一层还在、只是这次没数据。

**BR-90 / BR-91 / AC-94 / AC-95 失去约束对象**，在模块 13 需求说明里划掉并注明原因，
不是删掉：真要接回音素能力，那几条要一起接回来，它们是从精度数据推出来的不是审美偏好。

**归一化开关要按用途分。** 火山的 `enable_itn` 把 "two minutes" 转成 `2 minutes`、
`enable_ddc` 删语气词与重复词。字幕开着更好读，但跟读比对要的恰恰是用户**实际读出来的词**——
开着就会把正确朗读判成错读。判据是「这段文本要拿去和另一串词逐个比吗」，
实现在 `volc_asr.transcription_options()`。
