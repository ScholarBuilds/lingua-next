# ADR-015：贾维斯执行内核用 Open Interpreter Rust App Server，审批与权限装在内核协议上

- 状态：superseded by [ADR-018](ADR-018-移除贾维斯专属运行时.md)
- 日期：2026-09-02
- 决策人：scholar（按 [CR-010](../../../00.需求文档/07.需求变更/10.CR-010-贾维斯可打断语音与常驻开关.md) 拍板）
- 关系：从 [ADR-014](ADR-014-本机代理进程与桌面壳选型.md) 决策 3 拆出；换壳与换引擎的复审周期不同，不再合写

## 背景与约束

贾维斯要在这台 Mac 上写代码、管文件、操作浏览器与第三方原生 App，并且能被语音随时打断。它需要一个带工具循环、沙箱、审批协议与流式事件的执行内核。约束：

- 服务端唯一主栈 Python 3.12（STD-STACK-002）；内核若是别的语言，只能以预编译二进制的形式作为子进程存在，仓库不含其源码。
- 个人自用不分发，但 AGPL 代码不进仓库（CR-005 反转许可证裁决时的边界仍是「不混源码」）。
- 审批与权限必须是内核协议的一部分，不能只靠提示词（CR-007 D5-2）。

## 候选方案

| 候选 | 是什么 | 许可证 | 结论 |
| --- | --- | --- | --- |
| Open Interpreter Python 0.4.3（endolith 社区维护） | `chat(stream=True)` 的 confirmation 暂停当审批门；`computer` API | AGPL-3.0 | 官方已弃、其 WebSocket 服务吞 confirmation、需独立 venv；**退役** |
| openinterpreter/01 | Open Interpreter 上的语音层（LiveKit / RealtimeSTT） | AGPL-3.0 | 2024-11 停更，依赖全废，Light 路径无打断；只抄语音人格写法 |
| **Open Interpreter Rust `interpreter` 0.0.40**（openai/codex 的 fork） | `app-server --stdio` JSON-RPC v2：`thread/turn/item` 事件、`turn/steer` / `turn/interrupt` / `thread/queue/*`、`requestApproval` 系列、`approval_policy` + permission profile、Skills / Hooks / MCP、内置 `thread/realtime/*` | Apache-2.0 | **采用** |
| 自研 PydanticAI 代理 + 自写工具（旧 `domain/computer_use.py` 路线） | Playwright 有头窗口 + 12 个工具 + 内核审批席位 | — | 只覆盖浏览器范围；重造沙箱、流式、队列等于重写一个 codex；退役，审批语义与危险词表上提复用 |

## 决定

1. 执行内核 = 本机预编译的 `interpreter app-server --stdio`（0.0.40，Apache-2.0），由 `server/domain/open_interpreter_app_server.py` 以子进程托管，`domain/jarvis.py` 编排 thread / turn；**只用它的协议，不引入其源码**。这不构成 STD-STACK-002 意义上的「引入新语言」（仓库无 Rust 源码、无构建），但二进制版本必须登记在开源复用清单并由 `scripts/jarvis_probe.py` 在升级时重跑协议探针。
2. 审批与权限装在内核协议上：`approval_policy=on-request` + `default_permissions=jarvis`（自定义 permission profile，受保护路径 deny），客户端 `ApprovalBroker` 对 `requestApproval` 分级答复、未知请求 fail-closed；不再使用 `sandbox_mode=danger-full-access` 与「一律 acceptForSession」。
3. 电脑操控经内核的 MCP 接口，但**驱动器不直连内核**：cua-driver（原生 App）与 agent-browser（浏览器）经 Lingua 的 fastmcp 门代理挂成 `/mcp/desktop`、`/mcp/browser`，每次工具调用过同一个 `kernel.approval` 席位；cua-driver 跑 API 进程私有的 `bounded + capability manifest` daemon。
4. 流式事件（`item/*/delta`）只进内存 hub，`item/completed` 才落 `computer_step`；语音编排器与页面 SSE 消费同一个 hub。
5. 语音路径禁止触达内核的无沙箱直通方法（`thread/shellCommand`、`process/*`、`command/exec*`、`fs/*`），在客户端类里一刀切。
6. 内核内置的 `thread/realtime/*`（Codex 实时语音）本期不用：握手写死 OpenAI Realtime 形状，接火山需要自研翻译层；只保留探针，等有官方 realtime 供应商或明确需要 GPT 语音人格时再评估。

## 后果

- 得到：流式、可插话（steer）、可打断、有审批协议与权限档位的内核，和 codex 生态（Skills / Hooks / MCP）同构；升级只换二进制。
- 付出：整套 `turn/steer`、`thread/queue`、permission profile、realtime 都标 experimental 且 0.0.40 才发布两周，字段随版本变——所有调用封装在 `JarvisManager` 与 `ApprovalBroker` 后面，启动握手做 `experimentalFeature/list` 运行时探测，每条能力都有退路（steer 拒 → queue → interrupt+start；profile 拒 → `sandbox_mode=workspace-write` + 限期例外）。
- 旧 Playwright 执行器、Python 0.4.3 venv、`engine_runner/` 全部删除；`computer_session` / `computer_step` 两张表保留。

## 验证与复审日期

- 验证：`server/scripts/jarvis_probe.py` 的协议探针（M0）；`tests/fake_app_server.py` 剧本上的 `test_jarvis*`；真机五类危险动作弹卡、`cat server/.env` 在 profile 下被拒、急停后 `cua-driver revoke --all` 生效（CR-010 M3）。
- 复审：interpreter 升级到删除或改名上述任一方法时；出现可直接配置自定义 realtime 端点且协议不写死的版本时；或本机需要多会话并行时。
