# ADR-016：统一贾维斯本体并采用可恢复的桌面本地运行时

- 状态：superseded by [ADR-018](ADR-018-移除贾维斯专属运行时.md)
- 日期：2026-09-03
- 决策人：scholar
- 来源：[CR-012](../../../00.需求文档/07.需求变更/12.CR-012-NEXUS贾维斯本体内核与桌面运行时.md)

## 背景与约束

语音前台、普通助理和 Rust App Server 各自持有上下文；ComputerSession 和进程内事件不能表达跨重启任务；当前 Electron 包仍依赖仓库、uv、PostgreSQL 和 Redis。NEXUS 要作为单人本地工作台通过官网 DMG 分发，并允许用户配置自己的模型凭据。

## 驱动因素

- 身份、上下文、记忆与审批在所有入口保持一致。
- 长任务可暂停、恢复、取消和审计。
- 结构化工具优先，视觉操作只承担无正式接口时的最后一段。
- 待唤醒音频不上云，密钥只留在本地保险箱。
- 干净 Mac 不安装开发工具也能运行。

## 候选方案

| 方案 | 结论 |
| --- | --- |
| 继续扩充 ComputerSession 与进程内 hub | 无法稳定承载跨入口身份、长期任务和断线补齐，拒绝 |
| 引入另一套 actor/DAG 框架替换 StudioFlow | 形成重复调度器和迁移成本，拒绝 |
| Jarvis Kernel + StudioFlow + App Server | 采用；Kernel 管状态与策略，StudioFlow 管持久 DAG，App Server 管节点内代理循环 |
| 桌面继续依赖 PostgreSQL/Redis/Docker | 不满足下载安装即用，拒绝 |
| 桌面 SQLite WAL + 数据库队列，服务器档保留原栈 | 采用 |

## 决定

1. 新增 conversation、turn、mission、event、command、memory、announcement 七类持久对象。语义状态先写事件与投影，再向页面和语音广播。
2. StudioFlow 是唯一持久 DAG。Mission 通过 `mission_id` 关联 StudioFlowRun、StudioTask 和兼容期 ComputerSession；恢复依赖 checkpoint，不恢复失效的模型连接。
3. 本地队列至少一次投递，通过 idempotency key、lease 和 generation fencing 避免重复副作用与旧 worker 回写。
4. 工具按业务 API、外部 API/MCP、浏览器 DOM、macOS Accessibility、视觉 CUA 排序；MCP 是连接协议，不是电脑控制内核。
5. 桌面档以 SQLite 基线启动，sidecar 与必要 arm64 可执行文件随应用交付；运行数据与 0600 凭据主密钥文件存 Application Support，桌面运行时不访问 Keychain。
6. PostgreSQL + Redis/Arq 保留为开发与服务器档，通过领域端口与桌面实现共享业务逻辑。
7. 官网包采用固定 `com.lingua.nexus`、Developer ID、Hardened Runtime、公证与签名更新清单。
8. 熟人内测使用隔离的 ad-hoc 构建档，保留 Hardened Runtime 与所需 entitlement，不启用正式更新；官网发布要求不变。

## 后果

- 得到统一身份、可恢复任务、持久事件和可独立安装的产品边界。
- 付出 SQLite/服务器双运行档、历史数据迁移、嵌套二进制签名和更完整的故障测试。
- 高频音频与 token 不逐条持久化；它们必须带 trace 与持久轮次标识，避免数据库写入破坏实时性。
- CuaDriver 保持上游签名身份；若发布授权未确认，应用只下载并校验固定官方产物。
- 桌面启动令牌通过限定当次回环 Origin 的请求头注入，不写持久 Cookie，避免 Electron Safe Storage 引入额外的 Keychain 交互。

## 验证与复审日期

- 验证：CR-012 各阶段门禁、进程中断恢复、干净 Mac 安装、签名与公证检查。
- 复审：需要 Intel 支持、进入 Mac App Store、改用托管账号或 StudioFlow 无法表达目标任务时。

## 实施状态

Kernel 持久对象、Mission/StudioFlow 关联、SQLite 恢复队列、工具合同、长期记忆确认、自包含 sidecar、迁移工具、首启向导、持久事件补齐和发布脚本已落地。桌面运行时将 Open Interpreter 的 `interpreter` 与 `codex-code-mode-host` 成对打包，后者单独取得 V8/JIT 所需 entitlement；安装包已完成真实原生应用启动验证。CR-012 标记为“开发实现完成，公开发布门待验证”；Developer ID 公证、官网更新源发布和干净 Mac 验收仍是外部发布门。
