# ADR-011：音位示范音取自 Commons 独立录音，双元音走强制对齐切段

- 状态：accepted（2026-08-23）；**切段那一半于 2026-08-30 由 [ADR-012](ADR-012-转写外包给火山极速版并下线本地音素模型.md) 修订**
  —— 强制对齐所依赖的音素模型已下线，8 个双元音的示范音**不可再生**。
  磁盘上 44/44 都在且运行时走缓存，播放不受影响；本 ADR 的 Commons 那一半仍然成立。
  `server/data/media/phoneme_ipa/` 自此按不可再生资产对待，
  备份在 `归档/2026-08-30-发音评分模型下线/phoneme-audio-不可再生.tar.gz`（它不在 git 里）。
- 日期：2026-08-23
- 决策人：scholar

## 背景与约束

模块 13 的音位表上，点一个音标应该听到**那个音标的音**。

首版没有做到：点 /θ/ 播的是例词 `think`。旧代码的注释写明了理由——
「音位本身没法单独合成，把 /θ/ 丢给 TTS 得到的是字母名」。

**前半句成立，由它推出的结论不成立。** 合成不出来不等于拿不到：
语音学家早就把 IPA 的每个音段逐个录下来了，Wikipedia 的 IPA 表、ipachart.com
用的都是同一批录音。这是「抄开源优先」原则该起作用的地方，而首版把它做成了自研判断题。

硬约束：

- 44 个音位一个都不能哑。取不到要明说，不能给一个点了没反应的按钮（核心原则 4）。
- 音源的许可事实要登记，要署名的必须在界面上署名。
- 运行时不该依赖公网音源站的可用性。
- 不引入新的重量级依赖（对齐、合成两条链路仓里都已经在跑）。

## 选项对比

| 选项 | 优点 | 缺点 |
| --- | --- | --- |
| A. 维持现状，播例词 | 零成本 | **答非所问**。用户点的是音标，听到的是单词，这正是本次重构要修的那件事 |
| B. 把 IPA 符号丢给 TTS | 无新音源 | **实测不可行**，见下方「TTS 读不了 IPA 符号」 |
| C. 自己录 44 个音 | 音色统一 | 非母语者录 IPA 示范音，教学上不可接受 |
| D. **Commons 独立音位录音 + 双元音走强制对齐切段** | 语音学家录制；36/44 直接可得；对齐链路仓里已有 | 需要落地缓存与署名；双元音要另走一条路 |

## 决策

**采纳 D，两条音源按覆盖面分工：**

| 策略 | 覆盖 | 来源 |
| --- | --- | --- |
| `commons` | 12 单元音 + 24 辅音 = 36 个 | Wikimedia Commons 独立音位录音 |
| `word-clip` | 8 个双元音 | 项目自有 TTS 合成示范词，按已有的强制对齐结果切段 |

### 双元音为什么必须分出来

Commons 收的是**单个音段**，没有 /eɪ/ 这类滑动音。逐个试过 `Diphthong *.ogg`
与各种组合式描述标题，全部 missing；按分类搜也只有无关结果。这个结论是实测的，不是推断。

切段不需要新依赖：`/phonetics/word/{w}/timings` 早就在为「逐音素高亮」做强制对齐
（FR-392h，用第 2 层 GOP 的同一条 Viterbi 路径，**没有引 MFA**），同一份时间戳直接拿来定位。

### 三档发音在界面上分开给

语义不同就不合成一个「播放」按钮：

| 档 | 听到的 | 用途 |
| --- | --- | --- |
| 音标本身 | /θ/ 就是那个摩擦音 | 认识这个音 |
| 在词里 | 真词里切出的那一段 | 听它在语流里的样子 |
| 整词 | 完整例词 | 听完整的词 |

### 预热是内容生产期的事，不是运行时的事

这批文件性质等同 `web/public/phonetics/*.svg` 那 51 张剖面图——**静态内容**。
`scripts/seed_phoneme_audio.py` 离线跑一次落盘，运行时零外网依赖。
按需拉取的路径保留作兜底，但不是主路径（理由见下）。

## 影响

- 新增 `domain/phoneme_audio.py`（取源与缓存）、`domain/phoneme_audio_sources.py`（44 条出处表）。
- 新增 `GET /phonetics/phonemes/{symbol}/audio`；`_card_public` 增加 `audio` 字段透出出处。
- **署名义务**：Commons 这批 35 条是 CC BY-SA 3.0（`dʒ` 为 Public domain），
  `PhonemeCard` 常驻显示来源行。这是许可要求，不是可选装饰。
- 与 BR-93 的来源可见原则一致：「语音学家录的独立音位」与「从合成词里切的一段」
  在界面上可区分，后者明说切自哪个词。

## TTS 读不了 IPA 符号（2026-08-23 实测）

首版排除 TTS 的理由是「合成器读的是字符名」。这条结论后来被质疑过——
既然已经接了火山豆包 seed-tts-2.0，为什么不用它读音标？**实测了，不行。**

判定不靠耳朵：合成后用本仓的音素识别模型（`wav2vec2-lv-60-espeak`，
FR-398d 那套）把音频转回音素序列，客观看它读出了什么。

| 喂给火山 TTS | 识别出的音素 | |
| --- | --- | --- |
| `θ` | /t aɪ a/ | ❌ |
| `/θ/` | /s eɪ d a/ | ❌ |
| `ə` | /ʔ a l/ | ❌ |
| `ŋ` | 识别不出 | ❌ |
| `ʃ` | /ʃ/ | ✅（碰巧） |
| `think`（对照） | /t i ŋ/ | ✅ 词正常 |

六个里五个错。原因是 TTS 的前端会把非常用字符按字符名或最近的读音归一化，
这是文本归一化层的行为，不是音色或模型质量问题——换音色、换供应商都不解决。

我们的火山接入只发纯文本（`req_params.text`），没有走 SSML；
即便走 SSML 的 `<phoneme>` 标签，孤立辅音也不是合成器擅长的形态。
**所以 Commons 那条路不是「暂时的将就」，是这件事唯一可行的做法。**

不过这个问题带出了两件该做的事，见下节。

## TTS 该用在哪：示范词，而且要跟随用户配置

**降级音源。** Commons 会限流，一封十分钟。既然切段那条链路完全在本地，
就让它兜底：Commons 取不到时自动从该音位的例词切一段，而不是给 503。
覆盖因此变成 44/44 不依赖外网。降级的条目在缓存元数据里标 `degraded_from`，
`seed_phoneme_audio.py` 见到就重取原版——否则「一次限流 = 永远是降级版」。

**出处必须报实际那一份。** 降级之后如果还按计划报「Wikimedia Commons，CC BY-SA 3.0」，
就是给本项目自己合成的音频挂了别人的许可证，比不署名更糟。
`_audio_public` 因此改为读磁盘上的缓存元数据，不读计划表。

**示范词合成跟随场景绑定，不再硬编码 Edge。** 原先写死 `plugin_id="edge-tts"`，
等于绕过整个设置页——用户把火山配成了每个场景的默认音色，音标模块却自己用 Edge。
现在走 `tts-word` 绑定，火山返回的是流式音频，收干净再落盘。

**口音记要求不记音色 id。** 央化双元音要英音是硬要求，但音色 id 各家专有
（Edge 是 `en-GB-SoniaNeural`，火山是 `en_female_authoritative-british_uranus_bigtts`）。
表里存 `clip_accent="en-GB"`，由路由层按当前供应商挑——写死任何一家，
换供应商时这三个音位会悄悄退回美音，错得没有任何迹象。

## 三条实测踩坑

**一、Commons 的命名不自洽，靠猜必错。** `/r/` 要用不带 Voiced 的
`Alveolar approximant`——带 Voiced 的那个标题会重定向到
`Voiced alveolar non-sibilant fricative`，是**另一个音**；`/w/` 只有 `labio-velar`
写法，`labial-velar` 不存在；`/s/ /z/` 要 `sibilant` 不要 `fricative`。
而鼻音与 `j l r` 又都不带 Voiced 前缀，塞音擦音却带。44 条逐个打 API 验证过。

**二、逐个解析当场吃 429，而重试会让惩罚越滚越大。** 6 路并发预热立刻被限流，
`Retry-After` 从 10 秒一路升到 600 秒。根因有两层：解析用了 36 次请求（应该
一次带 50 个标题批量解析），以及**重试时等的比 `Retry-After` 要求的短**——
等 8 秒就再敲一次，每次重试都踩在惩罚窗口里。现在批量解析 + 要么照等要么当场认输。

**三、对齐侧用 r 化音素集，教学符号对不上。** `tour` 对出来是 `ʊɹ` 不是教学写的
`ʊə`，`here` 是 `ɪɹ`。不给等价写法，三个央化双元音的示范音永远是 503。
另外这三个音**美音里根本不存在**，示范词必须指定英音音色合成。

**四、对齐给的词尾边界偏早。** 实测 `no` 的 /əʊ/ 只报 80ms、`they` 的 /eɪ/ 报 100ms，
而重读的词尾双元音实际有 200ms 以上，余下的被算进了「静音」。按报的边界切出来
是掐掉滑动尾巴的半个音——正好丢掉双元音最要紧的那一段。词尾音素额外后延 220ms 后
切出 0.28–0.40s，才是完整的双元音。
